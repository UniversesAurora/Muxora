# Muxora 终端键盘标记模式设计

状态：行为、命令与适配要求；尚未实现、构建或运行测试。

关联：[V0 设计](v0-design.md)、[工作区设计](workspace-design.md)、[设置与命令设计](settings-and-commands-design.md)、[工程设计](../development/engineering-design.md)、[自动化测试规范](../development/testing-design.md)。

## 1. 使用目标

用户进入本地 Normal 模式后，可以用键盘浏览当前终端保留的内容，按字符、单词、行、页面或缓冲区边界移动，再进入字符、整行或矩形 Visual 模式选择和复制。浏览不要求始终带着选区；终端中的远端程序继续运行和输出。

这是 V0 必需功能，进入方式、浏览、选择、查找、复制和退出全部进入统一命令与快捷键系统。默认提供 Vim 风格按键，并允许用户修改。V0 范围是终端内容的浏览与选择，不实现编辑终端内容、Vim 寄存器、宏、完整操作符／文本对象语法或 Vim 插件兼容。

Windows Terminal 的 mark mode 提供键盘移动、按词／行／页导航、扩选、端点切换、矩形选择及复制。Muxora 参考这些能力，再增加独立 Normal 浏览状态和可配置的 Vim 风格绑定。[Windows Terminal 选择说明](https://learn.microsoft.com/en-us/windows/terminal/selection)、[动作说明](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/actions)

## 2. 每个终端的状态

状态属于稳定的 `TerminalId`，不属于某个 QWidget、窗口或当前全局焦点。一个终端有自己的本地浏览光标、视口、选区、查找、待完成按键和计数。远端程序的真实终端光标仍由 VT 核心管理，本地浏览光标不能修改它。

| 状态 | 行为 |
| --- | --- |
| `remoteInput` | 正常远端输入。未被应用命令消费的键交给终端输入编码器并发送 SSH。 |
| `normal` | 本地浏览。移动浏览光标，默认没有选区，普通字符不发送 SSH。 |
| `visualChar` | 从锚点到活动端点选择连续文本。 |
| `visualLine` | 选择锚点和活动端点涉及的完整逻辑行。 |
| `visualBlock` | 按终端显示行与单元格列选择矩形区域。 |
| `findInput` | 临时查找输入上下文，记住进入前的 Normal／Visual 状态与位置；文本交给搜索框。 |

进入标记模式从 `remoteInput` 转为 `normal`。默认初始位置是当前视口内的远端光标；光标不在视口内时，从视口第一条可选文本的有效单元格开始，保留用户正在查看的历史位置。

状态转换明确如下：

- `normal` 中 `v`、`V`、`Ctrl+v` 进入相应 Visual 状态，并以当前浏览位置设锚点。
- Visual 中再次执行相同选择模式命令，清除选区并返回 `normal`；执行其他选择模式命令则转换选区类型。
- Visual 中 `Esc` 清除选区并返回 `normal`；`normal` 中 `Esc` 或 `i` 返回 `remoteInput`。
- Visual 中 `i` 通过同一个退出命令直接返回 `remoteInput`。这次 `i` 事件仅用于退出，不作为远端输入重新发送。
- `y` 或 `Enter` 成功复制后清除选区，返回 `normal`。下一次普通按键仍用于本地浏览，用户通过 `i` 或 `Esc` 明确恢复远端输入。
- 没有选区时，复制命令不可用，`Enter` 不执行远端回车。错误或取消的复制保留当前模式与选区。
- `findInput` 中 `Esc` 关闭搜索框并回到进入前的模式、位置和选区；确认查找后恢复原模式并移动到结果。没有结果则保持原位置。

以上都是可配置的默认按键。若有待完成序列或数字计数，默认 Esc 先执行公共 `keybindings.cancelPending` 并消费事件，不同时退出模式；再次 Esc 才执行上述状态转换。

界面在终端自己的信息栏或局部提示中显示 Normal／Visual／查找状态、选区类型及待完成前缀。信息栏关闭时仍保留可见模式标识，避免用户误以为正在输入 Shell。状态提示更新不能抢走终端焦点。

## 3. 默认浏览与选择

以下按键是可覆盖的默认绑定。`gg` 表示连续两次 `g`，大小写 `G` 单独表示大写字母；它们有不同命令语义。

| 默认按键 | 命令行为 |
| --- | --- |
| 箭头、`h/j/k/l` | 左／下／上／右移动。上下按显示行，尽量保持目标单元格列；左右按完整字素移动。 |
| `w/b/e` | 后一个词起点、前一个词起点、当前或后一个词末尾。 |
| `0/^/$` | 当前逻辑行开头、首个非空白字符、结尾。 |
| `gg/G` | 当前屏幕上下文中仍保留内容的顶部／最新底部。 |
| `Ctrl+u/Ctrl+d` | 上／下半页。 |
| `Ctrl+b/Ctrl+f`、`PageUp/PageDown` | 上／下一页。 |
| `v/V/Ctrl+v` | 字符／整行／矩形选择。 |
| `o` | 在 Visual 模式切换活动端点；相应更新移动方向和可见端点标记。 |
| `y`、`Enter` | 复制现有选区，并回到 Normal。 |
| `/`、`?` | 打开向前／向后查找输入。 |
| `n/N` | 按最近查找方向／反方向定位后一个结果。 |
| `Esc` | Visual 返回 Normal；Normal 返回远端输入；搜索框取消查找输入。 |
| `i` | Normal 或 Visual 明确恢复远端输入。 |

逻辑行以真实换行分隔，自动折行后的多个显示行仍属于同一逻辑行。`0/^/$` 和整行选择采用逻辑行语义；上下移动、页面和矩形采用显示行语义。左右默认不跨逻辑行边界，跨自动折行仍在同一逻辑行内。单词移动使用明确的分隔符规则，与选词保持一致；空白、标点、中文、路径和 Unicode 样例必须有独立预期，不以当前实现反推规则。

Visual 中的移动命令更新活动端点，保留锚点；Normal 中只移动本地浏览光标。字素边界和终端占格尽量由核心公开接口提供。不能按 UTF-8 字节、UTF-16 代码单元或一个屏幕像素代表一个字符。

`gg` 只能访问当前保留的历史，不读取已经淘汰的内容，也不重新登录服务器获取旧输出。`G` 到当前最新底部；当前模式仍然保持 Normal／Visual，不能因此恢复远端输入。处于备用屏时只浏览该屏幕可用内容，不凭空合并主屏历史。

## 4. 统一命令与快捷键

所有行为通过公开命令执行。示意命令为 `terminal.markMode.enter`、`terminal.markMode.exit`、`terminal.markMode.move`、`terminal.markMode.setSelection`、`terminal.markMode.swapEndpoint`、`terminal.markMode.copy`、`terminal.markMode.find`、`terminal.markMode.findNext` 和 `terminal.markMode.appendCount`。移动命令使用 `motion` 表示字符、词、行、页或缓冲区边界动作，支持的动作另接受有界 `count`；例如 `motion: "bufferStart"` 表示 gg。复制命令可以接受成功后保留／清除选区等显式参数。

菜单、右键菜单、命令面板、快捷键和测试调用同一命令，不能为 Vim 按键另外建立一套不可修改的分发器。命令是否可用由当前状态决定：无选区时复制不可用，连接已断开时仍可浏览当前保留的内容，终端关闭后命令不能操作旧实例。

快捷键采用与应用一致的 `key`、`command`、`args`、`when` 结构。多键序列直接写在 `key` 中，例如 `"g g"`；不增加一套独立的 Vim 快捷键文件或第二种序列字段。

上下文包括 `terminalFocus`、字符串 `terminalMode`、`terminalMarkMode`、`terminalVisualMode` 和 `textInputFocus`。`terminalMarkMode` 表示非 `remoteInput`，`terminalVisualMode` 表示三个 Visual 状态。浏览绑定需要终端内容获得焦点，并排除搜索框、设置编辑器和命令面板的文本输入上下文。

数字计数是统一解析器对 `normal/visualChar/visualLine/visualBlock` 的有限前缀支持。示例 `5j`、`3w` 将 `count` 注入声明支持计数的公共移动命令，Visual 中按同样动作扩选。数字前缀通过公开追加计数命令和默认绑定设置，可以重新绑定或禁用，不藏在另一套固定按键表中。V0 计数范围为 1 至 9999，`0` 无计数时执行行首、有计数时追加零，由上下文规则表达；超界、零值及非法参数拒绝执行并提示，不分配相应规模的任务队列。计数不进入普通业务命令、不影响远端输入或搜索文本、不实现完整 Vim 语法；V0 的绝对顶部／底部命令不接受行号计数。

`g` 前缀、快捷键组合和数字计数使用统一解析器的有界超时及可观察提示。默认序列超时采用应用统一设置，不能为标记模式增加隐蔽的另一套时间规则。完整绑定与前缀按用户层优先、同层逆序选出唯一候选，完整绑定获胜立即执行，前缀获胜等待；失败不会自动执行较低优先级单键。无效续键取消并消费当前序列，不重新执行为新输入，原事件不能补发 SSH。进入文本输入、切换终端、打开命令面板、移动窗口导致焦点变化时取消待完成序列与计数。公共 `keybindings.cancelPending` 可绑定取消键，默认 Esc 只取消待完成状态。

Normal／Visual 的普通字母绑定只在对应上下文生效，不能接管全局 `Ctrl+k` 类命令序列。多层绑定依照统一优先级和用户覆盖规则选择唯一命令；冲突能在快捷键界面和诊断结果中解释。调用普通业务命令后清除计数，不把先前的 `5` 带到关闭标签或传输命令。

全局行为选项进入 `settings.json` 的 `terminal.markMode.*` 范围，默认键位进入内置快捷键，用户修改进入 `keybindings.json`。当前模式、锚点、查找结果和未完成序列属于运行状态，不能保存到全局设置文件。

## 5. 输入与远端的边界

应用先处理文本输入上下文、已注册命令和当前本地模式，再决定是否调用终端输入编码器。Normal／Visual 的按键只在本地解析；未知字符、无效序列和未绑定按键也不能自动恢复远端输入。用户可以执行明确的退出命令，模式提示应显示这一方式。

`Ctrl+c` 在远端输入模式下保留向远端发送中断的默认语义；标记模式可绑定本地复制，不能因没有选区而发送中断。重新绑定这些键也要遵循上下文，不能通过远端回退绕过本地模式。

标记模式不停止 SSH 读取、心跳、终端协议回复或 VT 解析。终端查询的协议回复仍由核心经传输层返回；“不向 SSH 发送按键”不代表禁止必要的协议回复。

输入法预编辑及提交交给当前文本输入控件。搜索框里的 `h`、`j`、`g` 和数字是搜索文本，不能触发浏览；IME 提交不重复触发快捷键，也不泄漏到远端。命令面板打开时暂停终端键上下文，关闭后恢复原模式；面板取消不等于退出 Normal。

恢复 `remoteInput` 时，默认滚回最新底部并显示真实终端光标，再启用正常输入。这次退出按键不会重新发送。以后若提供保留视口选项，应单独说明如何显示离屏输入状态，并建立相应测试。

## 6. 视口、持续输出与引用

Normal／Visual 中点击有效文本位置将浏览光标移到该位置并返回无选区的 Normal；拖选进入字符 Visual，按矩形选择修饰键拖选进入矩形 Visual，双击选词、三击选完整逻辑行。鼠标与键盘共用同一核心选区，随后 `o`、移动或复制可以接续；这些事件不发送远端鼠标报告。`remoteInput` 中的鼠标报告及本地强制选择沿用普通终端策略，不因一次鼠标操作自动进入 Normal。

进入 Normal 后默认关闭跟随输出，浏览移动按需要滚动本地视口；正在进行的远端输出继续更新核心和实际显示内容。此处冻结的是自动跟随行为，不是终端数据。选中位置的内容若被远端重写，界面按当前内容更新，复制当前可见版本；V0 不承诺进入时整份终端内容保持不变。

本地浏览光标及选区端点使用可跟踪的核心位置。每次读取、调整、格式化与更新选区，在终端的串行访问边界内重新获取有效快照，不缓存跨 VT 写入的裸引用。resize 重排后按核心映射更新位置与视口；单独保留旧行列数字不足以证明选区仍正确。

历史淘汰、reset、清屏或主屏／备用屏切换时检查端点归属和有效性。端点失效则清除选区并回到 Normal，在当前视口重新确定有效浏览位置，并显示原因；不能将旧端点自动指向一段无关新内容。无可选内容时保留 Normal 的空状态，移动与复制不可用。屏幕切换还应取消待完成前缀和查找临时输入，避免旧屏状态作用于新屏。

拖出、合并或跨窗口移动同一终端时保留 `TerminalId`、模式和有效选区，按新的尺寸与 DPI 重算显示；不能重建 SSH 会话或复制历史。每个窗格独立保存模式，只有获得焦点的窗格接收命令。隐藏窗格继续处理有预算的输出，可以跳过绘制，不能改变其选择归属。

关闭终端释放选择、跟踪位置、查找任务和视图缓存；迟到的搜索或复制结果不能作用于新建的同名会话。重新连接创建新终端实例时从 `remoteInput` 开始，不复用旧核心的引用或未完成序列。

## 7. 复制与内存

字符选择默认将自动折行合回连续文本，只保留真实换行。整行选择覆盖完整逻辑行；矩形选择按显示行分别输出，用换行分隔，不将各行接成一条。端点规范化到完整字素，不能复制半个中文宽字、组合字符或 Emoji。是否清理尾部空格和采用单行复制属于明确的设置／命令参数，不能悄悄改变原文本。

选区对象只保存状态及位置，不能为了方便导航复制完整 scrollback。复制时从当前有效选区提取有界文本快照，再交给系统剪贴板；保存的终端实例、屏幕和任务代次用于验证提交目标。快照和该次选区显示采用同一核心版本，不能混合旧高亮与新文本；之后的远端更新不改变已经生成的快照。可以复用流式 formatter 减少临时分配，但系统剪贴板要求的最终文本仍计入资源预算。

V0 必须有明确的复制字节上限及选区处理时间预算；实际值在原型基线建立时写入受审阅的测试配置。超过预算时保持选区并说明原因，可缩小选择或使用另行提供的导出命令，不能截断后报告复制成功、无界扩展缓存或阻塞 UI。为诊断和渲染保留的快照同样有界，不持久化真实终端内容。

## 8. 查找

`/`、`?` 打开本地查找框，普通字符、光标移动和 IME 提交遵循文本控件规则。查找记住方向，`n/N` 在 Normal／Visual 中按最近方向或反方向定位。当前查找是否到达底部后循环采用显式设置并提示，不能让导航结果不可解释。

V0 按固定核心版本的真实能力提供纯文本匹配和相应大小写选项。不能将 ASCII 忽略大小写描述成完整 Unicode 折叠，也不默认承诺正则、完整 Vim 搜索语法或已淘汰历史。不能支持的选项不可显示为可用。

Normal 查找定位只移动浏览光标；Visual 查找定位更新活动端点，锚点保持不变。取消搜索输入恢复进入前的位置与选区；历史变化导致原位置失效时按前述失效规则处理，不能恢复悬空引用。

大历史查找分步推进、允许取消，工作量与结果缓存受预算约束。当前活动终端的查找不得长期阻塞其他终端解析或绘制；关闭、替换查询或新结果到达时，以查询代次丢弃旧任务结果。

## 9. libghostty-vt 适配依据

截至本次核对，Ghostty `main` 的公开 C API 已包含选词、选行、矩形选择、端点调整、文本提取和可跟踪位置；核心选择与公开搜索可用于减少宿主自写逻辑。API 本身仍声明未稳定。实现前固定实际 commit、Zig 版本及构建选项，在小适配层验证行为，不能凭 `main` 的说明承诺所有未来版本直接可用。

核心负责 VT、终端状态、字素／单元格语义、位置跟踪、选择与格式化的可用能力。宿主负责 Normal／Visual 状态、命令上下文、快捷键配置、本地浏览光标、视口策略、Qt 输入法、提示和系统剪贴板。需要补充的导航行为只在适配或交互层实现，不能重新编写 VT 解析器。

特别注意 `gg/G` 的缓冲区边界与 API 的 screen home/end 不一定相同；需要根据当前屏幕可访问的 grid 范围定位，不能机械映射名称。选词 API 也不能自动证明 `w/b/e` 完全符合本设计，必须用边界样例验证。

公开证据：[API 状态](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty/vt.h)、[选择与文本提取](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty/vt/selection.h)、[终端选择状态](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty/vt/terminal.h)、[跟踪位置](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty/vt/grid_ref_tracked.h)、[文本格式化](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty/vt/formatter.h)、[搜索](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty/vt/search.h)。以上 `main` 链接用于设计核对；依赖清单必须另外记录最终选用的固定 commit。

## 10. 完整自动化覆盖

每条需求建立稳定 ID 和独立的预期。模型、真实核心适配、桌面输入、真实 SSH 字节及资源测试一起证明功能，不能只调用内部移动函数或观察选区颜色。

| 需求组 | 必需用例与断言 |
| --- | --- |
| `MARK-STATE` | 全部状态转换、无选区复制、复制失败、Visual Esc 到 Normal、Normal Esc／i 到远端输入；退出事件不补发，复制后按键仍本地处理。 |
| `MARK-KEY` | 默认键、用户覆盖、命令面板调用、参数校验、冲突解释、全局组合键、单键与多键、计数上下限、0／gg／G 区分、超时与焦点变化；事件恰好执行一次。 |
| `MARK-INPUT` | 用真实 SSH 测试服务记录收到的字节；Normal／Visual 的未知键、失效前缀、Ctrl+c、Enter、IME 与取消均零按键泄漏；远端输入和必要协议回复仍正常。 |
| `MARK-NAV` | 字符、词、逻辑行、显示行、页、半页、顶部和底部；空白、空行、无历史、只有历史、旧内容淘汰、软换行、边界计数；输入固定样例并比对精确位置。 |
| `MARK-UNICODE` | 中文宽字、组合字符、Emoji、多代码点字素、路径与标点、混合字体；移动不拆字符，复制与预期字节一致，矩形边界不产生半字符。 |
| `MARK-SELECT` | 正向／反向字符、整行、矩形、交换端点、选择模式转换、鼠标选择接续、键盘可见端点；锚点、方向及复制规则一致。 |
| `MARK-LIVE` | 持续输出、同位置改写、历史淘汰、resize 重排、reset、清屏、进入／离开 vim／tmux 等备用屏；不误指新内容，不持有失效引用。 |
| `MARK-FIND` | 正反搜索、n／N、大小写能力、无结果、取消恢复、Visual 中搜索扩选、软换行、旧查询失效、输出中结果变化；不把搜索输入解释为移动。 |
| `MARK-FOCUS` | IME 预编辑／提交、搜索框、命令面板、弹窗、多窗格、隐藏标签、跨窗口拖出／合并；模式属于正确 TerminalId，前缀不跨焦点，目标不串会话。 |
| `MARK-DPI` | 100% 至 250%、跨屏、resize、宽字符；浏览光标、选区、高亮、命中和候选窗按当前 DPI 一致显示。 |
| `MARK-RESOURCE` | 大历史、长选区、计数上限、并行搜索、反复进入／退出、复制取消、关闭／重连；有界快照、预算失败、引用与任务释放及迟到结果隔离。 |
| `MARK-PACKAGE` | 干净 Windows 中用最终发行包、固定核心和测试 SSH 服务，完成键盘浏览、搜索、复制及恢复远端输入；验证同一发布产物。 |

性能沿用工程文档的 Release 参考环境与经审阅的基线，分别测本地按键响应、搜索调度、复制准备、终端解析和内存趋势。测试配置固定历史规模、输出速率、循环次数、计数、复制上限、耗时及允许增长，不能随失败缩减负载或放宽阈值。

适配层用真实固定版本核心测试引用失效、分配失败、取消和线程访问边界；桌面测试检查焦点、文本输入和视觉位置，真实 SSH 测试检查字节。随机操作保留 seed 与可重放序列；失败后修复问题并保留回归用例。

所有测试遵守[自动化测试规范](../development/testing-design.md)：禁止删用例、改预期、跳过必需场景、放宽标准或反复重试掩盖失败。未执行、环境阻塞、不稳定和跳过均不算通过。本文件仅定义要求，不能作为已建立测试链路或已经通过验收的证据。
