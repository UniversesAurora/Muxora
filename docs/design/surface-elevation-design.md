# 表面与阴影设计

状态：设计要求。实施状态见 [8.28](../roadmap/implementation/phase-8-ui-quality.md#828-标签与卡片的一体表面和阴影)。

本文是“表面”的权威规则：标签组卡片、活动标签和它们的阴影、焦点怎样用高度表示、两块表面怎样接成一体。标签栏的排列和尺寸见 [标签栏设计](tab-strip-design.md)，卡片的间距和窗格分隔见 [窗口交互细则 · 标签组卡片与焦点](window-interaction-design.md#标签组卡片与焦点)。

用户 2026-10-25 提出：活动标签和它的内容像现实里的一张带标签的卡片，接成一体、没有缝；去掉卡片的强调色描边，焦点改用“抬得更高”的阴影表示；阴影参考 Material Design，并尽量贴近现实；高度变化有动画。以后能展开菜单的按钮也用同样的方式和菜单接成一体（§9），这是 Muxora 自己的外观特色。

## 1. 现实里的阴影

设计按下面几条物理现象来定，数值都从这里推出：

- **光从上方来。** 整个界面只有一个主光源，在正上方略靠前。所以阴影一律往下偏，上方只有很淡的一点。标签栏放在下方、竖向栏放在左右时，标签的形状镜像，阴影方向不镜像（这是 [标签栏设计 §2.2](tab-strip-design.md#22-功能组合时保持一致) “上下左右互为镜像”的唯一例外）。
- **一个物体有两层影子。** 主光造成的影子（下称“主影”）边缘较清楚、往下偏；环境光被挡住造成的影子（下称“环境影”）很柔、几乎不偏、范围更大。Material Design 3 的五级高度也是这样两层叠加：主影固定较深较小，环境影随高度变大变淡。
- **抬得越高，影子越大、越虚、越往下、越淡。** 主影的偏移和模糊都随高度增加，单位面积的深度反而略降；环境影扩大。只把影子整体加深不像抬高，像弄脏了。
- **边缘本身要看得清。** 浅色卡片放在浅灰底上，只靠柔和的阴影，边缘会发虚。现实里物体边缘有一圈很窄的接触暗部（环境光遮蔽）；深色界面里则是边缘受光后的细亮线。这一层叫“轮廓影”，它不是描边：颜色是中性的黑或白，不用主题强调色，焦点变化时也不变。

## 2. 高度等级

每个等级由三层组成：轮廓影、主影、环境影。数值是逻辑像素，记法同 CSS 的 `box-shadow`：`(纵向偏移, 模糊, 扩展, 不透明度)`。模糊值是影子从边缘淡到零的距离，高斯标准差取模糊值的一半；横向偏移一律为 0。不透明度是浅色主题的值，颜色是纯黑。

| 等级 | 用在哪里 | 主影 | 环境影 | 向下／两侧／向上能延伸 |
| --- | --- | --- | --- | --- |
| 0 平放 | 非活动标签、标签栏底色 | 无 | 无 | 0 |
| 1 标签静置 | 非焦点组的活动标签；分离的活动标签（§4.3）在非焦点组 | (1, 2, 0, 10%) | (1, 3, 0, 6%) | 4／3／2 |
| 2 标签抬起 | 焦点组的活动标签；分离的活动标签在焦点组 | (1, 3, 0, 14%) | (2, 5, 0, 7%) | 7／5／3 |
| 3 卡片静置 | 非焦点组的卡片 | (1, 3, 0, 10%) | (2, 8, 0, 6%) | 10／8／6 |
| 4 卡片抬起 | 焦点组的卡片 | (2, 6, 0, 14%) | (4, 12, 0, 8%) | 16／12／8 |
| 拖动提起 | 拖动中的标签（栏内拖动、浮窗拖回时鼠标下的标签） | (2, 4, 0, 16%) | (3, 6, 0, 8%) | 9／6／3 |

- **轮廓影**：等级 1–4 都有，数值相同：沿表面轮廓外侧 1 像素，浅色主题黑色 7%，深色主题白色 7%。它画在两块表面合并后的外轮廓上，接合处没有轮廓，所以不会在标签和卡片之间留下线（§4.1）。
- **为什么标签比卡片浅**：标签栏很密，标签上下只有 3 像素的底色边，用卡片那么大的影子会糊成一片，也会盖到相邻标签的文字。标签用 1–2 级，卡片用 3–4 级，两者在接合处平滑过渡（§4.2）。
- **为什么比 Material 原值小、淡**：Material 的数值是给手机上的小卡片和按钮定的；这里的卡片能占半个窗口，组之间只有约 5 像素的缝。等级 4 的环境影延伸 12 像素，在缝里能看出明显的明暗差，落到相邻组的标签栏上也只是淡淡一层。
- **拖动提起**：必须比等级 2 高，拖起来才像被拿起；所以不再用标签栏设计 §2.1 现有的提起阴影（向外 3、12%，比等级 2 还小），改用上表一级。向上只延伸 3，正好在横向标签栏上方 3 像素的底色边以内。提起的标签和其他表面一样画轮廓影，不再画细淡描边。
- **浮层展开面板和竖向栏悬停展开**：沿用 [标签栏设计 §4](tab-strip-design.md#4-竖向标签栏) 已有的阴影，本步骤只把它们改成从同一模块取值（§6.4），数值不变。

### 2.1 不同主题

- **深色主题**：深底上黑影不明显。主影和环境影的不透明度乘 2（上限 50%），轮廓影改成白色 7%，相当于边缘的细亮线。焦点组与非焦点组在深色主题里差别会比浅色小，这是预期的；截图检查时确认两者仍分得出。
- **高对比主题**（`hcDark`、`hcLight`，后续加入）：不画主影和环境影。卡片和接合的标签沿合并轮廓画 1 像素的 `contrastBorder`；焦点组改为 2 像素的 `focusBorder`。高对比主题要求焦点一眼可见，不能只靠阴影。
- 颜色来源：阴影颜色用颜色 ID `widget.shadow`，轮廓影用新增的 `muxora.surface.edge`；深色主题的倍数作为主题的一项数值提供。颜色注册表（阶段 2）完成前，先在 `Theme` 里各加一个字段。

## 3. 卡片

- **去掉描边和柔光。** 卡片不再画主题边框色的描边，也不再有焦点组的强调色描边和柔光。边缘只靠轮廓影和阴影。
- **圆角、外边距不变**：圆角 8，组内外边距 2，相邻组之间的分割缝 1。阴影可以越过这些缝落到别处（§6.1），所以不用为阴影加大间距。
- **焦点组**用等级 4，**其他组**用等级 3。窗口进入后台时所有组都回到等级 3，回到前台时焦点组重新抬起。
- 只有一个组时也一样：它在前台窗口里就是焦点组。
- 组内窗格之间的 1 像素直线、非焦点窗格 5% 的淡化都保持不变。

## 4. 活动标签与卡片接成一体

### 4.1 接合的形状

活动标签贴着卡片时，两者是同一块表面：

- 标签的填充色就是卡片的表面色（主题的内容区底色），两块之间没有任何线、色差或阴影。
- 形状沿用现在的横向活动标签：朝外的两个角半径 6；贴卡片的两个角向外翻出半径 4 的小弧，和卡片边缘相切。合并后的外轮廓是一条连续曲线。
- 轮廓影和阴影都按这条合并轮廓画；卡片在接合处不再“开口”，因为本来就没有描边。现在实现里把描边在标签下方挖掉的做法删除。
- **去掉非焦点组活动标签的淡化。** 现在非焦点组的活动标签底色会向标签栏底色退三分之一；接成一体后，这会在接合处留下色差，所以删除。焦点只用高度表示（§3、§2 的等级 1／2）。
- **有颜色的活动标签**：接合时填充用卡片表面色，不再用“接近白色的同色浅底”，否则接合处会有色差；颜色由标题和图标保留的同色系深色表示。未选中的有色标签仍是淡色块。分离的活动标签（§4.3）保持同色浅底。

### 4.2 接合处的阴影过渡

标签用等级 1／2，卡片用等级 3／4。两者各自算出阴影后，在接合附近取两者中**较大**的那个值，不相加：

- 相加会在标签两侧和卡片边缘相交的角落出现一块更深的影子；取较大值，影子从标签侧面的小影子连续过渡到卡片边缘的大影子，没有接缝。
- 标签的主影向下落，落在卡片上的部分被卡片表面盖住，看不到；能看到的是标签两侧和顶上（或横向栏在下方时，标签两侧和底下）的影子。
- 卡片的环境影向上延伸，落在标签栏底色上、非活动标签下面，非常淡，这是正确的：非活动标签是平放在底色上的。

### 4.3 什么时候接合，什么时候分离

原则：卡片显示的是哪个标签的内容，哪个标签就和卡片接合，前提是它确实贴着卡片。分离只在标签离开了贴着卡片的位置时发生（换到别的行、进了浮层、进了竖向紧凑置顶方块），拖动本身不会让标签分离（§4.4）。下面各种情况逐一规定：

| 情况 | 结果 |
| --- | --- |
| 横向单行，活动标签完全可见 | 接合 |
| 横向单行，活动标签被滚出一部分 | 只在可见部分接合；被裁掉的一端不画小弧，标签边直接垂直落到卡片边上（这只出现在滚动渐隐的区域里） |
| 横向单行，活动标签完全滚出视野 | 不接合，卡片边缘完整 |
| 横向多行，活动标签在贴卡片的那一行 | 接合 |
| 横向多行，活动标签在其他行 | 分离，靠卡片一侧被上一层盖住（§4.5） |
| 收起的多行，浮层展开时 | 浮层里的活动标签分离；浮层收回后活动行贴着卡片，重新接合 |
| 置顶标签单独一行（[标签栏设计 §3.6](tab-strip-design.md#36-置顶标签单独一行)），活动标签在不贴卡片的那一行 | 分离，靠卡片一侧被上一层盖住（§4.5） |
| 竖向栏常展开，活动的是普通标签 | 接合（§5） |
| 竖向栏图标模式，未悬停展开 | 接合（§5） |
| 竖向栏悬停展开成浮层 | 分离，随展开进度从接合过渡到分离（§5.2） |
| 竖向栏的置顶标签（正常、收缩尺寸的置顶行，一行一个） | 和普通行相同，接合（§5.1） |
| 竖向栏紧凑置顶方块 | 一行放好几个，不贴卡片，按分离处理：保持现在的方块样式（细描边、无阴影），不接合也不加阴影 |
| 横向栏的置顶标签 | 和普通标签相同，贴卡片就接合 |
| 标签栏隐藏、组里没有标签 | 只有卡片 |
| 拖动中 | 见 §4.4 |

**分离的活动标签**：横向多行里不贴卡片的行按 §4.5 处理。其他情况（浮层、悬停展开）是四个角都为半径 6 的圆角矩形，没有小弧；填充用内容区底色（有颜色的标签用同色浅底）；焦点组用等级 2，其他用等级 1。它和卡片各自投影，不合并。

**靠近卡片圆角时**：小弧和卡片圆角需要至少 4 + 8 = 12 的直边。横向栏第一个标签离卡片边缘 10，再加上标签自己的圆角，已经够用；竖向栏和滚动时可能不够。规则：接合范围限制在卡片直边上（两端各让出 8），超出的一端不画小弧，同“被滚出一部分”的处理。

完整可见的首尾标签临近卡片圆角时，连接轮廓以连续曲线收窄到直边，不能用矩形裁切在标签边上留下台阶或缺口，也不能填平卡片的圆角。已被视口裁掉的标签端部仍保持直切。

### 4.4 拖动

按下标签时就已经切到它（拖动要先按下），所以被拖的标签总是卡片正在显示的那个，不存在“拖的不是活动标签”的情况。

拖动时仍按 §4.3 的原则判断，标签被拖着走并不等于离开卡片。标签栏里的拖动是限位的：横向单行只能横移，多行只能在行内横移或换到相邻的行，竖向栏只能竖移。所以鼠标还在标签栏里时，被拖的标签始终留在它所在的那一层，没有高过上面的层：

- 在贴卡片的位置（横向贴卡片的行、竖向栏的普通行和正常／收缩尺寸的置顶行），它保持和卡片接合，接合的那条边不抬起；朝外一侧和左右（竖向是上下）两侧抬到 §2 的拖动提起，接合处仍按 §4.2 取较大值过渡到卡片阴影。
- 在横向多行的外侧行，它按 §4.5 被更近的一行盖住，拖动提起的阴影同样只画在另外三侧。
- 离开标签栏后它变成浮窗（[标签栏设计 §6.2](tab-strip-design.md#62-离开与回到标签栏)），在浮窗自己的标签栏里与浮窗的卡片接合，浮窗整体用窗口阴影；不存在四角都圆、四周带影子、单独飘着的标签。
- 拿起和放下会和“按下即切换”的阴影动画叠在一起：都从当前显示值继续（§6.5），不重新从零开始。

| 拖动情况 | 结果 |
| --- | --- |
| 横向单行在栏内拖动（只能横移）、竖向栏在栏内拖动（只能竖移），且鼠标还没离开标签栏 | 保持接合。接合范围和两侧小弧跟着标签一起滑动，另外三侧用拖动提起；其他标签照常让位。按 Esc 滑回原位，全程接合，回位后降回等级 1／2 |
| 横向多行，拖到不贴卡片的行 | 随换行分离，变成 §4.5 被盖住的样子：靠卡片一侧直角、自己的影子在这条边截断、有覆盖影；朝外一侧和左右两侧用拖动提起。在外侧各行之间换行时只是换一层，样子不变。拖回贴卡片的行时重新接合。松手后降回等级 1／2，仍是被盖住的样子 |
| 竖向栏拖进置顶段 | 置顶段是正常或收缩尺寸时仍是一行一个、贴着卡片，保持接合；是紧凑方块时进入即分离，按方块样式带拖动提起的阴影，拖回普通段时重新接合 |
| 拖出标签栏变成浮窗 | 原组按“切换活动标签”处理：接着显示的那个标签与卡片接合。浮窗有自己的卡片和接合 |
| 浮窗拖回任何标签栏（包括原来的） | 目标卡片按 [标签栏设计 §6.4](tab-strip-design.md#64-内容预览) 显示被拖内容的画面，鼠标下的标签和栏内拖动一样限位、另外三侧用拖动提起：落在贴卡片的位置就与目标卡片接合，落在多行的外侧行就按 §4.5 被盖住，目标组原来的活动标签暂时变成平放的普通标签；离开标签栏后恢复。一次拖回多个标签时，只有内容被预览的那个接合，其他标签按非活动标签显示 |

接合与分离之间的切换都按 §6.5 的形变动画进行，不跳变。

### 4.5 多行时不贴卡片的标签：被上一层盖住

用户 2026-10-25 提出。横向多行的标签栏按“一层层叠起来”来理解：卡片在最上面，贴卡片的那一行在它下面一层，再往外每一行都压在离卡片更近的那一行下面，像一叠索引卡露出的标签。行与行之间不画线，标签栏底色也不画层间阴影，平时看不出分层；只有分离的活动标签抬起来时，这个层次才显出来。不论标签栏在卡片上方还是下方，都按这个层次处理：

- **形状**：活动标签靠卡片的一边是被上一层盖住的边，这一边的两个角是直角，朝外的两个角半径 6。横向多行行与行之间没有缝，被盖住的边就是标签自己的边，正好落在上一行的边上；置顶单独一行时两行之间有 2 的间距，被盖住的边仍是标签自己的边，间距里露出的是标签栏底色。
- **自己的影子不越过被盖住的边**：标签按等级 1／2 投影，但只画朝外一侧和左右两侧；所有影子（包括两侧影子靠近这条边的部分和轮廓影）在被盖住的边所在的直线处截断，不伸到上一行那边。标签栏在下方时被盖住的是顶边，这时标签往下落的主影照常画在朝外的底边一侧。
- **上一层投下的影子（覆盖影）**：在标签里面、沿被盖住的边画一条渐变，从边上的较深处平滑淡到零（高斯淡出，不是线性渐变，不画成一条线）。光从上方来，所以两种位置不对称：
  - 标签栏在下方（上一层在标签上面）：主影落在标签顶部，宽 3，边上 10%。
  - 标签栏在上方（上一层在标签下面）：只有环境影能到达，宽 2，边上 5%。
  - 覆盖影是上一层的影子，不随这个组的焦点变化；深色主题按 §2.1 乘 2；高对比主题不画，只沿另外三条边画 `contrastBorder`／`focusBorder`。
  - 只画在分离的活动标签上。非活动标签平放在各自那一层，上一层的影子落在它们上面看不出来，不画。
- **不适用的情况**：
  - 浮层展开的多行和竖向栏悬停浮层：整块浮层是一张浮起来的板，板上的行在同一层，活动标签按 §4.3 四角都圆、四周都有影子。
  - 栏内拖动和浮窗拖回时鼠标下的标签不在此列：它们也是限位的，仍按本节被盖住（§4.4）。
- **动画**：活动标签从贴卡片的行换到外面的行（或反过来），包括拖动中换行，都按 §6.5 的接合↔分离过渡：直角与圆角、自己的影子在被盖住一侧的截断、覆盖影的深浅，由同一个进度一起变化。

## 5. 竖向标签栏

### 5.1 接合的几何

竖向栏的活动标签和横向一样接到卡片上，形状旋转 90 度。普通行和正常／收缩尺寸的置顶行（都是一行一个）都这样接合，只有紧凑置顶方块不接合（§4.3）：

- 现在竖向标签行左右各缩进 4，栏与卡片之间留 1。活动行靠卡片的一边延伸到卡片边缘，即多出 4 + 1 = 5，这一侧的两个角翻出半径 4 的小弧；朝外的两个角半径 6。
- 栏在左侧时，活动行向右延伸接到卡片左边；栏在右侧时镜像。阴影方向不镜像，仍然向下（§1）。
- 行与行之间的 2 像素间距不变。小弧占的是缩进区，不会碰到相邻行的内容。
- 图标模式下活动行宽 44，规则相同。
- 非活动行、悬停行不延伸，仍是现在的圆角 6 底色块。

### 5.2 悬停展开时分离

图标模式下鼠标停留后，整条栏以浮层展开、盖在内容上。这时栏和卡片不再相邻：

- 随展开进度（`peekExpansion`，0 到 1）分离：活动行的延伸部分从 5 收回到 0，小弧半径从 4 收到 0，接合处的卡片边缘恢复完整；到 1 时活动行是一块分离的标签，用等级 1／2 投影。收回时反向。
- 浮层本身的阴影照旧。卡片的等级不受悬停影响，焦点组仍是等级 4。
- 浮层中的活动标签和提起标签在浮层底色上方绘制，四周都可投影，不能被后面的内容卡片或栏的静止边界裁掉。
- 常展开和图标模式之间切换（`columnExpansion`）不分离，只是活动行跟着栏宽变化。

## 6. 架构要点

### 6.1 阴影由停靠表面统一绘制

卡片的阴影要越过 2 像素的边距和 1 像素的分割缝，落到相邻组的边距和标签栏上；每个组只在自己的矩形里绘制做不到这一点。所以：

- **`DockSurface` 画底板**：底色（现在各处填的 `headerBackground`）加上所有卡片和接合标签的阴影。每个组向 `DockSurface` 报告自己的表面：卡片矩形、圆角、当前等级（含动画中间值）、接合标签的形状和等级。数据变化时只重绘新旧阴影范围的并集。
- **中间各层不再自己填底色**：`GroupSplitter` 及其手柄、`GroupTabs`、横向 `TabBar` 的底色、静止时的 `VerticalTabPanel` 都改为不填充，让底板透出来。这些控件只画自己的内容（标签、按钮、分隔线）。
- **相邻卡片会盖住落过去的阴影**，看起来像影子落到邻居边缘就到头了，这是可以接受的效果，也避免了把阴影画到别人的终端内容上。
- **浮窗和固定侧栏组**都有各自的 `DockSurface`，规则相同。拖动用的标签载体（`compactPresentation`）没有卡片，也不画底板阴影。
- 不用 `QGraphicsDropShadowEffect`：它逐帧模糊整个控件，开销大，而且对含原生子窗口的内容无效。

### 6.2 卡片圆角的遮盖

`CardOverlay` 现在在卡片四个角外侧填 `headerBackground`，让方形的内容看起来是圆角。改成底板后，角上也有阴影，用纯色填会在四个角各留下一块缺口。改为：`CardOverlay` 在这几块角落里调用 `DockSurface` 提供的“按区域绘制底板”接口，画出与周围一致的底色和阴影，再画轮廓影。`CardOverlay` 不再画描边和柔光。

### 6.3 活动标签的填充与阴影分开

- 活动标签的**填充**仍由 `TabBar` 画（它在卡片外的标签栏里，和标签的其他部分一起滚动、拖动）。
- 活动标签的**阴影**由底板画。`TabBar` 把活动标签当前的绘制矩形（含滚动、滑动动画的中间位置）、是否接合和接合范围通过 `GroupTabs` 报告给 `DockSurface`。几何和判定写成纯函数（输入布局结果、栏的位置、卡片矩形，输出合并轮廓和接合范围），放在布局层旁边，不依赖控件，便于测试。
- **拖动中的标签**：要画在相邻标签和加号等尾部控件上方，所以拖动期间它的阴影改由 `TabBar` 的提起层画，`TabBar` 同时告诉底板不再画这个标签的阴影。提起层在标签附近的局部小图里先按 §4.2 算出卡片阴影和标签阴影的较大值，只画出比底板上已有的卡片阴影多出来的部分（按已有不透明度补差），叠上去后结果仍等于较大值，接合处不会变深。被盖住的一侧照样截断。放下、阴影降回等级 1／2 后交还底板。
- **滚动渐隐**：现在渐隐是向标签栏底色渐变的一层颜色；底板上有阴影后，这层颜色会盖掉阴影。改成对标签层做透明度遮罩（只让标签本身淡出），不再画底色。

### 6.4 阴影的绘制与缓存

- 新建 `style/elevation.hpp/.cpp`，集中定义 §2 的等级、§2.1 的主题差异和三层阴影的绘制；`TabMetrics` 里现有的 `shadowBlur`、`liftShadow*` 改为引用这里的等级，`TabPainter::paintShadow` 的“几圈逐渐扩大的半透明圆角矩形”删除（它会出现一圈圈的台阶）。
- **圆角矩形用九宫格缓存**：阴影图只取决于圆角、等级和设备像素比，与卡片大小无关。生成一次小图，按九宫格拉伸到任意大小；现有 `paintLiftShadow` 已经是这个做法，推广即可。
- **接合标签**的阴影按合并轮廓生成，按标签尺寸、接合范围、等级和像素比缓存；它只占标签附近一小块。§4.5 被盖住的标签同样按“截断的阴影 + 覆盖影”整体生成和缓存，截断用裁剪完成，不另算模糊。
- **取较大值**（§4.2）在接合附近的局部小图里完成：把卡片阴影和标签阴影的不透明度分别画进去，逐像素取较大值，再着色画到底板上。其他位置直接画卡片的九宫格。
- **动画的中间值**：等级之间对每个数值线性插值。为了能缓存，把进度量化成 32 档（理由见 §6.5），每档的九宫格用到时生成并保留；不在每一帧重新模糊。

### 6.5 动画

所有过渡都不能是线性的，也不能生硬地跳到终点：

- **曲线**：在 `style/motion.hpp` 里集中定义两条三次贝塞尔曲线（Qt 用 `QEasingCurve::BezierSpline` 加 `addCubicBezierSegment`），本文的动画只用这两条，不再直接写 `OutCubic`：
  - **抬起曲线** `(0.05, 0.7) (0.1, 1.0)`：同 Material 的强调减速曲线，开头快、结尾很长很柔地停下，像物体被托起后慢慢稳住。用于抬高、接合。
  - **标准曲线** `(0.2, 0) (0, 1.0)`：同 Material 的标准曲线，起步柔和、结尾平稳。用于降低、分离和在原地的形状变化。
- **一个进度驱动整件事**：同一次变化里的所有数值（主影和环境影的偏移、模糊、不透明度，接合范围、延伸长度、小弧半径）都由同一个经过曲线的进度插值，不各自计时，因此形状和阴影步调一致。
- **中途反向**：用 `ProgressAnimation` 从当前显示值继续，剩余时长按剩余距离比例缩短（例如反向时只走了 30%，就只用 30% 的时长回去），不从头播放，也不因为反向而突然变速跳动。
- **缓存不能造成台阶**：§6.4 的量化档数不少于动画的帧数；最长的 200 毫秒在 60 帧下约 12 帧，取 32 档，相邻两档之间看不出跳动。
- 系统关闭动画时直接显示最终状态。

| 变化 | 时长 | 曲线 |
| --- | --- | --- |
| 组获得焦点：卡片 3→4、活动标签 1→2 | 200 毫秒 | 抬起 |
| 组失去焦点：4→3、2→1 | 160 毫秒 | 标准 |
| 窗口回到前台／进入后台 | 同上两行 | 同上 |
| 切换活动标签：旧标签立即恢复平面，新标签的阴影从 0 升到它的等级 | 新标签 160 毫秒 | 抬起 |
| 接合 ↔ 分离（换行、进出紧凑置顶方块、拖回预览、拖动中换行） | 160 毫秒：延伸长度、小弧半径、四角圆角、阴影从接合等级到分离等级同步变化；进出 §4.5 的被盖住状态时，被盖住一侧的直角、影子截断和覆盖影也在同一进度里变化 | 接合用抬起，分离用标准 |
| 竖向栏悬停展开时的分离与接合 | 跟随栏展开的进度（它本身已是缓出曲线），不单独计时 | — |
| 栏内拖动中接合范围随标签滑动 | 直接跟随标签当前的绘制位置（含让位、落位的滑动动画） | — |
| 栏内拖起：三侧阴影从等级 1／2 升到拖动提起 | 200 毫秒 | 抬起 |
| 栏内放下或 Esc 回位：拖动提起降回等级 1／2 | 160 毫秒，与落位滑动同时开始 | 标准 |

- 切换活动标签时，**填充色立即切换**，只有阴影过渡：内容区本来就是立即切换的，填充慢慢出现会让接合处在动画期间露出色差。
- 接合进度属于同一个标签。新建、关闭后接着激活的标签和拖放落位，都先按自己的实际位置判断是否邻接卡片，不继承前一个标签的接合形状；退出图像保留退出前的轮廓。
- 抬起时卡片只变阴影，不移动、不缩放，内容不会有一个像素的抖动。

## 8. 验收

- **截图**：三种主题（默认浅色、深色、近纯黑；高对比主题加入后补上）× {单组、左右分组、上下分组} × {横向上方、横向下方、竖向左、竖向右、竖向图标模式、悬停展开} × {窗口前台、后台}。检查：接合处没有线和色差；焦点组明显更高；深色主题里焦点仍分得出；阴影没有台阶状的圈；卡片四个角没有缺口。另加横向上方、下方各一张多行截图，活动标签在不贴卡片的行，检查它像被上一行盖住（§4.5）。
- **自动测试**（按 [测试要求](../development/testing-design.md)）：
  - 纯函数：§4.3 表里每一行的接合判定；靠近卡片圆角和滚出一部分时的接合范围；竖向延伸与悬停分离的进度插值；等级插值与 32 档量化。
  - 绘制取样：接合处跨过标签与卡片交界的一列像素都等于表面色；卡片下方固定距离处，焦点组比非焦点组暗；接合处两侧角落的阴影不比远离接合处的卡片边缘更暗（检查取较大值而非相加）；卡片四角像素与邻近底板一致；高对比主题有轮廓线、无阴影；§4.5 被盖住的标签在被盖住的边外侧没有它自己的影子，边内侧有覆盖影且标签栏在下方时比在上方深。
  - §4.4 的每种拖动情况：栏内限位拖动保持接合且接合范围跟随标签；换行、进紧凑置顶方块时分离；栏内拖动和浮窗拖回时接合边或被盖住的边不抬起、只有另外三侧带拖动提起阴影，且比等级 2 深；拖出后标签与浮窗卡片接合；竖向正常／收缩尺寸的置顶行接合，紧凑方块不接合；浮窗拖回时被拖标签接合、原活动标签平放，离开后恢复。
  - 焦点切换、窗口前后台切换后等级正确；动画中途取样的值落在起止之间且单调（不线性：中点进度明显大于一半）；中途反向从当前值继续；关闭动画时立即到达最终等级。
- **性能**：焦点切换动画期间不得出现整窗大小的图片分配或逐帧模糊；用现有的绘制计时方式确认焦点切换一帧的底板重绘耗时，写进验证日志。

## 9. 以后：按钮与菜单接成一体

用户 2026-10-25 提出，以后能展开菜单的按钮（菜单栏按钮、下拉按钮、分体按钮的箭头）也这样做：按下后按钮和弹出的菜单是同一块表面，参考 Visual Studio 菜单栏按钮和菜单连在一起的逻辑，但外观用本文的表面与阴影，不用 Visual Studio 的方角扁平样式。

这部分属于 [8.27 菜单与浮动面板重做](../roadmap/implementation/phase-8-ui-quality.md#827-菜单与浮动面板重做)，届时细化。本步骤为它留好基础：

- `elevation` 模块的接口按“一块主体表面 + 一块锚点表面 + 接合边和接合范围”来设计，不出现“标签”“卡片”这类具体名字；标签与卡片只是它的第一个使用者。
- 菜单是顶层窗口，目前用系统阴影（[界面设计规范 §2.3](ui-design-system.md#23-圆角边框与阴影)）。系统阴影没法把按钮包进去，所以 8.27 要在“透明顶层窗口自绘阴影”和“系统阴影 + 按钮单独处理”之间做决定；本步骤不做这个决定。
