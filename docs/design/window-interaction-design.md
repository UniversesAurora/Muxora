# 窗口交互修订

日期：2026-10-12

本稿记录首个预览试用后的交互要求。窗口结构仍以 Visual Studio 为参考；设置页和标签滚动参考 VS Code。实际实现与验证见 [预览说明](../development/window-system-preview.md)。

## 拖拽与投放

标签达到拖动阈值后立即移入一个真实轻量窗口，窗口随鼠标移动；原位置不保留重复内容，空标签组立即消失。窗口中的业务内容、Pane ID 和控件实例保持不变，不能靠截图代替可交互内容。释放鼠标只决定最后的投放，不再创建第二个浮窗。

工作区内容区本身不是合并目标。目标组的中心指示表示合并，四方向指示表示中央分割；标签条表示按释放位置插入。已显示的自动隐藏边栏可直接接收标签，结果为自动隐藏。没有边栏时，不使用不可见的边缘热区。

四边各显示一个连接的双目标控件：靠边的一格为收纳，靠内的一格为固定。左右边为横排，上下边为竖排；右、下边镜像排列。固定投放在该侧靠外的位置建立新分区，保留已有固定分区。控件的绘制与命中使用同一几何定义，不能在窄组中显示能点但不执行的方向目标。

固定侧栏组可接收中心合并和标签条插入；新增固定分区通过四边指示完成。中央方向分割不适用于固定侧栏组，因此不显示其四方向目标。整窗投放包含所有标签，即便目标窗口只有侧栏也应正常执行。

Esc 恢复拖拽前的布局、位置和稳定 ID，并保留内容实例。关闭、恢复布局或其他结构操作中断拖拽时，先释放捕获再执行操作，不能用旧快照复活或丢掉刚处理的内容。目标悬停唤起保留鼠标捕获；移动过程只更新位置和落点指示。

## 边栏与窗格

临时展开只包含选中的一个标签，用同一行显示其标题、固定和关闭操作，不另加“临时展开”标题或其他标签条。拖动标题时，面板立即消失并形成浮窗。

固定按钮只处理当前标签，允许同一侧同时存在固定和收纳内容。固定后该标签离开边栏条带，出现在固定面板；取消固定后记录原分区、标签顺序和尺寸，重新固定时恢复。该侧的全部固定／取消固定另设明确按钮和命令。

全部固定按钮位于该侧标签末尾；全部固定与全部取消固定图标在右下角增加内部透明的叠层标记，区分单标签操作。边栏相邻角的归属在两条边栏同时显示时确定：底栏占两个底角，左右栏分别占顶角，上栏不占角。只有一条相邻边栏显示时，由它占用该角。临时展开保留真实内容、焦点和可用上下附加栏。

自动隐藏侧栏标签可按其所在条带的横轴或纵轴调整顺序，拖拽继续使用即时浮窗，在释放位置显示插入指示并重新收纳。该侧的可见标签形成一条序列，内部组边界不影响用户顺序；跨窗口插入与整窗载荷均保留内容身份和载荷顺序，Esc 恢复原布局。普通标签组与侧栏共用前移／后移命令及 `Ctrl+Shift+PgUp` / `Ctrl+Shift+PgDown`。

内层窗格只保留内容和细分隔线，不增加窗格标题、关闭按钮或各自的上下状态栏。标签共享一个顶部和一个底部位置，随焦点切换到当前 Pane 的附加栏；没有 Pane 栏时使用 Tab 的默认栏，没有任何栏时不占空间。提取 Pane 时，其专属栏按 Pane ID 一起移动。

关闭窗格通过内容右键菜单、菜单、命令面板或快捷键操作；编辑器原有的复制等右键操作继续可用。

## 标签条与设置

标签条使用可滚动的完整标签宽度，不显示左右滚动按钮。底部细滚动条在溢出且悬停时显示，鼠标移入滚动条后保持显示；滚轮只滚动条带，不切换活动标签。拖拽在左右边缘停留后自动滚动，离开或结束拖拽即停止。

单标签或整窗内容拖到标签条时，按释放位置插入；整窗标签保持原顺序。右侧下拉按钮显示全部标签，可滚动、选择，条目右侧仅悬停显示关闭按钮。标签上的关闭按钮同样只在悬停时显示。图标显示由 `TabOptions::showIcon` 和 `setTabIconVisible()` 控制，不增加用户命令。

标签右键菜单提供关闭左侧、右侧、其他和全部标签。关闭范围限于该组；关闭许可一次检查整个选定集合，拒绝时不部分关闭，确认期间新增的其他标签不能被误关。

设置和键盘快捷键均作为普通标签打开，具有搜索、分类或命令列表和可滚动内容。重复打开激活已有实例，支持移动、拆出和布局恢复。界面编辑立即生效；完整 JSONC、用户键位持久化和条件规则仍按 [设置设计](settings-and-commands-design.md) 的后续要求实施。

设置页始终呈现全部设置，按类别标题分组；搜索可过滤匹配项。侧导航使用可展开／折叠的分类树，点击或键盘选择只滚动定位，不以分类过滤内容。导航与内容之间仅保留一道分隔线，当前位置以粗体文字表示，内容滚动时同步定位。数字调整按钮平时无框、悬停显示外框，组合框使用明确矢量箭头且不增加内部竖线；启用勾选框使用白色勾。颜色来自主题值，暂不增加用户设置。

导航展开箭头的悬停只改变笔画颜色，不绘制底色或阴影。当前位置竖线使用独立的左侧空间，与箭头至少间隔八个逻辑像素，不使用平台原生树枝连接线充当指示器。

## 工具条与标题

菜单、工具和标题采用同一条带布局。解锁后拖动立即显示随鼠标移动的条带呈现，原位置移除；释放提交位置，取消恢复。把手只改变鼠标形状，不显示按钮高亮框。

右键菜单列出全部工具条及其显隐状态。窗口类型或停靠位置不适用的命令隐藏；操作仍有意义但当前没有对象，例如没有左侧标签，则保留禁用状态。

工具条可以压缩：拖动后一条的把手向前移动，前一条按钮溢出；再次向后拖动可释放宽度并恢复按钮。末尾常驻窄按钮，下半部显示下拉箭头；存在溢出项时，上半部再显示右箭头。菜单包含溢出操作和“添加或移除按钮”子菜单，修改当次更新条带和菜单。位置、宽度、显隐、按钮选择及尺寸策略随布局保存。

工具条尺寸分为内容宽度和弹性空间两种策略。弹性条带在任意行内位置占用扣除其他条带后剩余的空间，将其右侧条带推到右边；多个弹性条带分配余量，随窗口尺寸变化伸缩。标题默认采用弹性策略，文字从左侧开始；空白和标题区域保留拖窗、双击最大化等窗口交互。定制菜单可切换条带策略，也可通过统一命令 `window.toolbar.setSizing` 操作。完整窗口保留原生控制按钮，轻量窗口保留精简外壳。

标题条不提供工具条选项按钮，也不为其预留宽度。这是宿主的呈现策略，旧用户布局不能重新启用它；其他工具条继续提供选项。

所有下拉菜单按钮在菜单展开时再次点击应关闭菜单，不能因为关闭后的鼠标事件回放立即重新打开。工具条选项和其他按钮共用悬停、按下及键盘焦点样式；关闭菜单后正常恢复其他控件的悬停反馈。

从菜单外部关闭时，在真实鼠标按下处理期间禁止向底层控件回放该按下事件；定制子菜单沿父菜单链应用同一策略。关闭之后不能遗留按键状态、鼠标捕获或弹窗，悬停进入和离开的实际绘制均应恢复。检查使用 Windows 原生输入路径，不能只凭向控件直接注入事件的结果判断已修复。

## 验证

模型、公开 API、控件事件和 Windows 原生命中分别检查。重点回归包括松手前的浮窗与空组状态、Esc 恢复、非目标内容区、窄组方向、四边两种投放、整窗插入、临时面板拖出、逐标签固定与尺寸恢复、滚动条悬停交接、焦点共享栏、设置恢复、工具条溢出和窗口转换销毁。

用户明确修改了拖拽提交时机，旧的“释放后才创建窗口”预期随之更新；保留内容身份、取消恢复、遮挡和事务安全的断言。任何失败先修实现，不删用例、不缩负载、不降低阈值。

本轮弹性工具条与始终显示全部设置取代原来的行首扩展和分类过滤预期，相关用例按新要求更新，并保留更强的布局、搜索与实际输入覆盖。新增检查包括临时面板真实内容、16 种边栏存在组合、图标和按钮位置、缩窄后释放宽度、菜单关闭与悬停恢复、主题控件实际绘制及导航树滚动同步。
