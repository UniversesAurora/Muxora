# 窗口交互细则

本文是 [工作区与导航](workspace-design.md)、[双窗口形态与跨窗口拖拽](floating-window-design.md) 和 [通用窗口系统](window-system-design.md) 的交互细则：那三份文档讲结构、模型和概要，这里写拖拽各阶段、边栏、工具条、显隐与全屏等具体规则和尺寸；标签栏的规则在 [标签栏设计](tab-strip-design.md)。两边说法不一致时以本文为准，并同步修正概要。窗口结构以 Visual Studio 为参考；设置页和标签滚动参考 VS Code。实际实现与验证见 [预览说明](../development/window-system-preview.md)。

## 拖拽与投放

标签组和收纳条各自保留滚动位置。拆出、排序或重建视图不自动将条带定位到开头或活动标签；内容缩短时，偏移受剩余内容范围约束。布局或窗口缩放使可视范围变窄时，按 [标签栏设计 · 条带尺寸变化](tab-strip-design.md#条带尺寸变化) 调整。拖拽首尾驻留产生的滚动在移开鼠标后继续保留，取消拖拽也保留这次浏览位置。明确选择或键盘导航到一个标签时，仍应将它滚入可见范围。

拖拽期间的滚轮作用于鼠标下实际条带，不作用于捕获鼠标的浮窗内容；支持普通滚轮和触控板像素增量。条内标签预览与首次离开后的浮窗阶段共用此规则。滚动、插入位置和投放指示保持同步，不切换活动标签。

标签达到拖动阈值后，若鼠标仍在原标签条或收纳条内，标签在条内被提起、跟随鼠标，其他标签滑动让位，规则见 [标签栏设计 §6.1](tab-strip-design.md#61-在标签栏内拖动)。内容保持在原控件和原位置，已展开的侧栏内容也保持显示。释放时提交条内顺序，Esc 恢复原位；这一步不创建工作区窗口，不改布局模型。

鼠标第一次离开原条带时，标签立即移入一个真实轻量窗口；空标签组收起，侧栏临时面板消失。之后再进入任何条带，浮窗按 [标签栏设计 §6.2](tab-strip-design.md#62-离开与回到标签栏) 只留标签在鼠标下面，不回到条内阶段。业务内容、Pane ID 和控件实例保持不变。若达到拖动阈值的事件已经在原条带外，则直接拆出；拖动临时面板标题也直接拆出。按 Tab 明确选择另一目标窗口时进入浮窗阶段。释放鼠标只决定最后的投放，不再创建第二个浮窗。

工作区内容区本身不是合并目标。目标组的中心指示表示合并，四方向指示表示在目标所在区域内分割；中央组生成中央组，固定组生成同侧固定组。标签条表示按释放位置插入。已显示的自动隐藏边栏可直接接收标签，结果为自动隐藏。没有边栏时，不使用不可见的边缘热区。

四边各显示一个连接的双目标控件：靠边的一格为收纳，靠内的一格为固定。左右边为横排，上下边为竖排；右、下边镜像排列。固定投放在该侧靠外的位置建立新分区，保留已有固定分区。控件的绘制与命中使用同一几何定义，不能在窄组中显示能点但不执行的方向目标。

固定侧栏组可接收中心合并、标签条插入和四方向新建固定组，菜单新建相邻组使用同一规则。每侧固定区使用独立二维分割树，内部调整不改变中央区域或另一侧的分割比例。整窗投放包含所有标签，即便目标窗口只有侧栏也应正常执行。固定组较窄而导致十字指示与边缘双目标重叠时，将十字整体向内侧避让，保持 2 个逻辑像素的间隙。左右边缘的双目标与十字中心纵向对齐，上下边缘则横向对齐；命中沿用实际绘制位置。鼠标在显示中的整个十字范围内移动时，包括按钮间隙，保持原目标组；离开范围后再切换到鼠标下的组。

Esc 恢复拖拽前的布局、位置和稳定 ID，并保留内容实例。关闭、恢复布局或其他结构操作中断拖拽时，先释放捕获再执行操作，不能用旧快照复活或丢掉刚处理的内容。目标悬停唤起保留鼠标捕获；移动过程只更新位置和落点指示。

拖到标签条或收纳条的插入位置时，浮窗隐藏内容、标题工具条、窗口按钮和全局状态栏，只留标签在鼠标下面；目标条带空出位置、标签栏目标显示内容预览，规则见 [标签栏设计 §6.2–§6.7](tab-strip-design.md#62-离开与回到标签栏)。窗口句柄、鼠标捕获、内容实例与输入焦点保持；离开条带立即恢复轻量窗口。释放、取消和结构变更统一清理临时呈现，不能把它写入布局。

让位只改变绘制，不往模型和真实标签列表添加占位标签。普通栏横向滚动，左右收纳条纵向滚动，上下收纳条横向滚动；驻留自动滚动见 [标签栏设计 §6.6](tab-strip-design.md#66-自动滚动与经过收起的栏)。

条带插入优先于方向指示命中，方向指示避开可见条带和组标题，绘制与命中共用同一组矩形。组中央的十字按实际内容区定位和计算可用大小，不能把竖向标签栏当成顶部标题去扣高度。窗口四边的成对指示按扣除收纳条和贴边标签栏后的内容范围居中，条带方向取自实际布局位置，竖向栏包含其标题和底部按钮；左右栏不影响顶部扣除，上下栏不影响侧边扣除。内容区已排除标签栏时，不再次扣除条带；浮层展开盖在内容上时也遵循这一规则。拖动预览与真实侧栏标签共用绘制组件。宿主同步保存布局时，开始拆出、拖动、提交和取消过程均返回此前完整快照；全部模型、位置和焦点处理完成后通知宿主保存最终布局。

Windows 正常顶层窗口保留完整原生窗口样式，由 DWM 处理创建、最小化、最大化／恢复和关闭的过渡，遵循系统动画偏好。自绘标题通过客户区处理隐藏系统标题。首次显示前准备原生窗口；拖出浮窗先设到鼠标位置再显示。移动不重复播放创建动画，不添加窗口透明度淡入。

紧凑拖拽预览使用原窗口句柄及轮廓遮罩，不切换 Qt 窗口 flags。呈现切换先暂停客户区更新，完成布局与遮罩后再绘制。Windows 上从已准备的正常窗口切换为无原生标题样式，系统菜单入口及最小化／最大化能力保持；预览的边框处理见 [窗口缩放边框](#窗口缩放边框)。返回正常呈现时恢复完整样式并清除原生 region。实际 DWM 状态、精确轮廓及缺口命中须通过独立 Win32 和 Qt 窗口测试核验，不能只检查启用策略写入成功。模块拦截系统主题的标题绘制和激活重绘，正常边框仍由 DWM 处理；最大化边界、鼠标捕获及内容实例必须保持。自动化验证与低性能设备的逐帧视觉检查分别记录。

## 边栏与窗格

临时展开只包含选中的一个标签，用同一行显示其标题、固定和关闭操作，不另加“临时展开”标题或其他标签条。关闭按钮关闭实际标签，经宿主关闭许可处理；拒绝时保留面板与内容。拖动标题时，面板立即消失并形成浮窗。自动隐藏侧栏标签的右键菜单使用现有标签命令，操作对象为被点击的标签。

**八向调整。** 临时面板的四条边和四个角都可以拖动调整大小，包括贴着收纳条或窗口边缘的那一侧。面板位置仍按下文的对齐规则确定，拖动只改变宽度和高度：向远离面板中心的方向拖动为放大，向中心方向为缩小；拖动过程中面板按对齐规则实时重新放置。每条边的命中带宽 4、每个角 8×8，悬停 300 ms 后在该边显示 2 像素提示线。面板贴到窗口边缘时与窗口缩放的关系见本文“窗口缩放边框”一节。

四个方向的临时面板都支持独立调整宽度和高度，并在相交边缘提供角部调整。调整区域叠在面板边缘，不能为较大的鼠标命中范围增加内缘留白；外框与内容边框之间的四边间距保持一致且紧凑。拖动实时调整当前面板，不重建标签或内容，也不改固定分区的大小。

每个标签保存两套请求尺寸：左／右共用一套，上／下共用另一套，两套之间互不覆盖。每套的宽和高分别允许未设置。默认保持原展开比例：左右栏宽度为 250 个逻辑像素、高度填满可用区域；上下栏高度为 170 个逻辑像素、宽度填满可用区域。显式调整任一轴后，只覆盖该轴的请求值。同组切换、收起重开、固定再取消固定及跨窗移动都保留这些值。显示受可用空间和内容最小尺寸限制，窗口暂时变窄不改写保存值。

面板沿条带方向小于可用范围时，尽量对齐触发标签的起始边：左／右侧对齐上边，上／下侧对齐左边。超出可用区域时向内限制到最近位置。条带滚动、窗口调整或标签重排后重新计算锚点，不增加永久布局占位。

“布局 → 当前标签 → 此标签的侧边栏收纳 → 此标签的临时展开大小”和侧栏标签右键菜单提供设置／重置。`tab.peek.setSize` 接受 `tab`、`width`、`height`；省略 `tab` 使用当前标签，省略宽高则打开可键盘录入的对话框。宽或高为 `0` 时，该轴恢复默认宽／高或填满行为。`tab.peek.resetSize` 清除当前左／右或上／下方向套组的显式大小，保留另一套。两项操作可从命令面板调用或绑定快捷键，仅自动隐藏标签提供菜单入口。API 用 `PeekSizePolicy` 的可选宽高和明确的 `Edge` 表达同一策略。取消输入不修改值；输入期间目标被关闭或固定，停止应用本次输入。

默认收纳条厚度为 22 个逻辑像素，非固定面板临时标题为 20，其中固定和关闭按钮为 18×18，图标为 14。普通和固定标签组的标签、取消固定按钮和完整列表按钮的尺寸见 [标签栏设计 §2.1](tab-strip-design.md#21-外观) 和 [§8.2](tab-strip-design.md#82-完整标签列表)。全部固定按钮按收纳条厚度显示。增大字体时，临时标题高度至少为字体度量高度加 2，避免裁字；主题和字体刷新后仍遵守这些尺寸规则。拖动中的侧栏面板预览使用同样的临时标题高度。

固定按钮只处理当前标签，允许同一侧同时存在固定和收纳内容。固定后该标签离开边栏条带，出现在固定面板；取消固定后记录原分区、标签顺序和尺寸，重新固定时恢复。该侧的全部固定／取消固定另设明确按钮和命令。

没有固定历史的标签首次固定时，在该侧最靠外的位置建立分区，与直接固定投放一致：左侧靠左、右侧靠右、顶部靠上、底部靠下。已有取消固定历史的标签仍恢复原分区与顺序。整组和整侧操作遵循相同规则，首次整侧固定保留标签组之间的原顺序。

侧边收纳条另有窗口级显隐，独立于中央标签栏。菜单“视图 → 显示 → 显示侧边栏”、`Ctrl+Alt+B` 和命令 `window.sideBars.toggle` 使用同一入口。隐藏时收起四边收纳条和当前临时面板，固定分区保留；布局、内容和快捷键导航不变。明确通过命令激活收纳标签时仍可临时展开，面板按实际可见条带定位。状态随窗口保存，新建边栏继承该窗口设置。

全部固定按钮位于该侧标签末尾；全部固定与全部取消固定图标在右下角增加内部透明的叠层标记，区分单标签操作。边栏相邻角的归属在两条边栏同时显示时确定：底栏占两个底角，左右栏分别占顶角，上栏不占角。只有一条相邻边栏显示时，由它占用该角。临时展开保留真实内容、焦点和可用上下附加栏。

自动隐藏侧栏标签可按其所在条带的横轴或纵轴调整顺序，条内阶段保留内容，首次离开后使用真实浮窗，在释放位置显示插入指示并重新收纳。该侧的可见标签形成一条序列，内部组边界不影响用户顺序；跨窗口插入与整窗载荷均保留内容身份和载荷顺序，Esc 恢复原布局。普通标签组与侧栏共用前移／后移命令及 `Ctrl+Shift+PgUp` / `Ctrl+Shift+PgDown`。

内层窗格不增加窗格标题或关闭按钮。上下附加栏分别支持两种策略，默认共享：标签共享一个对应位置，随焦点切换到当前 Pane 的栏；没有 Pane 栏时使用 Tab 的默认栏，没有任何栏时不占空间。宿主可把顶部或底部独立设为逐窗格显示，各 Pane 的对应栏放在自己的内容边缘。显式 Tab 栏仍属于整个标签，只显示一次，不复制控件。提取 Pane 时，其专属栏和共享策略按 Pane ID 一起移动。

关闭窗格通过内容右键菜单、菜单、命令面板或快捷键操作；编辑器原有的复制等右键操作继续可用。

## 设置页

设置和键盘快捷键均作为普通标签打开，具有搜索、分类或命令列表和可滚动内容。重复打开激活已有实例，支持移动、拆出和布局恢复。界面编辑立即生效；完整 JSONC、用户键位持久化和条件规则仍按 [设置设计](settings-and-commands-design.md) 的后续要求实施。

设置页始终呈现全部设置，按类别标题分组；搜索可过滤匹配项。侧导航使用可展开／折叠的分类树，点击或键盘选择只滚动定位，不以分类过滤内容。导航与内容之间仅保留一道分隔线，当前位置以粗体文字表示，内容滚动时同步定位。数字调整按钮平时无框、悬停显示外框，组合框使用明确矢量箭头且不增加内部竖线；启用勾选框使用白色勾。颜色来自主题值，暂不增加用户设置。

导航展开箭头的悬停只改变笔画颜色，不绘制底色或阴影。当前位置竖线使用独立的左侧空间，与箭头至少间隔八个逻辑像素，不使用平台原生树枝连接线充当指示器。

## 默认视觉

默认紫罗兰主题的工作内容区域使用白色背景。非固定侧栏的标签保留原紫色背景和浅色文字，不随普通标签的浅色处理而改变。标签条与收纳条上没有标签的位置使用工具栏背景色；更换主题后这些区域一起更新。标签的外观见 [标签栏设计 §2.1](tab-strip-design.md#21-外观)，内容边框尽量贴近边缘，四边厚度和间距一致。

按钮和菜单采用直角矩形，高亮时四边同厚；标签栏的标签、尾部控件和标签组卡片例外，使用圆角（见下文“标签组卡片与焦点”）。普通按钮的悬停填充使用较浅的 `Theme.buttonHover`，菜单栏按钮继续使用原悬停配色。提示气泡和拖拽定位控件允许保留圆角，普通窗口轮廓仍遵循平台窗口策略。最大化与全屏时去掉客户区外围描边和留白，全屏使用平台全屏状态并覆盖显示器区域，不保留圆角。三控件紧邻屏幕边缘时，其命中和悬停范围延伸到对应屏幕边缘，包括最大化后的右上角。

菜单和下拉弹窗使用直角外框，不沿用系统的圆角 popup。相对触发控件定位时优先左边对齐、向下展开；可用屏幕不足时改为右边对齐或向上展开，再限制到当前屏幕可用区域。二级菜单显示、更新窗口列表和勾选状态不能反复改写未变化的父菜单项，避免父菜单闪烁。

命令面板等短时浮动面板默认为非模态，点击外部区域自动关闭。公开 `FloatingPanelOptions` 分别控制 `dismissOnOutsidePress` 和 `modal`；两项策略独立，可按宿主场景组合，不能把自动关闭等同于模态阻塞。命令面板保留打开时的命令目标，面板抢到焦点后不能误操作另一个标签。

### 标签组卡片与焦点

用户 2026-10-25 要求：去掉内容里亮起的矩形焦点框，标签组改成四角圆的卡片，组内窗格用细直线分隔，焦点用更自然的方式表示；整体审美偏向 macOS，以后移植 Mac 不显得违和。

- **卡片**：每个中央组和固定侧栏组的内容区是一张卡片，四角圆角 8，不画描边，边缘与焦点见[表面与阴影设计](surface-elevation-design.md)。卡片在组内保留 2 的外边距，相邻组的分割缝默认 1，露出的是标签栏底色。横向标签栏不画在卡片里，而是贴着卡片放在底色上；活动标签与卡片的接合按表面与阴影设计处理；首标签齐边规则见 [标签栏设计](tab-strip-design.md#22-功能组合时保持一致)。竖向标签栏在卡片旁边的底色上，间距见 [竖向标签栏](tab-strip-design.md#4-竖向标签栏)。最大化和多窗格全屏时保留圆角与间距。全屏实际只显示一个窗格时，包括禅模式，不保留外层背景、卡片边距、圆角遮盖或阴影，让内容贴到可用区域边缘；所有栏隐藏时，整个屏幕只有窗格内容。该状态临时派生，不保存、不改变栏的显隐偏好；退出全屏或重新显示多个窗格时恢复普通卡片。
- **边界拖动**：组分割线与竖向标签栏的调宽命中带至少 10 个逻辑像素，向两侧覆盖少量区域，但不扩大视觉上的缝隙。组分割线复用 Qt 的手柄边距、遮罩和原生拖动处理，最小尺寸与分割比例仍由原分割器负责。
- **窗格**：同一个标签里的窗格之间是 1 宽的直线（主题边框色），没有圆角，也不留间隔，一眼能分出“标签组之间”和“组内窗格之间”。
- **不画焦点框**：内容里的文本框、列表等不再用一圈强调色边框表示焦点（只保留设置页等表单控件的焦点）。
- **焦点组**：用卡片的高度（阴影）表示，不用强调色描边或柔光，等级与动画见[表面与阴影设计](surface-elevation-design.md)。
- **焦点窗格**：一个标签有多个窗格时，非焦点窗格盖一层 5% 的文字色，略微变淡，焦点窗格保持原样（终端里 iTerm2、WezTerm 的常见做法）；只有一个窗格时什么也不加。
- 收纳条仍贴在窗口边缘，在卡片之外；临时展开面板以卡片样式弹出。

## 独立显隐与全屏

每个窗口分别保存工具栏、全局状态栏、中央标签栏和四边收纳条的显示偏好，默认显示。这些开关与全屏范围无关，普通、窗口全屏、标签组全屏及窗格全屏共用同一组设置。工具栏开关同时控制顶部和底部工具区；中央标签栏隐藏不影响固定面板标签栏或临时展开标题；侧栏隐藏保留固定内容。其他窗口不受本窗口设置影响。

窗口全屏保留整个工作区；标签组全屏只呈现目标组的内容，组内仍可切换标签；窗格全屏只呈现目标 Pane 的内容。窗口各栏和收纳条仍按上述偏好显示，用户可以从可见收纳条选择其他内容，选择范围外内容时退回窗口全屏。内容视图使用原控件，进入全屏不修改 Group／Pane 布局树，退出后恢复分割尺寸以及窗口此前的正常位置和最大化状态。

普通窗口启用禅模式时按设置自动进入窗口、标签组或窗格全屏，默认窗口全屏；已有全屏保留范围。开启禅模式后，将全部栏的有效显示状态设为关闭，也隐藏固定标题和标签／窗格上下附加栏。原有偏好保留；关闭禅模式或退出全屏时恢复。禅模式中显示任意一栏，先退出禅模式并恢复全部原偏好，再显示用户指定的栏。隐藏已经关闭的栏不会改写原偏好。菜单勾选与图形设置呈现有效状态，因此开启禅模式时四项显示开关均为关闭。

全屏和禅模式都是本次运行的临时状态，不随布局恢复，也不在设置页提供当前状态开关。重启时恢复正常／最大化窗口、原分割和栏显隐偏好；普通窗口启动禅模式所采用的全屏范围仍是可保存的行为设置。

## 工具条与标题

菜单、工具和标题采用同一条带布局。解锁后拖动立即显示随鼠标移动的条带呈现，原位置移除；释放提交位置，取消恢复。把手只改变鼠标形状，不显示按钮高亮框。

顶部和底部工具区共用这一套条带，可互相拖动，均不限制为两行。底部工具区位于下侧收纳条之下、全局状态栏之上。行号从外侧开始：顶部向下增加，底部从状态栏一侧向上增加。普通行采用 28 个逻辑像素的紧凑基准，随字体或内容最小高度扩展，窗口控制保留自己的 32 像素高度。

拖到最后一行时，在靠工作区的一侧显示一行空白投放预览；顶部在下面，底部在上面。其他行不额外产生空白预览。移走某行最后一条工具条后该行立即消失，隐藏整行中的全部条带也不占高度；取消恢复原行和尺寸。空行的索引可用于恢复位置，不能为没有内容的行无界创建或保留隐藏控件。

`WindowManager::moveToolbar(window, stripId, ToolbarArea::Top/Bottom, row, index)` 可在已有行中插入或在末尾创建新行，`index = -1` 追加。命令 `window.toolbar.move` 接受 `strip`、`area: "top" / "bottom"`、从 0 开始的 `row` 和 `index`。缺参时显示工具条列表及区域／行选择菜单，可用键盘完成；无效目标或越界索引在修改布局前拒绝。菜单入口为“视图 → 工具条 → 移动工具条…”。

拖动呈现使用工具条当前的主题背景与文字颜色，系统深浅色模式不能使它变黑或变色。拖动前的控件绘制、首次截图及移动中的截图更新采用同一主题。

右键菜单列出全部工具条及其显隐状态。窗口类型或停靠位置不适用的命令隐藏；操作仍有意义但当前没有对象，例如没有左侧标签，则保留禁用状态。

工具条可以压缩：拖动后一条的把手向前移动，前一条按钮溢出；再次向后拖动可释放宽度并恢复按钮。菜单条被压缩时，被裁掉的菜单只能从溢出菜单打开：已打开一个菜单时鼠标移过被裁掉的区域不会切换到看不见的菜单；从溢出菜单打开的菜单像普通子菜单一样贴在溢出菜单旁边，不再出现在菜单条的原位置而遮住溢出菜单；用方向键切到被裁掉的菜单时，它在菜单条可见部分的末端打开。末尾常驻窄按钮，下半部显示下拉箭头；存在溢出项时，上半部再显示右箭头。菜单包含溢出操作、“重置尺寸”和“添加或移除按钮”子菜单，修改当次更新条带和菜单。位置、宽度、显隐、按钮选择及尺寸策略随布局保存。

`window.hideToolbarOptionsWhenLocked` 默认关闭。开启后，锁定且没有溢出按钮的工具条隐藏末尾选项入口并释放其宽度；出现溢出或重新解锁时恢复。标题和窗口控制条继续遵守自身不显示选项的约束。禁用工具按钮只显示灰色图标，不画悬停、按下或焦点边框，不产生鼠标强调。

“弹性空间”放在选项菜单顶层，紧接“重置尺寸”。“添加或移除按钮”只包含该工具条的内容项；强制弹性行的限制仍决定是否提供弹性操作。

工具条尺寸分为内容宽度和弹性空间两种策略。每行最多有一条弹性工具条，占用扣除其他条带后剩余的空间，将其右侧条带推到右边。标题必须采用弹性策略，不能改为普通条；标题所在行的其他条带不提供弹性设置，弹性条移入时自动改为普通条。模块使用宿主约束表达强制弹性，不能让同一行出现两个强制弹性条。没有强制弹性条时，新设置或移入的弹性条仍取代原弹性条。恢复布局时同样按宿主约束确定唯一弹性条。空白和标题区域保留拖窗、双击最大化等交互。可编辑条带仍通过定制菜单或统一命令 `window.toolbar.setSizing` 切换策略。

窗口变窄时先缩小弹性空间，再压缩普通条带。弹性右侧的条带从窗口右边缘向左排列，最后一条与右边缘的间距保持不变；右侧空间不足时从该侧靠近弹性的一条开始压缩。窗口恢复宽度后重新采用保存的请求宽度，缩放不改写这些值。

“重置尺寸”恢复当前工具条的自然宽度，不改变顺序或其他条带的请求宽度。目标位于弹性左侧，或该行没有弹性时，保持目标左端位置，在后方分配或收回空间。目标位于弹性右侧时，保持其右端及后方条带位置，在前方分配或收回空间。先调整弹性空间，不足时压缩相应方向的邻条；仍不足时，目标受最小宽度和窗口边缘限制。隐藏条带重置不影响当前可见布局；弹性条带重置只清除显式宽度，继续占用余量。

弹性空间耗尽且前条已经被压缩时，左侧重置应在现有头部位置受窗口边缘限制，不能通过压缩弹性右侧条带来让前条自动伸长，导致目标头部移动。

重置后的自然宽度优先级随布局保存，每行最多一个。手动调整宽度、改变尺寸策略、移动或拖动条带时清除受影响行的优先级，Esc 恢复原状态。公开 API 为 `WindowManager::resetToolbarWidth(window, stripId)`；统一命令 `window.toolbar.resetSize` 可指定 `strip`，未指定时显示可用键盘选择的工具条列表。

拖走一条工具条后，由它固定端一侧的普通邻条补上腾出的空间，另一侧的条带位置不变：位于弹性左侧（或该行没有弹性）时由前方条带补位，位于弹性右侧时由后方条带向左延伸补位。补位的邻条另一侧是弹性条带或行端时，邻条恢复自然宽度，空间交给弹性条带。固定宽度的条带不补位。已压缩和已拉伸的条带遵循同一规则。取消拖拽恢复原顺序、尺寸策略及宽度。

**按固定端调整宽度。** 每行以弹性条带为界分成两段：弹性左侧的条带从行首向右排，固定端是左边；弹性右侧的条带从行尾向左排，固定端是右边。拖动把手就是移动该条带左边的分界线，只由分界线固定端一侧的那一条改变宽度，另一侧的条带宽度不变、整体跟着移动，差值由弹性条带吸收：

- 弹性左侧（或该行没有弹性）：前方条带变宽或变窄，被拖条带保持宽度、随鼠标移动。
- 弹性右侧：被拖条带自己变宽或变窄，左边缘跟随鼠标，右边缘不动；前方条带保持宽度，只随之平移。
- 固定端一侧是固定宽度的条带（如窗口控制条）时，分界线不动，拖动只用于调整顺序，不改变任何条带的宽度。
- 从别处拖入时同样处理：放到弹性左侧，前方条带延伸到鼠标处，拖入的条带保持宽度；放到弹性右侧，拖入的条带从鼠标处一直延伸到右邻（或行尾），前方条带保持宽度；固定宽度的条带保持自然宽度。

所有宽度仍受各自的最小宽度限制。

标题文字在自身条带的内容区内居中，空间不足时在右侧显示省略号，完整标题仍用于窗口标题和可访问名称，标题区域悬停不显示气泡。标题内容区最小宽度为 96 个逻辑像素，把手另计；调整窗口尺寸时遵守该下限。

标题条不提供工具条选项按钮，也不为其预留宽度。这是宿主的呈现策略，旧用户布局不能重新启用它；其他工具条继续提供选项。

最小化、最大化／还原和关闭按钮组成一条独立的窗口控制工具条，完整窗口和轻量窗口都能调整其位置。它的宽度固定为三个按钮的宽度（见下文按钮顺序一节），不提供选项按钮，也不允许设为弹性。三个按钮始终完整显示并靠条带顶部排列，Windows 最大化按钮的原生命中继续使用实际按钮位置。轻量窗口默认在同一行依次显示 `floating-menu`、标题和窗口控制；菜单只提供本浮窗适用的入口，不创建完整工作区按钮条。

**按钮顺序与屏幕边缘。** 设置 `window.captionButtonOrder`（`WindowBehavior::captionButtonOrder`）提供三种顺序：Windows（最小化、最大化、关闭，默认）、反向（关闭、最大化、最小化）和 macOS（关闭、最小化、最大化）。后两种的关闭按钮在最左侧，适合把窗口控制工具条移到左上角。窗口控制条的宽度固定为三个按钮的宽度：不能拖宽，前后工具条移走时也不接收它们留下的宽度，恢复时由宿主的固定尺寸约束确定宽度，按钮旁边不会出现空白。工具条行的首尾不再保留 2 像素留白，每行第一个和最后一个工具条（包括菜单和窗口控制条）都贴到边缘：普通窗口中紧贴 1 像素窗口边框（与 Windows 原生标题按钮一致）；最大化或全屏时没有边框，四个屏幕角的最外侧像素都属于最外侧的按钮（底部的两个角要求全局状态栏隐藏，否则状态栏在按钮与屏幕边缘之间）。普通窗口中，按钮外侧仍有窗口缩放区，与按钮重叠的部分优先缩放；最大化按钮例外，它的整个矩形都返回 `HTMAXBUTTON`，以显示 Windows 11 的贴靠布局弹窗。缩放区移到窗口外侧见阶段 8.1。

所有下拉菜单按钮在菜单展开时再次点击应关闭菜单，不能因为关闭后的鼠标事件回放立即重新打开。工具条选项和其他按钮共用悬停、按下及键盘焦点样式；关闭菜单后正常恢复其他控件的悬停反馈。

鼠标打开选项菜单不留下键盘焦点外框；菜单关闭后清除遗留悬停，强调立即消失，不需要额外点击或移动。后续真实进入和离开继续更新悬停，键盘导航获得的焦点仍保留可见提示。

从菜单外部关闭时，在真实鼠标按下处理期间禁止向底层控件回放该按下事件；定制子菜单沿父菜单链应用同一策略。关闭之后不能遗留按键状态、鼠标捕获或弹窗，悬停进入和离开的实际绘制均应恢复。检查使用 Windows 原生输入路径，不能只凭向控件直接注入事件的结果判断已修复。

## 移动与循环导航

组操作明确区分：交换保留两处槽位与比例，交换整组；合并保留目标组，把源标签按原序追加或插到指定序号；移动将整组插入指定目标旁或更换窗口／区域父级。中央和四边固定组均参与交换、合并与选择目标，按实际位置提供上下左右循环操作。移动还可选择已有窗口、新完整／轻量窗口、四边固定或收纳；跨窗口保留全部内容与稳定 ID。非固定收纳条的内部组不作为可见组交换目标。

移动与聚焦按范围分别提供命令：整个中央或固定标签组向上下左右移动或移到已有窗口；组内标签前后重排；窗格移到同组前后标签；标签或窗格移到本窗口上下左右的可见标签组；移到已有完整或轻量窗口；当前标签内的窗格按方向交换位置。前后及方向操作在自己的范围内循环，只有一个对象时不生成额外对象。

组方向包括中央和固定分区，收纳标签不作为可见组目标。窗格方向只在当前标签内。空间导航优先同投影通道和实际位置，锚点落在分隔条细缝时选最近通道，同距按稳定布局顺序选择。连续方向聚焦保留正交锚点，跨全高或全宽组后仍返回原行列；切换轴、鼠标聚焦和布局变化重置锚点。

已有窗口按创建顺序前后循环，支持完整、轻量和最小化窗口；移动到最小化目标时恢复显示。选择命令也可用窗口或标签 ID 直接调用。窗格合入现有标签时采用目标标签的上下栏共享策略，保留 Pane ID、控件和专属栏；空目标窗口创建标签并沿用源策略。源标签最后一个窗格移走后清理空标签，不能重建业务内容完成搬运。

## 输入法状态

用户 2026-10-24 要求：输入法状态可以按层级分开记，切到哪里就恢复那里上次的状态。

- **记什么**：当前使用的输入法或键盘布局，以及它的开关和全部输入模式，例如中文的中／英、全角／半角，日文的平假名／片假名，韩文的韩／英。不针对某种语言，系统能读出的状态都整体保存、整体恢复。
- **层级**：设置 `window.inputMethodScope` 选择在哪一层分开记，从粗到细为：
  - `application`：整个程序共用一个状态；
  - `window`：每个完整窗口和它的轻量浮窗共用；
  - `floatingWindow`：每个顶层窗口各记各的，轻量浮窗和它的完整窗口分开；
  - `tabGroup`：每个标签组；
  - `tab`（默认）：每个标签；
  - `pane`：每个窗格，同一标签拆成几块时各记各的。
- **何时保存和恢复**：焦点离开一个范围时记下它的状态，焦点进入另一个范围时恢复那里记下的状态；在同一个范围里移动焦点不做任何事。切到别的程序再切回来，系统自己会保持原状态，也不做任何事。命令面板、对话框等临时界面不属于任何范围，沿用打开前的状态，关闭后回到原来的范围时也不重新恢复。
- **新建和移动**：新建的标签、窗格、标签组或窗口沿用新建时所在范围的状态。标签或窗格移到别的范围时，按当前层级的归属走：层级是标签或窗格时带着自己的状态走，层级更粗时用目标范围的状态。合并后消失的范围丢弃它的状态。
- **不跨重启**：状态只在本次运行中保存，不写进布局或设置；重新启动后各范围从系统当前的状态开始。修改层级设置时清空已记下的状态，从当前状态重新开始。
- **平台**：先在 Windows 上实现；macOS、Linux 的输入法接口不同，以后单独做。某个输入法不让程序读写它的模式时，至少恢复用的是哪个输入法，并在设置说明里写明。

## 窗口缩放边框

**问题**：原来的自绘窗口把缩放命中区放在客户区内侧（距窗口边缘 `SM_CXSIZEFRAME + SM_CXPADDEDBORDER` 以内，100% 缩放下约 8 像素）。隐藏侧边栏或该侧没有收纳条时，左右临时面板一直延伸到窗口边缘；非最大化状态下，面板外侧这 8 像素被窗口缩放占用，面板自己的外侧边无法拖动。为了让两者都能用而在面板外侧留出 8 像素空白，又会浪费空间、破坏贴边外观。

**做法：缩放区在窗口外侧的不可见边框里**，与 Windows 10 起的普通 Win32 窗口一致（实现 8.1）：

1. 窗口不带 Qt 的无边框标志，Qt 按实际客户区计算几何（`geometry()` 就是客户区）。非最大化时，`WM_NCCALCSIZE` 在左、右、下保留 Windows 为当前样式和 DPI 计算的边框（`AdjustWindowRectExForDpi`），DWM 把其中的缩放部分渲染为不可见；顶部不保留，自绘标题行一直到顶。
2. `WM_NCHITTEST`：客户区外的点交给系统默认处理，得到系统的边和角；固定尺寸的方向改为 `HTBORDER`。客户区内只在最上方保留一条细缩放带，标题按钮优先的规则不变。其余客户区像素全部归内容。
3. 可见外观：左、右、下的 1 像素窗口边框由 DWM 画在客户区外，和普通窗口相同；顶部的 1 像素由自绘框架画（Windows 11 上 DWM 的半透明边框四边都画，盖在它上面）。内容在左、右、下贴到客户区边缘，没有新增留白。真实边框已经带来 DWM 的阴影和边框，所以不再把 DWM 边框扩展进客户区。
4. 拖动预览的紧凑样式只去掉 `WS_DLGFRAME`、保留 `WS_BORDER`；紧凑时 `WM_NCCALCSIZE` 不内缩，整个外框都是客户区，不保留轮廓之外的系统缩放边框，也不在标签旁的透明缺口画矩形边线。切换呈现时保持客户区的位置和大小，外框按实际边框重新计算；返回正常呈现后恢复外侧缩放边框。
5. 最大化和全屏没有缩放边框。Qt 用无 `WS_THICKFRAME` 的弹出样式模拟全屏，并且先改样式、后更新自己的窗口状态，切换中途还会补发排队的旧状态，所以边框计算按原生样式判断是否全屏，不按 Qt 的状态。
6. 拖动尺寸限制（`WM_GETMINMAXINFO` 的跟踪尺寸）是外框尺寸，在客户区限制上加上边框。

这样窗口缩放和面板外侧调整各占一块不重叠的区域：鼠标在窗口可见边缘之外是窗口缩放，在可见边缘之内是面板调整，两者光标形状相同，但位置与 Windows 上所有普通窗口一致，不需要用户学习。

**备选方案**（当时设计、未采用）：保留客户区内的缩放带，但缩到 3 像素，面板外侧调整带放在其内侧 3–7 像素，并在悬停时显示面板调整提示线以区分。
