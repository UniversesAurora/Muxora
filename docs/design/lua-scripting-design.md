# Lua 脚本与组件扩展

## 目标与边界

Lua 是应用的用户编程接口。快捷键、菜单、命令面板和工具条使用相同命令；脚本既能调用已有命令，也能注册有稳定 ID 的新命令和回调。窗口、标签、窗格、四边栏、布局、外观和工具区通过正式公开 API 接入，不能绕过布局不变量或关闭许可。

本次先建立运行时、当前组件适配和宿主事件入口。真实 SSH／SFTP／终端业务尚未实现；终端输出触发源在终端接入时发布事件，不能用占位内容模拟真实连接完成情况。按月、按年、时区和夏令时的日历调度属于后续触发器设计，不能把固定毫秒间隔当成相同能力。

## 依赖选择

采用官方 Lua 5.5.1 与其嵌入 API，固定官方源码版本，在构建目录编译进程序；用户不必安装解释器。适配层只处理受控值转换、保护调用、回调引用和线程调度，不另写语言解析器。Lua 以 C++ 模式构建，避免 Lua 错误跳转跨过 C++ 对象析构。[Lua 下载与源码](https://www.lua.org/download.html)、[Lua 5.5 手册](https://www.lua.org/manual/5.5/)

嵌入构建对垃圾回收有一处明确改动：`__gc` 执行期间保留指令 hook，防止无限终结函数阻塞取消或关闭 VM。CMake 只生成该文件的构建目录副本，并核验固定版本中的改动位置；上游压缩包不变。升级 Lua 时必须复核该处及预算、OOM、终结函数和关闭回归，详见 [依赖说明](../../third_party/lua/README.md)。

没有引入自动映射整个 Qt 对象图的绑定层。当前边界使用字符串、布尔、数值、数组、对象表及稳定 UUID，不让脚本保存窗口指针。这样窗口移动、关闭、恢复和脚本重载均能在调用时重新检查目标。

Neovim 的 Lua 接口采用命名空间组织、统一命令、用户配置和可撤销回调；WezTerm 采用 Lua 配置与事件回调。Muxora 借鉴这些组织方式，保留自己的窗口模型与生命周期约束，不宣称兼容它们的脚本。[Neovim Lua 指南](https://neovim.io/doc/user/lua-guide.html)、[WezTerm Lua 配置](https://wezterm.org/config/lua/general.html)

## 模块职责

| 位置 | 职责 |
| --- | --- |
| `modules/lua-runtime/` | Lua 状态、脚本任务、保护调用、值转换、预算、取消和回调引用；只依赖 Qt Core 与 Lua。 |
| `modules/window-system-lua/` | 把值描述转换成 WindowSystem 公开操作；注册和释放脚本命令、工具条、状态项、事件订阅和计时器。 |
| `modules/window-system/` | 正式 UI API、命令、菜单及布局，不依赖 Lua、SSH 或 Muxora 配置。 |
| `src/app/` | 用户目录、启动脚本、重载、用户快捷键覆盖、弹窗、打开外部程序和声音等宿主服务。 |

未来 SSH／SFTP 等组件沿用这些边界：在命令注册表贡献带 `menuPath`／排序的命令，通过 `contextMenus` 增加按目标和内容类型过滤的右键操作，为工具条提供命令 ID。`ScriptHost::registerService` 注册组件自己的具名方法，`publishEvent` 发布值事件；组件对象销毁时可自动撤销所属服务，保留名称不能覆盖。卸载时移除自身贡献；不能把业务逻辑直接写进主窗口类或 Lua 解释器。

动态菜单根据当前注册表增加和回收 Action；共享分类仍有贡献时保留，空的动态分类才回收。模块不能依赖某个菜单控件指针长期存在。自定义工具条与状态项使用值描述，完整和浮动窗口各自保留布局策略。

## 执行、预算与错误

每个宿主使用一个专用脚本线程和 Lua VM，不为每个标签、计时器或回调创建解释器。每个任务使用协程；遇到 UI 操作时让出执行，由主线程处理后回执，再恢复该协程。主线程不等待脚本完成，脚本不能跨线程直接访问 QWidget。

默认 Lua 分配预算为 32 MiB，待处理任务最多 128 个，任务／回执保留数据最多 8 MiB；源文件、值深度、节点数、字符串、日志、保留回调及宿主注册资源也有上限。事件待投递队列遵守运行时的数量、字节及值大小预算，不复制完整布局或终端历史来保存订阅状态。

指令与执行时间预算作用于 Lua 执行片段；宿主等待有独立超时。计数 hook 使用让出及不可绕过的中止状态，避免用 `pcall` 吞掉普通错误后无限继续。标准库本地 C 算法不支持强制抢占，因而这不是针对恶意代码的进程级隔离；不能将 Lua 分配上限等同于整个应用的内存上限。

默认提供基础、字符串、表、数学和 UTF-8 库，不开放 `debug`、系统 shell、阻塞文件 IO、任意原生模块和未经约束的协程。`require` 只加载指定用户 Lua 目录中的文本模块，有路径边界、文件大小、严格 UTF-8 和循环加载检查；编码错误直接报告，不能替换无效字节后继续执行。外部程序按独立参数启动，不通过 shell 拼接命令。

语法错误、运行错误、超预算和失效目标以失败结果报告，不能终止 GUI。回调任务完成后释放临时协程和结果；取消、重载和退出会丢弃旧代回执，解除订阅和计时器并释放函数引用。初始化注册失败时回收该代注册资源；已经执行的普通 UI 命令不作假事务回滚。

重置完成通知也必须核验 VM 代次。`resetFinished` 仅通知投递时仍为最新代次的重置；连续请求重置时，已经过期的完成消息不能触发新一代初始化。不能仅在任务结果上检查代次，而让重置消息绕过检查。

## 窗口状态与面板策略

Lua 的 `windows.set_state` 使用 `window.minimize`、`window.maximize`、`window.restore` 统一命令；`windows.state` 分别返回最小化、最大化状态和当前全屏范围。全屏范围继续由 `windows.set_mode` 管理，避免把最大化与全屏混为一种状态。

`ui.command_palette` 与 `ui.window_selector` 接受 `modal`、`dismiss_on_outside` 布尔选项，默认非模态且外点关闭。面板策略沿用 WindowSystem 的 `FloatingPanelOptions`；打开面板不阻塞脚本，也不创建嵌套事件循环。当前 API 用法见 [Lua 使用说明](../development/lua-guide.md#窗口状态与浮动面板)。

## 配置与键盘入口

用户配置使用 `User/init.lua`，纯 Lua 模块放在 `User/lua/`。没有启动脚本时正常运行；程序不能自动执行下载目录、会话内容或远端输出中的代码。

脚本命令使用 `user.*` 命名空间，不能覆盖内置命令。Lua 函数引用只存在于当前 VM，不能把临时回调 ID 写入布局或 `keybindings.json`。快捷键最终绑定稳定的命令 ID；用户快捷键文件在脚本命令和默认绑定注册后覆盖它们。

重载期间暂停偏好自动保存，先恢复上一代的默认绑定和注册边界，载入新脚本，再重新应用用户规则。不能让卸载时的空绑定覆盖用户文件。普通快捷键编辑合并保存；不用每个新增命令都同步写一次文件。不同代命令默认值缓存须回收，卸载的用户规则须保留为未识别命令规则。

## 事件与后续触发器

当前提供有界事件订阅和可取消的一次／重复毫秒计时器。宿主用 `publishEvent` 注入事件，例如未来的 `terminal.output`、`connection.changed`、`transfer.finished`；脚本可以按内容自行判断，再调用弹窗、程序、声音或其他命令。

同一订阅串行处理事件。`layout.changed` 是状态通知，已有回调未完成时允许合并；其他事件按发布顺序进入有界队列。值非法或队列超出预算时明确报告错误并撤销对应订阅，不能静默丢掉终端输出或无限堆积。未捕获的计时器／事件回调错误同样停用该资源；一次性计时器完成后释放回调，周期计时器未完成时不积压重复任务。

完整触发器后续建立值描述规则，而不是把判断逻辑塞进终端绘制路径。应分别定义文本流跨块匹配、编码、正则预算、重复抑制、连接归属和关闭清理；时间规则分别处理单次、固定间隔及日历重复，包括时区、夏令时、无效日期、休眠唤醒和错过触发的策略。条件与动作使用可扩展注册表，Lua 回调只是其中一种动作。

## 验证要求

- 真实 Lua 语义、UTF-8、模块复用、保护调用、错误堆栈和错误后继续运行。
- 多段／多绑定快捷键执行 Lua 命令，菜单和组合命令使用同一条路径。
- 窗口、标签、窗格和停靠操作保持 ID 与内容实例，关闭许可仍生效。
- 初始化失败、重载、注销、自行关闭和回调中销毁宿主时正确释放资源。
- 宿主队列延迟投递多个重置完成消息时，只通知最新代次，不能重复初始化。
- 无穷循环、`pcall`／标准库回调逃逸、OOM、循环值、超深值、任务与日志容量。
- 工具条与状态项动态贡献、共享菜单及空分类回收，不在反复注册后增长。
- Release 的 Lua 分配计数、QObject、原生窗口及系统资源实测；工作集只作补充，不能凭单个数字声称内存已最优。

`window-system.lua-lifecycle` 把 Lua 重载与两个窗口的 UI 贡献一起验证：24 代加载、768 个有序事件、工具条布局保留及内容实例身份。每代断言命令、工具条、状态项、计时器、订阅和回调的精确数量；预热后比较 QObject 类型计数，卸载后检查 VM、回调与注册资源归零。原生内存和句柄读数作为测量记录，不用放宽阈值代替资源断言。该场景不显示窗口，不能据此完成实际应用峰值、渲染内存或长期资源验收。

实际完成情况与运行结果另记在预览状态，设计条目不能当作已通过的检查。
