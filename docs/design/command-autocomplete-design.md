# 终端命令补全设计

状态：规划，2026-10-20。实现步骤见 [阶段 7.11](../roadmap/implementation/phase-7-terminal-and-sessions.md#711-终端命令补全)，在 SSH 终端（7.5、7.6）可用之后开始。

## 1. 需求

在终端里输入命令时，光标处弹出一个类似 IDE 的补全列表，列出接下来可能要输入的内容：以前执行过的命令、当前目录下的文件和目录、常用命令的子命令和参数、保存的命令片段。选中后把剩余部分填进命令行。

- **可选功能**：默认关闭，在设置中开启，也可以按会话单独开关。关闭时不加载任何相关代码和数据（[工程设计 §3.4](../development/engineering-design.md#34-不用的组件不加载)）。
- 参考对象是 Termius 的 Autocomplete（付费功能）。下面先说明它的做法，再说明 Muxora 的取舍。

## 2. Termius 的做法

根据 [Termius 文档](https://docs.termius.com/terminal/autocomplete-and-shell-integration) 和 [官方博客](https://termius.com/blog/autocomplete-helium-vs-hydrogen)：

| 方面 | 做法 |
| --- | --- |
| 建议来源 | Shell 历史命令、文件和目录路径、内置的常用命令及参数（带参数说明）、用户保存的片段（Snippets）；检测到密码提示时，建议已保存的身份（Identity） |
| 知道“现在在输入命令” | Shell 集成：识别提示符、当前目录、是否有命令在运行 |
| 远端数据怎么取 | 在同一条 SSH 连接上，除了终端用的 `shell` 通道，再开额外的 `exec` 通道执行命令，读取路径列表和历史记录；不需要在服务器上安装任何东西 |
| 限制 | 远端要求 OpenSSH 7.2 以上、bash；本地终端只支持 bash 和 zsh；不支持 PowerShell 和 CMD。有些设备（网络设备、加固过的服务器）拒绝 `exec` 通道甚至断开连接，此时要关掉补全；服务器 `MaxSessions` 需要至少为 2 |
| 两代引擎 | 旧版 Hydrogen 支持路径、历史、片段、密码；新版 Helium 重写了界面，输入无延迟，目前只支持历史和路径 |
| AI | 在补全中用自然语言生成命令（按下方向键后输入描述）。Muxora 的 AI 能力见 [未来规划 §2](../roadmap/future-plans.md#2-ai-接入)，不在本设计范围内 |

文档没有公开弹窗的按键、Shell 集成脚本的具体内容和数据的保存方式，下面这些由 Muxora 自行设计。

## 3. Muxora 的做法

### 3.1 判断“正在输入命令”和输入了什么

补全必须准确知道命令行从哪里开始、用户已经输入了什么，否则会在 `vim`、密码提示或程序的交互输入里乱弹。按可靠程度分三级：

1. **有 Shell 集成（OSC 133）**：提示符结束（`OSC 133;B`）到命令执行（`OSC 133;C`）之间的输入就是命令行，终端核心能给出它在屏幕上的起点；`OSC 7` 给出当前目录。用户自己装了集成脚本（Windows Terminal、VS Code、iTerm2 的脚本都输出这些序列）时直接使用。
2. **自动注入（可选，默认关闭）**：仅对 bash、zsh 和 fish。连接时不发普通的 `shell` 请求，而是用 `exec` 请求启动用户自己的登录 shell，并通过命令参数内联加载一小段集成脚本（例如 bash 的 `--rcfile` 指向进程替换）；**不在远端写任何文件**。启动失败或检测到其他 shell 时退回普通 shell。这一选项在会话设置中可见，并说明它会改变 shell 的启动方式。
3. **没有集成**：不自动弹出。用户可以按快捷键（默认 `Ctrl+Space`）手动打开，此时用光标所在行、光标左侧的文字作为输入，只提供历史和片段，不推断参数。

下列情况一律不弹出、也不记录输入：备用屏幕（`vim`、`htop`、`less` 等全屏程序）、有命令正在运行（`133;C` 之后、`133;D` 之前）、鼠标选择或复制模式中、广播输入中。

### 3.2 建议来源

| 来源 | 说明 | 获取方式与上限 |
| --- | --- | --- |
| Muxora 记录的历史 | 通过 Muxora 执行过的命令，按主机（本地终端按 shell 配置）分别记录，带执行次数、最后执行时间、执行时的目录和退出码 | 只在有 Shell 集成时记录（从 `133;B` 到 `133;C` 之间的命令文本）。以空格开头的命令不记录（与 `HISTCONTROL=ignorespace` 一致）。每台主机最多 5000 条、1 MiB，超出淘汰最久未用的。存为普通文件，不加密（与 [启动时恢复会话设计](session-restore-design.md) 的历史文件一致），设置中提供“清除补全历史” |
| 远端 shell 历史 | 读取远端的 `~/.bash_history`、`~/.zsh_history` 等（只读） | 第一次弹出时通过一个 `exec` 通道读取最后 2000 行，结果只在内存中，该主机的最后一个会话关闭时释放。可在设置中关闭 |
| 路径 | 当前目录（或已输入的路径前缀所在目录）下的条目 | 优先复用已打开的 SFTP 通道列目录，没有时开一个 `exec` 通道执行只读命令；每次最多 500 项，结果按目录缓存 30 秒；本地终端直接读文件系统（WSL 走 `\\wsl$` 路径换算，见 [本地终端设计](local-terminal-design.md)） |
| 命令规格 | 常用命令（`git`、`docker`、`systemctl`、`kubectl`、`apt`、`ssh` 等）的子命令、选项和参数说明 | 采用开源的 [Fig autocomplete 规格](https://github.com/withfig/autocomplete)（MIT 许可，Amazon 维护，社区持续更新）转换成 JSON，按命令名分文件，第一次需要该命令时才读入；动态参数（例如 `git checkout` 后的分支名）通过 `exec` 通道运行规格中声明的只读命令获取 |
| 片段 | 用户保存的命令片段（会话管理器的“快速命令”） | 按名称或内容匹配 |
| 密码提示 | 检测到 `password:`、`[sudo] password for` 等提示时，列出该主机已保存的凭据名称 | 只显示名称，选中后由凭据库直接把密码写入终端，Muxora 界面和日志中不出现明文；绝不自动发送 |
| Lua 扩展 | 脚本注册自己的建议来源 | 见 §3.6 |

### 3.3 排序

输入前缀匹配优先，其次是不连续字符匹配（与快速输入相同的模糊匹配规则）。同等匹配时按“频率 × 最近使用”打分，并给以下情况加分：在同一目录执行过、上次执行成功（退出码 0）、与上一条命令在历史中经常连续出现。每次按键的匹配在 1 毫秒内完成：每台主机的候选按前缀建立有序索引，数据量有上限（§3.2），不需要后台线程；远端数据（历史、路径、动态参数）都是异步获取，到达后再刷新列表，不阻塞输入。

### 3.4 弹窗与按键

- 弹窗贴在光标所在单元格下方（空间不够时在上方），外观使用 [界面设计规范](ui-design-system.md) 中的快速输入列表样式：左侧类型图标（历史、路径、命令、选项、片段），中间是候选文字（已输入部分加粗），右侧灰色说明（参数说明、上次执行时间或目录）。最多显示 8 行。
- 触发：`terminal.autocomplete.trigger` 为 `auto` 时，在命令行输入至少 1 个字符、停顿 80 毫秒后弹出；为 `manual` 时只用 `Ctrl+Space`。另有可选的灰色行内提示（fish 风格）：只显示最佳候选的剩余部分，按 `→` 接受。
- 弹窗显示时：`↑`／`↓` 选择，`Tab` 接受，`Esc` 关闭；`Enter` 关闭弹窗并把回车照常发给 shell（执行当前已输入的内容，不偷偷替换成候选）；其他按键照常发给 shell，弹窗跟随输入刷新。弹窗关闭时，所有按键都按原样发送，shell 自己的 `Tab` 补全和历史 `↑` 不受影响。按键是否可改见阶段 3 的快捷键上下文（`terminalAutocompleteVisible`）。
- **接受时只发送按键**：Muxora 不直接改写终端内容，只把补全需要的字符发给 shell，就像用户自己输入一样。候选以当前输入为前缀时只发送剩余部分；否则先发送退格删除当前单词再发送完整单词。不发送 `Ctrl+U` 等会影响 shell 剪切板的组合键。

### 3.5 额外 `exec` 通道的约束

- 只执行只读命令（读历史文件、列目录、规格中声明的动态参数命令），命令文本在设置页的说明中列出。
- 每条连接同一时间最多一个辅助通道，空闲 30 秒后关闭；与 SFTP、端口转发共用 [SSH 连接层](../roadmap/implementation/phase-7-terminal-and-sessions.md#75-ssh-连接层libssh) 的通道计数。
- 服务器拒绝 `exec` 或通道数达到 `MaxSessions` 时，该主机本次运行内不再尝试，补全退回只用 Muxora 历史和片段，并在弹窗底部显示一行原因；不弹对话框、不断开主会话。
- 跳板机后面的主机同样适用（通道在最终主机的连接上打开）。

### 3.6 Lua 扩展

[Lua 扩展 API](lua-extension-api-design.md) 增加 `muxora.terminal.add_completion_provider(spec)`：脚本声明适用的命令名或匹配条件，收到当前命令行、光标位置、目录和主机，返回候选列表（文字、说明、类型）。脚本按 Lua 扩展的预算和超时运行，超时的结果丢弃，不阻塞弹窗。

### 3.7 加载与内存

- 关闭时：补全模块、命令规格、历史文件都不加载。
- 第一次在某个会话中触发补全时，加载补全模块和该主机的 Muxora 历史；命令规格按命令名逐个加载。
- 某台主机的最后一个会话关闭时，释放该主机的远端历史、路径缓存和索引；全部终端关闭时，释放规格缓存和补全模块的全部数据（模块代码本身不卸载）。
- 弹窗控件在关闭后销毁，不常驻。

### 3.8 本地终端

bash、zsh、fish（WSL、Git Bash 中）按同样方式工作，Shell 集成通过 shell 启动参数注入（[本地终端设计](local-terminal-design.md)）。PowerShell 自带 PSReadLine 预测补全，第一版不做；以后通过 PowerShell 的 OSC 133 提示符脚本接入历史和路径来源。CMD 不支持。

## 4. 设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `terminal.autocomplete.enabled` | `false` | 总开关；会话设置中可单独覆盖 |
| `terminal.autocomplete.trigger` | `auto` | `auto`／`manual` |
| `terminal.autocomplete.inlineHint` | `false` | 灰色行内提示 |
| `terminal.autocomplete.sources` | 全部 | 历史、远端历史、路径、命令规格、片段、密码提示，可逐项关闭 |
| `terminal.autocomplete.shellIntegration` | `detect` | `detect`（只使用已有集成）／`inject`（自动注入，§3.1）／`off` |
| `terminal.autocomplete.historyLimit` | 5000 | 每台主机的 Muxora 历史条数 |

命令：“打开补全（`Ctrl+Space`）”“清除补全历史”“清除当前主机的补全历史”。

## 5. 测试要点

- 按 §3.1 的三级分别验证：有集成时只在命令行弹出，`vim`、`htop`、`sudo` 密码提示、命令运行中不弹出也不记录。
- 接受候选后 shell 中的命令行与直接输入相同（含中文、空格、引号路径），`Enter` 不替换已输入内容。
- 远端拒绝 `exec` 通道（测试服务器把 `MaxSessions` 设为 1）时主会话不断开，补全降级。
- 1000 个会话中有 200 个开启补全时，未触发补全的会话不加载任何补全数据；每次按键匹配耗时 < 1 毫秒（基准测试）。
- 真实主机：本机 Windows OpenSSH、WSL 中的 sshd、Ubuntu 虚拟机。测试需要的服务器设置或文件改动在测试结束后全部还原。
