# Muxora 设置、会话存储与命令设计

状态：V0 设计要求；首个预览的命令、设置和快捷键实现范围见 [预览说明](../development/window-system-preview.md)。完整配置服务及编辑能力按本规范继续实现。

新增标签的位置可选组开头、组末尾、当前标签之前或之后，默认在当前标签之后。完整窗口和轻量浮窗各有独立的“只有一个标签时隐藏标签栏”设置，默认分别关闭和开启，按整个窗口的标签数量判断。固定面板标题与侧边收纳条不受该自动策略影响。

隐藏标签栏、工具栏、状态栏和侧边栏等偏好是布局的一部分。两种窗口分别保存新窗口使用的默认值，现有窗口继续保存自身的布局；旧窗口保存不能覆盖之后明确修改的默认值。升降级窗口时，恢复这个窗口在对应类型下的栏显隐历史。禅模式只投影有效显示，不写入这两套偏好。

命令面板默认非模态，点击其外部后关闭，原点击继续交付。通用浮动面板 API 分别控制自动关闭和模态。标签末尾新建按钮、类型下拉、菜单和快捷键调用同一套宿主命令。窗口菜单末尾按完整窗口及其轻量窗口列出可切换目标；状态栏右键可选择显示的状态控件。

平滑滚动的按组件开关是宿主运行期策略，不写入布局或用户设置；接口见 [模块说明](../../modules/window-system/README.md#组件滚动策略)，交互规则见 [界面设计](ui-design-system.md#48-滚动条)。

关联：[V0 设计](v0-design.md)、[工作区设计](workspace-design.md)、[终端 Normal 与选择模式](terminal-mark-mode-design.md)、[测试规范](../development/testing-design.md)。

## 1. 参考范围

设置和快捷键参考 VS Code：可直接编辑的 `settings.json`、`keybindings.json`，统一配置定义、默认值、搜索、校验、上下文和命令 ID。命令面板也参考 Windows Terminal 的搜索及动作入口。窗口视觉继续参考 Visual Studio 2019 之后的设计，不因配置借鉴 VS Code 而改变。

VS Code 的用户设置使用 JSONC，允许注释和尾逗号；窗口位置和工作台运行状态由独立状态／存储服务管理，并非都写进 `settings.json`。Muxora 借鉴这种职责分离，文件组织按本项目需要设计。[VS Code 设置](https://code.visualstudio.com/docs/configure/settings)、[JSONC](https://code.visualstudio.com/docs/languages/json)、[窗口状态源码](https://github.com/microsoft/vscode/blob/main/src/vs/platform/windows/electron-main/windowsStateHandler.ts)

配置和交互使用原生 C++／Qt 实现，不为模仿设置体验引入 Electron、Monaco 或 JavaScript 运行时。

## 2. 文件划分

**全局设置集中在一个文件，自建会话一会话一文件，快捷键和机器运行状态另存。** 不把所有内容堆进一个大 JSON，也不把每个设置项拆成一个文件。

```text
<UserConfigRoot>/
├── settings.json                 # 全局用户设置，JSONC
├── keybindings.json              # 用户快捷键覆盖，JSONC
├── sessions/
│   ├── catalog.json              # 分组、顺序等目录元数据，带版本的 JSON
│   └── items/<session-id>.json    # 每个自建会话，JSONC
└── ssh-alias-overrides.json       # 仅别名附加设置，JSONC

<LocalStateRoot>/
├── window-layout.json            # 窗口及工作区恢复，带版本的严格 JSON
├── runtime.json                  # 少量最近操作及界面状态，严格 JSON
└── transfers.json                # 有界任务记录，严格 JSON
```

Windows 用户配置目录建议为 `%APPDATA%\Muxora\User`，机器状态目录为 `%LOCALAPPDATA%\Muxora\State`。由路径服务通过 Qt 标准路径能力求值，不硬编码用户名或盘符；Windows 可以用 `AppDataLocation` 的 roaming 路径承载用户文件，状态使用 `StateLocation`。后续 macOS／Linux 使用对应标准配置及状态位置，公共服务只接收解析后的根目录。[QStandardPaths](https://doc.qt.io/qt-6/qstandardpaths.html)

默认值由应用内配置定义提供，命令可打开只读的默认设置及默认快捷键视图，不复制一整套默认值到用户文件。缓存、日志和临时文件不混入用户设置；导出用户配置时可独立选择会话，不默认携带机器窗口坐标或任务历史。

新增任何要保存的数据，按下面的顺序判断放在哪里，第一条符合的就是答案，并在同一提交里把它加进后面的归属表（用户 2026-10-24 要求定成规则）：

1. **只在本次运行有用**，例如输入法状态、悬停、未完成的拖动：不保存。
2. **密码、口令、令牌等机密**：不写进这些文件，交给系统凭据存储或外部来源（例如 SSH agent）。私钥按 [SSH 私钥存放设计](ssh-key-storage-design.md) 放 `~/.ssh` 或 Muxora 保管库。
3. **用户在设置里明确选的值**，用户可能手改、备份或带到另一台电脑：`settings.json`，用 `<区域>.<名称>` 形式的设置 ID，在设置定义里声明；阶段 4 之前按现有方式加进设置页，并记进阶段 4 的 ID 表。按键规则这类成列表的用户数据有专门的文件（`keybindings.json`）。
4. **用户创建、数量不定、各有生命周期的对象**，例如自建会话：一个对象一个文件，放在 `User/` 下对应目录。
5. **程序跟着用户的操作记下的工作区状态**：窗口、标签、分割、尺寸、位置，以及靠拖动和右键菜单形成的排布和显隐：`window-layout.json`。用户不需要手改；部分无效时只丢无效的部分（见 §4）。
6. **丢了也不影响使用的记录**，例如最近使用、历史、某条提示是否看过：`runtime.json`，有数量上限；传输任务记录放 `transfers.json`。
7. **能重新生成的内容**，例如缓存、索引、日志：缓存或日志目录，不进上面任何文件。

拿不准是第 3 条还是第 5 条时，看这个值是用户在设置里选的，还是程序跟着操作记下的：新标签插在哪里是在设置里选的，算偏好；新窗口各栏是否显示跟着用户最后一次的操作走，算状态。仍然拿不准就问用户，用户不在时写进交接记录的“待用户决定”。

现有数据按下表存放：

| 数据 | 文件 | 理由 |
| --- | --- | --- |
| 界面语言 `workbench.language` | `settings.json` | 用户偏好 |
| 界面字体、字号与缩放（见 [§3.3](#33-界面字体与缩放)） | `settings.json` | 应用级偏好，完整窗口与浮窗共用，不随布局保存 |
| 窗口行为 `window.*`：拖出方式、空窗口、拖动时唤起、新标签位置、单标签时隐藏标签栏、锁定时隐藏选项、窗口控制按钮顺序、禅模式全屏范围、输入法记忆范围 | `settings.json` | 用户偏好，对所有窗口生效 |
| 各范围当前输入法和输入模式 | 不保存 | 只在本次运行中有效，见 [输入法状态](window-interaction-design.md#输入法状态) |
| 标签外观 `tabs.*`：位置、多行、图标、编号、标题裁切、置顶标签、配色列表 | `settings.json` | 同上；配色列表是用户定义的数据，跟着用户走 |
| 快捷键 | `keybindings.json` | 用户偏好，规则列表单独成文件 |
| SSH 私钥 | `~/.ssh` 或 `User/keys/`（系统账户加密），由 `ssh.keys.storage` 决定 | 机密，按 [SSH 私钥存放设计](ssh-key-storage-design.md) |
| 代理的使用记录 | `runtime.json` | 丢了不影响使用 |
| 窗口、标签组、分割、标签、置顶和侧栏收纳、单个标签选的颜色 | `window-layout.json` | 工作区状态 |
| 每种窗口新开时各栏的默认显隐，以及每个窗口自己的显隐 | `window-layout.json` | 随窗口形态变化，属于布局（见文首） |
| 工具条排布：有哪些工具条、在哪一行、宽度、锁定、隐藏的菜单项和状态项 | `window-layout.json` | 由拖动和右键菜单产生，结构复杂且和窗口形态绑定；和 VS Code 的视图位置一样存为状态 |

当前预览中窗口行为和标签外观还随布局保存，按 [阶段 4.4](../roadmap/implementation/phase-4-settings.md#44-应用持久化) 迁到 `settings.json`，迁移时不读取旧布局里的这些值。

SSH config 仍是外部只读、动态来源，不复制到 `sessions/items/`。这些目录是安装后的用户数据位置，与源码中的 `src/sessions/` 等模块目录不同。

## 3. 全局设置与编辑

每个设置有稳定 ID、类型、默认值、说明、分类、允许范围、作用域和生效方式。设置界面与 JSON 编辑入口使用同一配置定义，支持搜索、查看修改项、恢复某项默认值、打开 JSON 与默认设置。键盘可以完成这些操作。

设置页的控件默认按类型生成：布尔值用复选框，枚举用下拉框（默认值由下拉列表在行尾标出，规格见 [界面设计规范 §4.7](ui-design-system.md#47-输入控件)，选项文字和说明不写默认值），数字用数字框，字符串用输入框，复杂对象只提供“在 settings.json 中编辑”。个别设置可以在定义里指定别的控件，例如标题长度用滑条加数字框，滑条只覆盖常用的一段，方便拖动。允许范围写在设置定义里，按程序能正确处理的值定，不按某个控件的范围定；数字框、`settings.json` 和 Lua 都按它校验（用户 2026-10-24 决定）。

用户文件只保存明确的覆盖值。以下键名为设计示意，最终 schema 在实现时固定：

```jsonc
{
  // 字体按顺序回退；仍采用逗号分隔的列表形式。
  "terminal.fontFamily": "JetBrains Mono, Sarasa Mono SC, monospace",
  "terminal.fontSize": 12,
  "workbench.colorTheme": "muxora-violet",
  "window.restoreLayout": true,
  "window.tabDragOutsideMode": "floating",
  "window.emptyWorkbenchAction": "keep",
  "window.dragReveal.enabled": true,
  "window.dragReveal.delayMs": 500,
  "window.newTabPosition": "afterActive",
  "terminal.markMode.defaultKeymap": "vim",
}
```

`window.restoreLayout` 控制是否恢复，实际窗口尺寸、标签和分割树写入状态文件。设置项不包含运行时句柄、当前鼠标位置、选区正文或当前终端 Normal 模式状态。

窗口行为设置必须有同等的图形入口：拖出类型 floating／workbench、完整空窗口 keep／close、拖拽悬停唤起开关及 200–2000 ms 延迟。搜索、修改状态、说明、恢复默认及 JSON 编辑共用 schema。判空包含整个窗口族，仍有从属浮窗不能自动关根；具体默认及生效时机见 [双窗口设计](floating-window-design.md)。

新建标签的位置同样提供图形设置与 `window.newTabPosition`。用户可选标签组开头、末尾、当前活动标签前或后，默认 `afterActive`。对应 `WindowBehavior::newTabPosition` 的四个枚举值为 `Beginning`、`End`、`BeforeActive`、`AfterActive`。加号、类型菜单、主菜单和命令创建共用这项策略；显式 API 插入索引优先，拖拽顺序不受影响。

`window.zenFullscreenMode` 设置普通窗口启动禅模式时进入的全屏范围，可选窗口、标签组或窗格，默认窗口全屏。已经全屏时保留当前范围。图形设置与 `WindowBehavior::zenFullscreenMode` 使用同一值。

`window.inputMethodScope` 选择输入法状态在哪一层分开保存：`application`、`window`、`floatingWindow`、`tabGroup`、`tab`（默认）或 `pane`，含义和恢复规则见 [交互细则 · 输入法状态](window-interaction-design.md#输入法状态)。设置页用下拉框，放在窗口行为分类。

`window.hideToolbarOptionsWhenLocked` 默认 `false`。开启后，已锁定且没有溢出项的工具条隐藏选项入口并释放宽度；解锁或出现溢出项后恢复。标题和窗口控制条原有的禁止选项策略不变。

### 3.1 标签外观与颜色

显式保存的标签配色按原值恢复，即使 ID 和名称与内置预设相同，也不按内置颜色替换。

标签外观提供以下设置，图形界面和统一命令使用同一份值。当前预览把它们存入严格 JSON 布局快照的 `tabAppearance`，设置页中的 `tabs.*` 是对应编辑项；完整 `settings.json`／JSONC 服务仍属于后续配置工作，不能把布局保存当作已实现注释保留编辑。

| 图形设置键 | 值与默认值 |
| --- | --- |
| `tabs.centralPlacement` | 普通标签栏位置：`top`（默认）、`bottom`、`left` 或 `right`；左右是竖向标签栏，见 [标签栏设计 §4](tab-strip-design.md#4-竖向标签栏)（`left`／`right` 随 8.23 实现）。 |
| `tabs.pinnedPlacement` | 固定侧栏标签栏位置，取值同上，默认 `top`，独立于普通栏。 |
| `tabs.verticalTabWidth` | 竖向标签栏的默认宽度，单位 `px`；范围和默认值见 [标签栏设计 §4](tab-strip-design.md#4-竖向标签栏)，拖动调整后的宽度保存在各组的布局里。 |
| `tabs.multiline` | 普通段多行排列，默认 `false`；开启后排满换行，不使用横向滚动条。置顶标签未独占一段时也使用这项设置。只用于横向标签栏。 |
| `tabs.showAllRows` | 默认 `true`，始终显示普通段所有行；关闭后平时只显示活动标签所在行。仅在 `tabs.multiline` 开启时生效，否则保留值。 |
| `tabs.stickyMultiline` | 默认 `false`，独立控制置顶段是否使用多行；只在 `tabs.stickyTabsOnSeparateRow` 开启时生效，否则保留值。 |
| `tabs.stickyShowAllRows` | 默认 `true`，始终显示置顶段所有行；关闭后平时只显示该段的活动行。仅在置顶段单独排列且开启多行时生效，否则保留值。 |
| `tabs.rowExpansion` | 置顶段和普通段共用的展开方式：`push` 推开内容、`overlay`（默认）浮层覆盖内容。所有收起的段一起展开和收起，见 [标签栏设计 §3.4](tab-strip-design.md#34-收起与展开)。 |
| `tabs.wheelExpandRows` | 默认 `false`。存在可收起的多行段时，用滚轮展开和收起；方向、横向滚动优先级与滚到边界后的保护见 [标签栏设计 §3.4](tab-strip-design.md#34-收起与展开)。不可用时保留值，设置页和菜单显示为不可用。 |
| `tabs.showIcons` | 默认 `true`；仅控制中央标签栏，开启时仍尊重单标签的宿主设置。 |
| `tabs.showNewTabButton` | 默认 `true`，同时控制末尾加号与类型下拉，隐藏不移除新建命令。 |
| `tabs.showGroupNames` | 默认 `true`；在标签栏右端显示有名字的标签组的名称，见 [标签栏设计 §13](tab-strip-design.md#13-标签组名称)。 |
| `tabs.showNumbers` | 默认 `false`；编号位于图标左侧，使用本栏当前顺序，从 1 开始。 |
| `tabs.showSidebarIcons` | 默认 `false`；固定和非固定侧栏的独立图标开关，仍尊重宿主逐标签设置。 |
| `tabs.showSidebarNumbers` | 默认 `false`；固定栏按本组编号，非固定条按整侧连续编号。 |
| `tabs.clipTitles` | 默认 `false`；开启后限制普通及固定侧栏标签栏的标题。 |
| `tabs.maximumTitleWidth` | 普通及固定标签栏的文字最大长度，显示单位为 `px`，对应 Qt 逻辑像素，默认 `160`，允许整数 `0–1000000`；`0` 不显示标题文字，图标和操作按钮保留。关闭裁切时保留数值但不限制自然长度。 |
| `tabs.clipSidebarTitles` | 默认 `false`；独立控制四边非固定收纳条的标题裁切，不影响普通及固定标签栏。 |
| `tabs.maximumSidebarTitleWidth` | 非固定收纳条的文字最大长度，单位、默认值和范围与 `tabs.maximumTitleWidth` 相同，数值独立保存。 |
| `tabs.colors` | 整体替换预设数组，缺省使用内置颜色。 |
| `tabs.stickySizing` | 置顶标签的尺寸，对应 VS Code 的 `workbench.editor.pinnedTabSizing`：`normal`（默认，和普通标签一样）、`compact`（宽 38，只显示图标，没有图标时显示标题首字，没有置顶按钮）、`shrink`（显示编号、图标和标题开头，标题长度由 `tabs.shrinkStickyTitleWidth` 限制，保留置顶按钮）。紧凑和收缩时，单行标签栏滚动时置顶标签留在视口开头，其他标签从它们下面滚过，最后一个置顶标签右侧有一条主题边框色的分隔线；多行时不固定。 |
| `tabs.shrinkStickyTitleWidth` | 收缩时置顶标签的标题最大长度，和 `tabs.maximumTitleWidth` 一样只限制文字，编号、图标和置顶按钮另占位置；单位、范围和控件与它相同（`px`，整数 `0–1000000`，`0` 不显示标题文字），默认 `40`，有图标时整个标签和 VS Code 固定的 80 差不多宽。标题短于限制时按原长显示。和普通标题裁切分开算：`tabs.clipTitles` 开关和长度都不影响收缩的置顶标签（用户 2026-10-24 决定）。VS Code 没有这一项，是用户 2026-10-24 要求加的；只在 `tabs.stickySizing` 为 `shrink` 时生效，设置页里其他尺寸下不可编辑但保留数值。 |
| `tabs.stickyTabsOnSeparateRow` | 默认 `false`，对应 VS Code 的 `workbench.editor.pinnedTabsOnSeparateRow`。开启后置顶段单独排列，可以与普通段选择不同的单行、多行和始终显示所有行设置，见 [标签栏设计 §3.6](tab-strip-design.md#36-置顶标签单独一行)。只用于横向标签栏。 |
| `tabs.preventStickyClose` | 哪些关闭方式不关置顶标签，对应 VS Code 的 `workbench.editor.preventPinnedEditorClose`：`keyboardAndMouse`（默认）、`keyboard`、`mouse`、`never`。按键指从快捷键执行的关闭当前标签（`workspace.closeTab`），以及会连带关闭标签的关闭窗格（`pane.close`，标签只剩这一个窗格时）；被拦下时和 VS Code 一样切到本组第一个未置顶的标签，本组没有就切到同一窗口其他组的第一个未置顶标签，都没有就什么也不做。鼠标指中键点击。菜单、命令面板、标签列表的关闭按钮、API 和 Lua 照常关闭。Lua 中取值写作 `keyboard_and_mouse`、`keyboard`、`mouse`、`never`。 |

置顶标签的尺寸和关闭保护在设置页“标签外观”下单独的“置顶标签”分类里。两段的排列开关和共用展开方式也可从标签栏右键菜单修改。

图标、新建入口、编号和多行开关也可从标签栏右键菜单修改。普通位置与固定位置分别控制标签栏位置。命令 `presentation.toggleIcons`、`presentation.toggleNewTabButton`、`presentation.toggleNumbers`、`presentation.toggleMultiline`、`presentation.toggleAllRows`、`presentation.toggleStickyMultiline`、`presentation.toggleStickyAllRows`、`presentation.toggleWheelExpandRows` 共用这些字段；带 `visible` 参数时必须是布尔值。`presentation.setRowExpansion` 使用字符串参数 `mode` 选择 `push` 或 `overlay`。不适用的开关保留原值，命令按设置的适用条件启用。

两套裁切开关和长度控件放在同一标签外观分类，明确标注普通／固定栏与非固定收纳条；各自关闭时禁用整组控件并保留数值。每项在同一行放滑条和 Qt 数字框，数字框保留上下微调按钮，后缀使用 `px`。滑条覆盖 `0–1000`，数字框支持该设置的完整范围；超出滑条范围的输入仍原样保留，不能被滑条夹回边界。

单位后缀只用于显示。界面读取开头的整数，用户删除或修改后缀后，确认或离开输入框时恢复为 `px`，不换算单位、不弹窗。没有数字或数值越界时保留最近的有效值；允许编辑中暂时清空。JSON、C++ 和 Lua 接口仍严格要求范围内的整数，不接受带单位的字符串。滑条与数字框即时同步，更新不卸载正在操作的控件，也不转移输入焦点。说明只写该设置的效果，不添加滑条操作教程或重复解释单位。

普通／固定栏右键菜单使用 `presentation.toggleTitleClipping`，非固定收纳条使用 `presentation.toggleSidebarTitleClipping`；全局菜单和命令面板可分别修改。长度只限制文字，不包含图标、编号、关闭按钮或内边距。逻辑像素随屏幕缩放映射到物理像素，不按字符数或主屏 DPR 计算；字体变更后重新测量自然宽度。左右收纳条限制旋转后文字的长轴，不能把它理解为条带厚度。

布局快照显式保存两套值，缺少可选字段时使用各自默认值。C++ 外观、Lua 外观和设置接口中的局部更新只修改指定字段，不让一套值覆盖另一套；非法值原子拒绝。格式维护遵守 [工程约束](../development/engineering-design.md#24-当前配置格式)。

标题始终保留完整字符串。绘制只显示文字开头在可用区域内的部分，允许截到字形中间，不产生省略号；提示、可访问名称、完整标签列表和宿主内容仍使用完整标题。单行、多行、上下位置及拖拽中的真实标签、标签预览与插入空位按各自呈现样式使用同一规则，来回拖动不修改标题或混用两套长度。标签被视口进一步压缩时仍直接裁切，图标及操作目标不与文字重叠；菜单、临时面板标题和窗口标题工具条不受此设置影响。

颜色预设包含 `id`、`name` 和四种完整状态：`groupActive`、`groupInactive` 用于普通或固定标签栏，`autoHideActive`、`autoHideInactive` 用于非固定侧栏。每种状态必须包含 `background`、`text`、`line`、`icon` 四个颜色；颜色格式为 `#RRGGBB` 或 `#AARRGGBB`。默认提供灰、蓝、红、金、绿、粉、紫、青、橙九项；未指定单标签颜色时继续使用主题默认值，非固定侧栏保留原紫色配色。

设置页的颜色编辑器接收严格 JSON 数组，点击“应用颜色列表”后校验并整体替换。列表最多 128 项；ID 非空、最多 128 个字符且不能重复，名称非空、最多 256 个字符。每个预设恰好有上述六个字段，四种状态分别恰好有上述四个颜色字段。错误类型、颜色、重复 ID 或不完整定义都拒绝应用，保留此前有效列表；空数组表示不提供可选预设。例：

```json
[
  {
    "id": "blue", "name": "Blue",
    "groupActive": {"background": "#e8f0fe", "text": "#202124", "line": "#1967d2", "icon": "#1967d2"},
    "groupInactive": {"background": "#f7f7f8", "text": "#3c4043", "line": "#1967d2", "icon": "#5f6368"},
    "autoHideActive": {"background": "#1967d2", "text": "#ffffff", "line": "#1967d2", "icon": "#ffffff"},
    "autoHideInactive": {"background": "#6A568C", "text": "#ffffff", "line": "#1967d2", "icon": "#ffffff"}
  }
]
```

单标签只保存 `colorId`，不复制整套预设。`tab.color.set` 的 `color` 参数为空时恢复默认；未知 ID 拒绝设置。颜色列表更换后不能按数组位置误关联到其他颜色，找不到原 ID 时使用主题默认显示。颜色列表和标签选择随布局快照恢复，校验失败须在替换现有内容前返回错误。

分割标签组以 `GroupId` 管理，支持六种排序、整组方向移动、移到已有窗口和关闭组。排序使用名称、打开次序和访问次序，不通过重建标签或业务内容完成重排。同一条标签栏里给标签归类的标签夹见 [标签栏设计 §12](tab-strip-design.md#12-标签夹)，它的名称、颜色和折叠状态随布局保存，不另设保存或恢复关闭标签夹的文件。

### 3.2 JSONC 用户文件

JSONC 支持 `//`、`/* ... */` 和尾逗号，不扩大为任意 JSON5 或可执行脚本。解析采用支持这些语法的成熟原生组件；Qt 严格 JSON 解析器不能单独承担此入口。Boost.JSON 的相应解析选项可作为候选，但其语义解析不自动解决注释保留编辑，必须分别验证。[Boost.JSON 解析选项](https://www.boost.org/doc/libs/latest/libs/json/doc/html/ref/parse_options.html)

配置文本与有效值分开处理。图形设置编辑采用针对目标字段的源码范围修改，保留已有注释、无关字段、顺序和格式，不解析后全量序列化覆盖用户文件；不能用正则剥注释。JSON 编辑提供语法、类型、未知键、重复键和范围诊断，以及从 schema 生成的键／值提示，不要求嵌入完整代码编辑器。

Windows 的默认字体链为 `Segoe UI, Microsoft YaHei, sans-serif`，参照 [VS Code 的 Windows 简中界面字体](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/browser/media/style.css)。其他平台从 Qt 系统界面字体开始回退。Qt 的字体匹配与整形处理缺字，不按字符手工选择字体，也不把系统没有安装的字体打包进应用。[QFont::setFamilies](https://doc.qt.io/qt-6/qfont.html#setFamilies)

三项均立即作用于本进程全部完整窗口和浮窗，包括之后新建的窗口。字体、字号与缩放分别保存，不把放大后的字号写回基础值。终端和编辑器的字体设置独立；界面缩放仍影响它们的呈现尺寸。屏幕 DPI 由 Qt 继续处理，实际绘制按目标屏幕重新生成文字与矢量图标；实现选择见 [ADR 0012](../adr/0012-live-interface-scaling.md)。

标题长度、竖栏宽度以及工具条 API 和布局中的保存宽度使用缩放前的逻辑长度；绘制与鼠标命中使用当前 Qt 坐标。恢复时按当前倍率求值，不能拿放大后的最小宽度拒绝未缩放的布局数据。

设置页“界面”分类使用现有的输入框和数字控件。字体列表完成编辑后应用；数字输入完成后应用，步进按钮立即应用。改变设置不重建标签或内容，不重置设置页焦点；应用拥有唯一的设置写入者，多个窗口不各自保存过期副本。JSON 写入失败保留已有文件并报告错误。

## 4. 作用域、加载与写入

V0 的显示／交互设置层次为：内置默认 → 全局用户设置 → 会话允许的设置。基本值和数组整体覆盖；定义为可合并的对象按 schema 递归合并，不把任意对象隐式当作连接参数。层次和来源在设置详情中可查看。

每个设置的 schema 明确能否用于会话。全局行为不接受会话覆盖；终端字体、颜色、光标和文件布局等允许按会话调整。**这些覆盖规则不作用于 SSH config 的 HostName、User、Port、IdentityFile、代理或认证参数。** 自建会话的连接字段由自己的会话文件管理，SSH config 会话的连接身份由原来源和成熟后端求值。

多工作区设置及独立用户 profile 留有作用域扩展位置，V0 不自动读取服务器目录里的配置来改变本地快捷键或执行程序。快捷键 V0 使用一份全局用户规则，通过上下文区分会话／视图；后续方案引用也使用同一解析器。

启动及运行中监听文件和父目录，合并事件并处理原子替换。配置读取、解析和 schema 校验成功后发布有效快照，按实际变化通知使用方，不重建所有终端和窗口。未知键保留并诊断但不执行；重复键或无效值不悄悄采用“最后一个”。

编辑中的损坏文件保留原文，报告位置，继续使用最近有效快照；首次启动没有有效快照时使用内置默认值，并显示配置错误。不能自动覆盖用户文件来“修复”。不能把损坏的 SSH 来源或会话连接文件按显示设置的回退规则处理，继而用旧参数建立新连接。

布局这类状态文件也不能因为一处无效值整份丢掉（用户 2026-10-24 决定）。恢复失败时先把原文件复制一份放在旁边，再试着部分恢复：随布局保存的几类设置（标签外观、窗口行为、各栏默认显隐、默认工具条排布）逐类恢复成默认值，窗口和标签照常恢复；窗口和标签本身的结构无效时，才用默认布局启动。两种情况都在状态栏说明原因和副本的位置。设置迁到 `settings.json` 后，设置的逐项校验由设置注册表负责。

写入前复核文件版本／内容哈希，外部变化后重新加载并合并不冲突修改；同一字段冲突明确呈现，不能覆盖另一编辑者。V0 同一配置根的多个窗口共享一个应用进程、配置服务与写入者，再次启动将打开窗口的请求转交该进程；独立数据根可使用独立实例。文件锁与版本复核共同防止写入竞争，锁不替代对外部编辑器变化的检测。[QLockFile](https://doc.qt.io/qt-6/qlockfile.html)

采用 `QSaveFile` 原子替换，写入失败不发布虚假的成功状态。短时间内的机器状态变更合并写入，未改变内容不重复写；内存只持有必要文本、当前有效快照和有限诊断，不保留无限配置历史。[QSaveFile](https://doc.qt.io/qt-6/qsavefile.html)

## 5. 会话拆分与删除

自建会话使用稳定 UUID 文件名，显示名和分组可以变化，不以服务器地址或显示名作为文件名。单文件包含 schema 版本、ID、连接定义和允许的会话设置；一项损坏不影响其他会话。密码和私钥口令使用凭据库引用，不写明文。

`sessions/catalog.json` 管理分组定义、会话顺序等目录元数据，不再保存第二份连接定义。会话文件是事实源，目录索引可增量重建；重复 ID 报错，损坏 catalog 不删除正常会话。新建先可靠写入会话再更新目录，删除先移除对应会话，再清理目录引用；跨文件操作有可恢复的明确顺序，不能把多次独立写入宣称为一个原子事务。批量导入逐项报告结果。

SSH 别名附加设置先集中在 `ssh-alias-overrides.json`，以“来源 ID + 原始别名”关联。集中存储便于一次原子提交删除及防止旧任务误删新条目；无需为每个动态别名复制配置文件。记录只允许显示名、分组、收藏、终端和文件偏好等字段。

完整有效刷新确认别名删除时，当前目录立即移除并原子提交附加设置删除；清理与同名重建按记录 ID／代数区分。临时保存中间态或来源读取错误不触发删除。旧目录、布局和备份不能自动复活已删除别名的设置；重新出现的同名别名使用新的默认设置。活动连接可以继续，不能据旧连接快照恢复或重连。

会话拆分粒度可以以后调整，但所有 UI 通过 `SessionStore` 使用，不直接操作文件。共享设置由 `SettingsService` 提供有效值和来源；两者不承担 SSH 协议解析。

## 6. 窗口与运行状态

`window-layout.json` 保存 schema 版本、WindowId、kind、FamilyId 与完整根映射、窗口正常几何及最大化状态、屏幕信息、四边栏、中央标签组、PaneTree、活动标签／窗格、标签颜色 ID 与打开／访问次序、顶部／底部条带区域、行与顺序及锁定状态。引用稳定内容 ID 及必要恢复描述，宿主业务状态与通用布局分开，网络句柄和终端历史不序列化。

工具栏、全局状态栏、中央标签栏和四边收纳条的显示偏好分别按窗口保存，图形设置、菜单、命令和 API 使用同一值。进入任一全屏范围都沿用这四项偏好，不另设“全屏时隐藏某栏”的第二套设置。隐藏中央标签栏仍保留固定组标签栏和收纳面板标题；隐藏侧栏仍保留固定内容。

状态栏内部控件另按稳定 ID 保存显示选择；右键菜单列出可选控件和勾选状态，API 与统一命令修改同一份值。隐藏某个控件不改变整条状态栏的显示偏好，隐藏整条状态栏也不清除控件选择。临时侧栏面板按 Tab ID 保存左／右与上／下两套可选宽高；这些请求尺寸独立于固定分区大小，窗口变小只限制实际呈现，不改写请求值。

全屏范围、禅模式及内容目标是临时运行状态，不写入窗口快照，也不作为图形设置中的当前值。运行时 `mode` 区分 `normal`、`windowFullscreen`、`groupFullscreen`、`paneFullscreen`，标签组／窗格目标引用有效的稳定 ID。禅模式从普通窗口启动时按 `window.zenFullscreenMode` 一次进入指定全屏范围，默认窗口全屏；已有全屏保留范围。禅模式使四项有效开关关闭，但不改写原偏好；显示任一栏先退出禅模式并恢复其他偏好。

重新启动恢复进入全屏前的正常矩形及最大化状态，保留四栏偏好，不恢复全屏或禅模式。窗口记录只接受当前格式的字段；格式错误在修改现有布局前拒绝。

两种窗口及明确的族归属进入同一完整快照，缺失或失效的归属拒绝恢复。不保存 OS 层叠顺序、前台权限、悬停计时或半次拖拽。浮窗与完整窗口的升降级、合并都只更新布局状态，不改用户设置。

恢复时按当前显示器和 DPI 重算可见几何，屏幕移除后将窗口放回可见区域；不能把旧物理像素直接当当前逻辑坐标。关闭最后窗口后的状态、异常退出和“恢复默认布局”都定义明确结果；正常退出等待有界提交并报告失败。

结构恢复与远程连接恢复分开：恢复标签不自动保证远端 shell 仍存在。会话及 SSH 别名须重新检查当前来源，删除后的配置不因旧布局重建。瞬时选区、待完成快捷键序列和 Normal 模式状态不跨应用重启恢复。

`runtime.json` 只保存有界的命令最近使用及必要界面状态；`transfers.json` 保存可展示的任务记录和真实恢复条件，不把中断任务标成已完成。损坏时给出可理解的提示，并恢复到可用默认状态，不覆盖用户 settings。

这借鉴 VS Code 独立状态服务、合并写入和持久化职责，不复刻其 Electron 实现或全部存储数据库。[VS Code 状态服务](https://github.com/microsoft/vscode/blob/main/src/vs/platform/state/node/stateService.ts)

## 7. 一个命令目录驱动全部入口

**每项公开用户操作先定义命令，再接入菜单、工具条、右键菜单、命令面板和快捷键。所有公共命令都可绑定快捷键，包括没有默认按键的命令。** 参数缺失时进入键盘可操作的选择器／对话框；不能因为需要选择服务器、目录或目标位置就取消快捷键入口。

主菜单按常见桌面软件组织，提供常用入口；完整命令目录继续用于命令面板、快捷键和 API。设置只提供统一“设置”入口，不把每项行为设置另列为主菜单命令。工具条定制和上下附加栏共享保留在对应右键菜单、命令面板及 API 中。

| 顶层菜单 | 归属 |
| --- | --- |
| 文件 | 新建标签、新建完整窗口、保存工作区布局、关闭当前标签、关闭窗口、退出应用。 |
| 视图 | 命令面板、四栏独立显隐、全屏范围和禅模式、工具条移动与锁定，以及标签、标签组和窗格的聚焦导航。 |
| 布局 | 分组、拆分、移动、交换、边栏停靠和尺寸调整；恢复工作区布局放在末尾。 |
| 窗口 | 窗口选择和切换、完整／轻量形态、窗口族归属及整窗移动。 |
| 工具 | 设置和键盘快捷方式。 |
| 帮助 | 应用说明和关于。 |

同系列命令使用语义明确的子菜单，方向按左、右、上、下排序，成对操作按前一个、后一个排序。菜单声明与执行处理者分开，启用、可见、勾选和快捷键展示共用状态解析；需要参数但没有交互选择器的内部投放命令不进入主菜单。宿主可用 `Command.menuPath` 和 `menuOrder` 声明路径与顺序，后注册命令及运行时键位修改在菜单展开时更新；菜单展示快捷键不另注册 QAction 快捷键。

“布局”先按来源对象分为“当前标签组”“当前标签”“当前窗格”，再按新建、调整边界、移动、交换、合并、转换和关闭组织。移动改变所属容器或在目标旁插入，交换只更换两处槽位，合并把来源内容放入目标并清理空来源；标题和选择器必须说明来源、目标及结果。组右键只提供整组操作，标签右键的“所在标签组”才进入该组的操作。选目标时显示窗口、组、标签和窗格层次，不能用未注明含义的“移动到窗格”概括整组转换。

“窗口”菜单末尾列出全部窗口，以完整工作窗口为顶层，其所属轻量浮窗缩进列在下面。标题、归属、创建和关闭变化在菜单展开时更新，当前窗口有选中标记。点击条目调用统一窗口激活命令，最小化目标先恢复；命令执行前核验 Window ID，不依赖过期标题或已销毁控件。

每个标签组的末尾加号与类型下拉调用宿主注册的新建命令。`setTabCreationCommands(defaultCommand, choices)` 声明默认项和类型选项，`requestNewTab(window, group, command)` 使用来源窗口和标签组上下文执行。窗口模块不解释宿主的业务类型，命令标题、可执行状态及处理者由统一命令目录提供。

退出通过一次完整工作区关闭许可处理所有窗口和浮窗；拒绝时保留全部内容。最后关闭通知发生在完整模型仍可保存时，不逐窗关闭后只保存最后一个窗口；保存失败时应用不执行退出。

| 覆盖领域 | 命令范围 |
| --- | --- |
| 设置与应用 | 打开设置／JSON／默认值、快捷键编辑、命令面板、布局恢复、字体、主题和条带布局。 |
| 会话与连接 | 搜索、分组、收藏、新建自建会话、打开终端／文件、刷新来源、连接、取消、断开和诊断。 |
| 工作区 | 两种新窗口、族内／全部／仅完整窗口切换、返回所属根、升降级及改归属、单标签／整窗移动、拖拽目标选择、空窗口行为、四边收纳／固定、外层分割／大小／焦点、独立显隐、全屏／禅模式及顶部／底部工具条移动。 |
| 窗格 | 内部分割、大小、方向焦点、最大化、关闭与提取为窗口。 |
| 终端 | 复制、粘贴、查找、滚动、字体调整、Normal 模式、移动／选择／端点／计数与查找动作。 |
| 文件与传输 | 导航、筛选、选取、创建／重命名／删除、上传／下载、双栏复制、目录跟随、任务取消和按实际能力重试。 |
| X11 与状态 | 组件配置、启用转发工作流、查看诊断／任务／通知等公开操作。 |

每个命令有稳定且带命名空间的 ID、标题、说明、参数 schema、可用前提和处理者。低层回调、内部资源释放等不是用户操作，不需要公开为可配置命令。命令覆盖清单随功能审查，不能只为少数按钮添加快捷键。

WindowSystem 提供通用命令注册、上下文及路由 API 和自己的窗口命令；Muxora 注册 SSH、终端和文件命令。宿主注入设置及用户按键规则，窗口模块不读取 Muxora 配置目录、不依赖其业务设置服务。

命令执行器统一校验参数、目标与前提。`when` 控制某个入口是否显示／匹配，命令前提决定实际能否执行；修改快捷键不能绕过前提。错误与取消有明确结果，菜单和快捷键调用同一处理者。[VS Code 命令及菜单定义](https://code.visualstudio.com/api/references/contribution-points)

命令面板默认 `Ctrl+Shift+P`，按标题、分类、别名和 ID 搜索，显示快捷键及有界最近使用。键盘可完成参数选择和执行。打开时捕获来源 Window／Group／Tab／Pane ID；面板获得焦点后仍操作原目标，执行前重新验证目标存活，不能误操作另一终端。[Windows Terminal 命令面板](https://learn.microsoft.com/en-us/windows/terminal/command-palette)

命令面板默认为非模态，点击外部区域自动关闭。通用 `FloatingPanel` API 的 `FloatingPanelOptions.dismissOnOutsidePress` 与 `modal` 独立，宿主可以分别配置自动关闭和窗口模态。非模态外部点击在关闭面板后交给原目标处理，不额外回放或合成一次点击；相关子菜单和下拉交互属于面板内部，不因临时获得焦点而关闭。模态面板限制所属窗口，显示方法返回，不启动额外嵌套事件循环。

窗口命令通过参数表达 `scope: family / all / workbenches`、新建 `kind: floating / workbench` 和中心／方向／边缘落点；缺参显示键盘选择器。`window.promote/demote`、`window.reassignFamily`、`window.moveAllTabs`、`window.redock` 和 `window.drag.selectTarget` 等均在命令目录中。具体 ID、默认键和焦点规则见双窗口设计；标题栏与鼠标拖拽复用其布局事务。

`window.toolbar.move` 接受 `strip`、`area: "top" / "bottom"`、`row` 和 `index`；缺参可用键盘依次选择工具条、区域和行。`window.toolbars.toggle`、`window.statusBar.toggle` 与原有标签栏／侧栏命令控制独立显隐。三个全屏命令与 `window.zen.toggle`、`window.fullscreen.exit` 使用同一目录，菜单勾选显示当前有效状态；设置页只提供行为偏好，不提供当前模式的持久化开关。具体默认键位见 [交互细则](window-interaction-design.md#独立显隐与全屏)。

### 7.1 命令行启动

应用提供面向用户的启动参数，支持打开一个会话、批量打开多个会话，以及启动后执行指定 Lua 脚本；参数结构可继续扩展。现有启动参数保持兼容，已实现范围见 [预览说明](../development/window-system-preview.md)，扩展步骤见 [7.12](../roadmap/implementation/phase-7-terminal-and-sessions.md#712-命令行启动请求)。

会话参数使用稳定会话标识，批量请求保留用户指定的次序，不依赖可能重名或翻译变化的显示名称。打开会话复用图形入口的会话解析、认证、连接队列和错误处理；批量启动遵守同一并发限制，不另建一套连接流程。Lua 文件执行复用现有脚本运行、初始化与停止流程，只在请求需要时加载运行时。

设置中提供独立偏好，决定命令行带单个或批量会话请求时是否同时恢复上次工作区会话。关闭时在 fresh 工作区／窗口中打开指定会话，不恢复原来的标签和会话；开启时执行会话恢复流程，再把显式会话请求交给打开服务。设置名、默认值及其与 [普通启动恢复模式](session-restore-design.md#2-设置) 的对应关系在 7.12 展开时确定，界面与 JSON 配置使用同一设置声明。

命令行提供以下显式覆盖，优先于上述持久设置；参数名和值不随界面语言改变：

| 参数 | 本次启动的恢复选择 |
| --- | --- |
| `--restore-sessions true`／`--restore-sessions false` | 用参数值选择恢复或不恢复，值必填 |
| `--restore` | 恢复，与带值选项的 `true` 等效 |
| `--fresh` | 不恢复，与带值选项的 `false` 等效，保留现有入口 |

未提供覆盖参数时使用设置。重复或组合指定相同选择有效，相互矛盾则报告参数冲突，在任何恢复或会话打开前退出；带值选项缺少值或使用非法值也按参数错误处理。命令行覆盖只影响本次启动，不改写持久偏好。没有会话请求且没有显式覆盖的普通启动沿用原有规则，已有 `--fresh` 行为保持兼容。

参数先解析、校验，再在对应配置、目标工作区和所需服务就绪后分发；每项请求只执行一次，不能因重复的就绪信号重放。语法错误在执行请求前报告；找不到会话、脚本文件读取失败、脚本运行错误和请求取消有可区分的结果。帮助文字和面向用户的诊断遵守翻译约定，参数名、会话标识和用户路径保持原样。

其余参数名、重复参数与混合请求的顺序、目标窗口和已有实例的选择方式，以及退出码代表请求接收还是执行完成，在本步展开时补齐设计并评审。明确命令行请求与自动恢复的先后关系，避免同一请求被恢复流程重复执行；没有新增参数时沿用既有启动行为。

## 8. VS Code 风格快捷键

用户规则使用 `key`、`command`、可选 `args` 和 `when`。内置默认规则只读，用户规则可以增加、覆盖或解除默认绑定；规则在运行中更新。多键序列用同一 `key` 字符串表达，例如 `ctrl+k ctrl+s` 或 Normal 模式的 `g g`。[VS Code 快捷键](https://code.visualstudio.com/docs/configure/keybindings)

```jsonc
[
  { "key": "ctrl+shift+p", "command": "workbench.showCommandPalette" },
  { "key": "ctrl+k ctrl+s", "command": "preferences.openKeyboardShortcuts" },
  {
    "key": "escape",
    "command": "keybindings.cancelPending",
    "when": "keybindingSequencePending || terminalMarkCountPending",
  },
  {
    "key": "ctrl+shift+m",
    "command": "terminal.markMode.enter",
    "when": "terminalFocus && terminalMode == 'remoteInput' && !textInputFocus && !imeComposing",
  },
  {
    "key": "g g",
    "command": "terminal.markMode.move",
    "args": { "motion": "bufferStart" },
    "when": "terminalFocus && terminalMarkMode && !textInputFocus && !imeComposing",
  },
  {
    "key": "alt+left",
    "command": "pane.focus.left",
    "when": "workspaceFocus && !textInputFocus && !imeComposing",
  },
]
```

示例命令和参数是拟定契约，具体默认键位在完整冲突检查后固定。为解除默认绑定提供 `-commandId` 规则和图形操作：匹配命令 ID 与键序列，提供 `when` 或 `args` 时进一步匹配规范化条件或参数；未提供时移除该 ID／序列的全部默认规则，不影响同命令的其他按键。图形删除操作生成精准移除规则，参数化移动命令不会因为删除 `j` 而丢失所有方向绑定。

用户层优先于默认层，同一层从后向前排序。一次按键按此顺序选择第一个上下文匹配的完整绑定或序列前缀：完整绑定获胜立即执行，前缀获胜进入等待。因此 `g` 与 `g g` 的竞争由明确顺序决定，并在编辑界面提示；超时不会自动执行较低优先级的单键命令。

V0 `when` 支持上下文键、布尔值、`!`、`&&`、`||`、括号及相等／不等比较，不运行 JavaScript；进一步表达式按需求增加并给出诊断。上下文至少包括窗口／组／标签／窗格焦点、内容类型、连接状态、`textInputFocus`、`imeComposing`、`terminalMode`、`terminalMarkMode`、`terminalVisualMode`、`keybindingSequencePending`、`terminalMarkCountPending`、选区、文件能力及平台。[VS Code 上下文机制](https://code.visualstudio.com/api/references/when-clause-contexts)

窗口相关上下文包括 `windowKind`、`windowFamilyId`、`hasOwnerWindow`、`windowDragActive`、`windowHasTabs`。拖拽时命令限于当前操作，原生移动循环的取消也交同一控制器，不将按键发给终端；悬停抬前不等于内容焦点变化。形态转换及显式窗口切换恢复对应实例焦点，不改变终端模式。

连续按键进入等待状态，显示待完成序列。提供公共命令 `keybindings.cancelPending`，默认 Esc 在存在序列／计数时执行它，优先于模式退出；这次只取消等待，下一次 Esc 才按当前模式规则执行。取消键同样可以重绑。超时、焦点变化、IME 开始、规则更新或目标关闭自动取消，属于生命周期处理。

待完成状态中先按同一优先级检查可配置取消命令的单次按键绑定，再匹配已开始序列的续键；取消不要求拼成 `ctrl+k escape` 一类续键。普通完整命令不会在无效续键后悄悄执行。取消键的重绑和这一路由均须覆盖自动化测试。

无效续键取消并消费当前序列，不将续键重新作为一次独立输入执行，也不执行较低优先级的命令；显示取消原因。已消费的前缀、续键和取消按键不能补发 SSH 或延迟发送给另一会话。没有待完成序列时，远端输入上下文中未消费的普通输入正常进入终端编码；Normal／Visual 中未绑定键仍留在本地，不回退 SSH。需要直达远端的组合键可以解除本地规则。

Normal 和三个 Visual 状态中的数字计数是这些模式限定的有界前缀，注入支持 `count` 的公共移动／选择命令，Visual 中 `5j` 可以扩选。数字追加通过 `terminal.markMode.appendCount` 等公共命令绑定；`0` 无计数时行首、有计数时追加零，由上下文规则表达。计数不在 `remoteInput` 或 `findInput` 生效。同一个解析器处理 Vim 单键和多键规则，不另建不可修改的 Vim 按键引擎。打开搜索框或命令面板后，普通字符和输入法优先输入控件，不被 `hjkl` 等规则抢走。

快捷键界面可搜索全部公共命令、录入按键、编辑条件和参数、查看默认／用户来源、解除／重置绑定，并显示同键与前缀冲突。提供可开启的分发诊断，记录匹配规则和目标 ID，默认不记录实际终端文本。匹配表在规则更新时编译，按键时不解析文件或线性扫描全部设置。

### 8.1 当前预览：快捷键与组合命令

同一命令可绑定多组按键，每组包含序列和独立的对象参数。`CommandBinding`、`CommandRegistry::bindings`、`setBindings`、`addBinding` 与 `removeBinding` 提供相同的公开操作；原 `setShortcut` 继续表示替换该命令的全部绑定。快捷键编辑器可逐条添加、修改和移除，并显示重复键和前缀冲突。

序列最多四段，例如 `ctrl+k z`、`ctrl+k g 1`。首段可以是组合键，后续可以是裸字母、数字、Tab 等按键。前缀和续键只分发一次，不能泄漏为编辑区文字；取消、超时、焦点或输入法变化以及规则修改结束等待。

状态栏的“等待下一按键”只是一条临时提示。完整序列已命中时在执行命令前结束等待；执行成功、失败、取消或目标消失后都不能留下提示。等待期间宿主更新的普通消息继续保留，结束等待时显示最新消息。

快捷键页搜索框旁提供“按键查询”按钮。开启后录入最多四段按键，按完整序列或前缀筛选绑定；录入不会执行命令或修改快捷键。退出查询后继续使用普通文本搜索，按键记录与新增／修改绑定的输入框分别工作。

组合命令使用 `runCommands`，与 [VS Code 的组合命令结构](https://code.visualstudio.com/docs/configure/keybindings#_running-multiple-commands) 一致地接受 `commands` 数组；元素是命令 ID 或含 `command`、`args` 的对象。当前模块的命令参数是命名对象，不支持 JavaScript 或任意可执行文本：

```json
{
  "key": "ctrl+k n",
  "command": "runCommands",
  "args": {
    "commands": [
      "host.newTab",
      { "command": "pane.split.right", "args": {} }
    ]
  }
}
```

第一步使用触发时的目标，后续步骤解析来源窗口中当前活动的标签和窗格，使“新建标签 → 拆分”作用于新标签。来源窗口消失、某步失败或目标无效时终止，不转而操作其他窗口。组合描述有嵌套深度和步骤数上限，递归调用会被拒绝。

`runCommands` 作为普通命令显示在快捷键目录中，使用同一套“添加绑定”和参数编辑；每条绑定可以执行不同的 `commands` 数组。命令目录中的一行代表命令类型，并不限制组合操作的数量：选择这一行后可反复“添加绑定”，分别录入按键与执行步骤，编辑或移除其中一条不影响其余绑定。上例描述整个绑定，在图形页选择 `runCommands` 后，参数框只填写其中的 `args` 对象。当前每步 `args` 仅接受 JSON 对象，不支持 VS Code 的其他参数形式；不能将这一子集表述为全部参数兼容。

用户绑定独立保存到 `User/keybindings.json`，采用严格 JSON 数组，使用 `key`、`command` 和对象 `args`；`-command` 规则移除对应默认按键，提供 `args` 时同时匹配参数。图形修改立即保存，同一应用的各窗口共享一份配置。外部编辑造成版本变化时拒绝覆盖旧文件并提示重新加载。当前正规则增加绑定，跨命令占用同一按键时须先解除原绑定；图形编辑器会提示冲突。应用在加载用户绑定前注册全部命令，动态命令默认值登记留在后续扩展阶段。完整 JSONC、`when`、文件动态监听与多层优先级仍按本设计后续实现，不能将当前子集表述为完整 VS Code 配置服务。

### 8.2 当前预览：界面语言

界面先提供简体中文和 English，另有跟随系统选项。`workbench.language` 的稳定值为 `system`、`zh_CN`、`en`，保存在全局 `User/settings.json`，与窗口布局分开。图形设置修改后重启生效；不会为换语言重建现有内容或修改用户标签名称。

使用 Qt Linguist 的 `.ts` 目录、`QTranslator` 和构建时生成并嵌入的 `.qm` 文件。窗口模块与宿主分别维护目录，模块的 `TranslationManager` 由宿主管理生命周期；Qt 标准对话框使用 Qt 官方翻译。语言名称使用各自语言显示，便于切回。源文本和翻译覆盖要求见下一节。

普通安装使用 Qt 标准用户配置路径的 `User/`；便携运行位于 `data/User/`，显式 `--state-dir` 则使用该隔离目录下的 `User/`。当前文件编辑保留不相关的有效字段；损坏文件不自动覆盖，完整 JSONC 注释保留仍属于后续配置工作。

### 8.3 翻译源文本与覆盖

界面翻译的源文本统一使用英文，简体中文放在翻译目录中。选择理由见 [ADR 0010](../adr/0010-english-translation-source.md)，迁移步骤见 [8.12](../roadmap/implementation/phase-8-ui-quality.md#812-英文源文本与全量翻译核查)。这项约定不改变界面语言偏好、系统语言识别或重启生效的行为。

全部第一方源码中的用户可见文字都要纳入核查，包括窗口与宿主界面、命令、动态菜单与分类、设置、提示、错误信息、命令行帮助，以及脚本接口向用户呈现的诊断。静态表和动态查询必须有 Qt 可提取的源文本；资源、模板或生成数据中的文字也要进入同一翻译流程。检查已有 `.ts` 条目完整不能代替源码覆盖检查。

翻译目录（`.ts`）的条目和排版只由 lupdate 写：源码里的文字改了以后，构建对应的 `window_system_lupdate`、`lua_runtime_lupdate` 或 `muxora_lupdate` 目标更新目录，再只改 `<translation>` 里的译文（Qt Linguist 或编辑器都行），不手工增删条目、不调整格式。目录不记源码行号（`-locations none`），改代码不会让目录跟着变（用户 2026-10-24 提出）。

中英文译文逐条核对含义与术语，保留参数占位符、快捷键助记符、换行和富文本结构；数量文案使用 Qt 复数机制。自动检查覆盖源码提取与目录的一致性、未翻译条目、动态文本和两种语言的实际输出，并能发现新增用户可见文本没有进入目录的情况。

命令 ID、JSON 键、内部菜单路径、快捷键文本和用户内容保持稳定。所有内部标识（命令分类、菜单路径、内置配色名、设置键等）都用英文 ID，不拿界面文字当标识（用户 2026-10-24 决定）；内置菜单和分类的 ID 是 `file`、`view`、`layout`、`window`、`tools`、`help`、`extensions`、`other` 等小写开头的驼峰词。内部标识需要显示时，映射到有提取标记的英文源文本，不直接修改标识；宿主或用户自己起的分类和菜单名不在映射表里，按原文显示。语言自称、产品名、协议文本、用户输入等按其语义保留；源码扫描中的豁免逐项说明原因，不能按整个业务目录排除。

诊断在产生处翻译，再原样传给显示层；不能按最终错误字符串匹配翻译，否则会改写碰巧同名的用户脚本输出。Lua 自身的标准错误保持标准库语义。新建 `User/init.lua` 的说明和示例文案使用当前界面语言，脚本标识、按键和 API 不变；已有文件不因语言切换而改写。

## 9. 自动化验收

用例由程序检查结果，不依赖人工或模型读取截图，也不以 computer use 执行测试。新增外观和排序检查与完整 JSONC 配置服务的后续验收分别记录，具体执行结果见预览说明。

- JSONC 注释、尾逗号、未知项保留和精确编辑；重复键、语法／类型错误、首次启动和最近有效快照。
- 标签外观严格 JSON 的类型、完整颜色状态、重复 ID、无效颜色和替换失败保留；多行与滚轮展开前提、两种位置、图标／编号／新建入口和跨窗口恢复一致。
- 六种排序保持活动标签、内容身份和稳定次序；整组移动、关闭许可及取消的命名集合层不残留命令或存储。
- GUI 与直接编辑一致，作用域来源正确；会话外观可覆盖，全局设置不能覆盖 SSH config 连接身份。
- 原子替换监听、并发窗口、外部编辑冲突、只读文件、写入失败和损坏恢复；不丢失用户注释或悄悄写旧版本。
- 自建会话 UUID、改名、目录重建、单文件损坏与删除；SSH 别名删除／同名重建不复活旧设置。
- 所有公共命令可发现、可绑定、可通过参数或选择器使用；菜单、面板和按键行为一致，可用前提不能绕过。
- 启动参数的解析与校验、单个及批量会话请求、Lua 文件运行、服务就绪后的单次分发、恢复衔接和错误结果；空格及 Unicode 路径、帮助和诊断的中英文输出。
- 用户覆盖、解除默认绑定、`when`、同键／前缀冲突、序列超时、焦点／IME 变化、参数校验和原目标关闭。
- Normal／Visual 键盘操作零远端按键泄漏；计数、多键、搜索输入和其他窗格互不污染。
- 窗口／布局恢复、混合 DPI、屏幕移除、关闭及异常退出；运行状态不写入 settings，状态损坏不破坏会话。
- 四项窗口显隐偏好不随全屏范围改变；普通窗口启用禅模式按配置自动全屏，有效勾选、显示任一栏退出、内容附加栏与偏好恢复一致。
- 顶部／底部工具行、跨区移动和键盘选择的布局保存／恢复一致；空行和未知条带不造成无界控件增长。
- 两种窗口的类型／归属／整窗移动和族内／全局导航均可绑定；GUI 与 JSON 的拖出、空窗口及悬停设置一致，拖拽中热更新按约定生效，取消键不穿透。
- 高频布局变化写入合并、无变化不写、配置快照及最近记录有界；文件变化不导致所有终端重建。

各项映射到有效用例并进入完整测试链路；失败修复问题后通过，不自行减少覆盖、改预期或放宽阈值。V0 只构建 Windows 应用，后续平台路径和键位扩展不宣称已验证。
