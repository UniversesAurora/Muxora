# 界面设计规范

状态：设计稿，2026-10-19。适用于 WindowSystem 模块和 Muxora 应用的全部界面。颜色规则见 [主题系统设计](theme-system-design.md)；现有界面与本规范的差距见 [界面审查](../roadmap/review-2026-10/ui-audit.md)；实现步骤见 [阶段 8 实现计划](../roadmap/implementation/phase-8-ui-quality.md)。

## 1. 原则

1. **以成熟软件为标准，按需求取舍**：参照对象按用途分开：
   - **视觉风格**：Visual Studio 2019 之后的风格（当前）；以后另有 Windows 7 Aero 风格的版本。
   - **页面与窗口的布局**：参考现代软件：VS Code（设置编辑器、快捷键编辑器、命令面板、JSON 配置文件）、Windows Terminal 的设置界面、Tabby、Termius 等。选最方便操作、最符合 Muxora 风格、好看的做法。
   - **功能**：Xshell、MobaXterm、SecureCRT 等老牌会话管理软件的**功能**要实现全（会话属性、隧道、登录脚本、文件传输等），它们的分类方式（例如会话属性页左侧的类别划分）可以参考；但它们的**界面和页面布局比较老，不照搬**，按上一条用现代方式重新设计。
   - **终端能力**：Windows Terminal、Ghostty、iTerm2、Alacritty、Tabby 等。Ghostty 以配置文件为主，没有完整的图形设置界面，主要参考它的终端能力和简洁的视觉。
   参考之前先确认 Muxora 有没有这个需求：VS Code 是编辑器，其中为编辑器和扩展生态服务的机制（例如通知中心）不照搬；同类终端软件普遍没有的东西，默认不做。用户在这些软件里形成的习惯在 Muxora 中照样成立；偏离时要有明确理由，并写进本文档。
2. **统一**：同一类界面只有一种实现。所有“输入后从列表中选择”的场景用同一个快速输入组件；所有确认用同一种对话框；所有设置页用同一套行布局。不允许为某个功能单独拼一个外观不同的弹窗。
3. **键盘完整、鼠标顺手**：每个操作都能用键盘完成，并出现在命令面板中；常用操作有鼠标直达的入口（右键、拖动、双击、中键）。
4. **不打断**：优先用非模态界面（快速输入、行内编辑、状态栏消息）。只有在必须让用户做决定、且不决定就无法继续时才用模态对话框；模态对话框不启动嵌套事件循环（不调用 `exec()`），用 `open()` 加回调。
5. **克制**：强调色只用于需要注意的地方；不用大面积饱和色；装饰性元素（渐变、粗边框、多余图标）一律不用。
6. **可预期**：同一个键在同一种界面里含义一致（`Esc` 永远是“关闭当前最上层的临时界面或取消当前操作”）；操作结果立即可见；破坏性操作可以撤销，或者事先确认。

## 2. 基础规格

所有尺寸为 Qt 逻辑像素。

### 2.1 间距

4 像素网格：`2, 4, 6, 8, 12, 16, 24, 32`。控件内边距、控件间距、分组间距只从这组值中取。

### 2.2 尺寸

| 元素 | 高度 | 说明 |
| --- | --- | --- |
| 列表行、树行、菜单项 | 22 | 菜单项左右内边距 8／24（右侧留给快捷键与子菜单箭头） |
| 标签 | 27（现有） | 由 `ThemeMetrics::tabHeight` 控制；横向排布见下文“标签内部排布” |
| 普通输入框、下拉框、按钮 | 26 | 设置页、对话框、快速输入的输入框 |
| 紧凑工具按钮 | 22×22 | 图标 16，圆角 4，悬停背景 `toolbar.hoverBackground` |
| 工具条行 | 28（现有） | |
| 状态栏 | 22 | 与 VS Code 一致；字体更大时随字体撑高。2026-10-19 已实现（`ThemeMetrics::statusHeight`） |
| 收纳条 | 22（现有） | |

**标签内部排布**：标签沿文字方向依次是编号、图标、标题，只有显示的部分占位，相邻部分之间只留一个 4 像素间隙；标题长度设为 0 时，图标后不再留空。普通和固定标签两端各 7，标签内容与关闭按钮（16×16）之间一个间隙；为了让按在标签中心总是选中或拖动、不会误点关闭，宽度至少 46。非固定收纳条的标签两端各 8，长度正好容纳内容，内容为空时不短于收纳条的厚度。标签条、收纳条、拖动预览和插入空位都按这一规则计算长度。关闭按钮只在悬停标签时出现；指针移到它上面时，按钮下衬一块圆角浅色（标签文字色的半透明），按下时加深，与 VS Code 标签上的操作按钮一致，在各主题和标签颜色上都可见。

### 2.3 圆角、边框与阴影

| 元素 | 圆角 | 边框 | 阴影 |
| --- | --- | --- | --- |
| 按钮、输入框、下拉框、复选框 | 2 | 1 像素 `input.border`／`button.border` | 无 |
| 工具按钮悬停背景 | 4 | 无 | 无 |
| 快速输入、菜单、下拉列表、工具提示、通知 | 6 | 1 像素 `widget.border` | 系统阴影（见下） |
| 对话框 | 8 | 1 像素 `widget.border` | 系统阴影 |
| 临时展开面板 | 0（贴边） | 内侧 1 像素 `muxora.peek.border` | 内侧阴影 `widget.shadow` |

**阴影实现**：菜单、快速输入等独立浮层使用顶层窗口。Windows 11 上使用 DWM 的圆角（`DWMWA_WINDOW_CORNER_PREFERENCE`）和系统阴影，不用 `QGraphicsDropShadowEffect`（逐帧模糊，成本高），也不用透明窗口自绘大面积阴影。Windows 10 不支持圆角时退化为直角加系统阴影。标签栏内的悬停展开保留为组内子控件，不创建新窗口，其表面与阴影见 [竖向标签栏](tab-strip-design.md#4-竖向标签栏)。

### 2.4 字体

| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 正文、列表、菜单、按钮 | [界面基础字号](settings-and-commands-design.md#33-界面字体与缩放) | 常规 |
| 说明、提示、徽标 | 8 pt | 常规，`descriptionForeground` |
| 分组标题（设置分类、快速输入分组） | 8 pt | 半粗，部分界面使用大写英文（中文不适用） |
| 页面标题（设置页“窗口”“拖拽”分类标题） | 14 pt | 半粗 |
| 等宽（快捷键、命令 ID、JSON） | Cascadia Mono／Consolas 回退链，9 pt | 常规 |

界面字体、回退链、字号和缩放按 [设置设计 §3.3](settings-and-commands-design.md#33-界面字体与缩放)；终端和编辑器的字体单独设置。本文尺寸表以未缩放的逻辑像素描述，应用内缩放与系统屏幕缩放分开处理。

**字体渲染（2026-10-20）**：界面文字跟随 Windows 系统的 ClearType 设置（系统默认开启；用户可在“调整 ClearType 文本”中关闭或调校）。Qt 6.12 在 Windows 上默认使用 DirectWrite 字体引擎，会遵守这个设置；代码中不关闭子像素抗锯齿（不设 `QFont::NoSubpixelAntialias`），也不为普通界面改字体引擎。ClearType 只能画在不透明的背景上，所以带文字的窗口、弹窗和面板保持不透明背景；半透明窗口（例如拖动标签时的预览）中的文字自动退回灰度抗锯齿，这是允许的。界面改动按规范导出三套主题截图时，同时检查文字在 ClearType 开启与关闭两种系统设置下都清晰、没有发虚或彩边异常。

| 抗锯齿方式 | 特点 | 用在哪里 |
| --- | --- | --- |
| ClearType（子像素） | 利用 LCD 的红绿蓝子像素，普通显示器、100%–125% 缩放下最清晰；字边有轻微彩边；BGR 排列、竖屏、部分 OLED 上不正确；背景必须不透明 | 界面文字（跟随系统设置）；终端可选 |
| 灰度 | 没有彩边，任何屏幕和背景都正确；高 DPI 下与 ClearType 差别很小 | 半透明窗口中的文字；终端默认 |
| 无抗锯齿 | 不做平滑，像素字体或极小字号时锐利 | 终端可选 |

终端的抗锯齿方式单独设置，见 [实现计划 7.2](../roadmap/implementation/phase-7-terminal-and-sessions.md#72-终端显示模块与渲染选型)。

### 2.5 图标

16×16 单色矢量，线宽 1.2–1.5 像素，风格统一（参照 VS Code Codicons 的几何简洁风格），颜色取 `icon.foreground` 或所在控件的前景色。同一含义只用一个图标（“固定”“关闭”“拆分”等在所有界面中相同）。现有矢量图标引擎（`theme.cpp` 中的 `VectorIconEngine`）保留，新图标按同一规格绘制。

### 2.6 动效

动效只用于帮助理解状态变化，悬停高亮不增加等待。系统设置“关闭动画效果”时直接使用最终状态。标签和标签栏的时长、尺寸与曲线统一在 [标签栏设计 · 动画](tab-strip-design.md#7-动画) 定义，其他浮层按各自设计执行。

内部共用 `style/motion.hpp`：`ProgressAnimation` 负责从当前显示值继续到目标值，使用 Qt 共享动画驱动，支持中途反向；`LabelPresenceEffect` 负责标签出现／消失的透明度、缩放和轻微位移。触发逻辑只决定哪些标签出现或消失，通过 `TabBar::animatePresence()` 调用，不复制绘制公式。置顶切换、新增、关闭和命令移入／移出共用这个效果，不写成各自专用动画。离开标签只保留当前可见部分的文字绘制缓存、图标、配色和几何，不引用已关闭的内容控件；标签栏末行收起或组被移除时，也用窗口内的绘制层完成这份过渡，不受新标签栏高度裁切。已经由拖入预览呈现的落位不重复播放出现／消失。标签的逻辑位置与内容实例不随绘制动画延迟，视图重建通过稳定标签 ID 交接旧几何。

动画不抓取整条栏或业务内容的逐帧图片，不反复整形标题，不新增永久轮询；浮层阴影复用小块缓存。

## 3. 交互规则

| 场合 | 规则 |
| --- | --- |
| `Esc` | 关闭最上层的临时界面（快速输入、菜单、临时展开面板、查找栏），或取消正在进行的操作（拖拽、续键等待、按键录制）。没有可关闭的东西时不做任何事。 |
| 焦点返回 | 临时界面关闭后，焦点回到打开它之前的控件；该控件已不存在时回到当前窗格内容。 |
| 布局刷新 | 保留活动窗格内仍然可见、可用的输入控件焦点；重复聚焦同一窗格不改到默认控件。明确切换窗格时正常转移焦点。 |
| 点击外部 | 非模态浮层在点击外部时关闭，点击照常传给被点的目标（现有 `FloatingPanel` 已实现）。 |
| 双击 | 标签栏空白处：新建标签；标签：无动作（VS Code 中双击标签用于取消预览，Muxora 没有预览标签）；窗口标题区：最大化／还原；分隔条：恢复等分。 |
| 中键 | 标签：关闭；标签栏空白处：无动作。 |
| 右键 | 打开对象的上下文菜单，并只把对象设为菜单目标，不改变当前活动对象（现有行为）。 |
| 悬停 | 工具提示延迟 500 ms，包含命令名和全部快捷键；同一组控件之间移动时立即切换。 |
| 拖动 | 起拖阈值使用 `QApplication::startDragDistance()`；拖动中 `Esc` 取消并恢复原状。 |
| 重命名 | 行内编辑（标签上直接出现输入框，`Enter` 确认、`Esc` 取消、失焦确认），与 VS Code 资源管理器重命名一致。 |
| 破坏性操作 | 关闭多个标签、删除设置等：能撤销就提供撤销（状态栏通知中带“撤销”），不能撤销的先确认。 |
| 文案 | 菜单项和按钮用动词开头（“关闭其他标签”）；需要进一步输入的项以“…”结尾；不用句号；同一操作在菜单、命令面板、工具提示中名称完全一致。 |

## 4. 组件规格

### 4.1 快速输入（Quick Input）

用于：命令面板、切换窗口、选择颜色主题、选择目标标签组／窗口／窗格（移动、合并、转换类命令）、切换标签、设置临时展开大小、移动工具条、重命名之外的单值输入。对应 VS Code 的 Quick Pick 与 Input Box。

**外观**：

- 位置：所属窗口内容区顶部居中，上边距 8；宽度 `clamp(480, 窗口宽度 × 0.62, 720)`。窗口太小时宽度为窗口宽度减 16。
- 结构（从上到下）：可选标题行（命令带多步时显示，例如“移动标签（1/2）：选择窗口”，右侧有返回、关闭按钮）；输入框（高 26，无外框，下边 1 像素分隔）；可选进度条（2 像素，异步加载时显示）；列表；没有表头、没有确定／取消按钮、没有底部提示文字。
- 列表行（高 22）：左侧可选图标；主文字，匹配的字符用 `list.highlightForeground` 加粗；同一行内用 `descriptionForeground` 显示说明（例如分类、路径）；右侧对齐显示快捷键，每个按键是一个小方框（`keybindingLabel.*`），续键之间留空格。
- 分组：用右侧带细线的小号分组标题分隔（“最近使用”“其他命令”），对应 VS Code 的 `pickerGroup`。
- 最多显示 12 行，超出时出现覆盖式滚动条。
- 空结果：显示一行说明（“没有匹配的命令”）。

**行为**：

- 打开即聚焦输入框；输入即时过滤，模糊匹配（按字符顺序匹配，连续命中和词首命中排名更高）。
- `↑`／`↓` 移动，`PgUp`／`PgDn` 翻页，`Enter` 执行，`Esc` 关闭；`Ctrl+Enter` 等修饰键操作按场景定义（例如“在新窗口中打开”）。
- 命令面板默认显示最近使用的命令在前；条件不满足的命令不显示（与 VS Code 一致），可以通过设置 `commandPalette.showUnavailable` 显示为灰色。
- 前缀切换模式：`>` 命令、`%` 已打开的标签、`@` 当前标签内的窗格、`#` 会话（阶段 7），无前缀时为该入口的默认模式。
- 多步流程（选窗口 → 选组 → 选方向）在同一个快速输入中前进，标题行显示步骤，`Backspace`（输入框为空时）或返回按钮回到上一步。
- 输入框模式（Input Box）：带提示文字和校验；校验信息显示在输入框下方，按严重程度着色（`inputValidation.*`）；`Enter` 在校验失败时不提交。
- 打开新的快速输入会替换当前的，同一窗口同时只有一个。

### 4.2 菜单

- 主菜单、上下文菜单、下拉菜单用同一套样式：圆角 6、系统阴影、行高 22、左侧可选图标列（有任一项带图标时为所有项预留）、右侧快捷键为 `descriptionForeground`、子菜单箭头。
- 分隔线 1 像素，上下各 4 像素间距；不允许连续分隔线或分隔线开头／结尾。
- 菜单项顺序遵循 VS Code 的分组习惯：上下文菜单中最常用的操作在最上面；破坏性的“关闭”类放在同一组；“复制路径／ID”类放在后部。标签右键菜单的分组为：关闭组（关闭、关闭其他、关闭右侧、关闭左侧、全部关闭）→ 固定与颜色 → 移动与拆分 → 转换 → 复制标题／ID。
- 菜单项禁用时显示为灰色但保留位置（VS Code 一致）；只在“对当前对象完全不适用”时隐藏（由 `when` 控制）。

### 4.3 对话框

- 只用于必须决定的情况：关闭含未保存内容的标签、覆盖外部修改的文件、危险操作确认。
- 结构：图标（信息／警告／错误）、一句话标题、可选的详细说明、按钮行右对齐；主要按钮在左、次要在右，主要按钮为强调色（Windows 惯例）。
- 键盘：`Enter` 触发主要按钮，`Esc` 等于“取消”。
- 宽度 400–560，高度随内容；居中于所属窗口。
- 不使用 `QMessageBox` 和 `QInputDialog` 的默认外观；用统一的对话框组件。系统文件对话框照常使用原生对话框。

### 4.4 通知：使用 Windows 系统通知

> 决定见 [ADR 0007](../adr/0007-windows-system-notifications.md)：不做通知中心，也不做程序内自绘的弹出提示。需要“弹一条带文字的消息”时，一律使用 Windows 系统自带的通知（屏幕右下角弹出，进入系统通知中心，遵守用户的“勿扰”设置）。

| 场景 | 呈现方式 |
| --- | --- |
| Lua 脚本调用 `muxora.ui.notify({ title, text })` | Windows 系统通知。现在的实现是程序内弹出带“确定”按钮的消息框，改为系统通知。Lua 需要程序内弹窗时用 `ui.message`、`ui.confirm`、`ui.dialog`（统一对话框，可模态或非模态，见 [Lua 扩展 API 设计](lua-extension-api-design.md#4-弹窗与通知)） |
| 长时间运行的命令完成、后台终端响铃（阶段 7） | Muxora 不在前台时发系统通知并闪烁任务栏按钮；在前台时不发（与 Windows Terminal 一致）。可在设置中关闭 |
| 连接失败、进程退出 | 显示在该会话自己的标签里（标签上的标记、内容区的原因和“重试”），不发通知 |
| 需要用户输入或确认（密码、覆盖文件） | 对话框（§4.3） |
| 命令执行失败、“布局已保存”这类短消息 | 状态栏消息（现有行为） |

点击系统通知时激活 Muxora，并切换到发出通知的窗口或会话标签。

### 4.5 工具提示

圆角 6、背景 `editorHoverWidget.background`、边框 1 像素；400 个逻辑像素（约 28 个汉字）以内保持一行；更长的文字自动换行，换行宽度随文字长度增大，让气泡保持横向的卡片形状（宽不超过高的 8 倍），既不出现细长的一整行，也不变成又高又窄的竖条；富文本和自带换行符的提示保持原有排版；连续移到相邻控件时立即换成新提示，大小和样式与第一次相同。最大化窗口的最小化、关闭按钮是普通 Qt 按钮，同样只显示这种提示；最大化／还原按钮悬停时显示系统贴靠布局，与 Windows 一致。包含快捷键时，快捷键用与快速输入相同的按键方框显示。

### 4.6 列表、树、表格

- 行高 22；悬停 `list.hoverBackground`；焦点内选中 `list.activeSelectionBackground`，失焦选中 `list.inactiveSelectionBackground`；焦点行内侧 1 像素 `list.focusOutline`。
- 键盘：方向键移动，`Home`／`End`，输入字符跳转到匹配项（type-to-navigate）。
- 树的缩进 12，缩进参考线 `tree.indentGuidesStroke`，展开箭头 16。
- 表格表头高 24，可排序列显示箭头；不使用交替行背景（VS Code 的列表和表格都不使用）。

### 4.7 输入控件

- 文本框：高 26，内边距 6，边框 `input.border`，焦点时边框 `focusBorder`；占位文字 `input.placeholderForeground`。
- 数字框：同文本框；上下箭头只在悬停或焦点时显示。
- 整数调节需要同时支持拖动和精确输入时，将滑条与 Qt 数字框放在同一行，共用标题与说明，垂直居中，不另加包围整组的边框。组合层只负责布局和数值同步，不处理单位或业务设置；使用方提供数字框、范围及步长。数字框的单位后缀和解析独立于组合层，标题长度的具体格式见 [标签外观设置](settings-and-commands-design.md#31-标签外观与颜色)。
- 下拉框：同文本框外观，右侧箭头；弹出列表样式同 4.2 菜单。参照 VS Code 设置页的下拉列表，每行依次是选项文字、可选的附加文字（`descriptionForeground`，例如选项对应的标识符，只有需要的列表才用）、行尾可选的“默认”（`textLink.foreground`，选中行用选中文字色）。默认项由控件按设置的默认值标出（`ThemedComboBox::setDefaultData()`），选项文字里不写“（默认）”；没有默认值的列表不显示标记（用户 2026-10-24 要求）。
- 复选框：16×16，圆角 3；选中背景 `checkbox.selectBackground`，勾为 `checkbox.foreground`。
- 开关（布尔设置项）：设置页用复选框，与 VS Code 一致；不引入单独的开关控件。
- 按钮：主要按钮强调色背景；次要按钮 `button.secondaryBackground`；图标按钮见 2.2。按钮文字两侧内边距 12。
- 滚轮：下拉框、数字框、日期时间框和滑块一律不响应鼠标滚轮，不论是否悬停或获得焦点；滚轮交给外层滚动区域，页面照常滚动，避免滚动页面时误改设置（与 VS Code 一致）。值用点击、键盘或输入修改。滚轮也不会让这些控件获得焦点（不出现文字光标），点击和 Tab 键照常可以聚焦。滚动条和已经打开的下拉列表照常响应滚轮。窗口模块在整个应用上统一处理，包括 Lua 生成的界面，不需要逐个控件设置。

### 4.8 滚动条

- 内容区：宽 10，覆盖式（不占布局空间），滑块颜色 `scrollbarSlider.*`；内容可滚动且鼠标在区域内时显示，停止 1 秒后淡出。
- 标签条和收纳条的滚动条规格见 [标签栏设计](tab-strip-design.md)。

滚轮使用平滑滚动，参考 [Edge 的 impulse 滚动](https://blogs.windows.com/msedgedev/2020/04/02/scrolling-personality-improvements/)：从静止开始的三次贝塞尔曲线为 `(0.25, 0) (0, 1)`，时长按剩余距离每逻辑像素 1.5 毫秒、限制在 200–500 毫秒。连续同向输入累加目标并延续当前速度，反向输入从当前位置换向；不越过内容边界。触控板的像素输入保持原生跟手，拖动滑块和程序定位立即停止尚未结束的滚动。

组件可以关闭平滑滚动，关闭策略对其子控件生效；未来终端内容使用这个入口，标签栏仍可平滑滚动。尊重系统关闭动画的设置。只对窗口模块管理的标准滚动区域和自绘标签／收纳条接入，不截取宿主业务子控件自己的滚轮处理。独立横向段、共享展开区和边界停顿仍遵循 [标签栏设计](tab-strip-design.md#34-收起与展开)。

### 4.9 设置页（参照 VS Code 设置编辑器）

```
┌──────────────────────────────────────────────────────────────┐
│ [ 搜索设置                                    ] 12 项设置  {}│  ← 搜索框全宽；右侧结果数与“打开 settings.json”
│  用户                                                         │  ← 作用域标签（以后加“工作区”）
├───────────────┬──────────────────────────────────────────────┤
│ ▸ 常用        │ 窗口                                          │  ← 分类标题 14pt
│ ▾ 窗口        │ ┃ 窗口 › 拖拽: 显示目标窗口                    │  ← 修改过的项左侧强调色竖条
│     拖拽      │   拖动标签停留在目标窗口位置时，显示该窗口……    │  ← 说明
│ ▸ 标签        │   [✓] 悬停时抬起被遮挡的目标窗口               │  ← 控件在说明下方
│ ▸ 外观        │                                       ⚙       │  ← 悬停时显示齿轮菜单
│ ▸ 快捷键      │ 窗口 › 拖拽: 悬停时间                           │
│ ▸ Lua         │   显示被遮挡窗口前的等待时间。                  │
│               │   [ 500 ] 毫秒                                │
└───────────────┴──────────────────────────────────────────────┘
```

- 内容区最大宽度 1000，左侧目录宽 200（可拖动调整，窄于 600 时目录折叠为下拉）。
- 每项：分类路径（`descriptionForeground`）+ 标题（半粗）在第一行；说明在第二行；控件在说明下方；设置 ID 在悬停时显示在齿轮菜单的“复制设置 ID”中，不在每行常驻（现有页面每行都显示 ID，信息太密）。
- 悬停整行背景 `settings.rowHoverBackground`；键盘聚焦行有 `settings.focusedRowBorder` 外框。
- 搜索：输入即过滤，匹配文字高亮；支持 `@modified`、`@id:`、`@tag:`；搜索框右侧有过滤器按钮，下拉中列出这些过滤器（用户不用记语法）。
- 修改立即生效；需要重启的项在控件旁显示提示。

### 4.10 快捷键编辑器（参照 VS Code 键盘快捷方式编辑器）

```
┌──────────────────────────────────────────────────────────────┐
│ [ 键入以搜索快捷键           ] [⌨ 录制按键] [↕ 按优先级] {}  │
├───────────────────────┬────────────────┬───────────────┬─────┤
│ 命令                  │ 快捷键          │ 条件 (when)   │ 来源 │
├───────────────────────┼────────────────┼───────────────┼─────┤
│ 关闭标签              │ [Ctrl]+[W]     │ !terminalFocus│ 默认 │
│   workspace.closeTab  │                │               │     │  ← 命令 ID 在标题下方灰色小字
│ 新建标签              │ [Ctrl]+[T]     │               │ 用户 │
└───────────────────────┴────────────────┴───────────────┴─────┘
```

- 表格（`QAbstractTableModel`），行高 22（含命令 ID 的两行模式为 36）；按键用按键方框显示。
- 双击行或按 `Enter`：在编辑器中央弹出“按下所需的组合键，然后按 Enter”的小浮层，实时显示已按的序列（最多四段），下方显示“已有 n 个命令使用此按键”，可点击查看；`Esc` 取消。与 VS Code 的定义快捷键浮层一致。
- 右键菜单：复制、复制命令 ID、修改快捷键、添加快捷键、修改条件、删除、重置、显示相同按键。
- “录制按键”模式：搜索框改为按键录制，按下的序列直接作为过滤条件（替代现有单独的“按键查询”区域）。
- 参数（`args`）不在表格中编辑：右键“编辑参数…”打开一个小型 JSON 编辑浮层（带校验），或打开 `keybindings.json` 定位到该规则。现有页面中内嵌的大块 JSON 文本框去掉。
- `runCommands` 组合命令同样通过参数编辑，不另设专门区域。

### 4.11 临时展开面板（侧栏 Peek）

- 贴所在边展开，内侧 1 像素边框和内侧阴影，标题行高 20（现有），右侧固定、关闭按钮。
- **八向调整大小**：四条边和四个角都可以拖动；面板位置仍按现有对齐规则确定（贴边，沿边方向跟随触发标签并保持在可用区域内），拖动只改变宽度和高度。拖动规则：向远离面板中心的方向拖动为放大，向中心方向为缩小；贴边一侧的边同样可用（例如左侧面板的左边，向左拖放大、向右拖缩小）。拖动过程中面板按对齐规则实时重新放置；松开后保存尺寸请求。
- **命中区域**：每条边的命中带宽 4，角为 8×8；悬停 300 ms 后在该边绘制 2 像素 `sash.hoverBorder` 提示线（VS Code 分隔条的做法），拖动中一直显示。
- **与窗口缩放边框的关系**：见 [窗口交互细则](window-interaction-design.md) 中的“窗口缩放边框”一节。规范要求：面板贴到窗口边缘时，面板自己的边仍然可以调整，窗口仍然可以从同一侧缩放，且两者不需要额外的留白。

### 4.12 会话编辑页

> 功能对标 Xshell 等软件的会话属性，界面不照搬。

- **形式**：工作区中的一个标签页（与设置页相同的行布局，§4.9），不是固定大小的模态对话框；可以同时打开多个会话的编辑页，和终端并排放。
- **结构**：左侧类别目录，右侧该类别的设置行；顶部有搜索框（在当前会话的全部设置中搜索），右上角“连接”“保存”。修改即时校验，未保存的修改在标签标题上标记。
- **类别**（参考 Xshell 会话属性的划分，按 Muxora 的功能调整）：常规（名称、分组、颜色、备注）、连接（主机、端口、协议、超时、保活、重连）、认证（方式、用户、密钥、agent、凭据）、代理与跳板（跳板链、SOCKS／HTTP 代理）、隧道（本地、远程、动态转发）、终端（TERM、编码、尺寸、回滚、响铃）、外观（字体、配色、光标）、登录脚本、X11、文件传输（SFTP 起始目录、传输选项）、日志、高级。
- **SSH config 会话**：同一页面，按 [SSH config 修改与同步设计](ssh-config-sync-design.md) 显示可编辑或只读，并标出每个值来自哪个文件。
- **新建会话**：先显示一个只含“主机、用户、端口、认证方式”的简洁表单，可以直接连接；需要更多设置时“展开全部设置”进入完整编辑页。

### 4.13 分体工具按钮

内部 `SplitToolButton` 组合两个原生 Qt 工具按钮，共用悬停反馈，菜单按下独立显示。组件负责联动、弹出状态、尺寸和镜像排列；调用方提供图标、文字、命令与菜单，不把标签业务写入组件。只在状态改变时更新样式，避免在两个按钮之间移动就反复重算样式。新建标签按钮的具体外观与尺寸见 [标签栏设计 §2.1](tab-strip-design.md#21-外观)。

## 5. 页面与窗口布局

- 窗口外框：非最大化时可见边框 1 像素（`window.activeBorder`／`window.inactiveBorder`），没有额外留白；缩放命中区在窗口外侧（见窗口交互设计）。
- 标题行：菜单、工具条、标题、窗口按钮在同一行，高度 30–32（现有实现保持）。
- 内容区与收纳条、固定分区之间无留白，只有 2 像素组间分隔（现有）。
- 状态栏：左侧为当前上下文信息，右侧为全局状态与通知图标。

## 6. 评审与验收

每个界面改动在提交前完成：

1. 在组件画廊（[主题设计 §6](theme-system-design.md#6-保证配色协调的机制)）中加入或更新对应组件，导出浅色、深色、黑色三套截图放到 `out/diagnostics/ui-review/<步骤>/`。
2. 对照本文档逐条检查尺寸、间距、颜色 ID、状态、键盘行为、焦点返回、文案。
3. 自动化测试至少覆盖：键盘操作路径、焦点返回、`Esc` 行为、关键几何（尺寸、位置）。像素级测试只用于有明确规格的部分（例如边框颜色、指示线粗细），不用整图对比。
4. 截图和测试不能代替在真实桌面上的试用；预览说明中如实写明哪些经过了试用。
