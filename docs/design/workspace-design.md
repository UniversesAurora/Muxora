# WindowSystem 工作区与导航设计

版本：0.7，讨论稿\
日期：2026-10-15\
关联：V0 设计文档第 4、12、18 节，以及通用窗口系统设计。本文规定交互目标；实际实现与验证范围见 [预览说明](../development/window-system-preview.md)。Muxora 的终端与文件行为是后续宿主接入要求。

## 1. 统一标签模型

顶部与底部工具条、窗口按钮、命令入口和全局状态栏由窗口壳承载。其余功能内容都作为 `WorkspaceTab`；Muxora 接入终端、文件浏览器、会话列表、传输队列、连接诊断和设置等。

窗口系统位于独立的 `modules/window-system/`，其他代码通过其公开 API 使用。两处工具区、全局状态栏、紫罗兰 VS 风格与 DPI 规范见 [通用窗口系统设计](window-system-design.md)。

不把会话列表永久限定为工具面板，也不把终端永久限定为中央文档。内容类型决定功能，所在位置由用户调整。任何功能标签都可以进入中央标签组、四边自动隐藏栏、固定边缘区域或独立窗口。

本文统一使用以下术语：

| 名称 | 含义 |
| --- | --- |
| 工作区窗口 `WorkspaceWindow` | 共用布局能力的顶层窗口，kind 分完整工作窗口与轻量浮窗。 |
| 完整工作窗口 `Workbench` | 有完整菜单／工具条、全局状态栏，是一个窗口族的根。 |
| 轻量浮窗 `Floating` | 默认拖出形态，有紧凑标题栏，支持正常窗口控制、标签与分割，属于一个完整窗口的窗口族。 |
| 窗口族 `WindowFamily` | 一个完整根窗口及其轻量浮窗；逻辑归属不等于 Qt parent 或 Win32 owner。 |
| 标签组 `TabGroup` | 用户所说的“tab 列”：一组叠在一起的标签，同时展示其中一个。 |
| 标签 `WorkspaceTab` | 一个可移动的内容单元；整体移动时带走内部布局。 |
| 窗格 `Pane` | 标签内部的内容实例，拥有自己的焦点和生命周期。 |
| 中央分割 | 将一个窗口中央区域划成多个标签组。 |
| 标签内分割 | 将一个标签划成多个窗格，不增加外层标签组。 |
| 自动隐藏栏 `AutoHideBar` | 窗口某一边收纳标签的条带；有条目才显示。 |
| 临时展开 `PeekOverlay` | 点击边栏条目后覆盖在工作区上的内容，不占永久布局空间。 |
| 固定边缘区域 `PinnedEdgeRegion` | 将边栏标签固定后使用的边缘空间，中央区域随之缩小。 |
| 标签附加栏 | 属于具体标签的可选顶部导航／操作栏与底部信息栏，未设置时不占空间。 |

X11 图形程序继续作为正常独立桌面窗口，不进入此模型。

## 2. 三层结构

```text
WorkspaceWindow（完整 Workbench 形态）
├── 融合顶部菜单／工具条与命令入口
├── 四边 AutoHideBar + 临时 PeekOverlay
├── 四边 PinnedEdgeRegion
├── 中央 CentralSplitTree
│   ├── TabGroup A
│   │   ├── Tab A1 → 可选上栏 + PaneTree + 可选下栏
│   │   └── Tab A2 → 文件浏览器
│   └── TabGroup B
│       ├── Tab B1 → 终端 3 / 终端 4
│       └── Tab B2 → 传输队列
├── 底部工具区（行向上增加）
└── 全局状态栏
```

```text
┌──────────────────────── 融合顶部命令区 ──────────────────────┐
│                       上自动隐藏栏                           │
├──┬───────────┬───────────────────────────────────────┬──┬───┤
│左│ 左固定区  │ 中央标签组 A        │ 中央标签组 B     │右│右固│
│边│ [会话]    │ [终端 A][文件 A]    │ [终端 B][任务]   │边│定区│
│栏│           │ ┌──────┬──────────┐ │ ┌─────────────┐  │栏│    │
│  │           │ │窗格1 │ 窗格2    │ │ │窗格3        │  │  │    │
│  │           │ └──────┴──────────┘ │ └─────────────┘  │  │    │
├──┴───────────┴───────────────────────────────────────┴──┴───┤
│                 下固定区／下自动隐藏栏                       │
├─────────────────────────────────────────────────────────────┤
│                         底部工具区                          │
├─────────────────────────────────────────────────────────────┤
│                         全局状态栏                          │
└─────────────────────────────────────────────────────────────┘
```

图中的区域按存在与否显示。四边没有收纳标签时没有条带；没有固定标签时也没有空白占位。

默认紫罗兰主题的内容区域使用白色。标签条和收纳条的空白处与工具栏同色，标签本身去掉左右内部边框线。内容、按钮和菜单采用四边同厚的直角矩形；内容边框紧贴边缘且四边留白一致。普通按钮悬停填充较浅，菜单栏悬停色保留；提示气泡与拖拽定位控件可以保留圆角。

轻量 Floating 形态复用同一中央树、四边区域和标签内窗格，在标题同一行最左侧提供本浮窗菜单，保留标题与窗口控制；不创建完整工作区按钮条或全局状态栏。菜单使用本窗口的标签／窗格上下文，省去退出整个应用等入口；标签自身上下栏仍正常显示。窗口形态不改变内容类型或命令能力。

中央分割树与固定边缘区域分开管理。固定侧栏占据窗口边缘，中央分割只发生在剩余的中央空间内。两者可以分别调整大小，不将“侧栏固定”解释为在中央新增一列。

## 3. 四边栏的状态与操作

### 3.1 收纳

任何标签可通过图形投放目标、菜单或命令收纳到左、右、上、下栏。标签只改变所属区域，不重建内容或连接。

条带中显示标签名称与图标，同一边可以有多个条目；内容较多时提供滚动和选择菜单。临时展开只显示选中的一个标签，不展示其他收纳标签；固定面板仍支持多标签组。

默认只在点击条目或执行“显示这个边栏标签”命令时展开。单纯悬停不强制弹出，避免鼠标经过时遮住内容。

### 3.2 临时展开

临时展开覆盖工作区，保持中央布局尺寸。它属于当前工作区窗口，不增加任务栏窗口。

- 点击条目显示并聚焦内容；再点击同一条目可收起。
- 同一窗口默认只展开一个临时侧栏。
- Esc 或点击其他工作区内容收起，并恢复先前的合理焦点。
- 与内容关联的右键菜单、下拉框或对话交互不触发意外收起。
- 四个方向的面板都能调整宽、高和角部，调整命中范围叠在边缘，外框与内容之间四边留白保持一致且紧凑。

每个标签分别保存左／右共用、上／下共用的两套请求宽高，两套互不影响，各轴都允许未设置。默认左右展开宽 250 个逻辑像素、占满可用高度；上下展开高 170 个逻辑像素、占满可用宽度。显式调整只改变对应方向套组的对应轴。切换同组标签、换边或跨窗口移动保留这些值。窗口空间不足时只限制实际显示大小，不覆盖请求值，扩大窗口后恢复。内容的最小尺寸也约束实际显示。

临时展开大小与固定分区的 `edgeExtent` 独立。固定、取消固定及重新固定不会拿临时尺寸替换固定尺寸，也不会反向覆盖临时尺寸。菜单、命令面板和可绑定快捷键共用设置／重置入口，支持用键盘输入宽高。

收起后，活动终端仍维护状态和协议回复，传输仍由任务管理器执行；只停止无效绘制。

### 3.3 固定与取消固定

点击固定按钮只处理当前标签，使其进入所在方向的固定边缘区域，并离开收纳条带。该区域正式占据空间，中央区域重新布局；其他收纳标签不随之固定。该侧全部固定／取消固定使用另外的明确按钮和命令。

取消固定同样只处理当前标签，回到对应自动隐藏栏，并记录原固定分区、标签位置与尺寸以便重新固定。用户也可以把它拖入中央或另一边。位置与固定状态分别保存。

固定区域中允许多个标签叠成组，组内切换遵循同一套规则。对相邻固定区的调整使用实际分隔条；V0 不为边缘区域再实现一套无限递归的外层分割，复杂多组布局主要放在中央。

## 4. 中央标签组与分割

中央区域使用递归分割树。用户可以在任一现有标签组的左、右、上、下插入新的标签组，也可以把标签合并进已有组。

不预设只能两列、四格等固定模板。分割受可见空间、内容最小尺寸和资源预算约束；空间不足时目标不可投放，不能生成看不见的窗格。

- 标签组内部可重排标签，前后切换。
- 拖到组中心合并为标签，拖到组方向目标创建相邻组。
- 标签组之间的分隔空白默认为 2 个逻辑像素，固定边缘分区与中央区域也使用该值；标签内部窗格默认为 1 个逻辑像素。两者使用独立的主题尺寸，都可拖动调整比例，也提供键盘命令。
- 关闭或移走组的最后一个标签后，删除空组并合并冗余分割节点。
- 移动标签保留整个 PaneTree、终端历史、目录跟随状态及传输引用。

标签条在任何布局或窗口变化后都应保留合理的可视位置。在左侧新增组、固定边栏或从窗口左边缩小时，以未改变的右侧显示位置为基准，向前增加偏移；右侧缩小时保留左侧偏移。上下变化未改变横向范围时不滚动，单独移动窗口也不滚动。当前标签此前完全可见而随后被截断时，优先将该标签对齐可视区左边；尾部可用不超过一屏的临时滚动空间实现，不能创建假标签或累计空白。此前已经隐藏的活动标签不自动找回，用户的新滚动不能被延迟布局覆盖。[条带尺寸规则](window-interaction-design.md#条带尺寸变化)

每组最后一个标签后提供随条带滚动的加号与窄类型下拉，全部标签列表按钮也采用标签等高的窄条。加号调用默认宿主新建命令，类型菜单调用其他宿主新建命令。新标签位置可选组开头、末尾、活动标签之前或之后，默认在活动标签之后；明确的插入索引和拖拽落点优先。

应用记录逻辑归属和稳定 ID；具体布局引擎负责几何计算。不能让应用模型和第三方停靠引擎同时计算并反复覆盖尺寸。

## 5. 每个标签内部的窗格

### 5.1 递归分割

每个标签持有自己的 `PaneTree`。在当前窗格的任一方向创建分割，新节点只修改该标签内部，不改变外层 TabGroup。

宿主用 `TabOptions.topBarSharing` / `bottomBarSharing` 或对应 setter 分别决定上下窗格栏的共享方式。`PaneBarSharing::Shared` 随活动窗格在标签公共位置显示；`PerPane` 在各窗格内部显示自己的栏。控件不复制，缺失栏不占空间，显式标签附加栏仍显示一次。共享策略属于标签，拆分继承，提取窗格时随内容描述保留。

终端标签可包含多个终端实例，分别保持 shell、光标、历史与目录上下文。创建终端窗格默认创建新 shell，不复制正在运行的远程进程。

标签容器支持通用窗格内容。任何标签都可通过添加内容形成分割；单一设置页默认保持单窗格，也可以与其他内容并列，不要求复制不能重复的实例。终端、文件浏览器以及以后新增内容按自身能力提供创建与操作。文件浏览器的本地／远程双栏仍是文件功能内部布局，不自动等同两个 SSH 终端窗格。

结构用二叉 SplitNode 表达即可，允许不断嵌套；每个节点保存方向和比例，每个叶子对应一个 Pane ID。Qt QSplitter 可作为呈现候选；若不适合交互、尺寸或性能要求，则自行实现轻量窗格布局与分隔条。公开 API、焦点与内容归属不依赖这个选择。[QSplitter](https://doc.qt.io/qt-6/qsplitter.html)

### 5.2 窗格操作

- 拖动内部边界或使用命令调整窗格大小。
- 上下左右移动焦点，显示当前活动窗格边框。
- 切换分割方向，关闭窗格，必要时暂时最大化一个窗格再恢复。
- 通过快捷键、右键菜单或命令面板把当前窗格移到新标签、新标签组或独立窗口。
- V0 不要求鼠标直接拖拽窗格成为独立窗口。

提取窗格是移动操作：同一个 Pane ID 和终端实例进入新的标签容器，不重新连接。源分割树去掉该叶子并合并冗余节点；最后一个窗格移走时，删除空标签。目标创建失败则恢复原结构，不能遗失内容。

Windows Terminal 的窗格分割、方向聚焦和大小调整可作为内层交互参考；外层标签组另行设计。[Windows Terminal 窗格说明](https://learn.microsoft.com/en-us/windows/terminal/panes)

### 5.3 可选上下附加栏

每个标签可设置内容上方的导航／操作栏与内容下方的信息栏。上下独立可选，未设置或清空时没有空白占位。它们按 Tab ID 保存归属，随标签移动、收纳和跨窗口，不属于窗口全局状态栏。

窗格如需独立附加栏，使用同一能力按 Pane ID 绑定；提取窗格时只带走属于它的栏。整个标签的栏保留在标签上。直接 QWidget 由调用者明确设置或隐藏，不通过猜测其文本判断空栏。

### 5.4 内容全屏范围

窗口、标签组、窗格是三个全屏范围。标签组范围只显示原 Group 的内容，窗格范围只显示原 Pane 的内容；不复制业务实例或修改分割树，退出后恢复原布局。标签组允许在本组内切换标签，窗格按稳定 Pane ID 跟随同窗口移动；目标关闭或跨窗口移走后安全退出。选择范围外的内容先退回窗口全屏。

工具区、全局状态栏、中央标签栏和四边收纳条的显隐独立于这些范围，进入全屏沿用当前窗口偏好。固定组标签栏与收纳面板标题继续遵守原来的显隐规则。禅模式仅在全屏时可用，隐藏全部栏及内容上下附加栏，关闭后恢复原偏好；显示任意一栏也会退出禅模式。操作命令和键位见 [交互修订](window-interaction-design.md#独立显隐与全屏)。

## 6. 两种窗口与跨窗口合并

默认拖出标签得到归属于来源窗口族的轻量浮窗；显式命令可直接创建完整工作窗口，拖出默认形态也可设置。两种窗口共享标签组、四边、内层窗格和内容命令，区别在外壳及归属。浮窗可升级为新的完整窗口；完整窗口可选择另一根窗口后降为浮窗，原有从属浮窗同时改属，保持所有内容实例。

任意标签可在同族或不同族的两种窗口间拖动。拖轻量浮窗标题栏则移动整窗内容：放到组中心合并所有标签；放到组的上下左右保留中央分组，存在边缘组时按预览转换成中央组再组成子树；未命中目标只移动原窗口。单个标签可继续从该浮窗拖出。完整窗口标题栏保持正常移动，另有全部标签移动命令。

标签即时拖出时清理来源空组，源轻量浮窗移空后自动清理；完整窗口移空后的保留／关闭由设置决定，默认保留。判空包含整个窗口族的中央、固定、自动隐藏和浮窗标签，不能因为最后一个标签刚拖成浮窗就关闭根窗口。Esc 恢复原结构，成功投放后再清理其移空浮窗。

移动保留 ID、PaneTree、上下栏、终端历史和业务资源，旧 parent 销毁不能删除已转移视图。新尺寸与 DPI 更新显示及 PTY；操作失败或取消恢复来源。关闭浮窗只协调本窗内容，显式关闭完整根窗口先协调全族，任一拒绝则整次取消。

类型转换、整窗合并顺序、窗口归属、空窗口策略与关闭的完整契约见 [双窗口形态与跨窗口拖拽](floating-window-design.md)。

## 7. 拖拽时的图形辅助

参考用户提供的 Visual Studio 截图，用图形目标说明放下后的结果，而不是要求用户猜测鼠标区域。

1. 拖动标签后，在目标标签组显示中心及四方向指示。
2. 中心表示合并到该组；方向表示在相应位置形成中央标签组分割。
3. 窗口四边分别提供连接的收纳／固定双目标；靠边的一格收纳、靠内的一格固定。固定投放建立靠外的新分区。
4. 固定边缘区域提供合并目标；边栏条带也可以直接接收标签。
5. 悬停有效目标时高亮图标并显示半透明落点预览，预览范围与最终结果一致。
6. 标签达到拖动阈值后，条内先显示标签预览，保留源内容；鼠标首次离开原条带即形成轻量浮窗，移除来源条目和空组，不必移出工作区。经过内容区不会合并，只有指示、标签条和已显示的边栏接受投放；Esc 恢复原布局和焦点。
7. 拖拽中在被遮挡的合格目标处短暂停留，将目标抬到前方再显示落点；保持拖拽捕获，不把操作键交给目标终端。默认 500 ms，可设置；完全遮挡或最小化目标另有可键盘操作的目标窗口列表。

高 DPI、多屏和最大化状态下，命中区域使用 Qt 的统一坐标与正确转换；图标清晰，目标有提示文本。无效位置不出现可投放预览。即时浮窗只在开始时调整结构，随后移动窗口和指示，不在每次鼠标移动中重建内容或整个布局。紧凑窗格、标签滚动和工具条的补充规则见 [交互修订](window-interaction-design.md)。

## 8. 键盘导航与命令面板

### 8.1 窗口、标签组、标签与窗格分别导航

| 层次 | 命令 | 行为 |
| --- | --- | --- |
| 窗口 | `window.focusNext/Previous`、`window.select`、`window.focusOwner` | 分别支持族内、全部窗口、仅完整窗口循环；选择目标窗口及返回所属完整根。 |
| 标签组 | `workspace.focusGroup.left/right/up/down` | 聚焦当前组指定方向的可见组。 |
| 组内标签 | `workspace.previousTab`、`workspace.nextTab` | 在当前组内前后切换，不跳进其他组。 |
| 当前标签的窗格 | `pane.focus.left/right/up/down` | 聚焦该标签内指定方向的窗格，不隐式越过外层标签组。 |
| 外层大小 | `workspace.resizeGroup.direction` | 调整标签组或固定边缘区域的相关边界。 |
| 内层大小 | `pane.resize.direction` | 调整当前窗格的相关边界。 |
| 创建内部窗格 | `pane.split.left/right/up/down` | 按指定方向插入新窗格。 |
| 移动与收纳 | `workspace.moveTabToEdge`、`workspace.moveTabToWindow`、`workspace.moveTabToNewWindow`、`pane.moveToWindow` | 改变所属容器；新窗口显式选择 floating／workbench，保留内容实例。 |
| 窗口形态与整窗操作 | `window.promote/demote`、`window.reassignFamily`、`window.moveAllTabs`、`window.redock` | 升降级、改归属、整窗合并与回停靠，同样可绑定快捷键。 |

外层方向导航在当前窗口的可见标签组间进行，可以到达固定边缘区域。收起的边栏条目通过“显示边栏标签”或命令面板激活，不让方向导航跳进看不见的内容。跨窗口切换使用独立命令。

方向目标按实际矩形位置寻找：先考虑方向和垂直于该方向的投影交集，再选最近邻。没有邻居时保持焦点；是否循环可配置，不能意外触发另一层导航。

每个组记住最近活动标签，每个标签记住活动窗格。切回时恢复合理的编辑焦点；Esc 关闭临时展开后回到先前内容。

### 8.2 默认键位建议

| 操作 | Windows 默认候选 |
| --- | --- |
| 标签组上下左右导航 | Ctrl + Alt + 方向键 |
| 当前组前后标签 | Ctrl + PageUp／PageDown |
| 当前标签窗格方向导航 | Alt + 方向键 |
| 调整窗格 | Alt + Shift + 方向键 |
| 调整标签组 | Ctrl + Alt + Shift + 方向键 |
| 命令面板 | Ctrl + Shift + P |
| 所属族的窗口前后切换 | Ctrl + Alt + PageUp／PageDown |
| 全部应用窗口前后切换 | Ctrl + Alt + Shift + PageUp／PageDown |
| 返回所属完整窗口 | Ctrl + Alt + Home |

默认键位是可更改的方案，不是硬编码约束。所有操作先注册为命令，再由快捷键、菜单、右键菜单或命令面板调用同一入口。窗格创建与提取也可以完全通过命令面板完成。

窗口循环使用稳定创建顺序，普通循环跳过最小化窗口，显式选择可恢复。拖拽期间通过 `window.drag.selectTarget` 选择被遮挡目标，悬停抬前与普通激活窗口分开；具体焦点与取消规则见双窗口设计。

命令目录覆盖所有公开操作，未分配默认键的命令也可以绑定；需要服务器、路径或目标位置等参数时提供键盘选择器。命令面板打开前捕获来源窗口／组／标签／窗格，执行前验证目标仍有效，面板焦点不改变操作目标。

采用 VS Code 风格 `keybindings.json`，支持 `key`、`command`、`args`、`when`、用户覆盖、默认解绑、多键序列和冲突诊断。上下文匹配与命令前提分开，解析规则统一；具体优先级、序列竞争、取消和文件更新见 [设置与命令设计](settings-and-commands-design.md)。

区分工作区、窗格、文本输入、IME 预编辑及终端模式；应用已消费的命令键不再次送给远端。仅 `remoteInput` 上下文中的未消费输入正常编码发送；本地 Normal／Visual 中的未绑定键、失效前缀和取消键也不发送 SSH。方向导航不能破坏输入法组合或依赖某个控件私有快捷键。

### 8.3 终端本地 Normal／Visual

每个 TerminalId 有独立本地浏览状态。进入后用 Vim 风格键浏览输出，支持计数、词／行／页、gg／G、查找、字符／整行／矩形 Visual、端点切换和复制；普通浏览不强制带选区。复制后回到 Normal，Visual Esc 回 Normal，Normal Esc／i 明确回远端输入；存在前缀时默认 Esc 先取消前缀。

远端继续输出和处理协议，浏览只控制本地视口及输入。跨窗口保留同一实例的模式和有效选区，待完成序列在焦点变化时取消；隐藏窗格不抢走按键。所有动作都注册公共命令，Vim 默认键可通过同一快捷键文件修改。历史、重排、输入法和完整规则见 [终端 Normal 与选择模式](terminal-mark-mode-design.md)。

未来 macOS 的修饰键方案放在平台键位配置中，不把 Windows Ctrl 规则写进布局或终端核心。

## 9. 停靠实现与接入边界

公开 API、布局模型及交互规范属于 WindowSystem。V0 采用自有停靠与拖拽实现，Qt 的分割、事件、菜单和绘制能力按实际需要复用；不引入 KDDockWidgets，不同时维护多个完整引擎。模块自有代码采用 MIT 方向。

自有实现分别承担：

- 布局模型和事务：中央组、四边区域、Tab／Pane 归属、稳定 ID、取消与空组清理。
- 停靠视图与交互：单标签与整窗拖拽、图形目标和预览、悬停唤起、自动隐藏展开、边缘固定及跨两种窗口移动。
- PaneTree：标签内轻量递归分割，不为每个窗格创建完整停靠引擎。
- 导航与恢复：基于实际几何的焦点路由、结构快照、版本迁移和资源生命周期。

`EdgeRegionHost` 控制独立边缘区域；`WorkspaceWindow` 的两种壳共用 DockSurface，WindowFamily 记录归属。模型、视图和输入处理分开，拖拽只在提交时改变归属；预览和取消不能重新连接、重建业务内容或丢失焦点。

KDDockWidgets 的既有调查保留为参考：它支持分割、标签、四边自动隐藏、跨窗口和自定义投放指示，并非由于缺少基本能力而排除。其 auto-hide 恢复原停靠位置的语义与本设计的独立固定边缘区需要额外适配；普通 FloatingWindow 也不自动等于完整 WorkspaceWindow。深层视图定制可能涉及私有 API，开源版 GPL 会改变发行许可条件。[官方功能](https://kdab.github.io/KDDockWidgets/)、[主窗口实现](https://github.com/KDAB/KDDockWidgets/blob/v2.4.1/src/core/MainWindow.cpp)、[私有 API](https://kdab.github.io/KDDockWidgets/private_api.html)、[许可](https://kdab.github.io/KDDockWidgets/licensing.html)

未来只有确有收益且满足许可与交互要求时再考虑额外停靠组件；供应方对象及格式仍隔离在内部。当前自研方案必须通过状态转换、实际桌面、混合 DPI 和长期资源测试，不以“采用 Qt”代替验证。

## 10. 保存与恢复

保存窗口列表、四边条目及顺序、固定区域尺寸、中央组归属与分割比例、每个标签的 PaneTree、上下栏配置引用、顶部／底部条带布局与锁定、独立显隐偏好、全屏／禅模式及其目标、快捷键方案和 DPI 相关尺寸信息。中央、自动隐藏栏和固定边缘区都保存组 ID、成员标签、顺序与活动标签；整组收纳后恢复仍是一组，不散成多个条目。

临时展开请求尺寸按 Tab ID 保存，左／右与上／下各有独立可选宽高；固定尺寸另存。状态栏控件的显隐按窗口和稳定控件 ID 保存，右键菜单、命令及 API 使用同一值。标签滚动快照用于当前布局变化，临时尾部空间与拖拽占位不写成真实标签或业务数据。

窗口列表同时保存 kind、WindowId、FamilyId 和完整根映射；统一校验归属后恢复。旧版窗口迁移成一窗口一族，缺根浮窗按恢复规则补根；不保存临时拖拽、系统层叠顺序或前台权限。

实际键位规则保存在用户 `keybindings.json`，布局仅保存方案引用或对应结构；窗口状态由宿主保存到独立版本化 JSON，移动窗口不修改全局 settings。Normal／Visual 瞬时状态、选区正文和未完成序列不跨应用重启恢复。[文件组织](settings-and-commands-design.md)

稳定的逻辑 ID 与结构是应用数据。供应方序列化结果只是带版本的适配数据；升级不兼容时按应用逻辑结构重建，失败可回到默认布局。恢复模型与尺寸仍需通过适配原型确认，不提前保证任意上游布局格式永久可用。

网络句柄、线程、裸指针和终端库内部内存不写入布局文件。重启恢复的是工作区结构，远程进程恢复遵循 SSH 会话规则。来源别名已删除的标签不因布局恢复而重新生成会话配置。

## 11. 重点验收

以下条目映射到稳定需求 ID 和自动化用例，检查模型、Qt 视图与真实鼠标／键盘结果。独立 WindowSystem 与 Muxora 宿主分别验证；测试失败修复实现后重跑，不自行删除用例、放宽断言或更新错误基线。完整测试及发布规则见 [自动化测试与质量要求](../development/testing-design.md)。

- 会话列表、传输、终端、文件等标签具有相同移动能力，不存在类型决定的永久位置。
- 四边条带为空时隐藏，有内容时出现；点击临时覆盖展开，固定后占用独立边缘空间。
- 固定／取消固定不在中央新增分割；从中央收纳标签时按空组清理规则收缩分割树，不重新连接。
- 中央标签组递归分割与标签内窗格递归分割互不混淆。
- 组方向导航、组内标签切换与窗格方向导航各自生效，焦点可见。
- 内外两层均支持可控尺寸调整，空节点正确合并。
- 标签拖出、跨窗口合并，以及窗格命令提取后，原终端 ID、历史和远程 shell 保持。
- 两种窗口有相同内容布局能力；轻量外壳与完整外壳区分，升降级、改归属和族关闭无内容丢失。
- 顶部／底部工具条可跨区移动并形成多行；完整窗口全局状态栏可独立隐藏，轻量窗口省去该状态栏，标签上下附加栏独立可选且移动后归属正确。
- 三个全屏范围保留原布局树与内容身份，四项显隐偏好与范围独立；禅模式隐藏全部栏，显示任一栏后退出并恢复，目标关闭／移动及窗口正常／最大化恢复均有回归。
- 图形投放辅助及预览与最终结果一致；取消、边界位置、多屏 DPI 均正确。
- 单标签与轻量标题栏整窗拖拽、中心合并与方向保留分组、遮挡唤起和系统拒绝均验证；浮窗移空清理、完整空窗口可配置且不误关仍有浮窗的根。
- 反复收纳、固定、拆分、合并和跨窗口移动后，视图、订阅与资源没有持续增长。
- 全部公开操作可通过命令及快捷键完成；参数选择、用户覆盖、条件、解绑、序列与面板目标都有有效测试。
- 本地 Normal／Visual 导航、计数和选择不串窗格、不泄漏按键，复制后仍为本地模式；运行状态与用户设置分别保存。
