# 窗格活动：通知、进度与运行状态

状态：设计稿，2026-10-24 用户提出需求并认可第 7 节的建议。实现步骤见 [8.17–8.19](../roadmap/implementation/phase-8-ui-quality.md#817-状态项的点击与悬停) 和 [7.15](../roadmap/implementation/phase-7-terminal-and-sessions.md#715-终端活动协议)。补充 [功能对标计划](../roadmap/feature-parity-plan.md) 中“完成通知”“Shell 集成”两行；状态栏的点击与悬停见 [通用窗口系统设计 §7.3](window-system-design.md#73-状态项的点击与悬停)。

## 1. 同类软件的做法

| 软件 | 做法 |
| --- | --- |
| Windows Terminal | 读 ConEmu 的 OSC 9;4 进度序列，在标签图标位置画进度环，同时把窗口的任务栏按钮变成进度条；状态有普通、错误、不确定和暂停。响铃（BEL）可选声音、闪烁窗口或任务栏，标签上显示铃铛。 |
| Ghostty | 读 OSC 9、OSC 777 和 kitty 的 OSC 99 桌面通知、OSC 9;4 进度；响铃可选系统提示音、请求关注或在标题前加铃铛。 |
| kitty | OSC 99 桌面通知，可带标题、正文、点击后的动作。 |
| iTerm2 | OSC 9 发通知；“触发器”按正则匹配输出后发通知、高亮或运行脚本。 |
| VS Code | OSC 633（基于 FinalTerm 的 OSC 133）标出提示符、命令开始和结束，命令旁的标记显示退出码，悬停显示耗时。 |
| [Kero](https://kero.sh/docs/status) | 每个窗格有一个状态：工作中、等你处理、空闲、出错、已退出，侧栏按会话显示，快捷键跳到下一个等你处理的会话，程序坞图标显示等待数。程序用 OSC 7501（Program Status Protocol）报告状态、进度和需要什么（批准、回答、登录）；OSC 9;4 只用来显示进度，不当成“工作中”，因为 Neovim 加载语言服务器时也会发它。“完成”和“出错”保留到用户在窗格里输入为止。 |

## 2. 以窗格为单位

终端、传输、编辑器都在窗格里运行，所以活动状态按窗格记录，标签、标签组、窗口和整个程序只是把下级汇总起来显示。窗格移到别的标签或窗口时，状态跟着走。

每个窗格的活动：

| 内容 | 说明 |
| --- | --- |
| 状态 | `idle`（空闲）、`working`（工作中）、`waiting`（等你处理，可带原因：批准、回答、登录）、`done`（完成，还没看）、`error`（出错）、`exited`（程序已退出） |
| 进度 | 没有、百分比、不确定、暂停或出错；带开始时间 |
| 命令 | 当前或最近一条命令：开始时间、结束时间、退出码；需要 shell 集成 |
| 未读通知 | 条数、最近一条的标题和正文、时间 |

汇总时按“最需要你”排序：等你处理 > 出错 > 工作中（有进度的优先） > 完成 > 有未读通知 > 空闲。一个标签显示它最需要你的那个窗格，标签组、窗口、程序同理。

窗口模块只提供通用的接口和显示，不认识终端协议：宿主调用 `setPaneActivity(PaneId, PaneActivity)` 报告某个窗格的状态，模块负责汇总、画在标签上、给出汇总查询和变化通知。终端、传输、Lua 都通过这一个接口报告。

## 3. 状态从哪里来

终端会话在终端核心里识别下面这些序列，转成第 2 节的活动：

| 来源 | 变成 |
| --- | --- |
| OSC 9;4（ConEmu、Windows Terminal） | 进度。只显示进度，不改状态，原因同 Kero。 |
| OSC 7501（Program Status Protocol） | 状态、进度、原因、消息；支持查询应答。同一窗格里多个任务按 `id` 分别记录，显示最需要你的那个。 |
| OSC 9 文本、OSC 777;notify、OSC 99 | 一条通知 |
| BEL | 一条通知（没有正文），按设置决定是否响声音 |
| OSC 133 或 OSC 633 | 命令开始、结束和退出码；长命令结束时可选发一条通知（时长阈值可设） |
| 进程退出 | `exited`，退出码非零时同时算出错 |
| 触发器（以后，参照 iTerm2） | 按正则匹配输出后发通知或改状态 |
| Lua | `muxora.pane.report{...}`、`muxora.pane.notify{...}`，字段和 OSC 7501 相同 |

OSC 9 后面是数字和分号时是 ConEmu 的子命令（9;4 进度、9;9 目录），否则是 iTerm2 的通知文本，两种都支持。远端程序发来的通知文本只显示，不当成命令执行，长度有上限。

“完成”“出错”和未读通知在用户看到这个窗格时清除：窗格所在标签是活动标签、窗口在前台、焦点进入这个窗格。“工作中”“等你处理”跟程序走，程序报告别的状态或退出时结束。

## 4. 显示

### 4.1 标签

- **图标位置**：工作中有进度时，图标换成进度环（强调色；不确定时一段弧旋转；暂停用警告色；出错用错误色整圈）；等你处理、完成、出错、有通知时，图标临时换成对应的状态图标（问号或手、对勾、叉、铃铛），状态清除后换回原图标。标签不显示图标时，进度环和状态图标画在关闭按钮的位置，和置顶标签的操作按钮一样，悬停时换回关闭按钮，所以标签宽度不变。
- **底色**：等你处理、出错和有未读通知的非活动标签换成主题的提示底色（新增颜色 ID，例如 `tab.attentionBackground`、`tab.errorBackground`），颜色只比普通底色稍重，和 VS Code 的“已修改”同一个分量，不用闪烁。活动标签不变色，因为你正看着它。
- **悬停提示**：标题下面加几行：状态和消息、进度和已用时间（“45% · 3 分 12 秒”）、当前命令和运行时长、最近一条通知和时间。
- **收纳条和完整列表**：自动隐藏和固定侧栏的标签、标签列表菜单使用同样的图标和底色。

### 4.2 状态栏

- 右侧一个“活动”状态项：铃铛加未读数；有任务在跑时显示进度汇总（“2 个任务 · 45%”）。范围可设为本窗口或全部窗口。
- 点击弹出面板（按 [§7.3](window-system-design.md#73-状态项的点击与悬停) 的弹出方式），列出所有有活动的窗格：标题、状态、进度条、时长、最近通知；点一行跳到那个窗格，另有“全部标为已读”。
- 命令 `workspace.nextAttention`（默认快捷键待定）跳到下一个最需要你的窗格，和 Kero 的 ⌘J 一样。

### 4.3 系统

- **Windows 通知**：窗口不在前台或窗格不可见时，等你处理、完成、出错和程序发出的通知弹出 Windows 通知；点通知激活窗口并聚焦那个窗格。哪几种要弹可设。
- **任务栏**：窗口里有进度时任务栏按钮显示汇总进度（`ITaskbarList3`，和 Windows Terminal 一样）；有等你处理的窗格时任务栏按钮闪一次，按钮上叠加数字角标。
- **声音**：BEL 默认不响，可选系统提示音。

### 4.4 以后的会话管理窗格

每个会话一行显示同样的图标和颜色、已运行时间，参照 Kero 侧栏和截图里的样子：标题右侧是时长和状态（旋转、对勾、叉）。

## 5. 隐藏和未显示的窗格照常工作

1.7 之后，没显示过的标签不创建页面视图，但窗格的内容控件和它背后的会话一开始就创建（[通用窗口系统设计 §3.1](window-system-design.md#31-标签视图与内容可见性)）。所以：

- 终端输出照常进入终端核心，识别 OSC、更新屏幕和历史，只是不画；这本来就是 [工程设计 §3.3](../development/engineering-design.md#33-隐藏收纳与关闭) 的要求。通知和进度在会话里产生，与视图无关。
- Lua 读取终端内容、状态和历史走会话接口，不经过控件，未显示的窗格也能读。
- 标签上的指示画在标签条项上，没显示过的标签也有标签条项，所以能看到。

要注意的地方：

- **终端尺寸**：没显示过的终端没有自己的控件尺寸，但 PTY 和 SSH 需要行列数。新会话用同一标签组可见区域的尺寸，第一次显示时再按实际尺寸调整。7.x 接入终端时写进测试。
- **依赖几何的接口**：窗格位置、相邻窗格导航这类接口对没显示过的标签没有几何信息，返回“未知”，不能当成 0。
- **释放 GPU**：可见性通知只让宿主释放绘制资源，不能借此暂停会话或停止解析。

## 6. 主题和设置

- 颜色 ID 按 [主题系统设计 §4](theme-system-design.md#4-颜色-id-清单) 新增：标签提示底色、出错底色、进度环、状态图标颜色，三套主题都要设计和截图审查。
- 设置（ID 草案）：`notifications.system`（哪些情况弹 Windows 通知）、`notifications.bell`（无、声音、闪任务栏）、`notifications.longCommandSeconds`（长命令通知阈值，0 关闭）、`activity.statusBarScope`（本窗口或全部窗口）、`terminal.allowProgramStatus`（是否接受远端的 OSC 7501 和通知）。

## 7. 已确认的取舍

用户 2026-10-24 认可下面四条建议：


1. 标签不显示图标时，进度环和状态图标放在关闭按钮的位置（标签宽度不变），还是临时占出图标位置（标签会变宽）？建议前者。
2. 状态底色只用于等你处理、出错和未读通知，“工作中”和“完成”不变底色，只换图标，避免一排标签同时变色。可以吗？
3. Windows 通知默认只在窗口不在前台时弹，窗口在前台但窗格不可见时不弹，只显示在标签和状态栏上。可以吗？
4. OSC 7501 是 Kero 提出的协议，目前用的程序还少。是否支持？建议支持，成本小，也方便我们自己的 Lua 和以后的代理集成用同一套字段。

## 8. 实现顺序

先做窗口模块的 `PaneActivity` 接口、标签和收纳条显示、状态栏活动项与弹出面板（不依赖终端，用 Lua 和测试驱动）；再在终端接入（7.x）时识别各序列；Windows 通知和任务栏单独一步，先验证未打包程序弹 Windows 通知需要的应用标识和快捷方式。
