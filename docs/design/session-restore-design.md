# 启动时恢复会话设计

状态：设计稿，2026-10-20。实现步骤见 [阶段 1.8](../roadmap/implementation/phase-1-layout-performance.md#18-启动时恢复会话对象界面按需创建) 与 [阶段 7.10](../roadmap/implementation/phase-7-terminal-and-sessions.md#710-启动时恢复会话)。

## 1. 能恢复什么，不能恢复什么

退出程序时，所有连接都会断开。远端 shell 和其中正在运行的程序随连接结束（除非在远端用 tmux／screen 保持，见 §6）；Muxora 无法把一条已经断开的连接“存起来”下次接着用。V0 设计 §6.4 已经写明：“重连会建立新的远程 shell，不可能自动恢复已丢失的远程进程。”

因此“恢复”指的是：

| 恢复内容 | 说明 |
| --- | --- |
| 窗口与布局 | 窗口、标签组、标签、窗格、侧栏、全屏状态（已经实现） |
| 每个标签的连接目标 | 哪个会话配置或本地终端配置，以及当时的终端尺寸 |
| 终端历史 | 上次退出前的屏幕内容和一段回滚历史，作为只读历史显示在新连接的上方 |
| 工作目录 | 本地终端在上次报告的目录启动；SSH 会话可选在登录后进入上次的目录（§4.4） |
| 文件面板 | 上次浏览的路径、跟随或固定状态 |
| 连接本身 | **重新建立**，不是恢复原来那条 |

这与 Xshell、SecureCRT、MobaXterm、Tabby 的“启动时恢复上次会话”一致；Windows Terminal 1.21 起的“恢复窗口布局和内容”也是重新启动 shell，再把上次的缓冲区内容放回去。

## 2. 设置

| 设置 | 取值 | 默认 | 含义 |
| --- | --- | --- | --- |
| `workbench.restoreSessions` | `none`／`layout`／`reconnect` | `reconnect` | `none`：每次都从默认布局开始；`layout`：恢复窗口、标签和历史，但不连接，每个标签显示“未连接，按 Enter 连接”；`reconnect`：恢复并重新连接全部会话 |
| `terminal.restoreHistory` | 布尔 | `true` | 是否保存并恢复终端历史 |
| `terminal.restoreHistoryLines` | 整数 | `1000` | 每个终端保存的最多行数（另有全局字节上限，§5） |
| `ssh.restore.maxConcurrent` | 整数 | `8` | 恢复时同时进行握手的连接数上限 |
| `ssh.restore.restoreDirectory` | 布尔 | `false` | SSH 登录后是否自动 `cd` 到上次的目录（§4.4） |

本地终端（PowerShell、cmd、WSL、Git Bash）在 `reconnect` 模式下重新启动进程；在 `layout` 模式下同样显示“按 Enter 启动”。

设置页“窗口 › 启动”分类下显示这些项。命令面板提供“重新连接全部已断开的会话”“断开全部会话”。

## 3. 连接与界面分开：连接在，界面按需

窗口系统的阶段 1.7／1.8 让“看不见的标签不创建界面控件”，用来节省内存。这只针对**界面**。用户的要求是：恢复后所有连接都要在，即使标签没显示。因此分成两层：

| 层 | 是什么 | 何时创建 |
| --- | --- | --- |
| 会话对象 | 连接、终端状态（Ghostty 核心与历史）、传输、目录跟随状态；不是 QWidget | 恢复时为每个标签立即创建，并按 §4 的顺序连接 |
| 界面控件 | 终端视图、滚动条、查找栏、窗格框 | 标签第一次显示时创建；隐藏时可以释放渲染资源，会话对象不受影响 |

没有界面的会话照常接收输出：数据进入终端核心并更新历史，只是不生成渲染快照（工程设计 §3.3：不能因为视图隐藏就停止协议处理）。标签上的活动标记（有新输出、响铃、进程退出、连接断开）由会话对象驱动，与界面是否创建无关。

窗口系统对应的接口改动见 [阶段 1.8](../roadmap/implementation/phase-1-layout-performance.md#18-启动时恢复会话对象界面按需创建)：恢复布局时一次性把所有标签的内容描述交给宿主，宿主立即创建会话对象；界面控件仍然在标签第一次显示时才通过工厂创建，工厂从已存在的会话对象生成视图。

## 4. 重新连接的顺序与限流

一次打开几百个连接，如果同时握手，会把网络、跳板机和本机都压住，还可能触发服务器的连接频率限制。做法：

1. **先恢复界面再连接**：窗口和布局先显示出来，所有标签立即可见，状态为“等待连接”。启动不等连接完成。
2. **优先级**：
   1. 当前显示的标签（每个窗口的活动标签、可见的窗格）；
   2. 其余标签按上次访问时间从近到远（模型已有 `visitedOrder`）。
3. **并发上限**：同时握手不超过 `ssh.restore.maxConcurrent`（默认 8）；同一台主机、同一个跳板机分别再限制为 2 个，避免触发服务器的 `MaxStartups` 限制。本地终端也限流（默认同时启动 4 个进程），避免几十个 WSL 发行版同时启动。
4. **用户操作优先**：用户切到一个还在排队的标签，或在其中按键，这个标签立即提到队首。
5. **进度与失败**：恢复期间状态栏显示一行“正在恢复连接 37/200”，全部完成后消失。连接失败的会话就显示在它自己的标签里（标签上的错误标记，内容区写明原因并提供“重试”），不另设列表或通知。
6. **共享跳板连接**：经过同一个跳板机的多个会话共用一条到跳板机的连接（libssh 一个会话多个通道），减少握手次数。这也是平时打开几百个会话时的优化，不只用于启动。

### 4.1 需要输入密码或验证码的会话

使用密钥、SSH agent，或已在凭据管理器中保存密码的会话，直接自动连接。

需要交互输入的（未保存的密码、私钥口令、MFA 验证码）**一个一个弹出输入框**：一个输完（或跳过），再弹下一个。（2026-10-20 按用户要求修订：此前的“先进入需要登录状态、从状态栏逐个处理”不合理——服务器对登录有时限，等用户想起来去处理时连接早已超时。）

- **按顺序握手，避免超时**：需要交互输入的会话排成单独的一队，同一时间只处理一个。轮到它时才开始握手，握手完成立即弹出输入框，这样不会在排队等待时超过服务器的登录时限（OpenSSH 默认 `LoginGraceTime` 为 120 秒）。不需要交互输入的会话在此期间继续并行连接。
- **输入框**：统一对话框，标题写明服务器和用户（例如“admin@10.0.0.12 的密码”），弹出前切换到该会话的标签，让用户知道是哪个会话。按钮：“登录”“跳过”（这个会话保持未连接，标签里显示“按 Enter 连接”）、“全部跳过”（剩下等待输入的会话都跳过）。选项：“记住密码”（存入系统凭据库）；同一服务器同一用户还有其他会话等待时，显示“其余 n 个会话也使用此密码”（只在本次运行中有效，不保存），勾选后它们不再弹框。
- **输入超时**：用户迟迟没输入导致服务器断开时，输入框不消失，提示“连接已超时，登录时将重新连接”，用户点“登录”时自动重新握手并提交。
- **密码错误**：在同一个输入框里提示“密码错误”并允许重试，次数按服务器限制；不会悄悄跳到下一个会话。
### 4.2 主机密钥变化

主机密钥与已知记录不符时，该会话停在“主机密钥已变化”状态，**不自动接受、不重试**，标签上显示警告标记，内容区说明情况并提供“查看详情”。这与平时连接的规则相同（V0 设计 §5.5：不为了连接成功关闭主机密钥校验）。

### 4.3 连接失败

网络不可达、超时、认证被拒绝等：按 V0 设计的自动重连策略（退避重试，可设置最大次数）处理；认证被拒绝不重试。失败的会话保留标签和历史，内容区显示原因和“重试”。检测到本机网络整体不可用时暂停整个恢复队列，网络恢复后继续。

### 4.4 恢复工作目录

- 本地终端：在上次报告的目录启动（ConPTY 的工作目录参数；WSL 用 `--cd`）。
- SSH 会话：默认不自动 `cd`（`ssh.restore.restoreDirectory` 关闭），只在历史分隔线上显示“上次的目录：/srv/app”，避免在用户的 shell 中自动执行命令。打开该设置后，登录完成并收到第一个提示符（Shell 集成的 OSC 133）后发送一条安全引用的 `cd` 命令；没有 Shell 集成时不发送。

## 5. 终端历史的保存

- **内容**：每个终端最后一屏内容加最多 `terminal.restoreHistoryLines` 行回滚历史，以终端核心的格式保存（保留颜色和属性），不保存原始字节流。
- **上限**：每个终端最多 1000 行（可设置）且最多 512 KiB；全部终端合计最多 256 MiB（`terminal.restoreHistoryBudget`），超出时最久未访问的终端先被截短。
- **位置**：直接保存在 Muxora 状态目录 `sessions-history/<内容 ID>.bin`，不加密（与 Windows Terminal 等终端保存缓冲区内容的做法一致）。关闭 `terminal.restoreHistory` 时删除全部历史文件。
- **时机**：正常退出时写入；运行中每 60 秒对有新输出的终端增量写一次（后台线程），防止崩溃时全部丢失；标签关闭时删除对应文件。
- **显示**：恢复后，历史显示在新连接上方，中间是一条分隔线“以下为新连接 · 2026-10-20 09:15 恢复”（与 Windows Terminal 的恢复标记类似）。历史只读，可以滚动、搜索、复制、进入 Normal 模式浏览。

## 6. 想让远端程序在断线和重启后继续运行

普通重连做不到这一点，只能靠远端的 tmux 或 screen。提供一个会话选项：

- **“在 tmux 中运行”**（会话设置，默认关闭）：连接后执行 `tmux new-session -A -s muxora-<标签 ID 短码>`。断线或重启后重新连接时，自动重新接入同一个 tmux 会话，远端程序和屏幕都还在。远端没有 tmux 时提示并按普通 shell 打开。
- 这是用户明确开启的远端行为，与“不偷偷在用户 shell 中执行命令”的原则一致：执行的命令在会话设置中可见。
- 以后可以加入 iTerm2 那样的 tmux 控制模式集成（tmux 窗口直接映射为 Muxora 的标签和窗格），列为后续项。

## 7. 程序没有正常退出时

布局已经每 700 毫秒合并保存一次；会话描述随布局保存；历史每 60 秒增量保存。崩溃或断电后再次启动，按同样的设置恢复，历史最多缺最后 60 秒的输出。
