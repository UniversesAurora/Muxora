# Qt Quick 呈现与高刷新率

状态：设计要求，实施见 [阶段 10](../roadmap/implementation/phase-10-qt-quick.md)。当前默认预览仍为 Widgets。采用理由见 [ADR 0013](../adr/0013-qt-quick-rendering.md)。

## 1. 外观与交互

[标签栏](tab-strip-design.md)、[表面与阴影](surface-elevation-design.md)、[窗口交互](window-interaction-design.md)、[字体与缩放](ui-design-system.md) 的要求不变。Quick 不另定尺寸、布局、配色、缓动或文字规则。右键不切换活动标签、起拖按下锚点、四边镜像、置顶、多行、收起、悬停展开、滚动位置及渐隐安全区等都从共用状态和纯布局取值。

输入法记忆、键盘焦点、辅助功能、跨窗口内容身份、显隐通知、首次按需创建、原生命中和窗口动画也是等价要求。

## 2. 模型、呈现与线程

- `LayoutModel` 是布局和 ID 的唯一来源，命令和布局事务不依赖绘制后端。输入与动画状态逐步从 QWidget 中分离，两种适配器使用相同结果。
- GUI 线程提交按稳定 ID 索引的有界快照。渲染线程只读快照，在 `updatePaintNode()` 中更新保留节点；没有变化的几何、纹理和文字不重建。
- 每个 `QQuickWindow` 管理自己的 GPU 资源。隐藏、销毁、场景图失效及跨窗口移动按 Qt 生命周期处理，不跨设备复用资源指针。
- 最终路径不使用整窗 CPU 绘图上传纹理，也不把 GPU 结果读回交给 QWidget。

迁移同时重构职责混杂的现有代码，保持外观、交互和数据契约。可复用的布局、手势路由和动画放在只依赖 Qt Core 的内部呈现层，不能让共用逻辑依赖某种窗口或图形后端。平台操作和 GPU 资源留在适配层，控制器返回明确动作，不在内部执行可能销毁宿主的回调。

优先使用当前 SDK 的公共 Qt 能力，并核对引入版本和实际成本。缓存、批次和局部更新通过基准确认；不用多层工厂、无实际使用方的通用接口或复制另一份状态来代替复用。

## 3. 绘制

卡片与标签继续使用 `surfaceGeometry()` 的轮廓。路径转换保留非凸形状与四边接合；无法支持的输入必须报告，不能静默画错。尺寸或轮廓变化时更新几何，平移、透明度和层叠由保留节点处理。

阴影保留原高斯核、预乘 alpha 和接合处取较大值的规则，不能用另一种近似阴影改变外观。迁移可先复用有界冷生成资源，由 GPU 合成；CPU 冷生成、上传和 GPU 合成分别计量。稳定尺寸的动画不生成整卡片中间图。标题渐隐只作用文字，滚动渐隐、图标和动作按钮保持各自遮罩范围。

文字复用字体链、fallback、真实字形边界、基线、DPI 和有界的可见文字数据。首先采用 Qt Quick 的原生文字路径，与当前文字效果核对；不能仅为提高基准更改抗锯齿、字重或字体。

## 4. 帧与资源预算

目标是交互和动画跟随当前屏幕刷新率，不设固定的 60 Hz 更新上限。每帧预算按 `1000 / 刷新率` 毫秒计算，144 Hz 为约 6.94 ms。正常目标场景的帧间隔 p95 不超过一个刷新周期，同时记录超过两个周期的帧数、输入延迟、CPU/GPU 时间和资源峰值。未测量前不承诺具体设备达到目标。

曲线和时长复用现有动画定义，由单调时间推进；中断或反向从当前显示值继续。隐藏时停止请求帧，恢复时重新同步；空闲界面不持续重绘。只提高绘制频率而保留低频的布局或动画更新不算完成。

缓存有字节和复杂度预算。极长标题、巨量标签、连续调整尺寸、DPI 切换及反复开关窗口不能使节点、整形、图片或 GPU 资源无界增长。

## 5. 测量与完成条件

先保存当前 Widgets 同机基线，再比较同一内容、布局、主题、尺寸、字体、DPI 和输入序列。离屏渲染成本、`frameSwapped` 提交间隔和系统实际呈现分别报告，不把它们互称为 FPS。GPUI 对比须有等价场景和测量条件，否则只报告本项目结果。

定向检查覆盖几何、状态、生命周期和性能；外观仍由用户试用调整时不新增截图基线。桌面测量遵循 [测试入口](../development/testing-design.md#3-工具与统一入口)，全量回归仍须另行授权。只有实际完成的步骤才能标为通过。
