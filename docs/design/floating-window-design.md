版本：0.1，讨论稿\
日期：2026-10-11\
状态：V0 行为与接口要求；实际预览实现、构建和桌面验证范围见 [预览说明](../development/window-system-preview.md)。

关联：[工作区设计](workspace-design.md)、[窗口系统 API 与外观](window-system-design.md)、[设置与命令](settings-and-commands-design.md)、[测试要求](../development/testing-design.md)。本稿取代旧稿“标签拖出一律创建完整窗口”的规定。

## 1. 两种窗口，同一套内容能力

默认把标签拖到桌面空白处，得到用户截图中的轻量浮动窗口；“移到新的完整工作窗口”则创建带完整应用外壳的新窗口。轻量表示外壳精简，不限制标签和分割。

| 项目 | 轻量浮动窗口 `Floating` | 完整工作窗口 `Workbench` |
| --- | --- | --- |
| 外壳 | 紧凑标题栏、标题／归属提示、最小化／最大化／关闭按钮。 | 融合菜单与可移动工具条、命令入口、窗口按钮、全局状态栏。 |
| 标签能力 | 多标签、多组自由分割、标签内部 PaneTree。 | 相同能力。 |
| 内容上下栏 | 保留各 Tab／Pane 自己设置的附加栏。 | 相同能力。 |
| 四边区域 | 使用同一布局能力，按需出现；空栏不占空间。 | 相同能力。 |
| 全局菜单、工具条、状态栏 | 不创建整套隐藏控件；命令面板、右键及快捷键仍可用。 | 正常显示。 |
| 归属 | 必须属于一个完整工作窗口所在的窗口族。 | 是一个窗口族的根窗口。 |
| 系统窗口操作 | 可单独移动、缩放、最小化、最大化／恢复和关闭。 | 相同能力。 |

`PeekOverlay` 仍是边栏临时展开层，不是这里的浮动顶层窗口。远程 X11 窗口也不加入 WindowSystem 的窗口族。

## 2. 窗口族和身份

一个 `WindowFamily` 有一个完整根窗口和零个或多个轻量浮窗。应用可以同时存在多个窗口族；同一配置根下，它们共享同一个进程和业务服务。

```text
应用 WindowManager
├── 窗口族 A
│   ├── 完整工作窗口 A
│   ├── 轻量浮窗 A1 → 标签组／标签／窗格
│   └── 轻量浮窗 A2 → 标签组／标签／窗格
└── 窗口族 B
    ├── 完整工作窗口 B
    └── 轻量浮窗 B1 → 标签组／标签／窗格
```

模型使用稳定 `WindowId`、`FamilyId`、`GroupId`、`TabId`、`PaneId`。一个窗口只属于一个族，一个标签只属于一个组；浮窗不能再成为另一浮窗的归属根。由浮窗拖出的新浮窗属于同一族。

类型转换保留 WindowId 和内容 ID。具体 Qt／原生窗框可以在事务内重建，不能让原生句柄变化变成业务实例重建，也不能用父 QWidget 的销毁隐式结束 SSH。一个 `DockSurface` 负责每个窗口的中央树和四边区域；两种外壳共用它，不复制布局引擎。

“归属于根窗口”首先是应用逻辑关系。V0 Windows 采用可独立激活的普通顶层窗口，两种形态均可由系统任务切换器找到，浮窗可单独最小化；最小化根窗口默认不隐藏其浮窗。标题、窗口列表和“返回所属窗口”命令呈现其归属。避免用永久置顶或 native owner 强制模拟关系：Windows 的 owned window 会受所有者层叠、最小化及销毁影响。[Windows 窗口关系](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)

这是初版选定行为，不声称 Visual Studio 所有版本只有一种处理方式；其官方文档也区分浮窗 ownership 策略。[Visual Studio 窗口说明](https://learn.microsoft.com/en-us/visualstudio/ide/customizing-window-layouts-in-visual-studio?view=vs-2022)

## 3. 拖出与类型转换

| 操作 | 提交结果 |
| --- | --- |
| 标签开始拖拽 | 达到阈值即形成 Floating，来源空组立即收起；在无有效目标处释放则保持浮窗，或按设置升级为 Workbench。 |
| 命令“移到新轻量浮窗” | 显式创建 Floating，不受拖出默认设置影响。 |
| 命令“移到新完整工作窗口” | 显式创建 Workbench 及新窗口族。 |
| 浮窗“转换为完整工作窗口” | 原 WindowId 升级，创建新族；其他原族浮窗保持原归属。 |
| 完整窗口“转换为轻量浮窗” | 选择另一完整窗口作为目标根；原窗口及它原有的全部浮窗转入目标族，原族移除。 |
| 浮窗“更改所属工作窗口” | 改 FamilyId，保留窗口内容、几何和分割。 |
| 窗格“移到新窗口” | 先把原 Pane 移入新 Tab，再按显式 kind 创建窗口，保留内容实例。 |

完整窗口降为浮窗时，中央和四边内容仍留在原窗口；原族浮窗保持各自窗口，不能藏起来或丢弃。没有其他完整窗口时，该命令解释缺少目标，并提供先创建完整窗口的入口；不允许生成没有根的窗口族。

类型转换只装卸相应外壳。完整窗口的条带描述及用户布局可以作为有界配置保留，再次升级时恢复，不保留一套不可见的完整工具条控件。调整外壳高度后内容区域、DPI、IME 和 PTY 最终尺寸重新计算，SSH、历史、传输引用及有效 Normal／Visual 状态不变。

## 4. 单标签和整窗拖拽

### 4.1 单标签

两种窗口里的任意单标签均可拖入同族或其他族的窗口，或继续拖出新窗口。移动一个标签不会同时改变源窗口其他标签或浮窗的归属。

目标标签组中心为插入／合并标签，方向目标为创建相邻标签组，窗口边缘目标为四边收纳。标签的 PaneTree 与可选上下栏整体移动；活动实例不重新认证或创建。

### 4.2 轻量浮窗标题栏

拖动轻量浮窗的标题栏空白区域，载荷为这个窗口里的全部标签和布局。窗口按钮、标题栏菜单及交互控件不触发整窗拖拽。移动到没有有效目标的位置，结果只是移动原浮窗，不能再生成一个窗口；双击最大化／恢复和系统 Snap 保持正常。

| 放置位置 | 整窗载荷的处理 |
| --- | --- |
| 目标组中心／标签条插入位置 | 将全部标签按确定顺序合并到目标组；来源外层分组解除，各 Tab 内部 PaneTree 不变。 |
| 目标中央组左／右／上／下 | 将来源布局作为一棵分割子树插入对应方向，保留来源中央组、组内顺序、活动项及可满足的比例。 |
| 目标四边条带或固定边缘组 | 按预览合并为一个边缘标签组；不引入另一套边缘递归分割。 |
| 无有效目标 | 保留原浮窗和全部内容，仅更新位置。 |

整窗载荷包含中央、固定和收纳中的全部标签，不只当前可见标签。扁平合并顺序为中央树按存储的子节点顺序遍历，各组按标签顺序，随后上／右／下／左边缘按区域、组和标签保存顺序；中央之外同一边先固定区后自动隐藏区。该顺序同时用于预览和提交，不受窗口实时 z-order 影响。落点插入处加入整个有序列表，来源活动标签成为目标活动标签，其活动 Pane 保持。

方向投放需要一棵可插入的树。来源已有边缘组时，先将它们按原边方向整理为普通标签组，围绕来源中央树依次加入；没有中央组时从首个边缘组起构造。边缘的自动隐藏／固定位置由落点预览明确转换，不能把来源 DockSurface 嵌进一个标签或悄悄遗漏隐藏内容。普通中央组与内层 PaneTree 保留；比例按目标最小尺寸约束调整。放不下时目标禁用，而不是创建不可见组。

预览标明“合并 N 个标签”或“保留分组并停靠”，并显示将转换的边缘位置。只有整批成功后才销毁源浮窗空壳。已有目标标签保持相对顺序；目标若是轻量浮窗也采用同一规则，移动进去的内容归属目标族。

完整窗口标题栏默认保持系统移动行为，不隐式搬走整个窗口族；其单标签可跨窗拖动。“移动当前窗口的全部标签”命令提供与整窗载荷相同的移动能力，但只操作当前窗口，不携带其所属浮窗。该命令在完整和轻量窗口中均可用。

### 4.3 拖拽事务

拖拽开始记录来源、活动项、几何和结构；达到阈值后立即把标签移入真实轻量窗口，来源空组随即清理，窗口随鼠标移动。内容、窗格 ID 和业务实例不重建。放下只决定最后投放，不能再生成第二个窗口；内容区不是隐式合并目标。具体命中、边栏及取消规则见 [交互修订](window-interaction-design.md)。

提交前检查目标仍存活、ID／版本匹配、内容能力、最小尺寸、模态阻塞及目标配置根。整窗载荷不能投回它自己包含的组或节点；单标签在原组重排则正常允许。V0 不跨进程／不同数据根移动活动视图，外部文件拖拽也不进入此路径。不能通过不可信拖拽 MIME 构造内部内容移动。

即时拖出后先清理来源空组；成功投放后再清理移空浮窗及符合设置的完整空窗口。无目标或投放失败保留当前浮窗，Esc 恢复原布局和位置；旧 parent 销毁不能删除已移动的视图。取消后计时器／异步回调失效，不保留多份终端内容。

拖拽期间来源或目标收到关闭／形态转换请求，先结束当前拖拽，再按正常命令流程处理请求。取消恢复不复活已被用户成功关闭的实例；目标已销毁时回到仍有效的来源位置。布局结构版本与请求 ID 共同防止迟到提交。

Windows 系统标题栏移动循环、输入捕获和停靠预览由一个平台适配协调，不能让 Qt 拖拽循环与系统移动循环同时争抢捕获。若系统移动循环不适合承载全部目标交互，则在允许的标题栏区域实现受控停靠拖拽，并保留原生缩放、Snap、系统菜单和双击行为；真实桌面验证后固定实现。

## 5. 拖拽时唤起被遮挡窗口

**必须支持：拖着标签或整窗载荷时，在有效候选窗口处短暂停留，把被挡住的目标窗口抬到前面，继续选择落点。** 抬到前面只改变可见层次，不意味着已经投放或把键盘输入交给目标终端。

1. 活动拖拽期间，从 WindowManager 的窗口注册表寻找同进程、同数据根、可接收载荷的窗口。命中忽略拖拽预览和正在移动的来源浮窗；来源窗口的其他有效组仍允许普通组内／组间移动。
2. 候选取鼠标下实际可见的合格窗口；移除来源浮窗遮挡后露出的下层窗口也参与。鼠标直接进入当前前方目标即可显示指示，无需先等待；只有把被遮挡候选抬前才使用停留时间。
3. 同一候选停留默认 500 ms 后，执行一次抬前请求。离开、候选变化、Esc、失去捕获、模态阻塞或拖拽结束取消计时；移动容差按逻辑像素计算。唤起后保持当前目标，重新离开才允许再次竞争，防止窗口来回翻转。应用失活、会话锁定或捕获丢失时取消拖拽并清理预览，不在后台继续计时抬前。
4. 使用不激活的层叠调整路径优先露出目标；不设置永久置顶，不调用目标内容的 setFocus，不把悬停写入正常焦点 MRU。更新图形目标和落点预览，拖拽控制器持续持有操作状态。[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)
5. 如果候选完全被另一个目标窗口挡住，或已最小化，提供拖拽期间的“选择目标窗口”列表。列表显示完整／轻量标记、所属族和标题，键盘选择或指针停留到某项可显式唤起该窗口；显式选择允许恢复最小化。仅靠猜测桌面矩形不应循环翻出所有窗口。
6. Windows 拒绝层叠／前台请求时保持拖拽和内容完整，呈现目标入口供用户显式激活，不虚报成功或循环抢前台。不能用模拟用户输入、永久 topmost 或线程输入附着绕过系统前台限制。[SetForegroundWindow 限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)
7. 松开并成功提交后才聚焦目标内容。Esc 取消恢复原结构、来源浮窗原几何和合理焦点；临时抬前的相对层次仅在相关窗口仍存活、期间无其他用户激活时尽力恢复，不重排全桌面，也不强行盖过用户刚切换到的其他软件。

自动悬停不恢复最小化窗口、不切换 Windows 虚拟桌面、不激活其他应用。目标选择器和普通键盘移动命令覆盖自动唤起不适用的场景；不能将这些限制变成遗漏悬停唤起功能的理由。

标题栏原生移动时，最前方的载荷本体不得继续遮住落点反馈。平台适配可以使用不拦截输入的轮廓／半透明预览；真实内容仍只存在一份。标题栏拖动、单标签拖动分别验收，不能以一种成功代替另一种。

## 6. 键盘、焦点和模式切换

以下均为公开命令，可以从菜单、右键、命令面板、可编辑快捷键使用。需要目标时打开可搜索、可键盘操作的选择器；在移动命令开始时捕获来源 ID，选择器取得焦点后来源不改变。

| 命令 | 含义 |
| --- | --- |
| `window.focusNext`／`window.focusPrevious` | `scope: family / all / workbenches`；族内包括根与全部浮窗，all 包括所有两种窗口，workbenches 只切完整根窗口。 |
| `window.select` | 显示窗口选择器；支持按族及两种形态筛选并激活。 |
| `window.focusOwner` | 从浮窗回到所属完整窗口，恢复其上次活动组／标签／窗格。 |
| `window.promote`／`window.demote` | 轻量升级为完整；完整选择目标族后变为轻量。 |
| `window.reassignFamily` | 浮窗改归另一完整窗口。 |
| `workspace.moveTabToNewWindow`、`pane.moveToWindow` | 显式 `kind: floating / workbench`；缺参提供选择，菜单明确写出两种。 |
| `workspace.moveTabToWindow` | 选目标窗口、组与 `placement: center / left / right / up / down / edge`。 |
| `window.moveAllTabs` | 当前窗口全部标签按整窗规则投放；参数或选择器可指定目标和布局方式。 |
| `window.redock` | 浮窗整批停靠回所属根窗口，默认按保留分组方式；目标位置由选择器确定。 |
| `window.drag.selectTarget`／`window.drag.cancel` | 仅在拖拽中使用，唤出目标列表或取消；同一拖拽控制器负责。 |

默认候选：`Ctrl+Alt+PageDown/PageUp` 族内前后切换；加 Shift 为所有应用窗口前后切换；`Ctrl+Alt+Home` 返回所属根。升级、降级及移动先提供命令和自定义绑定，不强占所有常用终端组合。完整根窗口专用循环同样可绑定。系统 Alt+Tab 保持系统行为，不被应用覆盖。

窗口循环按稳定创建顺序进行，关闭后移除；不因切换更新顺序而只能往返两个窗口。普通循环跳过最小化窗口；选择器能找到并显式恢复它们。每个窗口保留最近活动 Group／Tab／Pane；不存在时按可见内容回退，空窗口聚焦空白工作区入口。

切换和抬前必须区分：普通窗口切换激活目标并恢复内容焦点；拖拽悬停只露出投放目标。输入前缀在实际焦点变化时取消，模式和有效选区随同 TerminalId 保持。拖拽中命令只作用于该拖拽，按键不发远端；原生移动循环中的 Esc 也交同一取消事务，不能穿透为终端输入。

上下文增加 `windowKind`、`windowFamilyId`、`hasOwnerWindow`、`windowDragActive` 和 `windowHasTabs`；`windowFamilyId` 是瞬时匹配值，不要求用户在常规快捷键中硬编码 ID。以上键名是当前设计契约，实装前与完整命令目录共同校验。

## 7. 空窗口与关闭

空组在提交后收缩；最后一个标签移走的轻量浮窗自动销毁空壳。完整工作窗口的空壳策略可在图形设置及 JSON 中选择，默认保留，显示新建／打开会话入口。

`window.emptyWorkbenchAction = keep / close` 的“空”指整个窗口族都没有 WorkspaceTab，包括中央、固定区、自动隐藏区和所属浮窗。根窗口自身没有标签但仍有浮窗时必须保留：特别是把最后一个标签拖成轻量浮窗，不能立刻关闭它的归属根。欢迎空白入口是壳的空状态，不作为伪标签阻止真正的空判断。

设为 close 后，只有在本次移动／关闭事务成功且族真正为空时，才请求关闭完整空壳。修改设置本身不批量关闭现有空窗口；后续产生空状态的操作才应用。最后一个族为空时仍经过应用退出与任务协调，不能因 Qt 的 lastWindowClosed 信号提前退出正在传输的进程。

关闭浮窗按钮／Alt+F4：请求关闭该浮窗里的所有内容，宿主按实际业务决定是否需提示；不会关闭所属根或其他浮窗。想保留内容回主窗，使用“停靠回所属窗口”。标题栏拖拽成功后清理源空壳是移动完成，不触发关闭内容提示。

显式关闭完整根窗口：协调关闭整个族，提示范围包含其浮窗里的活动内容。先收集所有关闭许可；任一内容拒绝或用户取消，就保持整个族与业务运行，不先关闭一半。许可通过后再提交关闭；关闭许可不提前断开业务，旧许可通过请求 ID／结构版本失效。转换为完整窗口已脱离原族的窗口不在关闭范围。

全局传输任务的继续、后台运行或退出提示由宿主任务策略统一决定；布局引擎不能因关闭文件标签或一个窗口族直接取消全局任务。浮窗存在时即使根为空，进程也不能退出。

## 8. 设置与恢复

所有以下用户设置必须同时在可搜索图形设置页和 `settings.json` 中出现，有说明、默认值、取值校验、修改状态和恢复默认入口；不能只提供 JSON 隐藏项。

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| `window.tabDragOutsideMode` | `floating` | 另可选 `workbench`，只影响标签向窗口外拖出。 |
| `window.emptyWorkbenchAction` | `keep` | 另可选 `close`，按整个族为空判断。 |
| `window.dragReveal.enabled` | `true` | 拖拽悬停唤起；关闭后显式目标选择仍可用。 |
| `window.dragReveal.delayMs` | `500` | 初始允许 200–2000 ms，拖拽开始时捕获设置，不在操作中途改变计时语义。 |

恢复结构保存 WindowId、kind、FamilyId、根映射、正常几何、最大化状态、每窗 DockSurface、活动项及完整外壳布局。两种形态以同一快照提交，不能一份文件恢复窗口、一份文件恢复归属而产生中间孤儿。运行时 Normal／Visual 延续不等于把选区或模式写到磁盘。

先验证身份与归属，再恢复根窗口及其浮窗，最后选择一个恢复焦点。缺根的有效浮窗先组成恢复族并创建完整根；重复 ID、非法引用和循环归属报告诊断并修复结构，不静默丢弃有效内容。恢复根不自动生成新的 SSH 配置；会话来源仍须重新校验。

旧版只有完整窗口的快照迁移为“一窗口一族”，保留原树；屏幕变化后校正可见坐标。不保存 OS z-order、前台权限、拖拽计时器、临时预览或正在执行的事务。异常退出只恢复最近完整快照，不复现一半拖拽。

## 9. 模块边界与验收

WindowSystem 公开 API 增加 WindowKind、WindowFamily、类型转换、整窗载荷、目标选择和焦点 scope。模型维护归属及事务；DockSurface 负责布局；两种 Chrome 负责壳；DragController 负责载荷与预览；平台适配负责原生移动、层叠、捕获、DPI 与请求结果。宿主仍只负责业务内容、关闭许可、设置注入与持久化。

资源按需创建，浮窗不加载完整命令条控件，不复制设置服务、字体库或历史；共享服务和缓存遵守原有预算。窗口选择器按需列举注册表，悬停最多一个定时候选，结束后清理；不常驻扫描全桌面。

必须验证两种形态、族归属、升降级、单标签／整窗中心及方向投放、边缘内容转换、部分失败回滚、空窗口两种策略、关闭否决、所有键盘入口、被遮挡窗口唤起、系统拒绝、取消与焦点、混合 DPI、屏幕移除、恢复和长期资源。模型/API 用例之外必须有真实 Windows 桌面的标题栏拖拽、Snap、最小化、层叠和输入捕获测试；结果尚未取得，不能由设计文档冒充已通过。
