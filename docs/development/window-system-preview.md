# Muxora 窗口系统首个预览

日期：2026-10-12\
状态：首个交互预览，用于试用并继续改进窗口系统；完整 V0 的业务功能和验收尚未完成。

本阶段交付 Muxora 应用的首个预览。应用通过 WindowSystem 公开 API 组织界面，后续远程业务继续在这套代码中接入。入口为 `src/app/main.cpp`，占位内容由 `src/workspace_host/` 提供，用来试用布局、拖拽、窗口和键盘导航；SSH、SFTP、终端解析、远程桌面与会话管理留在后续阶段。

目前不添加应用 logo；顶部先使用菜单、工具和标题按钮，整体使用紫罗兰色系。窗口模块保留独立 API 与构建边界，复用验证通过测试夹具完成。

## 开发环境

首个预览针对 Windows x64，采用 C++20、Qt 6.12 Widgets 和匹配的 MinGW 工具链。当前 kit 所需的 GCC 15.1 工具链已对齐，原有编译器保留；脚本检查 Qt 编译元数据与实际编译器版本，避免误用不匹配工具。`-QtRoot` 指向具体 kit，例如 `E:/develop/sdk/Qt/6.12.0/mingw_64`。

```powershell
pwsh ./tools/build.ps1 -Configuration Debug -Test -Run
```

脚本通过 `-QtRoot` 或 `QT_ROOT` 绑定 kit，也会发现仓库旁的 SDK 和忽略提交的 `.local/sdk.json`。使用显式路径时，例如：

```powershell
pwsh ./tools/build.ps1 -Configuration Debug -QtRoot E:/develop/sdk/Qt/6.12.0/mingw_64 -Test -Run
```

| 参数 | 作用 |
| --- | --- |
| `-Configuration Debug` / `Release` | 选择构建类型 |
| `-QtRoot <path>` | 指定本机 Qt kit 目录，覆盖自动发现 |
| `-Test` | 构建后运行自动化测试 |
| `-Run` | 构建后启动 Muxora |
| `-Package` | 收集 Muxora 所需运行文件到本地部署目录 |

需要单独试用 Release 部署目录时：

```powershell
pwsh ./tools/build.ps1 -Configuration Release -Test -Package
./out/package/muxora-preview/muxora.exe
```

应用构建目标为 `muxora`。部署目录中的 Qt 运行文件保留其许可证；该目录是本机试用产物，正式分发仍需完成依赖清单与许可证检查。

交付到另一台 Windows x64 电脑试用时，使用 7-Zip 便携包：

```powershell
pwsh ./tools/package-portable.ps1
```

构建机器需要 7-Zip，脚本从 PATH 查找 `7z` 或 `7zz`，也可通过 `-SevenZip` 指定程序路径。Qt 的选择仍使用 `-QtRoot` 或原有自动发现方式。每次打包使用新的部署目录，避免旧插件、私人布局和重复许可证目录混入包内；`build.ps1 -PackageDirectory <path>` 可指定部署位置。

压缩包和 SHA-256 校验文件位于 `out/dist/`。解压整个 `Muxora` 文件夹后双击 `muxora.exe`；运行电脑不需要 Qt、编译器或 PowerShell。包内的空 `data/` 目录启用便携状态，布局保存在 `data/window-layout.json`，可随文件夹一起移动。显式 `--state-dir` 优先；没有相邻 `data/` 的普通构建继续使用系统用户状态目录。

脚本检查 7-Zip 压缩包完整性，再解压到含空格和中文的路径。在子进程中移除 SDK、编译器和 Qt 插件路径覆盖，分别检查首次启动、本地布局保存与重启恢复；验证记录为 `out/test-results/portable-package.json`。解压检查使用另一个目录，不把检查生成的布局放入交付包。

完整验证入口：

```powershell
pwsh ./tools/verify.ps1
```

该脚本运行 Debug / Release 自动化测试，单独配置窗口模块并运行其测试，安装模块后构建外部宿主夹具，最后在移除 SDK 和编译器目录的 PATH 中检查部署应用启动。入口存在与验证通过分别记录，下文列出实际取得的结果。

完整窗口系统设计见 [窗口模块](../design/window-system-design.md)、[工作区](../design/workspace-design.md) 和 [浮动窗口](../design/floating-window-design.md)。本次以能交互的基础版本为起点，继续根据试用结果修订。

## 当前可试用的功能

| 范围 | 当前实现 |
| --- | --- |
| 模块 API | `WindowManager` 提供窗口、内容接入、布局与命令接口；`LayoutModel` 独立维护布局及不变量 |
| 标签与分割 | 中央区域可拆成多个标签组；每个标签内部可继续拆分窗格，分别导航与调整大小 |
| 四边停靠 | 内容可移到上下左右的自动隐藏边栏，点击展开，也可固定占用空间 |
| 两种窗口 | 默认拖出轻量浮窗，支持升级为完整窗口、降级回轻量窗口与逻辑窗口族 |
| 跨窗口移动 | 标签达到拖动阈值立即形成随鼠标移动的真实浮窗，空组立即消失；按指示或标签条投放，内容区不误合并 |
| 命令与键盘 | 命令面板、窗口选择、标签组与窗格导航；图形编辑器可为已注册公开命令绑定或修改快捷键 |
| 图形行为设置 | 在可移动设置标签中搜索、分类和修改拖出形态、空窗口策略、目标唤起和悬停延迟 |
| 保存恢复 | 带版本的严格 JSON 布局，宿主通过 `QSaveFile` 原子写入；行为设置随布局保存 |

本轮补充逐标签固定／取消固定、原分区与尺寸恢复、四边收纳／固定双目标、紧凑窗格及随焦点切换的共用上下栏。标签条提供细滚动条、滚轮滚动、拖拽边缘自动滚动和完整列表；右键可关闭该组左侧、右侧、其他或全部标签。

工具条可显隐、拖动、压缩、显示溢出和增删按钮；每行只保留一个弹性条带，默认是标题，吸收余量并将右侧条带推到右边。新设或移入弹性条带会把该行原弹性条带改为普通条带。拖走后一条时，前条按新邻居恢复自然宽度或接收腾出的空间；弹性右侧的普通条带可改变左边界，后方条带或窗口边界保持不动。窗口转换保留条带布局及按钮选择。轻量窗口最后一个标签拖出后，Esc 也会恢复原窗口缓存的工具条配置和内容实例。完整交互规则见 [修订设计](../design/window-interaction-design.md)。

普通工具条选项增加“重置尺寸”，恢复自然宽度；弹性左侧保持头部位置，右侧保持尾部位置，先调整弹性空间，再按最小宽度让邻条腾出空间。其他条带的请求宽度和顺序保持不变。命令面板中的“重置工具条大小…”提供键盘选择列表，标题和窗口控制条也可从这里重置。窗口缩放时，弹性右侧的条带相对右边缘定位，最后一条与边框的距离保持不变；放大后恢复请求宽度。

完整和轻量窗口的标题均在自己的条带内居中，过长时显示省略号，提示与辅助名称保留完整文字。标题内容区至少 96 个逻辑像素，解锁把手的宽度另计。

三个窗口按钮组成独立的窗口控制工具条，可移动和拉伸，不能压缩到按钮自然宽度以下，不允许弹性且没有选项按钮。按钮靠顶部排列，最大化／还原同步更新图标与提示。轻量窗口只创建标题和窗口控制两条；两种窗口共用锁定命令，升降级仍保留完整窗口的菜单与工作区定制。

临时展开显示真实标签内容与可用附加栏；全部固定按钮移到侧栏标签末尾，并以内部透明的叠层图标区分单个操作。侧栏标签可拖动调整顺序，按四边条带的横／纵位置插入，支持跨窗口和整窗载荷；排序命令可使用 `Ctrl+Shift+PgUp` / `Ctrl+Shift+PgDown`。边栏相邻角由底栏优先占底角、左右栏优先占顶角；仅一条邻边显示时由它占角。设置页以类别标题排列全部设置，分类树支持折叠、点击定位和随滚动同步，当前位置为粗体及独立竖线，箭头悬停只变深色且与竖线留有间距。箭头、数字按钮和勾选框统一采用主题绘制；下拉菜单重复点击关闭。

标题条取消了选项按钮及其宽度占位，普通工具条继续支持定制。菜单每次事件保持禁止回放，避免关闭后遗留左键状态或下一次关闭时重新打开。选项按钮区分鼠标与键盘产生的焦点提示；鼠标打开菜单不留下焦点外框，关闭后清除遗留悬停，不需要额外点击或移动。真实进入和离开继续更新悬停，键盘导航仍显示焦点。

窗口设置与快捷键编辑分别可从菜单或命令面板打开。快捷键修改立即生效，当前只保留在本次运行内，重启后恢复默认绑定。

先拖动一个标签，观察松手前已经出现浮窗且来源空组消失；经过内容区不合并，放到中心或方向指示才投放。放到标签条时按释放位置插入，Esc 可恢复原布局。再试用四边双目标、逐标签固定、标题栏整窗回并和工具条压缩。已注册命令的菜单和键盘入口使用同一执行接口。

布局状态默认位于 `QStandardPaths::StateLocation` 下的 `window-preview/window-layout.json`。程序自动合并短时间内的布局变化后保存；占位编辑器中的文字不会保存。通过命令面板选择“恢复初始工作区布局”，或启动 `muxora.exe --fresh`，可从初始布局重新试用；`--state-dir <path>` 可指定独立状态目录。

## 已取得的验证记录

本轮代码通过 `tools/verify.ps1` 完整检查及 `tools/package-portable.ps1` 便携交付检查，取得以下结果：

窗口模块十组包含 224 个实际测试行，不含各组初始化和清理；Debug、Release 与独立构建均无失败、跳过或黑名单用例。与上一轮相比新增 30 个实际测试行，覆盖工具条重置的左右边界、空间不足、请求宽度恢复、隐藏条带、公开 API 与键盘选择、标题居中及省略，以及深色系统调色板下的标签条空白区域。窄窗口中前条已被压缩的重置回归会检查头部不移动，不能为恢复目标宽度而让前条自动伸长。

应用另有四个状态目录用例：相邻目录启用、普通默认路径、显式路径优先和同名文件排除。Debug / Release 分别通过十一组、228 个实际测试行；窗口模块独立构建为十组、224 行。

拖拽测试在 Windows 桌面上向 Qt 控件注入输入事件，同时检查 Windows 原生命中和独立进程的透明、非透明遮挡窗口。它验证事件排队、跨窗口投放和遮挡回归，不等同于全部系统输入、混合 DPI 或 Snap 行为的实机验收。

菜单悬停回归使用 Windows 原生输入，覆盖独立工具条空白、完整窗口标题及正文、其他按钮、Esc、命令项和定制子菜单七条关闭路径。用例检查按钮状态、鼠标捕获和实际悬停颜色，关闭后均能恢复。原有菜单切换用例改用同一原生输入路径，分类绘制用例等待真实移动事件后取图；这两项夹具修正经独立核查，原有状态、颜色及像素范围断言均保留。

此前补充了四条鼠标关闭路径的完整按钮截图比较，菜单显示次数必须为一，不能以瞬间关闭后再次打开冒充通过；另用原生 Tab／Space／Esc 检查键盘焦点提示。窗口控制用例检查两种形态中的按钮尺寸、位置、关闭许可，以及第二行最大化按钮的 Windows 原生命中。

标题绘制参考使用独立 `QLabel`，与实际窗口截图同样绘制到 `QPixmap`，保留逐像素相等及未省略参考不相等的断言。直接绘制到 ARGB 图像会采用不同的 Windows 字体抗锯齿；修正前独立核对了字形范围、背景及实色像素数量。菜单切换用例在实际显示事件后计时，等待排队的关闭输入完成，保留原有 30 毫秒间隔、300 毫秒 watchdog 和全部状态断言，并增加菜单只显示一次的检查。

关闭确认期间增加标签、窗格或族内窗口，递归关闭请求，无效标签命令参数，以及新宿主和现有宿主的窗口标题恢复都有对应回归用例；通过后保留这些用例。部署启动记录与 `build-info.json` 记录同一个可执行文件的 SHA-256，结果只适用于此次本机部署目录。

Qt Test 的逐用例日志保存在相应构建目录的 `modules/window-system/tests/*-results.txt`；独立构建为 `tests/*-results.txt`。本轮还检查了设置内容区的实际绘制颜色，防止系统深色调色板使浅色主题出现不可读的深色区域。部署版默认界面、设置和快捷键页面均有启动截图检查，图片位于 `out/screenshots/`。

历史截图为 `polish-workspace.png`、`polish-settings.png`、`sidebar-order-settings.png`、`toolbar-sizing-workspace.png` 与 `toolbar-sizing-floating.png`。本轮检查 `toolbar-reset-workspace.png` 和 `toolbar-reset-floating.png`，标题在各自条带居中，窗口控制按钮完整且靠顶部排列。截图发现轻量窗口标签条空白区受系统深色调色板影响；先以深色调色板复现两种窗口的绘制失败，再为滚动区域指定主题背景，原像素断言保留。

前轮截图检查发现分类箭头后方仍有 Qt 选中行底色；补充基线像素检查复现后，先清除分支底色再绘制箭头，父类别和叶子类别均保留纯色背景。矢量控件按最近主题根读取颜色，避免 Qt 样式表初始化后改写调色板导致对勾颜色失效；数字按钮外框按逻辑像素对齐。绘制回归保留原白色勾、悬停外框、箭头及无内部竖线断言，修复实现后全部通过。

启动参数 `--command <id>` 可执行已注册命令，例如 `muxora.exe --command window.settings` 直接打开设置标签；同一命令目录仍用于菜单、命令面板和键盘。

测试采用 Qt Test / CTest。完整质量要求仍按 [测试规范](testing-design.md) 执行，失败时修复实现并保留回归用例。
