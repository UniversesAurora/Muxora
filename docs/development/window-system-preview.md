# Muxora 窗口系统首个预览

日期：2026-10-15\
状态：首个交互预览，用于试用并继续改进窗口系统；完整 V0 的业务功能和验收尚未完成。

本阶段交付 Muxora 应用的首个预览。应用通过 WindowSystem 公开 API 组织界面，后续远程业务继续在这套代码中接入。入口为 `src/app/main.cpp`，占位内容由 `src/workspace_host/` 提供，用来试用布局、拖拽、窗口和键盘导航；SSH、SFTP、终端解析、远程桌面与会话管理留在后续阶段。

目前不添加应用 logo；顶部先使用菜单、工具和标题按钮，整体使用紫罗兰色系。窗口模块保留独立 API 与构建边界，复用验证通过测试夹具完成。

## 开发环境

首个预览针对 Windows x64，采用 C++20、Qt 6.12 Widgets 和匹配的 MinGW 工具链。当前 kit 所需的 GCC 15.1 工具链已对齐，原有编译器保留；脚本检查 Qt 编译元数据与实际编译器版本，避免误用不匹配工具。`-QtRoot` 指向具体 kit，例如 `E:/develop/sdk/Qt/6.12.0/mingw_64`。

```powershell
pwsh ./tools/build.ps1 -Configuration Debug -Test -Run
```

脚本通过 `-QtRoot` 或 `QT_ROOT` 绑定 kit，也会发现仓库旁的 SDK 和忽略提交的 `.local/sdk.json`。使用显式路径时，例如：

```powershell
pwsh ./tools/build.ps1 -Configuration Debug -QtRoot E:/develop/sdk/Qt/6.12.0/mingw_64 -Test -Run
```

| 参数 | 作用 |
| --- | --- |
| `-Configuration Debug` / `Release` | 选择构建类型 |
| `-QtRoot <path>` | 指定本机 Qt kit 目录，覆盖自动发现 |
| `-Test` | 构建后运行自动化测试 |
| `-Run` | 构建后启动 Muxora |
| `-Package` | 收集 Muxora 所需运行文件到本地部署目录 |

需要单独试用 Release 部署目录时：

```powershell
pwsh ./tools/build.ps1 -Configuration Release -Test -Package
./out/package/muxora-preview/muxora.exe
```

应用构建目标为 `muxora`。部署目录中的 Qt 运行文件保留其许可证；该目录是本机试用产物，正式分发仍需完成依赖清单与许可证检查。

日常 Release 固定覆盖 `out/package/muxora-preview/`。替换前清除旧程序、运行库、Qt 插件和许可证目录，保留相邻 `data/` 与未知用户文件；如果该目录的程序仍在运行，脚本停止替换并说明占用。Debug、Release、独立模块和外部宿主分别复用固定构建缓存，不按每轮创建新部署目录。

交付到另一台 Windows x64 电脑试用时，使用 7-Zip 便携包：

```powershell
pwsh ./tools/package-portable.ps1
```

上轮按用户要求制作了固定 7Z。本轮先更新常规 Release 部署，不主动重打便携包；已有 7Z 不代表本轮程序。需要交付便携包时，脚本从 PATH 查找 `7z` 或 `7zz`，也可通过 `-SevenZip` 指定程序路径。Qt 的选择仍使用 `-QtRoot` 或原有自动发现方式。打包先更新固定 Release 部署，再按 `deployment-files.json` 复制运行文件到 `out/package/portable-input/`，不带入部署目录中的私人布局或未知文件。

压缩包固定为 `out/dist/Muxora-preview-windows-x64.7z`，SHA-256 校验文件使用相同文件名加 `.sha256`，再次生成时覆盖旧文件。解压整个 `Muxora` 文件夹后双击 `muxora.exe`；运行电脑不需要 Qt、编译器或 PowerShell。包内的空 `data/` 目录启用便携状态，布局保存在 `data/window-layout.json`，可随文件夹一起移动。显式 `--state-dir` 优先；没有相邻 `data/` 的普通构建继续使用系统用户状态目录。

脚本检查 7-Zip 压缩包完整性，再解压到 `out/portable-checks/current/便携包 解压检查/`。在子进程中移除 SDK、编译器和 Qt 插件路径覆盖，分别检查首次启动、本地布局保存与重启恢复；验证记录为 `out/test-results/portable-package.json`。上轮上述检查全部通过，暂存与解压检查目录已清理，检查生成的布局不在交付包中；本轮未执行便携包检查。

完整验证入口：

```powershell
pwsh ./tools/verify.ps1
```

该脚本运行 Debug / Release 自动化测试，单独配置窗口模块并运行其测试，安装模块后构建外部宿主夹具，最后移除 SDK 和编译器路径，检查实际部署程序的启动、退出、重启、显隐、全屏、禅模式及底部工具条恢复。入口存在与验证通过分别记录，下文列出实际取得的结果。

完整窗口系统设计见 [窗口模块](../design/window-system-design.md)、[工作区](../design/workspace-design.md) 和 [浮动窗口](../design/floating-window-design.md)。本次以能交互的基础版本为起点，继续根据试用结果修订。

## 当前可试用的功能

| 范围 | 当前实现 |
| --- | --- |
| 模块 API | `WindowManager` 提供窗口、内容接入、布局与命令接口；`LayoutModel` 独立维护布局及不变量 |
| 标签与分割 | 中央区域可拆成多个标签组；每个标签内部可继续拆分窗格，分别导航与调整大小 |
| 四边停靠 | 内容可移到上下左右的自动隐藏边栏，点击展开，也可固定占用空间 |
| 两种窗口 | 默认拖出轻量浮窗，支持升级为完整窗口、降级回轻量窗口与逻辑窗口族 |
| 跨窗口移动 | 原条带内只拖动标签预览、保留内容；首次离开即形成真实浮窗、收起空组；按指示或条带投放，内容区不误合并 |
| 工具区 | 顶部／底部共用工具条，均支持多行、跨区拖动、末行投放预览和空行自动收起 |
| 显隐与全屏 | 四栏独立显隐；窗口、标签组、窗格全屏共用原偏好，禅模式临时隐藏所有栏 |
| 命令与键盘 | 命令面板、窗口选择、标签组与窗格导航；图形编辑器可为已注册公开命令绑定或修改快捷键 |
| 图形行为设置 | 在可移动设置标签中搜索、分类和修改拖出形态、空窗口策略、目标唤起、悬停延迟、四栏显隐和当前显示范围 |
| 保存恢复 | 严格 JSON 布局由宿主通过 `QSaveFile` 原子写入；行为设置、正常几何／最大化状态、顶部／底部工具条、四栏偏好及全屏／禅模式随布局保存 |

此前已经完成以下交互：

1. 工具条“弹性空间”移到选项菜单顶层，紧接“重置尺寸”；“添加或移除按钮”子菜单保留内容项。标题行的强制弹性限制继续生效。
2. 标签条的四像素细滚动条叠加在标签底边，显示或隐藏时保持标签与内容的边界，不另占一行。
3. 普通和固定组的标签列表下拉为宽 12、与标签等高的窄矩形条；固定组的两个取消固定按钮仍为 20×20。主题重应用、字体变化和禁用状态保持这些尺寸。
4. 临时展开标题行默认高 20，固定和关闭按钮为 18×18；增大字体时标题随字体度量扩展；四边收纳条厚 22，末尾全部固定按钮为 22×22。图标均为 14×14；这些尺寸使用 Qt 逻辑像素。
5. 增加标签和窗格移到相邻组、已有窗口及窗格前后标签的命令，以及当前标签内的方向交换。空间导航包括中央组与固定组，按实际位置和同一行列优先选择；前后和方向操作在各自范围内循环。移动保留内容、Pane ID 和附加栏，最小化目标窗口会恢复显示。
6. 拖到标签条时，同一个浮窗临时收起全局标题和窗口按钮，保留标签与真实内容；拖到四边收纳条时采用对应方向的紧凑标签与面板。目标条带让出插入空位并绘制标签色块，模型不增加占位标签。收纳条提供有界滚动，靠两端停留 200 毫秒后自动滚动，随后每 35 毫秒更新落点；离开或结束拖动恢复常规呈现，取消时恢复原布局。

本轮补充了以下行为：

1. 标签离条拆出时尽量保持原条带的滚动位置。拖到两端自动滚动后，即使移开且没有投放，滚动位置也保留；拖动中可用滚轮滚动鼠标下的标签条或四边收纳条。
2. 每个收纳标签独立记住临时展开大小。拖动面板靠内容区一侧的细边可调整宽度或高度；右键或命令面板提供“设置临时展开大小…”和重置入口。窗口较小时只约束实际显示，不改写保存的请求值。固定后的分区尺寸与此独立。
3. 完整窗口和浮窗分别保存工具条布局，窗口升降级也保留各自缓存。当前窗口保持自己的排列；新窗口采用本类型最近完成的工具条编辑。旧窗口的保存、缩放和退出不会覆盖较新的默认配置；在旧窗口完成新编辑时，只合并这次改变的属性或排列。
4. 中央组之间及固定侧栏分区与中央区域之间使用 2 个逻辑像素的分隔，内部窗格使用 1 像素；边界仍可用鼠标及键盘调整。
5. 非最大化时，最大化按钮的实际可见区域优先于顶部缩放边缘命中。浮窗反复进入标签预览再离开时保留同一个原生窗口，恢复窗口样式和完整轮廓，避免系统主题绘制的 Basic 三控件叠到自绘工具条上。Windows 11 的系统 Snap 弹窗已在本机实际悬停验证；低性能设备逐帧效果仍待试用。

主菜单采用“文件、视图、布局、窗口、工具、帮助”。文件菜单包含新建、保存工作区布局、关闭标签、关闭窗口与退出；工具菜单只保留统一设置和键盘快捷方式入口。标签组、窗格、移动、导航和窗口形态按操作对象分成二级菜单，工具条大小与定制保留在相应右键／选项菜单，不把每个设置项重复列进主菜单。命令面板与可绑定快捷键的命令仍完整保留。

“文件 → 退出”默认使用 `Ctrl+Q`，保存整个工作区后统一申请关闭许可，覆盖全部完整窗口族及轻量窗口。保存失败时保留窗口并提示；许可拒绝或回调改变布局时不部分关闭。关闭单个窗口仍通过“文件 → 关闭窗口”及原生窗口按钮完成。

边缘投放指示保持在本侧边缘；标签条横跨中部时，指示只沿边避让，不横推到内容中央。目标窗口移动、调整大小、最大化／恢复以及 DPI 通知会使指示失效并合并刷新，即使鼠标静止、悬停唤起关闭也能更新。四边收纳条仅在实际溢出时显示细滚动条，刚好放下、删掉多余标签或取消插入空位后重新隐藏。

菜单“视图 → 显示 → 显示标签栏”或 `Ctrl+Alt+T` 可切换当前窗口中央标签组的标签栏，其他窗口不受影响。侧边收纳条、固定面板标签栏和临时展开标题继续显示。隐藏的中央栏不保留占位；内容与键盘导航继续可用。新建中央组继承本窗口的显示状态，重启后恢复。

菜单“视图 → 显示 → 显示侧边栏”、命令面板或 `Ctrl+Alt+B` 单独切换本窗口四边收纳条。隐藏时收起当前临时面板，固定分区继续显示；明确通过命令激活收纳标签仍可临时展开。中央标签栏显隐与此独立，两个状态分别保存。没有固定历史的收纳标签首次固定时位于该侧最靠外的分区，与直接固定投放一致；已有历史的标签仍恢复原位置。

工具栏与全局状态栏也有独立开关。工具栏开关同时控制顶部和底部工具区；全屏不改变这些开关。三种全屏范围均铺满当前显示器，分别呈现整个工作区、当前标签组或当前窗格，内容 ID 和控件保持。退出后恢复正常矩形、最大化状态及原分割尺寸；范围内目标消失时退出全屏，选择范围外内容时切换为窗口全屏。

禅模式只在全屏时可开启，临时隐藏全部栏，包括固定组标题和内容上下附加栏。菜单及设置的四项有效开关均显示关闭，原偏好继续保存。显示任一栏会退出禅模式，恢复其他偏好并应用这次显示操作；关闭禅模式或退出全屏同样恢复原偏好。

顶部和底部工具区支持多行，底部在下侧收纳条之下、全局状态栏之上，行从状态栏一侧向上排列。解锁后可跨区拖动；到达末行时，在靠工作区的一侧出现一行临时空白投放区。移走一行最后的工具条后该行立即收起。普通行基准高 28 个逻辑像素，随字体和内容最小高度扩展；窗口控制保留 32 像素高度。保存的空逻辑行不创建隐藏控件。

“视图 → 工具条 → 移动工具条…”及命令面板提供键盘选择工具条、顶部／底部及目标行的路径。宿主可调用 `moveToolbar(window, stripId, ToolbarArea, row, index)`；移动保留工具条内容、按钮选择和尺寸策略。

窗格上下附加栏分别支持共享和逐窗格显示，默认为共享。宿主通过 `TabOptions.topBarSharing` / `bottomBarSharing` 或 setter 设置；模式切换保持原栏、内容和焦点，提取窗格时策略随描述保留。显式 Tab 栏仍只在整个标签外围显示一次。标签图标采用紧凑排布；溢出悬停时，标签底边的四像素细滚动条可拖动，没有前后按钮，滚轮不切换标签。

窗口移动、缩放和最大化状态变化合并通知保存；最小化保留正常几何。恢复使用所有屏幕的逻辑可用区域，越界或原屏幕消失时调整，保留仍有效的负坐标和跨屏位置。关闭最后一个窗口前同步保存当前快照，避免立即退出错过延迟保存。

此前已实现逐标签固定／取消固定、原分区与尺寸恢复、四边收纳／固定双目标、紧凑窗格及随焦点切换的共用上下栏。标签条提供细滚动条、滚轮滚动、拖拽边缘自动滚动和完整列表；右键可关闭该组左侧、右侧、其他或全部标签。

工具条及拖动预览显式使用当前主题背景，系统深色调色板不再从截图透明区域透出。拖动前、首次浮动显示及后续鼠标移动采用同一颜色。

临时侧栏关闭按钮关闭实际标签，宿主拒绝关闭时保留面板和内容。收纳标签右键使用现有标签菜单，菜单 Esc 只关闭菜单；标签完整列表悬停使用主题选择背景和文字颜色，运行中切换主题也更新。

工具条可显隐、拖动、压缩、显示溢出和增删按钮；每行只保留一个弹性条带，吸收余量并将右侧条带推到右边。标题必须保持弹性，移入标题行的弹性条自动改为普通条；该行其他条带不能设置弹性。没有标题或其他强制弹性条的行仍允许切换弹性归属。拖走后一条时，前条按新邻居恢复自然宽度或接收腾出的空间；弹性右侧的普通条带可改变左边界，后方条带或窗口边界保持不动。窗口转换保留两种形态各自的条带布局及按钮选择。轻量窗口最后一个标签拖出后，Esc 也会恢复当前及另一种形态缓存的工具条配置和内容实例。完整交互规则见 [修订设计](../design/window-interaction-design.md)。

旧布局即使把标题保存成普通宽度，也会按宿主约束恢复为弹性；加载过程不直接改写用户文件，后续正常保存使用修正后的状态。菜单条重置能回收标题空间，保持右侧条带位置。命令面板“切换工具条弹性空间…”列出可编辑条带，标题行和窗口控制不进入候选。

普通工具条选项增加“重置尺寸”，恢复自然宽度；弹性左侧保持头部位置，右侧保持尾部位置，先调整弹性空间，再按最小宽度让邻条腾出空间。其他条带的请求宽度和顺序保持不变。命令面板中的“重置工具条大小…”提供键盘选择列表，标题和窗口控制条也可从这里重置。窗口缩放时，弹性右侧的条带相对右边缘定位，最后一条与边框的距离保持不变；放大后恢复请求宽度。

完整和轻量窗口的标题均在自己的条带内居中，过长时显示省略号，提示与辅助名称保留完整文字。标题内容区至少 96 个逻辑像素，解锁把手的宽度另计。

三个窗口按钮组成独立的窗口控制工具条，可移动和拉伸，不能压缩到按钮自然宽度以下，不允许弹性且没有选项按钮。按钮靠顶部排列，最大化／还原同步更新图标与提示。轻量窗口在标题同行左侧增加局部菜单，使用本浮窗的标签与窗格上下文，不提供退出程序、布局重置等全局入口；不另建工作区工具条或全局状态栏。独立菜单条带保留完整窗口的菜单位置与定制，升降级和拖拽取消均恢复原缓存。

Windows 完整和轻量窗口在首次显示前准备原生帧，保留原生窗口样式并允许 DWM 过渡。拖出的窗口先放到鼠标位置再显示，移除原有透明度淡入；最大化可见边框与完整内容区对齐工作区。正常矩形由模块单独记录，避免 Qt 用最大化边框扣减正常尺寸；最小化、保存恢复和拖拽取消使用同一矩形。原生调用和状态测试已通过，创建／关闭等动画的实际运动效果仍需桌面试用确认。

临时展开显示真实标签内容与可用附加栏；全部固定按钮移到侧栏标签末尾，并以内部透明的叠层图标区分单个操作。侧栏标签可拖动调整顺序，按四边条带的横／纵位置插入，支持跨窗口和整窗载荷；排序命令可使用 `Ctrl+Shift+PgUp` / `Ctrl+Shift+PgDown`。边栏相邻角由底栏优先占底角、左右栏优先占顶角；仅一条邻边显示时由它占角。设置页以类别标题排列全部设置，分类树支持折叠、点击定位和随滚动同步，当前位置为粗体及独立竖线，箭头悬停只变深色且与竖线留有间距。箭头、数字按钮和勾选框统一采用主题绘制；下拉菜单重复点击关闭。

标题条取消了选项按钮及其宽度占位，普通工具条继续支持定制。菜单每次事件保持禁止回放，避免关闭后遗留左键状态或下一次关闭时重新打开。选项按钮区分鼠标与键盘产生的焦点提示；鼠标打开菜单不留下焦点外框，关闭后清除遗留悬停，不需要额外点击或移动。真实进入和离开继续更新悬停，键盘导航仍显示焦点。

窗口设置与快捷键编辑分别可从菜单或命令面板打开。快捷键修改立即生效，当前只保留在本次运行内，重启后恢复默认绑定。

问题分析中已观察到完整窗口首次普通状态、最大化状态、恢复后普通状态以及轻量浮窗的系统 Snap 弹窗；两种窗口的 Alt+F4 关闭正常。显示的是系统弹窗，没有自行绘制布局菜单。这些观察用于确认原因，不作为自动化测试的判据。Alt+Space 被本机 Raycast 全局快捷键截获，不能将它记为桌面菜单验收通过；菜单的命令与生命周期由程序另行验证。

上一阶段条内预览的销毁回调回归发现重复删除：宿主关闭源标签时，清理流程再次删除正在销毁的预览。现先清空观察成员再删除对象，并保留关闭源标签、拆出通知销毁宿主及目标菜单中关闭／销毁的四行回归；修复后通过。调用栈为 `out/diagnostics/strip-lifecycle-crash.log`，修复记录为 `out/test-results/strip-lifecycle-fixed.txt`。

上一阶段的独立 Win32 夹具证明：带完整原生标题样式的窗口设置 region 后，即使策略写入成功，也会关闭 DWM 非客户区绘制。本轮发现正常窗口恢复时，系统主题还可能重新设置 region 并画出 Basic 三控件。现在紧凑预览移除原生标题样式，保留缩放与系统控制能力；正常窗口恢复完整样式并清除 native region。独立夹具保留原来的限制检查，另验证从正常样式切换到无标题样式的两种调用顺序：精确 region 在显示、重算和消息处理后保持，实际 DWM 状态为启用。

实际 Qt 窗口回归检查精确原生轮廓及缺口命中，三控件位于中间、第二行或底部时各覆盖投放与取消。正常恢复后的九处屏幕像素须精确等于 Qt 客户区参考，普通内容另须等于指定 RGB；捕获、句柄、内容实例、最大化和恢复几何断言均保留，没有增加色差容差。低性能设备逐帧视觉仍待试用。

临时面板尺寸回归还发现，宿主在内容 resize 回调中销毁管理器会打断 Qt 正在进行的布局。此时窗口和内容延期释放，让当前布局调用结束；回归检查延期删除前的排队输入安全停止，并确认窗口与内容随后释放。普通销毁路径继续立即释放。失败调用栈保留在 `out/diagnostics/current-peek-crash.log`。

本轮旧夹具的修订经过独立审阅：窗格分隔从 4 改为需求明确的 1 像素，同时增加真实外层间隔和拖动尺寸检查；三条形态切换用例改为严格检查两份独立配置及原内容身份；最大化命中在排队布局完成后再采样原生坐标，保留精确命中与像素断言。滚动条键盘方向由独立 Qt 滚动条核验，再同步派发按键并检查计时器运行前后的精确位置，避免键盘模拟延迟提前消耗待恢复状态。临时分区尺寸夹具通过取消固定再固定使内部模型尺寸应用到控件；原尺寸、滚动和身份断言未放宽。

补充 200% 原生检查发现两项旧夹具错误：本机叠加系统缩放后 DPR 为 4，逻辑工作区高 516；像素夹具从 y=140 放置高 520 的窗口，底部采样已经越出屏幕。经独立审阅，只调整夹具位置和大小，并增加完整可见前置断言，所有顶部／底部采样及精确像素检查保留。另一项最大化尺寸原预期为 680×4=2720，超过工作区实际高 2064；现在由独立 `GetMonitorInfoW` 取工作区与公开最大尺寸的较小值，并新增 `ptMaxSize` 精确比较，原四项拖动限制和正常几何恢复断言全部保留。[最大化与拖动尺寸定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-minmaxinfo)、[显示器工作区定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfo)。失败证据保留在 `out/diagnostics/scale-2-native-before-fixture-fix.txt`。

逐点诊断还显示，DWM 创建过渡会短暂混合前后画面，像素条件并非单调；Qt 的 `QTRY` 多次立即读取同一条件，可能在首次匹配后再次读到过渡帧，产生误导性的超时提示。经独立审阅，改为每 50 毫秒采样原位置，连续三次全部精确匹配才判定稳定，任一点失败就清零。预期只生成一次，原 5 秒超时不变，原生消息后的即时像素、轮廓、捕获和身份断言全部保留。诊断记录为 `out/diagnostics/scale-2-top-pixel-misses.txt`，比原先一次匹配要求更严格。

此前工具条选择器关闭回归曾失败：窗口已从管理器移除但 Qt 控件尚未销毁，操作被当成普通取消。现在同时检查管理器生命周期和窗口归属；原断言通过。失败日志为 `out/test-results/view-commands-close-baseline.txt`。

禅模式部署检查另发现隐藏栏时 Qt 自动转移焦点，导致活动组变成固定侧栏。两个组件用例复现后，显示投影期间暂停该窗口的临时焦点更新，再将隐藏控件的输入焦点交还原活动内容；原模型和身份断言保持。失败证据为 `application-view-failure.json` 和 `zen-focus-baseline.txt`，修复后的组件记录为 `zen-focus-fixed.txt`。

跨窗口复核还发现非活动窗口的隐藏栏留下旧焦点记忆。现在按本窗口的焦点记忆恢复原内容；回归同时断言另一窗口的焦点不被抢走、返回后聚焦原编辑器且模型保持。前后记录为 `zen-cross-window-focus-baseline.txt` 和 `zen-cross-window-focus-fixed.txt`。

上一阶段两项旧夹具按需求修订并独立审阅：设置项由四项增加至十项，测试改为精确核验全部键、类别和过滤结果；普通工具行改为 28 像素后，第二行窗口按钮按真实行边界检查。原数字／箭头绘制、42×32 窗口按钮及 Windows 原生命中断言保留。

200% 下原正常位置夹具高 520、起点 y=28，超出 516 高的逻辑工作区，恢复应调整为 y=0、高 516。独立审查确认这是夹具与可见恢复要求冲突：保持位置用例增加矩形完全可见的前置断言，原精确比较全部保留；另加三种范围 × 禅模式的六行越界恢复，独立推导预期为可用屏幕矩形，检查进入、退出及再次保存的精确几何，不调用被测函数生成预期。
