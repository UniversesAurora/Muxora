# Qt Quick

### 拖动前景与基础运行段分开裁剪

基础标签运行段需要视口裁剪；被提起的标签、外部载荷和落位标签在窗口前景绘制，不能沿用基础层的 clip，否则阴影在标签栏边缘消失。两个适配器共用载荷投放规则，传入每个 piece 的局部接合几何，出现姿态只应用一次。阴影形状不变时只更新变换和透明度，避免在提起动画中重新生成小图。资源复用、跨窗口与场景图恢复的定向结果见 [前景记录](../verification-log/2026-10.md#quick-拖动前景的保留合成2026-10-29)。

### 视觉父项不负责对象释放

**现象**：标签栏销毁后，按稳定 ID 保存的标签和文件夹对象仍存活；清空地图的检查没有发现泄漏。

**原因**：`QQuickItem::setParentItem()` 只改变视觉树。无 parent 创建的项，即使挂入另一个项，也不会获得 QObject 所有者。反过来，删除一个裁剪父项也可能先让子项脱离窗口，导致本可保留的 GPU 资源重建。

**做法**：创建时指定稳定的 QObject 所有者，视觉父项按布局移动；删除运行段前，把仍存活的项移到同一窗口的稳定父项。测试保存实际项的 `QPointer`，验证销毁后为空，不能用地图数量代替释放检查。

**出处**：[GPT 审查 DeepSeek 标签合成](../verification-log/2026-10.md#gpt-审查-deepseek-提交标签合成与运行段资源2026-10-29)。

### 透明遮罩与空心描边不能用普通填充替代

**现象**：滚动渐隐盖住背景、方向相反，文件夹轮廓虽然创建了路径却没有绘制。

**原因**：用背景色覆盖不能替代内容 alpha 相乘；把闭合描边转为填充又会产生内轮廓，而原填充器明确不支持洞。忽略 `setPath()` 失败掩盖了缺失。

**做法**：渐隐在 GPU 层乘以原遮罩，各运行段独立裁剪；跨轴渐隐相乘。闭合描边交给 Qt Quick Shapes 的曲线渲染器。无需裁剪的文字直接绘制，避免额外离屏目标及原生 RGB 字形混合的背景变化。需要离屏合成的字体效果仍由试用确认，不能仅凭节点成功建立宣称等价。

**出处**：[GPT 审查 DeepSeek 标签合成](../verification-log/2026-10.md#gpt-审查-deepseek-提交标签合成与运行段资源2026-10-29)。

### 文字渐隐不要切字符串或增加格式边界

`QSGTextNode` 只为整段输入使用一种颜色。按可见范围截字符串会改变连字和 fallback，按渐变添加格式区间又会在 `QTextLayout` 中引入新的 itemization 边界。保留完整 `QTextLayout`，用有界矩形切片裁剪同一个节点，再分别设置静态裁切透明度和关闭按钮覆盖透明度，可以保持整形结果并在动画帧里只改裁剪与透明度。

标题、字体、方向等整形输入改变时才重建布局；动作透明度和普通视口变化不能触发重新整形。跨窗口和场景图释放后由新窗口重建 GPU 字形资源，CPU 整形可继续复用。验证检查实际资源复用与恢复，不用截图或固定像素判断渐变外观。

`QSGTextNode` 的 viewport 只按纵向筛选行；横向裁剪不会减少它保留的整串字形。切片数有界也不代表总资源有界，必须计入源长度、字形实例和实际物理面积。当前公开入口尚不能消费可见的原始字形子集，不能把预算拒绝说成该路径已经实现。出处：[GPT 审查 DeepSeek 文字实现](../verification-log/2026-10.md#gpt-审查-deepseek-提交文字资源与源语义2026-10-29)。

### 丢弃准备数据不能重置场景图版本

拒绝一个输入后，GUI 可能在同一轮里马上提交有效帧，Qt 最终只同步后者；旧渲染节点仍然存在。如果新准备数据从零重新编号，旧节点可能把不同图像误作同一版本。版本序列随 item 存活，清空或拒绝只释放准备数据。错误状态也不能因窗口或 DPR 变化被空帧洗掉。资源上传计数与跨窗口重建的功能检查见 [记录](../verification-log/2026-10.md#自有标签组背板的-quick-保留合成2026-10-29)。

### 路径预算不能代替冷图预算

接合阴影先生成冷图、后生成填色几何时，后者的元素限制保护不了前面的图片分配。资源入口在生成前检查最终图片和卷积 padding mask 的尺寸与累计字节，矩形网格及分割后的 quad 也各有限额。阴影路径可能有合法的洞，不能用不支持洞的填色三角化器代替这项预算检查；原始裁剪与小图语义保持。分数 DPR 的合并小图仍按图片自然逻辑尺寸绘制，再用原 band 裁剪，不能额外缩放到 band 宽高。

### 几何变化不应丢弃静态标签内容

布局或选择变化不意味着标题、编号和图标变化。静态内容按字体、方向、策略、目标 DPI 和标签元数据失效；编号变化只更新相关条目。被旧帧持有的数据保持不可变，字体和图标引擎仍由 GUI 侧准备。测量须包含实际受影响的负载：无编号的单标签绘制不能证明带编号标签的布局收益。


### 验证直边复用时避开圆角的模糊范围

标签矩形没有碰到主体圆角，不代表它的阴影图也远离圆角。局部图先扩展阴影范围，卷积还要读取裁剪外的输入；圆角落在这个范围内时，平移后重新生成是正确行为。验证零暖态上传要把几何放在真正的直边范围，圆角场景另外核对形状，不能通过固定旧纹理消除正确的变化。

### 标签槽位与接合轮廓的锚点分别比较

逻辑标签矩形不一定等于接合后的 surface anchor：竖栏会按内容连接边调整宽度。检查标签和阴影同步时，比较两份绘制贡献的实际 surface anchor；布局命中另与逻辑槽位比较。不能把两种矩形误作一个量，或为错误断言改掉既有连接规则。

### 局部资源的像素与裁剪分开

接合阴影移动时，图像可复用，目标位置和覆盖边的裁剪仍会改变。资源值要同时交付局部图像、绘制范围和裁剪范围，不能把每次不同的裁剪都烘焙进普通阴影纹理。高对比的完整覆盖描边与普通阴影不同，必须区分其缓存条件；暖态命中与像素持有生命周期分别验证。

### 尺寸更新不等于纹理更新

卡片变宽时，先确认阴影图是否真的重建。已有小图缓存命中后，卡顿还可能来自 CPU 合成与裁剪，不能继续归因于模糊。Quick 保留原小图和固定数量的周边顶点；目标尺寸只改顶点，样式、有效圆角或 DPR 变化才重新准备资源。场景图线程只接收只读图像值，不调用生成器或控件；每个节点的纹理跟随所属窗口销毁和重建。用暖态图片生成数与上传数验证，不能仅凭画面流畅推断缓存命中。


### 尺寸回调之后先确认适配器仍存活

帧推进会通知宿主重新布局，宿主可能在同步回调里关闭窗口或销毁来源。回调前保留弱引用，返回后先确认来源仍存活，再更新层级、输入区或重绘；状态计算自身不执行宿主回调。

### 隐藏载体从状态变化发布数据

**原因**：拖回标签栏时，载体保持 HWND、内容和捕获，但停止 QWidget 绘制。若快照只在 paintEvent 或鼠标移动时更新，鼠标停住后的动画、排版或字体变化不会及时交付目标。

**做法**：从状态改变处使 GUI 缓存失效，合并发布不可变帧；目标只读数据。内容与几何采样分开，未变化的内容共享，仍被消费者持有的帧不改写。发布只更新预览，不能再进入完整的拖动命中与样式设置流程。松手位置单独同步查询，不能把读取最终布局的位置表改成每帧扫描。

**验证**：关闭 QWidget 更新后仍能收到状态通知，未变化的帧共享，两个已释放缓冲复用，字体与内容变化使缓存失效。定向运行及旧桌面夹具的改前对照见 [验证日志](../verification-log/2026-10.md#拖动预览改为自有数据帧2026-10-27)。

### 测量帧率前先确认屏幕处于工作状态

**现象**：Quick 窗口已 exposed，第一帧可以绘制，但后续 `afterAnimating` 不再到达，帧动画停在初值。

**原因**：Qt 6.12 的 Windows 平台使用 DXGI 刷新通知驱动 `QWindow::requestUpdate()`。`QDxgiVSyncThread::run()` 在 `WaitForVBlank()` 失败或立即返回时只休眠，不调用通知。源码注释提到屏幕开关可能触发立即返回。屏幕休眠期间，exposed 和场景图已初始化都不足以证明正常刷新正在进行。

**做法**：先用独立探针确认刷新等待，再在唤醒屏幕并临时保持亮屏的条件下测量。仅创建防休眠请求不一定能唤醒已经休眠的屏幕。测试结束撤销请求，不把关闭 Qt 刷新通知的诊断开关加入产品，也不把休眠时的停帧当作界面性能退化。

**验证**：本轮休眠探针的等待接近零；唤醒后恢复为正常刷新周期，默认配置下 `quick-rendering` 全部通过。逐次失败、诊断开关和正常运行的区别见 [验证日志](../verification-log/2026-10.md#quick-保留绘制与屏幕刷新验证2026-10-27)。

### 不持有渲染线程共享锁调用 quit 或关闭窗口

**现象**：帧测量已结束、窗口已经隐藏，进程却不能退出，桌面隔离一直等不到测试结束。

**原因**：测量回调持有采样互斥锁时调用 `quit()`。退出可能同步关闭窗口并等待渲染线程；渲染线程的尾部采样也要取同一把锁，形成等待环。

**做法**：在锁内只读取完成状态，解锁后再调用可能进入 Qt 窗口生命周期的操作。渲染回调捕获的数据应比窗口活得更久；退出或失败时也保留部分测量报告。

**验证**：修正后的 Quick 基准在正常显示条件下连续三轮退出并产出完整报告；首次挂起已按测试进程路径核对后清理，没有终止用户预览。

### 填充几何与边缘抗锯齿的能力分开声明

**原因**：能三角化的非凸轮廓不一定能用中心偏移边缘做 coverage AA。单独封闭的接合肩部有尖点，部分接合的凹角会让内外偏移之间的连线相交；直接填那些四边形会形成错误覆盖。

**做法**：保留全部填充输入，单独验证可选 AA 的支持范围；不能静默换形状或删输入。尖肩和部分接合采用调用方明确配置的 MSAA 路径。几何可绘制不代表抗锯齿、字体和整界面外观已经等价验收。

**验证**：`quick-path` 覆盖四边、裁切、接合进度、覆盖、浮层和紧凑轮廓；`quick-rendering` 检查 MSAA 目标的部分接合与尖肩。新矩阵最初错误地假设全部轮廓支持 coverage AA，修正依据和原始失败数字保留在验证日志中。
