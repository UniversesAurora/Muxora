# 版本控制经验

规则见 [参与开发](../../../CONTRIBUTING.md)：只用 rebase 或快进，不产生合并提交，提交标题带改动范围前缀。

### 改写历史时只改被要求改的部分

- **现象**：只要求删掉提交说明里的署名尾注，结果连其他说明文字一起改了，只能重做。
- **做法**：改写历史时用脚本只处理目标内容（例如只删除匹配的尾注行），其余文字逐字保留；改写后检查每个提交的说明差异只包含目标行。文档里引用的提交哈希要同步映射到新哈希。

### 改写前留备份分支，删除前先问

- **做法**：改写前建 `backup/<用途>` 分支；改写已公开的历史和删除备份分支都要使用者明确同意。指向旧历史的标签（例如 `v0.1.0-preview.1`）是否移动，也要先确认。
