# 桌面测试经验

测试规则见 [测试要求](../testing-design.md)；这里记录在真实桌面上跑测试时遇到的问题。

## 真实输入

### 真实输入只能发给本进程的窗口

- **现象**：跑 `window-system.toolbar-popup` 时，Claude Code 的当前任务和远程控制被中断。
- **原因**：测试用 `SendInput` 发送 Esc / Tab / 空格和鼠标点击，以复现原生弹窗的捕获和焦点恢复。`SendInput` 发给当时的前台窗口或指针下的窗口；测试窗口因前台锁没抢到前台时，Esc 落到了别的程序上。
- **做法**：
  - 桌面测试和全量测试用 `pwsh tools/tests/quiet-desktop.ps1 -Elevate <命令>` 运行（整批经 UAC 以管理员权限运行，见下文“权限更高的前台窗口挡住真实输入”）。它先记下所有可见的应用窗口并全部最小化（包括 Claude 等正在使用的程序），命令结束后在 `finally` 里按原来的层叠顺序和状态恢复；窗口列表存在 `out/test-results/quiet-desktop-windows.json`，运行被意外打断时用 `-Restore` 恢复，`-List` 只列出将被最小化的窗口。
  - 真实输入统一走 `modules/window-system/tests/native_input.hpp`。按键前检查前台窗口、点击前检查指针下的顶层窗口属于本测试进程，否则判测试失败，不发送。
  - 能用 Qt 合成事件验证的行为就不用真实输入。
- **出处**：2026-10-20。

### 合成的鼠标移动不会移走真实光标

- **现象**：`compact-ui` 的 `scrollbarOverlaysTheTabsWithoutMovingTheContent` 偶尔等不到滚动条隐藏（2026-10-24 两轮重复共 17 次失败 2 次，此前也有首报）。诊断显示每个数据行开始时真实光标都停在新窗口的标签条上：上一行把光标移到滚动条手柄，下一行的窗口又出现在同一位置。
- **原因**：`QTest::mouseMove` 只发送 Qt 内部的合成移动，真实光标不动；系统随后对真实位置的悬停又把滚动条显示出来。
- **做法**：前提依赖原生悬停状态时（“指针不在某控件上”或“指针在某控件上”），用 `QCursor::setPos` 移动真实光标，再等待状态成立；不要用合成移动建立这类前提。修正后连续 20 次通过，见 [验证日志](../verification-log/2026-10.md#compact-ui-滚动条用例的真实光标前提2026-10-24)。

### 不在测试里用真实输入做按下拖动

- **现象**：一次实验性测试用 `SendInput` 按下鼠标后进入系统移动循环，测试卡死，左键在系统里一直处于按下状态。
- **做法**：拖动用 Qt 鼠标事件或模块 API（例如 `moveStrip`、`setStripWidth`）驱动；如果已经卡住，用一次 `MOUSEEVENTF_LEFTUP` 松开按键。

## 环境

### 移除开发工具路径前，先记录验证元数据

- **现象**：部署程序和各阶段检查已经完成，临时脚本最后却因找不到 Git 而无法写总报告。
- **原因**：为验证部署目录不依赖 SDK，脚本主动把进程的 PATH 缩小到系统目录；收尾代码仍假定能通过命令名找到开发工具。
- **做法**：隔离运行环境前记录源码提交及所需工具路径，或恢复原进程环境后再采集元数据。各阶段先单独写盘；汇总失败时可从这些记录恢复，但必须标注错误和恢复依据，不能重跑产品检查来补一份元数据。
- **出处**：临时脚本错误及恢复过程见 [验证日志](../verification-log/2026-10.md#debug-接受后的验证收尾2026-10-22)。

### 收起应用窗口后必须核验结果，再开始测试

- **现象**：测试前仍有应用浮窗和工具面板留在屏幕上。旧脚本只枚举无 owner、非工具窗口，发出 `ShowWindowAsync` 后固定等待 500 ms；命令失败时仍然开始测试。
- **原因**：应用的 owned/modal/tool 窗口也可能遮挡测试；异步消息未必在固定时间内处理。普通权限进程还不能控制权限更高的应用。窗口恢复时，发给不同线程的异步请求也不能仅靠调用顺序保证 Z 序。
- **做法**：
  - 包含屏幕内实际可见的应用浮窗、模态窗口和工具面板，排除桌面、任务栏、气泡、cloaked 和不可见辅助窗口。原本隐藏或最小化的窗口不动。
  - 改动前原子保存窗口身份、placement、Z 序及前台窗口。先请求最小化，拒绝最小化的面板临时隐藏；逐项确认已收起，失败则恢复并拒绝启动测试。新出现的应用窗口也要纳入核验。
  - 恢复时核验 HWND 对应的 PID、线程和窗口类，避免把复用的句柄当成原窗口；按原状态和层叠次序恢复并等待确认。恢复失败保留快照；`-Restore` 只读取当前身份快照，不支持的版本不执行窗口操作。
  - 恢复顺序不依赖把后台应用强制抬到最前。先恢复置顶状态，再把跑到目标前驱上方的窗口向下归位；原本已在前驱下方的窗口留待后续排序，最后核验全序、置顶状态和原前台窗口。前驱可能已关闭，每轮重新计算。仅发一次请求再等顺序变化，会错过其他线程稍后到达的恢复动作。[`SetWindowPos` 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos) 还明确限制了后台进程将窗口提到最前的权限；API 返回成功不能代替实际顺序检查。
  - 一律使用原生 `-Elevate` 入口（用户 2026-10-21 要求：隐藏和恢复窗口必须提权，不先用普通权限试）。当天起整批以管理员权限运行，原因见下一条。`-Elevate -Restore` 可用于有记录的恢复。脚本不强杀进程、不针对某个本机应用添加例外。
- **验证入口**：`tools/tests/quiet-desktop-test.ps1` 创建原生窗口，程序核验 owned/tool/禁用 owner、慢响应与拒绝最小化、原隐藏／最小化状态、placement 与 Z 序、命令失败后的恢复、未支持版本拒绝及句柄身份。气泡用各自的初始可见性作比较，并检查不进入恢复快照；标准气泡没有工具条目时不能假定它一定可见。
- **出处**：2026-10-21，用户报告测试前仍有窗口未收起；实际运行结果见 [验证日志](../verification-log/2026-10.md)。

### 权限更高的前台窗口挡住真实输入，测试要以管理员权限运行

- **现象**：同一份代码下午 Release 全量 61/61 通过，傍晚重跑时 `tab-bar-presentation`、`chrome-interaction`、`compact-ui` 失败，失败点都是 `SetCursorPos` 返回 FALSE 或之后的悬停断言。测试之外直接调用 `SetCursorPos` 同样失败，`OpenInputDesktop` 成功（没有锁屏）。
- **原因**：前台窗口属于一个权限更高的程序，桌面隔离脚本没有收起它（它不是普通应用窗口）。Windows 的 UIPI 不允许低完整性级别的进程替高完整性级别的前台窗口移动鼠标或发送输入。下午那次运行时这个窗口恰好不在前台。
- **做法**：整批测试以管理员权限运行（用户 2026-10-21 决定）。只提权窗口控制不够：前台可能是收不起来的弹出窗口，而真实输入发自测试进程本身。排查同类失败时，先在测试外调用一次 `SetCursorPos` 并查看前台窗口所属进程，再看代码。
- **验证**：在同一状态下，经桌面隔离、测试命令用管理员权限重跑这 3 个套件，全部通过。同一时期 Debug 全量的超时与此无关：管理员权限重跑后仍然超时，原因是 Debug 版慢 5～8 倍，见验证日志。
- **出处**：2026-10-21，Claude 整理仓库时的 verify 运行。

### 最小化脚本自己的回归也要完整放进一次隔离

- **现象**：用户看到真实应用还在最小化时，空白夹具已出现，其中还有最大化的空窗；中间恢复桌面后仍有测试继续运行。
- **原因**：自测直接创建原生夹具，然后逐个调用 runner。每次调用只包住一个探测命令，夹具的创建、后续断言和下一轮检查都落在外层隔离之外。runner 还只等命令返回，无法保证它的 GUI 子进程和辅助进程已退出。
- **做法**：自测入口先进入唯一的外层 runner，核验真实应用已收起才创建夹具；内部按 PID 操作独立的夹具快照，销毁全部夹具后才结束外层。runner 用窗口线程消息屏障和稳定状态检查等待准备完成；开始命令前把自身加入无 breakaway 的专属 Job，等待所有后代退出后才恢复。查询进程状态失败时保留恢复快照，不能直接恢复。Job 关联不可解除，因此 runner 必须用独立 `pwsh` 进程运行。
- **验证**：保留原生慢响应、拒绝最小化、隐藏状态、恢复顺序等断言，并加入外层收起前置检查和夹具销毁检查。`quiet-desktop-test.ps1 -Headless` 验证准备失败不运行命令、命令提前返回时仍等待后代、退出码及中文参数保留。本次该无窗口回归、PowerShell 解析和内嵌原生类编译通过；按本轮约定未再次创建桌面夹具，改造后的完整原生路径尚未复跑。
- **出处**：2026-10-21，用户明确要求最小化完成后才创建夹具，全部测试清理完成后才能恢复。

### 测试窗口关闭后，前台可能交给外壳窗口再被它夺回

- **现象**：完整 Debug 运行中 `toolbar-popup` 偶发报告“另一个程序在前台”，单独运行或只跑前序套件大多通过。
- **原因**：测试窗口关闭时，Windows 把前台交给 Z 序里下一个可激活的窗口；收起应用窗口后，这个窗口可能是外壳的 `Windows.UI.Core.CoreWindow`（`ShellExperienceHost.exe`）。新测试窗口激活后，外壳窗口仍可能在几百毫秒内重新拿走前台。
- **做法**：输入保护失败时报出前台窗口的类名和程序，先看是谁再看代码；需要过程时在测试外按 50 ms 间隔记录前台窗口变化。夹具的修正尚未完成，见验证日志。
- **出处**：2026-10-24，Claude 的完整验证，[验证日志](../verification-log/2026-10.md#全量中测试窗口的前台被外壳窗口夺走2026-10-24)。

### 置顶窗口会挡住测试窗口

- **现象**：截图、像素和提示框断言随机失败。
- **原因**：桌面上有置顶窗口压在测试窗口上方；Qt 也会在窗口失去激活时立即关闭提示框。
- **做法**：用 `quiet-desktop.ps1` 运行，先把其他窗口最小化；提示框测试还要先激活自己的窗口，并关闭 `UI_FadeTooltip` / `UI_AnimateTooltip` 动画（测试结束后恢复）。

### 最大化后要等几何真正稳定

- **现象**：最大化后立刻读取按钮位置，得到的还是还原状态的坐标。
- **原因**：Qt 先报告最大化状态，原生尺寸调整稍后才完成。
- **做法**：`QTRY_COMPARE(window->geometry(), screen->availableGeometry())`，并等待关键控件到达工作区边缘后再断言。

## 菜单

### 用 `setActiveAction()` 驱动菜单悬停，不用合成的鼠标移动

- **现象**：用 `QTest::mouseMove` 或一串 `QMouseEvent` 悬停菜单项来打开子菜单，大约十次里有一次打不开，失败时菜单的 `activeAction()` 为空。
- **原因**：`QMenu` 在指针离开菜单弹出时的位置不到拖动距离、且移动不超过 6 次时忽略移动，而弹出位置取的是真实光标，所以结果取决于光标当时停在哪里；另外子菜单打开时，指针朝它移动会被推迟切换（sloppy submenu）。
- **做法**：测试悬停时调用 `QMenu::setActiveAction()`（`tests/menu_hover.hpp` 的 `hoverMenuItem`），它和悬停走同一条延迟弹出路径（`internalDelayedPopup`）。只有要测鼠标路由本身时才发鼠标事件。
- **验证**：两个原生子窗口回归用例改用它之后各连续 10 次通过。
- **出处**：2026-10-20。

## 回归用例

### 全量失败而定向通过时，先保留失败过程的证据

- **现象**：同一份窗口系统实现的 Debug 全量中，菜单关闭、滚动条悬停和跨窗口多行插入失败；随后分别运行完整套件、再加入各自紧邻的前序套件，都通过了。
- **尚未确认**：两次定向运行没有抓到失败过程，不能据此判断是产品、测试时序还是桌面状态问题。成功记录中的坐标和事件顺序只能说明成功路径。
- **做法**：先归档整批原报告，再围绕失败边界记录状态。菜单区分定时器进入、输入排队、原生分发与真正隐藏；悬停区分实际坐标、窗口命中、可见性与 Enter 交接；跨窗拖拽区分目标窗口被拒绝、拖拽取消和预览生成后被清除。观察器有界缓冲，结束后写文件；不加输入、不调整原断言或等待。真实输入仍按统一入口处理，见 [测试要求](../testing-design.md#3-工具与统一入口)。
- **出处**：本次没有确认修复，首次失败与各次诊断结果分别见 [验证日志](../verification-log/2026-10.md#完整验证与-debug-新失败2026-10-22)。

### 回归用例必须先在旧代码上失败

- **现象**：为原生子窗口问题写的第一版测试在修复前后都通过。
- **原因**：夹具和真实路径差了关键条件：菜单栏扩展按钮从未创建过，菜单也只打开了一次（见 [Qt Widgets](qt-widgets.md#qmenu-关闭后句柄会被销毁abouttoshow-比重新创建句柄更早)）。
- **做法**：写完回归用例后，用 `git stash push <修复文件>` 暂时撤掉修复，确认用例失败、失败信息指向问题，再恢复修复确认通过。测不出来时，把能复现的实验步骤逐步删减，找出真正必需的条件，而不是放宽断言。
- **出处**：2026-10-20，`CaptionStripTest::compressedMenuStripMovedUpKeepsTheWindowAlien`。
