# Muxora 自动化测试与质量要求

状态：实现阶段必须遵循的测试规范。窗口系统首个预览开始建立测试；实际执行范围与结果见 [预览说明](window-system-preview.md)。

关联：[V0 设计](../design/v0-design.md)、[工程设计](engineering-design.md)、[通用窗口系统](../design/window-system-design.md)、[工作区设计](../design/workspace-design.md)、[浮动与完整窗口设计](../design/floating-window-design.md)。

## 1. 必须遵守的规则

**建立完整的自动化测试链路，覆盖需求、实现、集成、真实交互、资源、依赖升级和最终发行包。测试失败时必须定位并修复问题，再通过原有检查；实现者和自动化代理不得自行降低标准来让结果通过。**

成功编译、单元测试或截图不等于 DPI、长期资源、安装包和全部桌面交互的验收；这些各自按本文对应章节验证。

测试必须由程序判断通过或失败，开发者和用户只需编写、执行并检查结果。截图可以辅助定位问题，但不能把人工读图作为自动化测试的判定步骤；绘制检查应使用程序执行的像素、几何或可访问性断言。Computer use 仅在分析问题确有必要时使用，不参与测试执行或验收链路。

执行按一批实际代码改动安排：多个改动完成后集中进行一次全量检查，不在每个小改动之后重复。没有实质代码变化、仅切换 Debug / Release 或重新打包时复用已有测试结果。失败后的诊断与修复运行相关用例；只有新的广泛影响才扩大复测范围。哈希校验代码的适用范围见 [仓库规则](../../AGENTS.md#必须遵守)。

外观仍由用户快速试用调整时，按“提出修改、实现、编译交付试用”推进，暂不新增或固化外观断言；外观确定后再补对应测试。已有功能与逻辑测试保持，是否执行遵循用户当轮要求；仅编译的版本不能写成测试通过。

以下做法不能作为解决失败的方式：

- 删除、禁用、跳过失败用例，移除关键断言，或将失败转换为预期失败。
- 把错误输出改成期望输出，直接接受失败截图作为新基线。
- 放宽延迟、内存、误差或超时阈值，减少负载、缩短循环次数，以掩盖缺陷。
- 关闭告警、静态分析、内存诊断或必需的 CI 检查。
- 反复重试直到偶然通过，只保留成功结果。
- 用 mock 成功替代真实协议、真实桌面或发行包的必需验收。

按 [§2 退役与重写](#退役与重写) 的条件删除或重写用例不属于上面这些做法，但不能用来处理正在失败的用例。

确有用例错误时可以修正，但必须先给出独立依据，例如协议规范、已确认的产品要求或测试环境故障；记录旧断言、修正内容、理由及审阅结果，保留等价或更严格的有效覆盖。不能用当前实现的行为反推正确预期。涉及产品要求、性能阈值、覆盖范围或发布标准降低时，必须由用户明确确认，实施者不得自行决定。

环境故障应修复环境；不稳定用例应定位时序、隔离或实现问题。允许为诊断重跑，但首次失败和后续结果都要记进验证日志（见 [§3 测试结果与排查文件](#测试结果与排查文件)），单次成功不能抵消未解决的不稳定性。不得悄悄隔离必需用例或让发布忽略它。

## 2. 从需求到用例

主要需求建立稳定编号，例如 `WS-MOVE-001`、`SSH-CONFIG-001`、`TERM-IME-001`、`FILE-COPY-001`。每条需求关联用例 ID、覆盖层级、环境、输入、明确的预期结果和运行证据。V0 验收表、工作区和窗口壳验收表都必须映射到测试清单。

在实现一项功能前确定它的外部行为和关键断言；实现与对应自动化用例一同交付。不能等全部功能写完才补测试，也不能把“能编译”当成行为正确。

预期结果来自要求、协议文档或经过审阅的固定样例，不直接复制被测代码的算法。用例包含正常路径、边界、非法输入、取消、错误、恢复和生命周期；重点覆盖可能改变用户数据、连接或布局的行为，不为每个 getter 堆积无效用例。

发现缺陷后，先增加能够复现问题的用例，确认它在有缺陷的版本上失败，再修复并保留该用例。用例按下文“回归用例”写成行为用例，不写成只针对这次缺陷的专用检查。无法稳定复现时先补充诊断证据，不凭一次成功关闭问题。

用例结果分别记录通过、失败、不稳定、跳过、环境阻塞和未执行。**不稳定、跳过、未执行、环境阻塞均不算通过。** 每个阶段只报告实际完成的覆盖；V0 发布前所有必需场景都必须完成。

### 测什么，不测什么

用例检查**行为契约**：用户能观察到的结果（哪个标签活动、内容在哪个组、顺序、可见范围、能否点到），以及设计文档写明的不变量。不检查实现细节：私有成员、调用次数、中间状态、恰好是第几次重绘。实现换一种写法、行为不变时，用例不应失败。

几何断言写成关系，而不是坐标：不重叠、在可视范围内、对齐、相邻、绘制位置与命中位置一致、放下后的位置与预览一致。设计文档写明的尺寸（例如标签高度、按钮宽度）是规格，集中在一个规格用例里按主题和缩放检查一次，其他用例不重复写这些数字。

像素断言只用在像素本身就是要求的地方：原生边框和 DWM 绘制、透明缺口、主题颜色是否生效、截图类回归。取样用有代表性的区域和有理由的容差，不逐像素比较整块界面，也不把字体渲染细节写进预期。

### 分层

| 层 | 测什么 | 用例数量 |
| --- | --- | --- |
| 逻辑 | 布局计算、模型操作、命中与插入位置、状态机、解析。不建控件，毫秒级。 | 最多：所有维度组合、边界和随机序列都放在这一层 |
| 控件 | 事件、布局、绘制和命中接到了一起；设置和命令改变了实际控件。不显示窗口或只用离屏控件。 | 每条接线几个有代表性的情况 |
| 桌面 | 真实输入、原生窗口、鼠标捕获、输入法、DPI、多屏、系统动画。 | 最少：只验证平台集成，不在这一层重复逻辑层的组合 |

复杂逻辑先抽成可以在逻辑层测试的纯函数或模型，再写控件和桌面层的少量接线用例。一个行为在较低层已经充分覆盖时，较高层只检查接线，不再穷举。

### 覆盖复杂逻辑

每个功能在它的测试源码开头列出状态维度和取值，例如标签栏的“位置 × 单行／多行 × 收起方式 × 置顶尺寸 × 置顶单独一行 × 拖动来源 × 标签块大小 × 落点所在的段”。覆盖分三部分：

- **组合**：维度两两组合都至少出现一次（pairwise），由数据驱动用例生成；风险高的维度（会改变用户数据或布局的）用全组合。
- **边界**：空、一个、恰好放下、超出一个像素、极窄、极长、超大载荷、反复来回。
- **不变量与随机序列**：对每个生成的状态检查不变量；对模型和布局再跑有界的随机操作序列，失败时输出种子和操作序列，可以原样重放。

动画在测试中默认关闭，只有专门测动画的用例打开；等待用具体事件或可观察状态，不用固定时长。

### 回归用例

修复缺陷时加的用例，按行为命名、放进这个功能的测试源码，最好是组合表里的一行数据或一条不变量，而不是以缺陷命名的独立函数。修复前它必须失败。已有的不变量或组合用例本来就应该抓住这个缺陷却没抓住时，先补强它们，再看是否还需要单独的用例。

### 退役与重写

符合下面任一条件时，用例可以删除或重写：

1. 它检查的行为已经按设计文档删除或重新设计；
2. 同一行为在同层或更低层已有同等或更强的用例；
3. 它断言了上文不允许的实现细节——这时必须换成同等强度的行为断言，不能只删不补。

退役不是让失败通过的手段，§1 的规则不变：失败的用例要先查清楚，不能借退役删掉。退役和重写单独提交，不和修复混在一起；每次退役在验证日志里列出用例名、依据的条件、覆盖同一行为的用例。整套测试的审计按 [8.20](../roadmap/implementation/phase-8-ui-quality.md#820-测试标准与审计) 进行。

### 组织

- 一个测试源码对应一个功能契约（例如标签栏布局、标签栏交互、拖动、原生窗框），文件开头写它对应的设计文档章节和状态维度表；超过约 800 行时按子功能拆开。
- 用例名说明行为：`行为_条件_结果` 的英文写法，例如 `dropIntoStickySection_makesWholeBlockSticky`。
- 共用的夹具、生成器和断言辅助放在测试目录的公共头文件里（例如 `support/`），不在各套件里复制。
- 本节和 §5、§7 的“必需用例”清单冲突时，以本节的写法为准；那些清单在 8.20 中改成按功能列出的覆盖矩阵。

## 3. 工具与统一入口

以 CMake／CTest 组织构建和运行，Qt Test 作为 Qt／C++ 单元、组件及事件交互测试的首选。可使用数据驱动用例、`QSignalSpy` 和 `QAbstractItemModelTester` 检查信号与目录模型契约；测试目标使用与被测程序匹配的 Qt SDK。[Qt Test](https://doc.qt.io/qt-6/qttest-index.html)、[CTest](https://cmake.org/cmake/help/latest/manual/ctest.1.html)

测试不强制依赖某一款付费 GUI 工具。模型测试通过公开命令／API 运行，Qt 控件测试检查实际视图、事件、焦点与尺寸；系统拖拽、原生窗框、输入法和混合 DPI 测试通过具备交互桌面的 Windows 测试环境执行。仅调用内部移动函数，不能证明真实鼠标拖拽也正确。

桌面和全量检查通过独立的 `pwsh tools/tests/quiet-desktop.ps1 -Elevate <命令>` 进程运行，严格遵循以下顺序：

1. 记录开始时可见且未最小化的应用窗口，包含应用浮窗、模态窗口和工具面板。收起后等待窗口线程处理完成，并核验状态稳定；在这之前不能创建交互夹具或启动测试。
2. 一次隔离内执行整批测试，等待命令、全部子孙进程退出和夹具清理完成。命令返回不代表它启动的 GUI 程序已经退出；runner 先把自身加入专属 Windows Job，再启动命令，核验只剩 runner 自身后才进入恢复。无法确认时保留快照，不带着残留测试进程恢复用户桌面。运行期间 runner 保留一个透明的 1×1 窗口，放在虚拟屏幕之外，用来接住测试窗口关闭后交出的前台，并允许下一个测试窗口取走；否则前台可能交给外壳窗口，又被它从新测试窗口手里夺回。测试自行明确管理通过已有应用或系统代理创建的进程。
3. 只恢复起始快照中的窗口。恢复开始后不再执行测试，不在批次中途反复恢复用户窗口。原本已最小化、隐藏、cloaked 或不在可见桌面内的窗口不改动，也不进入恢复列表；准备时新出现的窗口阻止测试，不擅自追加进快照。

测试中的真实输入（`SendInput`、`SetCursorPos`）只通过 `modules/window-system/tests/native_input.hpp` 发送；它在发送前确认目标窗口属于本测试进程。窗口模型、公开 API 和真实交互分别验证，不能用其中一层代替另一层。

清理或恢复失败必须报错，恢复未完成时保留快照，不能忽略遮挡继续发送真实输入。桌面和全量检查一律带 `-Elevate` 运行，整批以管理员权限执行：权限更高的应用会拒绝普通权限的窗口控制；权限更高的程序窗口停在前台时，普通权限的测试也无法移动鼠标或发送输入（`SetCursorPos` 返回失败），悬停类用例会失败或等到超时。`-Elevate` 通过 Windows 原生 UAC 一次确认，收起窗口、测试命令及其子进程、恢复窗口都在提权后的进程中进行。测试进程确认全部结束后才恢复；主进程异常退出时不猜测测试是否已结束，保留快照，不擅自恢复。不依赖第三方提权程序，不针对本机应用写例外。已经是管理员的会话可以省略 `-Elevate`。

脚本自己的选项（`-Elevate`、`-Restore`、`-List` 等）按全名匹配，只能写在被测命令之前；从第一个不是选项的参数起全部原样交给被测命令，所以被测命令可以带 `-Test` 这类参数。被测命令本身以 `-` 开头时，在它前面加 `--`。PATH 中有同名程序时执行第一个。

脚本只保留两个入口：`tools/tests/quiet-desktop.ps1` 是当前实现，`tools/tests/quiet-desktop-test.ps1` 是回归用例，没有旧实现或备份版本。恢复只接受当前身份快照版本；不支持的版本在任何窗口操作前拒绝，并保留快照。后者默认先经过一次外层隔离，收起用户应用后才创建原生夹具；内部仅操作独立快照中的夹具窗口，全部销毁后才退出外层并恢复用户桌面。其 `-Headless` 模式不创建窗口，用程序检查参数解析、同名程序选择、三阶段顺序、准备失败不启动命令及等待后代进程退出；它不能替代原生桌面验收。原生模式还核验 `-Elevate` 下的测试命令确实以管理员权限运行。

提供共享 CMake build／test presets 和明确的快速、集成、桌面、诊断、压力、性能、发行包测试入口，供本机与 CI 使用。脚本语言按 [工程设计](engineering-design.md#8-推荐目录组织) 的规定。入口返回真实退出状态，保存报告，不能吞掉子进程失败；选定的必需测试组收集到零个用例时也应失败。

`tools/verify.ps1` 默认运行 Debug、Release、独立模块、外部宿主和部署检查（翻译检查在全量测试里）。步骤明确要求仅验证 Release 时，可传 `-ReleaseOnly`：仅省去 Debug 全量，其余检查仍全部执行，失败仍立即退出。

```powershell
pwsh tools/tests/quiet-desktop.ps1 -Elevate pwsh tools/verify.ps1 -ReleaseOnly
```


便携包的默认 `Full` 验证经上述桌面隔离入口运行。只交付外观试用包时可用 `-Validation Archive`，只检查压缩与解压文件，不执行应用测试；报告必须保留 `applicationChecksExecuted = false`，不能写成完整验证通过。入口与参数见 [预览说明](window-system-preview.md#开发环境)。

### 翻译覆盖

```powershell
python tools/check-translations.py
python tools/tests/translations-test.py
```

`check-translations.py` 用 `lupdate` 重新提取第一方源码，与三组目录逐项比较：窗口模块（含 Lua 适配）、LuaRuntime 和应用。它检查源语言、缺失或多余条目、未完成和空译文、占位符、复数、换行、助记符及富文本结构，并对每份目录再跑一次 `lupdate`，结果和提交的文件逐字节不同就失败（目录被手工排版过，或忘了构建 lupdate 目标）；另扫描未标记的中英文文字候选，包括内嵌 Lua。扫描不以现有目录为范围，测试代码和第三方代码不参与产品提取。新增资源或模板时，同时检查它是否进入提取范围，不能仅凭候选启发式判断完整覆盖。

全量测试里的 `translations.coverage` 和 `translations.checker` 就是这两个脚本：配置测试时 CMake 必须找到 Python 3.10 或更新版本，并把构建所用 Qt 的 `lupdate` 用 `--lupdate` 传给它们。C++ 测试本身不调用脚本。

`tools/translation-exemptions.json` 按文件、原文和出现次数列出非界面候选及理由；增减次数会失败，禁止整目录豁免。新增候选先判断显示路径，面向用户的文字在产生处标记翻译，其余才加入具体豁免。内部标识一律用英文 ID，不需要豁免。翻译行为见 [源文本与覆盖](../design/settings-and-commands-design.md#83-翻译源文本与覆盖)。

单独运行时，脚本依次用 `--lupdate`、`--qt-root`、环境变量 `QT_ROOT`、`.local/sdk.json` 里的 `qtRoot` 找 `lupdate`，都没有时在 `PATH` 里找。`--catalog WindowSystem`、`LuaRuntime` 或 `Muxora` 只查对应目录，默认检查全部；`--source-root` 用于临时源码夹具，`--report` 可指定 JSON 报告。反向用例 `translations-test.py` 把源码复制到名字含中文和空格的系统临时目录，每次改坏一处，核验检查因指定原因失败，结束时删除副本；它不修改工作区，也不操作桌面。

`tools/tests/application-language-test.ps1 -PackageDirectory <部署目录>` 用独立中英文设置检查部署程序的命令行帮助。它移除 SDK 和插件搜索环境，检查语言、稳定参数及未创建工作区，结果写入 `out/test-results/application-language.json`；统一验证入口会执行它，单独运行时也经桌面隔离入口。

### 测试结果与排查文件

验证日志本身就是证据。失败、反向验证和测量的关键内容直接写进日志：用例名、断言或错误信息、代码版本、数字和结论。`out/` 不进仓库，文件只是当时的工作位置，不能作为唯一依据；日志里提到的 `out/` 路径过后可能已经不存在。

`out/` 下只有这几类内容：

| 位置 | 内容 | 谁来清理 |
| --- | --- | --- |
| `build/`、`install/`、`package/muxora-preview/` | 构建目录、`verify.ps1` 安装的独立模块、固定预览 | 脚本管理 |
| `application-*-checks/`、`lua-deployment-checks/`、`package smoke checks/`、`portable-checks/` | 脚本自己的临时夹具 | 检查通过后由脚本清理，失败时保留现场 |
| `test-results/` | 只放统一入口的输出：`build.ps1 -Test` 的 JUnit、`test-summary.ps1`、`verify.ps1` 与各检查脚本的 JSON 和日志、`bench.ps1` 的 `bench-<名字>.json`。文件名固定，再次运行覆盖 | 不手工放文件 |
| `diagnostics/<主题>/` | 一次排查或一个步骤的工作文件：首次失败报告、反向验证报告、临时测量、截图、`-o` 输出。重跑不覆盖首次失败 | 主题结束（验证日志已写好、改动已提交）时删除整个目录，最晚在交出时删除 |

主题目录用步骤编号或简短英文名，例如 `diagnostics/8.12/`、`diagnostics/tab-scroll/`；不在 `diagnostics/` 根目录直接放文件。只为排查写的脚本放系统临时目录。确需长期保留的样例数据放进仓库的测试夹具目录并提交，不留在 `out/`。

### CTest 分层标签

每个 CTest 套件只带一个标签，按测试源码判断：

| 标签 | 规则 | 运行方式 |
| --- | --- | --- |
| `desktop` | 调用 `showWindow`、`show()`／`showMaximized()` 等显示窗口、`qWaitForWindowExposed`、`QTest::mouse*`、`QCursor::setPos` 或 Win32 API（包括 `windows.h` 的进程计数）的套件 | 保留 `RUN_SERIAL TRUE`，一次只运行一个 |
| `widget` | 创建 `QWidget` 或 `WindowManager`，但不显示窗口 | 可以并行 |
| `model` | 只用布局模型、`CommandRegistry` 或 Lua 运行时，不创建控件 | 可以并行 |

初步分类用下面的命令列出可能属于 `desktop` 的源码，再逐个打开确认（例如 `view-state` 通过 `restorePlacement()` 最大化窗口，命令匹配不到，也属于 `desktop`）：

```bash
cd modules/window-system/tests
grep -lE "showWindow|\.show\(\)|qWaitForWindowExposed|QTest::mouse|QCursor::setPos|windows\.h" *_test.cpp
```

`pinned-layout`、`pinned-positions` 写在控件套件的同一个循环中、链接控件库，但只调用 `LayoutModel`，标为 `model`。并行运行中失败而串行通过的套件说明分类有误，应改回 `desktop`，不改测试本身。

```powershell
. ./tools/toolchain.ps1
$tc = Enter-Toolchain (Resolve-QtKit "" (Get-Location).Path)
try {
    & $tc.Ctest --test-dir out/build/dev-release -N -L model # 只列出
    & $tc.Ctest --test-dir out/build/dev-release -L "model|widget" -j 8
} finally { Exit-Toolchain $tc }
pwsh ./tools/tests/quiet-desktop.ps1 -Elevate pwsh ./tools/build.ps1 -Configuration Release -Test -TestLabel desktop
pwsh ./tools/build.ps1 -Configuration Release -Test -TestLabel "model|widget"
```

`-TestLabel` 把值作为 `ctest -L` 的正则传入，junit 报告文件名加上标签后缀，例如 `out/test-results/dev-release-model-widget.xml`。

测试行数用 `tools/test-summary.ps1` 统计，不再手工计数。它读取构建目录中各套件的 `*-results.txt`，按“套件 + 函数 + 数据标签”去重，不计 `initTestCase`／`cleanupTestCase`；同一行既有 `PASS` 又有 `FAIL!` 时算失败。没有结果的已注册套件单独列出。结果文件会被下一次运行覆盖，只运行部分层时，其他套件的数字来自旧结果，应看输出中的修改时间。

```powershell
pwsh ./tools/test-summary.ps1 -BuildDirectory out/build/dev-release -Output out/test-results/summary.json
```

异步测试等待具体事件或可观察状态，并设置有理由的超时；不能依赖固定长 sleep、网络运气或执行顺序。每个用例可独立运行，临时资源清理明确，随机场景记录 seed 和操作序列。

Qt 生命周期夹具须遵循对象销毁契约。控件正在处理 Show、Hide 等通知时，宿主请求销毁该控件或其所有者，应使用 `deleteLater()`。事件过滤器返回 `true` 只能停止事件继续分发；Qt 的 `show()` / `hide()` 调用栈还可能继续访问控件的私有状态，不能把这一返回值当成同步删除窗口的保证。[QObject 析构与延迟删除说明](https://github.com/qt/qtbase/blob/6.12/src/corelib/kernel/qobject.cpp)、[QWidget 显隐实现](https://github.com/qt/qtbase/blob/6.12/src/widgets/kernel/qwidget.cpp)

### CTest 套件总时限

CTest 的套件总时限用于防止整套测试挂起，不替代单次操作的响应断言。MSVC Debug 下，`custom-chrome`、`pane-settings`、`caption-strip`、`drag-presentation`、`view-state`、`tab-viewport`、`tab-group`、`memory-lifecycle`、`native-frame` 使用 300 秒，`strip-drag` 使用 720 秒；这些套件在其他配置中仍为 60 秒。其余套件保持各自的时限，内部等待、watchdog、数据行和循环次数不变。

其他套件出现超时时，先按原负载逐个确认是否能完成，记录实际耗时并评审方案，不能套用以上数值。配置改动前后比较 Debug／Release 的完整测试属性，只允许已批准的总时限字段变化。诊断清单和正式验收分别记录；显式 `TIMEOUT` 属性不受 CTest 的 `--timeout` 默认值覆盖。测量和评审见 [验证日志](verification-log/2026-10.md#msvc-debug-套件总时限诊断与评审2026-10-21)。

## 5. WindowSystem 必需用例

模块测试位于 `modules/window-system/tests/`，其中 `fixtures/external-host/` 只使用公开接口和普通 QWidget。除 Muxora 接入测试外，必须验证外部宿主夹具通过安装后的 CMake package 使用模块，防止根项目路径、资源或依赖隐式渗入。夹具用于自动化验证，用户试用的应用始终是 Muxora。

- 中央标签组与标签内窗格分别递归分割、调整大小、方向导航；组内标签前后切换独立生效。
- 四边条带为空时隐藏；点击覆盖展开；固定占独立边缘空间，不在中央新建分割。检查原中央空组收缩规则。
- 单标签与整组收纳、固定、拆出及合并；任何内容类型都具有相同移动能力。
- 拖拽指示、落点预览与最终布局一致；Esc、非法目标、窗口关闭和拖拽中途取消正确回滚。
- 跨完整／轻量浮动窗口移动、窗格命令提取后稳定 ID、内容实例及上下附加栏归属正确；宿主移动不触发关闭或重新创建。
- 视图始终只有一个所有者；关闭回调次数正确；迟到事件不访问已销毁控件，异步关闭结果不作用于新实例。
- 标签上／下栏分别添加、隐藏、移除、取回及替换；无内容时高度为零，焦点和 parent 随移动更新。
- 菜单和工具条解锁重排、锁定、窄窗溢出及宽度恢复；窗口按钮和合法拖窗区域保持可用。
- 主菜单逐命令核对语义分类、二级路径与顺序；单一设置入口、关闭窗口和退出分别可用。浮窗菜单与标题同行，使用本窗口的标签及窗格上下文，过滤退出及布局重置等全局操作；升降级保留完整窗口菜单的原位置。宿主新增命令、中文路径与命令 ID、快捷键修改、窗口形态转换和菜单晚于宿主销毁均有回归，不能靠重复注册 QAction 快捷键实现键盘入口。
- 全部退出只申请一次覆盖所有窗口族的关闭许可；拒绝、回调修改布局或销毁宿主时不部分关闭。最后通知保存完整快照，最终通知只发一次。活动拖拽先恢复稳定布局，取消时的焦点通知也须核验宿主生命周期。
- 四边收纳条只在内容超出可见范围时显示滚动条；逐边检查初始单标签、恰好放下、超出一像素、缩放恢复、删除末尾标签及撤销插入空位。无溢出时停止自动滚动。
- 边缘投放指示保持在本侧边缘，只沿边避让标签条。拖拽中移动、缩放、最大化或恢复目标窗口后，即使鼠标静止也必须更新绘制和命中；禁用悬停唤起后再检查，避免定时刷新掩盖失效。
- 工具条移走后的空间回收分别覆盖空邻居、弹性邻居和普通邻居，以及压缩和拉伸两种起点；弹性右侧调整保持后方条带或窗口边界不动。拖动预览、提交、Esc 与保存恢复使用同一几何预期。
- 每行只有一个弹性条带，覆盖新设置、跨行移动、旧多弹性布局迁移和特殊条带拒绝弹性。标题必须保持弹性，移入的普通弹性条自动改为内容宽度，强制策略冲突在修改前拒绝。旧普通标题布局须恢复弹性，并能重置右侧菜单条尺寸。窗口控制条带可伸长但不能隐藏任何按钮，移动后仍有正确的原生命中和关闭许可。
- 重置尺寸分别覆盖弹性条左侧、右侧和没有弹性条的行，包含压缩、拉伸、空间不足、隐藏条带及保存恢复。左侧保留头部，右侧保留尾部；其他条带的请求宽度和顺序不变。窗口缩放后，弹性右侧的条带按右边缘定位，并在空间恢复后回到请求宽度。
- 弹性空间耗尽且前条已经因窄窗口被压缩时，重置左侧目标仍保留头部；不能只测前条有完整请求宽度的布局，遗漏因前条自动恢复而发生的位移。
- 重置同时验证公开 API、工具条菜单、统一命令和键盘选择入口；无效参数不修改布局，取消选择不产生错误，选择期间窗口关闭能够安全退出。
- 标题在条带内居中，窄条带显示省略文字，可访问名称保留完整标题，悬停不显示标题气泡；三控件保留各自提示。以独立文本绘制参考核验实际像素，覆盖完整与轻量窗口、最小宽度、展开恢复及拖窗／双击交互。
- 标签条的空白滚动区域遵循主题，覆盖深色系统调色板、完整窗口及新建浮窗后的实际绘制，不能从截图中的错误颜色反推测试预期。
- 窗口级标签栏显隐只隐藏中央组，固定、收纳和临时展开区域继续显示及接受操作；覆盖新组、窗口形态与保存恢复。中央隐藏后无布局占位或隐藏命中目标，内容 ID 和键盘导航不变。
- 单标签自动隐藏按整个窗口计数，完整窗口和轻量浮窗默认值分别为关闭／开启；覆盖增加、关闭、收纳、固定、升降级及拖拽预览。显式隐藏优先，固定标题与收纳条仍可用，非法策略和可选字段默认分别检查。
- 四栏显隐分别保存当前窗口、另一形态历史及两种新窗口默认值；旧窗口保存、缩放和关闭不能覆盖新默认。显式编辑、升降级、拖出、提取、拖拽取消及重启恢复保持对应类型偏好；禅模式有效隐藏不写入原偏好，显式创建参数可选择不继承。
- 独立的侧栏显隐只隐藏四边收纳条并关闭当前临时面板，固定分区保留。检查两种窗口、四边、新边栏、中央显隐独立性、菜单／命令／真实快捷键与可选字段默认值；隐藏后明确激活标签仍可展开，定位不计入隐藏条带。
- 四边首次固定分别位于靠外分区；单标签、整组和整侧操作一致，已有取消固定历史仍恢复原位置与尺寸。整侧首次固定和反复收纳／固定保留组间顺序，内容 ID 不变。
- 工具条拖动前后及移动中的预览截图使用相同主题背景，交叉覆盖系统深浅色调色板和应用深浅色主题，检查实际像素及取消后的清理。
- 标签滚动条叠加显示前后，标签与内容的几何不变；紧凑控件在主题、字体及启用状态更新后保持外尺寸，检查实际滑块和内容像素。
- 白色内容背景、矩形四角和四边等厚、标签左右无内部边线、内容边框贴边使用精确像素与几何断言。普通按钮浅色悬停与菜单栏原配色分别检查；标签条与四边收纳条的空白跟随工具栏主题，主题更新不能留下旧局部样式。
- 标签列表下拉宽 12 且与标签等高，加号宽 26、类型下拉宽 12 且组合无边框；检查末尾位置、随标签滚动、联动悬停、类型菜单展开状态、关闭后清理及菜单销毁。新建四种位置、默认活动标签之后、显式索引优先、宿主命令与来源组上下文同时覆盖。
- 浮动面板的外点关闭和模态策略覆盖四种组合、运行中修改、面板内部子菜单、原外部点击只交付一次、所有者销毁及排队回调取消。命令面板执行保留打开时的目标，原目标关闭或跨窗口后不能替换成当前焦点。
- 窗口菜单按完整窗口与所属浮窗列出全部目标，检查创建、关闭、标题变化、改属、最小化恢复、当前标记及失效目标。状态栏控件显隐与整栏显隐独立，右键菜单、命令、API 和布局恢复共用值，非法或重复控件 ID 在修改前拒绝。
- 条带插入让位不改变真实标签数量、顺序或当前项，空位内索引稳定；静止鼠标时自动滚动并重算落点，离开与结束后停止。四边动态呈现检查窗口句柄、捕获、遮罩、真实内容和键盘焦点，并覆盖侧栏→窗口→标签栏连续切换。
- 原条带内起拖不创建工作区窗口，源内容的父控件、位置和可见性保持；只缓存标签图像和阴影。中央、四边固定组及四边收纳条覆盖首尾排序、原标签范围内松手、Esc、首次离开与再次进入、驻留滚动和无鼠标移动的几何刷新。预览销毁回调关闭源标签、拆出通知销毁宿主、目标菜单中关闭浮窗或销毁宿主，都不能崩溃、复活内容或遗留捕获。
- 标签组与固定侧栏组的实际分隔占用默认 2 个逻辑像素，调整比例、窗口缩放和主题更新后仍匹配；内部窗格使用独立尺寸。
- 同步 `layoutChanged → saveLayout()` 检查拖动开始、侧栏呈现、提交和取消期间没有中间 carrier 快照，最后通知必须返回完成后的布局；四边拖动标签与真实收纳标签逐像素比较。
- 标签、窗格和已有窗口的各维度循环移动保留 ID 与附加栏；覆盖唯一窗格、空目标、空源浮窗、非法参数原子失败。T 型布局、全高／全宽组、分隔细缝和稳定顺序分别检查导航；比例命令要改变实际分割而不重建控件。
- 临时侧栏关闭按钮关闭实际标签并经关闭许可，拒绝时保留面板及内容；侧栏右键使用被点击标签的现有命令，Esc 仅关闭菜单。标签完整列表的悬停背景与前景检查真实像素，覆盖浅色、深色和运行中主题切换。
- 窗格上下栏覆盖四种独立组合、缺失栏、显式 Tab 栏、焦点与控件身份、拆分、提取、移动、关闭及策略恢复；无效枚举和不一致快照须在收养或替换内容之前拒绝。
- 位置保存覆盖移动、缩放、最大化、最小化、立即关闭最后窗口及实际应用重启。屏幕归一化覆盖负坐标、多屏并集、缺口、断开屏幕、任务栏可用区域和屏幕小于最小尺寸的情况；不得用主屏 DPR 换算其他屏幕。
- Windows 原生帧在首次显示前准备，保留正常窗口样式且不启用 layered 透明窗口；最小化／最大化／恢复保持几何与内容身份。DWM 转场设置核验实际调用结果及参数，系统动画偏好不改写。动画时序与视觉效果仍需桌面验收，不能把样式检查等同于逐帧验收。
- 原生 region 的限制通过不调用模块的 Win32 夹具核验：完整原生标题样式在无 region 时启用 DWM 非客户区绘制，赋 region 后关闭，即使策略调用成功，清 region 后恢复。另用独立夹具验证从正常窗口切换为无标题完整客户区后的精确 region、显示及重算，要求实际 DWM 持续启用，并覆盖生产调用顺序。实际 Qt 紧凑预览核验完整 region 与缺口命中；普通窗口保留 DWM 边框及精确最大化边界。真实原生绘制消息前后客户区像素、HWND、遮罩、捕获、几何和内容实例保持。同步 placement 消息中回放旧 QWindow mask 时，必须在事务结束立即恢复实际区域；不能仅比较 QWidget 缓存，也不能靠排队重试通过。错误假设的修订须有独立证据和评审，不把启用策略参数当作实际 DWM 状态。
- 细滚动条验证溢出悬停后的实际滑块像素、无前后按钮、拖动同步和不切换标签；图标与文字间距从实际绘制检查，关闭目标仍可点击。
- 鼠标打开工具条菜单后，四种关闭路径均无残留焦点外框；键盘 Tab／Space／Esc 仍能访问菜单并显示合法焦点。检查真实输入后的像素，不能靠再次点击或主动改焦点使测试通过。
- 布局保存／恢复、版本迁移、损坏文件、未知内容、显示器移除；恢复不会生成已删除的业务会话。

模型不变量包括：每个 Tab／Pane ID 唯一且只归属一个位置；分割树没有非法空节点；活动标签和焦点引用有效；取消操作不改变已提交布局；保存恢复后逻辑结构等价。增加有界随机操作序列与故障注入，失败时输出可重放序列。这些断言应独立于具体 Qt 布局实现。

两种顶层窗口共用同一套布局与内容 API。以下矩阵同时进入独立模块、Muxora 接入及必要的真实桌面测试；不能只验证单标签、单组或同一完整窗口内的移动。

## 7. 桌面、DPI 与视觉

新建相邻标签组分别从公开 API 和真实命令调用，覆盖左右两侧、显示前后及原活动标签可见／不可见；原组活动 ID、访问顺序和滚动锚点不得被中间临时标签改变。完整窗口首次普通显示，以及首次直接进入三种全屏或禅模式再退出，都检查整个外框位于屏幕工作区；后续有意移动不反复归位。

侧栏图标和编号与中央栏分别验证默认、设置、菜单和持久化；非固定栏在整侧连续编号。右键普通、固定和非固定标签时，菜单目标必须是鼠标下标签，但活动标签、焦点及当前展开内容保持。颜色检查覆盖四种选中／未选中状态、切换其他标签后再返回和列表前导色条。细滚动条以底层真实像素分别计算普通和悬停的精确 alpha 合成，不用不透明参考或色差阈值代替。原生鼠标定位后，先确认控件已收到进入事件，再检查悬停绘制。

整组移动、交换与合并分别断言源和目标槽位、树结构、比例、顺序及原内容实例；覆盖中央与固定侧栏、方向循环、指定目标、跨窗口、新窗口和四边收纳。收纳命令结束时不自动展开；固定移动可以聚焦目标。参数类型和整数范围必须严格拒绝错误输入，失败不部分修改模型。

标签条滚动回归覆盖中央、四边固定组和四边收纳条：在非零位置拆出标签、首尾驻留后移开及 Esc 取消，保持有效偏移；标签总长度缩短只允许范围截断。分别在条内预览和真实浮窗捕获期间发送滚轮角度／触控板像素增量，检查鼠标下条带滚动、活动标签不变和捕获保持。明确导航到标签仍须使其可见。

单行条带的最大偏移始终来自实际内容宽度，禁止为活动标签补出可滚动的空白。能放下全部标签时偏移必须为零；连续从两侧缩小、扩大和拖动分隔线时保留未受约束的显示位置，边缘触及原先可见的活动标签后只移动必要距离。取消固定会新增收纳条，使用实际视口坐标与偏移共同检查内容锚点，不能假定两种布局的原始偏移必然相等。

多行模式逐行检查标签几何、点击、插入序号和单行预览空位，不再使用横向滚动条。覆盖顶部／底部位置、全部行／仅活动行、行首行末、超宽载荷及跨行重排；隐藏行不能成为投放目标。条内阶段保留真实内容和窗口数，首次离开整个可见标签区域才拆出；跨组投放和 Esc 分别核验精确顺序、空源组清理、窗口清理及原 Pane／内容身份。颜色、编号和图标开关检查实际绘制与几何，不能只读配置值。

最大化三控件的回归取显示器工作区的真实顶边和右上最后一个物理像素，检查命中、悬停、捕获、单次点击及内容身份。先等待 Win32 客户区达到独立计算的工作区矩形，再转换这个固定屏幕点，避免使用动画前缓存的客户端坐标。应用菜单和设置下拉检查原生方角、触发矩形对齐及子菜单展开时父项不反复隐藏／重排；全屏另检查实际 Qt／原生状态、显示器矩形、零边距与平台绘制参数。

伸缩矩阵分别覆盖左右／上下新建组、固定四边、分隔调整、实际完整窗口从左／右缩小及扩大、视图重建。原活动标签完全可见和原先不可见分别检查；尾部标签也遵守真实内容范围，不添加空白。连续缩放保持真实标签数和内容身份，滚轮、滑块、明确导航及拖拽驻留可取消排队旧定位；单纯窗口平移不滚动。短标签初次显示和未显示状态恢复必须自然适配，不能因初始临时几何出现多余偏移或尾部空白。

临时展开尺寸逐标签检查左／右共用、上／下共用的两套请求，两套各有独立可选宽高。覆盖四边两轴和角部拖动、各轴缺省的填满或默认大小、只改一轴、关闭重开、跨边／跨窗口及持久化；四边边框留白一致且调整命中范围不挤占内容。固定分区尺寸和临时尺寸互不修改；小视口只限制本次显示，不覆盖已记忆请求。尺寸 API 显式指定方向，重置不修改另一套策略；非法类型、非整数和越界尺寸拒绝恢复并保持现有状态。

最大化按钮覆盖普通／最大化、完整／轻量窗口的上沿、中央和下沿原生命中、Qt 悬停／离开及图标状态，同时保留四边角缩放和固定尺寸轴。隐藏、禁用、全屏和紧凑预览不提供 Snap 命中；这些自动化证据不能替代实际系统弹窗验收。

屏幕边缘回归还覆盖正常窗口已占满工作区再最大化：最小化、还原和关闭按钮必须命中真实工作区的最后物理像素。最大化外框使用独立 Win32 接口计算，实际客户区必须精确等于工作区或公开最大尺寸；普通 tracking 值不加框，Qt 与系统命令还原后复核。位置纠正只允许修改已确认的框架工作区纠正请求，模拟跨屏目标和其他拟定矩形保持不变；该消息分派检查不替代真实多屏／DPI 切换。

工具条布局分别验证完整和轻量形态的当前布局、另一形态缓存和新建默认。多个旧窗口晚保存、缩放、恢复或取消拖动不发布默认；旧窗口只修改宽度、锁定或某个按钮时，通过字段和按钮差分保留较新顺序及其他修改。恢复完成后通知同步保存者，所有坏输入在内容工厂调用前拒绝，精确检查旧模型、控件和保存快照保持。

浮窗工具条位于中间、第二行和底部时，实际整窗拖拽连续两次进入标签条再离开，分别检查释放和取消。正常窗框保留 DWM 绘制；客户区右上角像素在原生激活、绘制及主题绘制通知前后必须精确等于 Qt 参考，不用色差容差代替 Basic 三控件回归。

这类屏幕像素用例的辅助投放目标不播放自身的系统过渡，防止它的动画画面短暂覆盖被测窗口；只在该辅助 HWND 上设置，不修改全局系统偏好。被测浮窗保留原生动画、原像素采样点和等待上限。

自动化覆盖 100%、125%、150%、175%、200%、250%，以及工作区、独立窗口、菜单、拖拽浮层、侧栏和输入法的混合 DPI 变化。验证逻辑尺寸、物理像素、命中位置、文字裁切、焦点、可访问性语义、负坐标屏幕和屏幕移除。

```powershell
        New-Item -ItemType Directory -Force out/test-results | Out-Null
        $env:QT_SCALE_FACTOR = "1.5"
        & $tc.Ctest --test-dir out/build/dev-debug --no-tests=error --output-on-failure --output-junit out/test-results/ui-scale-1.5.xml -R "^window-system\.(tab-bar-presentation|tab-viewport|tab-strip-layout|tab-appearance|edge-tab-interaction|caption-strip|native-frame|popup-menu|pane-settings|compact-ui|menu-structure|tab-group)$"
        $taskExitCode = $LASTEXITCODE
    } finally { Exit-Toolchain $tc }
    exit $taskExitCode
'
```

将倍率改为 `"2"`、报告文件改为 `ui-scale-2.xml` 后再运行一次；每次都检查 CTest 的通过／失败结果及退出码。`QT_SCALE_FACTOR` 只在该测试子进程中设置，会叠加系统缩放，不能把 `1.5` / `2` 直接当作最终屏幕 DPR。这十二套程序判定的组件检查不代表混合 DPI、跨屏原生交互或完整倍率矩阵已经验收。

视觉回归使用固定 Windows／Qt／字体版本及有理由的局部像素容差，由程序检查原分辨率图像。不能为消除失败而扩大容差、遮掉变化区域或自动更新截图基线。合法视觉变更附需求依据和程序差异报告，经审阅后更新；图像只作为问题分析的辅助材料。

Qt 事件模拟与离屏渲染用于快速组件检查；真实桌面测试另外覆盖系统拖拽、Snap、最大化、系统菜单、输入法和跨屏缓存更新。人工观察可帮助分析清晰度或系统行为，测试通过仍须有程序判定规则。缺少判定或执行环境的项目分别记录为未执行或环境阻碍，不用人工读图或 computer use 代替测试，也不宣称已通过。

真实 Windows 桌面必须覆盖完整／浮动窗口重叠、跨窗口族及混合 DPI 拖拽；分别从标签与浮动标题栏开始，经过被遮挡目标、拖拽预览及非应用窗口，核验实际置前、指针捕获、焦点和落点。最小化、最大化、Snap、系统拒绝置前和完全遮挡的目标选择都要有独立证据。取消后的恢复检查仅约束应用自身可恢复的状态，不要求重建其他软件的全局层叠顺序，也不能为了恢复而重新抢焦点。

## 8. 性能、压力与内存

改动热路径（脚本运行时、布局刷新、绘制、按键分发等每次操作都会经过的代码）时，在同一台机器上对比改动前后的耗时，把数字写进验证日志；不能只验证功能。

长标题绘制定向基准为可选目标 `window-system-title-benchmark`，负载和输出字段定义在 [基准源码](../../modules/window-system/benchmarks/title_rendering_benchmark.cpp)。它只把真实标签控件绘制到固定大小的离屏图像，不显示窗口、不发输入，也不设置依赖机器的性能阈值。首帧单列，重复绘制均值不包含控件构造和初次尺寸计算；不能据此宣称首次排版开销消失。

布局规模基准的 `restore` 场景先用模型生成完整标签和内容描述，再通过一次 `restoreLayout()` 创建全部宿主内容、显示窗口并进入事件循环；内存记录的 `workspace` 为 `restore`。它衡量“未显示标签不创建页面视图”，不能和逐个添加并激活的 `create` 场景混为一谈。可用 `pwsh tools/bench.ps1 -Name <名字> -Tabs 1000 -Repeat 1 -Scenario restore` 单独测量；前后比较必须使用同一机器、平台、参数和基准源码。

```powershell
. ./tools/toolchain.ps1
$tc = Enter-Toolchain (Resolve-QtKit "" (Get-Location).Path)
$priorPlatform = $env:QT_QPA_PLATFORM
try {
    & $tc.Cmake --preset dev-release -DWINDOW_SYSTEM_BUILD_BENCHMARKS=ON
    & $tc.Cmake --build out/build/dev-release --parallel 4 --target window-system-title-benchmark
    $env:QT_QPA_PLATFORM = "offscreen"
    ./out/build/dev-release/modules/window-system/benchmarks/window-system-title-benchmark.exe --commit <源码版本> --out <报告文件>
} finally {
    $env:QT_QPA_PLATFORM = $priorPlatform
    Exit-Toolchain $tc
}
```

前后使用相同的标题、字体、平台、画布和迭代参数；具体数字只写进验证日志。基准目标默认关闭，普通构建和 CTest 不执行它。

依据工程文档的资源预算和响应目标，在固定参考机器、构建、数据量及负载下测量。首个原型建立经审阅的基线与容差，后续变更保留前后数据；失败不能通过重新定义基线解决。本地操作初始 p95 50 ms 目标和网络往返分别统计。

自动化场景包括多终端持续输出、文件传输并行、大目录、快速切换与调整尺寸、反复连接／关闭、四边展开／固定、跨窗口移动、传输取消、配置刷新和退出。循环次数、运行时长、输出速率、文件规模及允许增长在测试配置中固定，不能随失败结果缩减。

窗口压力矩阵加入反复拖出／回并、浮动与完整模式转换、整窗移入、窗口族关闭取消和悬停切换目标；检查窗口、预览、计时器、捕获、命令上下文及关闭协调对象最终释放。移动期间不复制终端历史或整套业务状态，隐藏目标不持续重绘；转换后的连接数与传输任务数保持符合操作语义。

检查 private bytes、native heap、句柄、线程、对象、连接、队列、缓存和辅助进程总量。允许有依据的预热与分配器保留，但资源必须受预算约束，关闭后不保留失去用途的实例；定位持续增长和引用残留，不能只看一次工作集截图。

Windows 建立 ASan 诊断构建检查非法内存访问，另用资源计数、堆快照和循环趋势检查泄漏；ASan 不等于完整泄漏检测。第三方诊断覆盖范围如实记录。[MSVC ASan](https://learn.microsoft.com/en-us/cpp/sanitizers/asan?view=msvc-170)

已确认泄漏、越界、悬空访问、双重释放、无界增长、错误关闭用户资源，以及普通操作明显阻塞 GUI 均阻断发布。节约内存与快速响应必须有测量证据。

## 9. 持续集成与发布

完整链路如下：

```text
需求与断言
→ 固定工具链和依赖
→ 格式／静态检查及构建
→ 单元、模型、组件和独立模块测试
→ 真实 SSH／SFTP／终端与应用桌面测试
→ Windows／DPI、诊断、压力及 Release 性能测试
→ 生成发行包
→ 干净 Windows 发行包端到端验收
→ 汇总证据并决定是否可以发行
```

| 时机 | 必需运行 |
| --- | --- |
| 每次变更及合并前 | 固定 Windows 工具链构建、格式／静态检查、快速单元与模型、相关组件及回归；协议或桌面行为变更必须运行对应真实测试。 |
| 定期完整运行 | 全部协议、桌面、DPI、诊断、压力、长期运行及性能组，不依赖开发者偶尔手动执行。 |
| 依赖升级 | 固定新版本，重建适配和测试；完整运行受影响领域、资源对比、当前布局恢复与打包验证，不只证明新头文件能编译。 |
| 每次发布 | 完整必需套件、补充人工检查、许可证与组件清单、最终包在干净 Windows 中的端到端运行。 |

原生桌面及多屏测试使用专用可复现 Windows 环境；不把无交互桌面的普通 CI runner 当作已经覆盖这些场景。必需检查不能通过脚本的忽略错误设置放行。环境缺失时说明缺什么并补齐，发布不能把缺失项当成默认成功。

干净发行包验收移除开发 SDK 和工具对 PATH 的影响，只使用声明的运行前提。检查核心 SSH、终端、文件、布局和 X11 可选组合；保存构建来源、产物路径及版本清单，记录实际验证的发行文件。哈希校验遵循 [仓库规则](../../AGENTS.md#必须遵守)。

报告保留提交、依赖 commit／版本、工具链、Windows、Qt、字体、屏幕缩放、测试配置、各结果分类数量、日志、截图、崩溃／诊断记录及性能数据。缺陷修复至少重跑原失败用例与相关回归；最终发行仍须满足完整发布检查。

## 10. 测试目录规划

窗口模块的测试已放在 `modules/window-system/tests/`，本机完整验证入口为 `tools/verify.ps1`。

`tools/tests/deployment-test.ps1` 检查固定部署目录的反复覆盖：清除旧运行库、插件和重复许可证目录，保留 `data/` 与未知用户文件；生成清单只包含程序运行文件。删除操作须拒绝输出根目录、根外路径和链接，不能把清理临时部署当作用户状态迁移。

`tools/tests/toolchain-test.ps1` 不需要编译器，检查构建目录能否沿用：编译器不同，或 `rules.ninja` 记录的头文件依赖前缀与当前 `cl` 输出不同（另一种代码页或语言）时必须判为过期。

窗口显隐与全屏的回归分别检查保存偏好和有效状态：普通窗口与三种全屏范围共用四栏偏好，普通窗口启动禅模式按配置原子进入对应全屏范围，已有全屏保留范围，显示任一栏后恢复其他偏好。模型、公开 API、真实 Qt 快捷键、菜单勾选、设置页以及原控件和分割尺寸都需核验；非法禅模式范围必须在内容工厂调用前拒绝。标题区无提示气泡，窗口控制按钮保留各自提示。工具行覆盖顶部／底部多行、跨区移动、末行预览、空行消失和十万行稀疏布局的控件数量，不能只验证最终坐标。

全屏和禅模式改为临时状态后，分别断言运行时切换有效、快照不含当前模式，以及重启恢复正常／最大化状态和原栏偏好。非当前窗口字段在内容创建前原子拒绝，不读取临时模式字段。按键等待提示覆盖完整命中、执行失败、取消、超时、焦点、输入法、绑定和命令目录变化，等待期间写入的普通消息结束后仍显示。按键查询覆盖前缀与完整序列，并断言没有执行命令或修改绑定。

固定区域按四侧 × 四方向分别检查模型和实际控件几何，覆盖单标签、整组、整窗投放、内部比例与中央／其他侧隔离、取消固定重建原槽位和当前快照往返；显式固定树中的重复、错侧与失效引用必须原子拒绝。层级转换分别检查原 Pane ID、内容与栏实例、活动目标、源清理、跨窗口、无效目标，以及内容 reparent 回调关闭目标、恢复布局或销毁管理器的重入。内容最小尺寸覆盖显式值、hint、动态变化、多层分割和大于屏幕的要求，调整后不能发生内容重叠。

`tools/tests/application-view-test.ps1` 使用实际 Release 部署程序和隔离状态目录，移除 SDK／插件路径后反复启动，检查独立显隐、三种全屏及正常／最大化位置恢复、禅模式恢复和底部工具条布局。它不接触用户状态，失败立即停止；进程正常结束后清理临时目录。记录包含实际运行结果。GUI 检查串行执行，避免多个用例同时改变前台窗口和输入状态。

后续业务测试与 CI 按以下结构逐步建立，并随模块代码一起维护；未创建的目录不代表已有覆盖：

```text
modules/window-system/tests/   # 模型、公开 API、控件与独立复用
tests/unit/                   # 会话、路径、预算、任务状态等
tests/integration/            # 第三方适配与宿主模块接入
tests/e2e/                    # 真实协议、应用桌面和最终发行包
tests/fixtures/               # 可复现服务、输入样例和固定数据
tests/support/                # 有明确用途的测试辅助代码
benchmarks/                   # Release 性能与资源测量
ci/                           # 检查编排及测试环境说明
tools/testing/                # 本机和 CI 共用的执行入口
out/                          # 忽略提交，内容见 §3 测试结果与排查文件
```

测试框架、fixtures 与 runner 也有维护责任和版本记录。完整链路从最初的独立窗口及协议原型开始建立，功能增加时补齐对应用例；设计阶段的清单不能冒充已经实现的测试覆盖。
