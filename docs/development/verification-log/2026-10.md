### 钉住行占满时单行标签栏多出滚动条（2026-10-24）

用户试用时发现：钉住标签单独一行、而且钉住的很多时，单行标签栏莫名出现横向滚动条，下面一行也被滚走一点，其实两行都放得下。原因是单行时画布宽度一直按“标签条宽度 + 新建按钮宽度”计算；钉住的几行换行后宽度接近视口，标签条宽度取的是它们，再加上新建按钮就超出视口，而新建按钮实际在下面一行靠前的位置。修正：画布宽度取标签条宽度与新建按钮右端两者中较大的，普通单行时两者相同，行为不变。

`StickyTabsTest::fullStickyRowsDoNotMakeTheStripScroll` 让钉住行排满到离视口边缘不足一个新建按钮的宽度：去掉修复时滚动范围为 31 像素而失败，修复后为 0、下一行从 0 开始。`sticky-tabs`、`tab-strip-layout`、`tab-viewport`、`tab-bar-presentation`、`compact-ui`、`tab-creation`、`strip-drag`、`drag-presentation`、`edge-tab-interaction`、`view-reuse` 通过。

### 关闭多行时保留滚轮展开（2026-10-24）

用户试用时提出：关闭再开启多行标签后，滚轮展开要重新勾选，应该保持不变。原设计是关闭多行时清除滚轮展开，外观校验也拒绝“单行 + 滚轮展开”的组合。按用户决定改为：两者独立保存，滚轮展开只在多行时生效；设置页复选框和菜单项在单行时不可用但保留勾选，单行时的滚轮照常横向滚动。删除了设置页和菜单命令里的清除，以及校验中的这条限制；标签条按“多行且开启”决定是否收起。

原先断言“关闭多行即清除”的三处测试（外观命令、设置页、菜单）按新决定改为断言保留并在重新开启后恢复；校验失败用例中这一项换成非法的钉住尺寸，JSON 非法值表删去这一行并在命令用例里补了往返检查。新增 `TabStripLayoutTest::keptWheelExpansionWaitsForMultipleRows`：单行时滚轮横向滚动，开启多行后收起到活动行，滚轮再展开全部行。`tab-appearance`、`tab-strip-layout`、`menu-structure`、`pane-settings`、`popup-menu`、`view-commands`、`tab-viewport`、`view-state`、`sticky-tabs`、`tab-bar-presentation` 和三个 Lua 套件通过。

### 多行拖动最后一行唯一的标签时插入位置来回跳（2026-10-24）

用户试用 8.15b 预览时发现：多行标签栏的最后一行只有一个标签，拖着它在加号右边横向移动，插入空位在上一行和原位置之间快速来回闪。临时用例在 925–1550 像素的多种窗口宽度下复现，有无钉住行都一样，是多行模式原有的问题：拖起这个标签后最后一行只剩插入空位，命中计算只按标签找最近的一行，指针在最后一行却被算成上一行中间的位置；空位移上去后上一行挤不下，又把标签推回最后一行，下一次移动再算回原位。修正：插入空位也算作它所在行的一员，参与“最近一行”和左右比较；指针在只剩空位的行上时保持当前位置。

`TabStripLayoutTest::draggingTheOnlyTabOfTheLastRowAlongItKeepsItsSlot` 用真实拖动沿最后一行逐 5 像素移动，检查插入位置和空位所在行不变；去掉修复时在第一步失败（插入位置变成上一行的 1），修复后通过。`tab-strip-layout` 61 行，以及 `sticky-tabs`、`strip-drag`、`drag-presentation`、`drag-interaction`、`tab-viewport`、`tab-group`、`edge-tab-interaction` 通过。

### 钉住标签的外观与保护（8.15b，2026-10-24）

多行标签栏的悬停提示：QTabBar 按它自己的单行排布找提示属于哪个标签，多行时第二行起的标签对不上，在第三个标签（第二行）上悬停没有提示。钉住标签固定在视野里以后单行也会用自绘排布，所以先修：自绘排布时按显示的位置找标签。`TabStripLayoutTest::multilineTooltipsNameTheDisplayedTab` 逐个标签检查提示文字，去掉修复时在第三个标签处失败（提示为空），恢复后通过；`tab-strip-layout` 60 行、`tab-bar-presentation`、`compact-ui` 通过。

第 1 项 `tabs.stickySizing`：查了 VS Code 的实现（`multiEditorTabsControl.ts`）：紧凑宽 38、收缩宽 80；紧凑只显示图标，没有图标时显示名称首字大写，不显示标签上的操作按钮；单行时钉住标签用 sticky 定位留在开头。这里照做，并照 VS Code 的 `tab.lastPinnedBorder` 在最后一个钉住标签右侧画一条主题边框色的线：截图核对时，收缩尺寸下被遮住一半的标签标题紧贴在钉子后面，看起来像同一个标签。实现上，单行固定显示时标签栏改用自绘排布（多行原本就是），钉住标签按滚动位置平移；点击、悬停、提示、插入位置都按显示的位置算，盖在下面的标签不响应；激活被遮住的标签时滚到它露出为止，外观变化和视口重排的锚点也扣掉钉住段的宽度。拖动时，插入空位在钉住段里就用钉住标签的宽度，在其他标签之间用标签的正常宽度；放下时按空位所在的一段决定钉住与否（只有拖出到别的窗口再拖回时才和模型的默认规则不同）。

第 2 项 `tabs.stickyTabsOnSeparateRow`：有钉住标签时，它们排在上面单独的行里，单行模式下这几行放不下也换行，并随滚动平移保持不动；其他标签从下一行开始照常滚动。列表按钮跟着下面一行。多行收起时显示钉住的行和活动标签所在的行，激活钉住标签不改变显示的那一行。两行各是一个落点：最后一个钉住标签之后这个位置在两行都存在，由拖动时指针所在的行决定钉住与否，放下后按空位所在的行修正。只剩被拖着的那个钉住标签时，钉住的行仍然保留（空着），标签栏高度在拖动中途不变。

### 计数钩子恢复用例的取消时机（2026-10-24）

8.12 的统一入口在 `a04fa57` 加入口接入改动上运行 `verify.ps1 -ReleaseOnly`：翻译覆盖、11 个反向用例、部署 12 项及工具链 5 项自测通过；Release 全量 62/63、320.86 秒，实际数据行 2716 通过、1 失败、0 跳过。菜单两个套件本次通过；失败为 `ScriptRuntimeTest::retainedCoroutineCountHookKeepsItsInterval`，`recovered.ok` 为假，错误来自恢复脚本第 2 行的挂起状态断言。入口因此停止，独立模块、外部宿主和部署尚未执行。

**独立对照**：从 `c4149e9` 导出原 LuaRuntime 和测试，使用同机同 Qt／MSVC Release，链接本轮没有修改的同一官方 Lua 库；只给原状态断言加输出状态的诊断，不改条件。按预定次数运行原用例：

| 版本与原夹具 | 通过／运行次数 | 失败运行及结果 |
| --- | --- | --- |
| 迁移前 `c4149e9` | 38/40 | 第 2、34 次，恢复前协程为 `dead`，原 `suspended` 断言失败 |
| 迁移后 `a04fa57` | 38/40 | 第 11、24 次，同一 `recovered.ok` 断言失败 |

根因是测试没有控制取消点：ready 日志只唤醒另一线程，取消可能在用户计数回调中发生。回调通过无 continuation 的 C `lua_pcall` 执行，此处不能挂起；停止会以错误结束协程，合法地得到 `dead`。这与“保留下来的挂起协程恢复后，首次 count 回调不能提前”是两种前提，依据见 [Lua C 调用的让出边界](https://www.lua.org/manual/5.5/manual.html#4.5) 及现有 worker 的停止分支。

### 标签长度变化时的条带滚动（2026-10-24）

用户反馈：在 Codex 交出的版本里调标题长度，设置页内容会自己滚动，把滑条滚到屏幕中间；在当前版本里没有出现。新增 `PaneSettingsTest::titleWidthUpdatesKeepScrollPositions`（键入、上下键、拖动滑条，检查设置页滚动位置），在临时工作树里用 `d31eaa8` 构建同一用例，设置页在旧版本和当前版本都没有滚动，**原因没有找到**，我的改动也没有触及设置页；只能如实记为“自动化无法复现、用户试用时未再出现”。该用例保留，检查这一要求。

### 标签内部排布与关闭按钮反馈（2026-10-23）

用户报告：收纳条标题长度调小或设为 0 时，标签两端到图标、文字的留白反而变大；标签栏标题设为 0 时，图标与关闭按钮之间是两个间隙；收纳条标签本身留白偏大；关闭按钮悬停没有反馈。原因：收纳条标签长度有 64 的下限，标签栏有 46 的下限，内容不足时多出的长度都变成两端留白；图标、编号的宽度各自自带尾随间隙，标题为 0 时间隙仍在；同一套尺寸在标签栏的尺寸、绘制、拖动预览三处各写一遍。

现在由 `style/tab_label_geometry.hpp` 统一计算：只在显示的部分之间留一个 4 像素间隙；收纳条两端各 8（原 12），长度正好容纳内容，空内容不短于收纳条厚度；标签栏两端仍为 7，保留 46 的下限，因为没有图标的单字标签更窄时，中心会落进关闭按钮的点击区（首轮 `strip-drag` 中 20 行固定栏失败即为此，报告 `out/test-results/claude-tab-geometry/strip-drag-first.txt`；收纳条单字标签的 4 行失败是测试假定标签长于 40，改为在标签内、超过拖动阈值的距离）。关闭按钮悬停时下衬标签文字色 16% 的圆角底色，按下时 28%。规格写入 [界面设计规范 §2.2](../../design/ui-design-system.md#22-尺寸)。

新增回归：标签栏标题为 0 时宽度 50、图标在 7–22、关闭按钮底色从 26 开始；收纳条标题 0／1／40 时长度和两端各 8 的图标位置（横竖两向）；关闭按钮悬停与按下的底色、移开松手不关闭、在按钮上松手关闭。原有用例中按旧公式写死的长度（+35、+24、编号 +5、下限 64）按新规则改写，断言内容不变。相关 12 个套件经 `quiet-desktop.ps1 -Elevate` 通过；随后在 `15635b9` 加本节改动上跑 Release 全量 63/63 通过（329 秒）。未做三主题截图审查和真实试用，没有用 computer use。

### 标签栏替换的删除时机（2026-10-23）

审查 Q3 时核对 `TabContent::setTopBar()`／`setBottomBar()`：替换时立即 `delete` 旧栏，而窗格栏用 `deleteLater()`。宿主在旧标签栏自己的按钮回调里替换标签栏时，同步删除会在信号发出途中删掉发送者。现与窗格栏一致，旧栏立即隐藏、由事件循环删除。

### 完整 Lua 标准库与协作停止（2026-10-20—21）

### 窗口控制按钮顺序与四角点击（2026-10-20）

设置“窗口 › 显示 › 窗口控制按钮顺序”（`window.captionButtonOrder`，Lua 中为 `caption_button_order`）是一个下拉框，有三种顺序：Windows（最小化、最大化、关闭，靠右，默认）、反向（关闭、最大化、最小化，靠左）和 macOS（关闭、最小化、最大化，靠左）。把窗口控制工具条拖到左上角并选后两种之一，关闭按钮在最左侧。设置随布局保存；同日早些时候的“反向排列”复选框（`reverseCaptionButtons`）没有发布过，已由这个下拉框取代，旧值不迁移。

工具条行的首尾不再保留 2 像素留白：普通窗口中，每行第一个和最后一个工具条（菜单、窗口控制条等）紧贴 1 像素窗口边框，与 Windows 原生标题按钮一致。按钮外侧与窗口缩放区重叠的部分仍优先缩放，最大化按钮整块仍返回 `HTMAXBUTTON`：原有的贴靠测试增加了三种顺序，普通和最大化窗口下最大化按钮的顶部、中部、底部都返回 `HTMAXBUTTON`。

窗口控制条的宽度固定为三个按钮宽（126 个逻辑像素）。此前它可以被拖宽，相邻工具条移走时还会接收对方的宽度（为保持其他工具条位置不变的规则），按钮旁边因此出现空白；用户的实际布局中完整窗口存了 138、轻量浮窗存了 349。现在它不能拖宽、不接收相邻宽度，旧布局里保存的宽度在恢复时忽略。原来借用窗口控制条测试宽度保存、按窗口类型记忆和重置的用例，改用菜单或工作区工具条，断言不变；另增加窗口控制条拒绝调宽、不接收移走工具条的宽度、恢复时忽略旧宽度的检查。

**最大化时切换按钮顺序（2026-10-20）**：最大化窗口的“最大化”按钮角色是 `restore`，重排时没有被认出，这个按钮被移出布局却没有放回，叠在其他按钮上，窗口控制条也只按两个按钮计算宽度。现在重排时把 `restore` 当作最大化按钮，并且任何没有匹配到的按钮都会放回布局。新增用例在最大化状态下依次切换四次顺序，检查三个按钮都可见、首尾相接、没有重叠、条宽 126，还原窗口后顺序保持；撤掉修复时该用例失败。

**滚轮不再修改控件的值（2026-10-20）**：下拉框、数字框、日期时间框和滑块（不含滚动条）上的滚轮不再改值，而是交给外层滚动区域，设置页等页面照常滚动。规则由窗口模块的应用级事件过滤器统一处理：滚轮先到达的可能是数字框或可编辑下拉框内部的输入框，因此从收到事件的控件向上找所属的值控件，但不越过窗口边界，已经打开的下拉列表照常滚动。新增用例：设置页中“禅模式默认全屏范围”“显示延迟”“窗口控制按钮顺序”上前后滚动，页面移动、值和保存的布局不变，键盘仍能改值；另一组覆盖普通下拉框、可编辑下拉框、整数和小数数字框、日期时间框、滑块，以及滚动条和打开的下拉列表仍能滚动。

**最大化时右上角的关闭按钮（2026-10-20）**：窗口最大化后，鼠标顶到屏幕右上角点关闭没有反应（200% 显示器与 150% 笔记本屏幕都出现）。最后一列物理像素换算成逻辑坐标后超过最后一个整数像素（1919.5、1279.33），Qt 找不到子控件，点击交给了窗口本身；上一轮把最小化、关闭改为 Qt 按钮后才出现。现在最大化和全屏时，平台层把客户区鼠标坐标收到最后一个整数逻辑像素以内，贴在屏幕右边和下边的控件都能被最边上的像素点到。角落和边缘用例改为发送 Windows 鼠标消息，新增 `window-system.caption-strip-scaled` 以 `QT_SCALE_FACTOR=0.75` 模拟 1.5 倍率再跑一遍。150% 的笔记本上由用户试用确认前，这一点尚未在真实 150% 屏幕上验证。未最大化时窗口边缘仍用于调整大小。

**溢出菜单让整个窗口状态异常（2026-10-20）**：菜单条在下方区域压缩后拖到上方一行，再在溢出菜单里来回悬停被隐藏的菜单，状态栏会只剩背景色，按钮没有悬停高亮，最大化按钮也不再出现 Snap 浮窗，重启才恢复。原因是弹窗的方角设置在 `aboutToShow` 里调用 `winId()`：菜单关闭时 Qt 会销毁它的句柄，再次打开时这个调用会让 Qt 把菜单栏的所有子控件标成原生窗口，已创建过的扩展按钮随即带着整条父链和各级兄弟控件变成 15 个原生子窗口。现在只在句柄已存在时设置，句柄由 Qt 在显示前创建；下拉框的列表弹窗同样受益。新增 `CaptionStripTest::compressedMenuStripMovedUpKeepsTheWindowAlien` 和 `ToolbarPopupTest::hoveredOverflowMenusKeepTheWindowAlien`，撤掉修复时分别检出 15 个和 1 个原生控件。`caption-strip`、`toolbar-popup`、`popup-menu` 三个套件在修复后通过；之后为真实输入加了只发给本进程窗口的防护（`tests/native_input.hpp`），并新增 `tools/tests/quiet-desktop.ps1`：先最小化其他应用窗口再运行测试，结束后恢复。

**压缩菜单条中被裁掉的菜单（2026-10-20）**：菜单条变短时后面的菜单被裁掉、列入溢出菜单。此前打开一个可见菜单后把鼠标移到被裁掉的区域，仍会打开那里看不见的菜单：菜单打开期间 Qt 按坐标把鼠标移动转给菜单栏，不区分是否被裁掉。现在菜单栏只在可见部分响应鼠标。另外，溢出菜单里的菜单就是菜单栏上的同一个菜单，显示时一律定位到菜单栏原位置下方，遮住溢出菜单；现在按实际打开它的菜单定位，从溢出菜单打开时贴在溢出菜单旁边；用方向键切到被裁掉的菜单时在菜单条可见末端打开。新增用例 `clippedMenusDoNotOpenFromThePointer`、`clippedMenusOpenBesideTheOverflowMenu`，撤掉修复时分别复现“打开隐藏菜单”和“子菜单与溢出菜单重叠（x=460 与 460..617）”。

**工具条按固定端调整宽度（2026-10-20）**：弹性条带右侧的工具条从行尾向左排，固定端在右边。拖动其把手时改为由被拖条带自己变宽变窄（右边缘不动、左边缘跟随鼠标），前方条带只平移、宽度不变；固定宽度的窗口控制条拖动时只能调整顺序，不再出现“窗口控制没动、前面的工具条却在缩小”。从其他行拖入右侧时，拖入的条带从鼠标处延伸到右邻，前方条带不再随鼠标伸缩；从右侧拖走时由右邻补位，左侧条带位置不变。弹性左侧的行为不变。规则写在 [窗口交互设计](../../design/window-interaction-design.md)。原有用例 `rightOfElasticStripsResizeAgainstAnAnchoredRightEdge` 断言的正是旧的“前方条带反向变宽”，按新规则改为检查前方条带宽度不变、随分界线平移、弹性条带吸收差值；新增固定宽度只排序、拖入右侧延伸到右邻、从右侧拖走由右邻补位三个用例，在旧逻辑下全部失败。

**最大化时窗口控制只显示一种提示（2026-10-20）**：上一版拦下 `WM_NCMOUSEHOVER` 后，最大化时系统提示与 Qt 提示同时出现：只要命中测试返回系统标题按钮，Windows 就自行跟踪悬停并显示提示，与窗口如何处理悬停消息无关。现在最小化和关闭在任何状态下都是 Qt 客户区（`HTCLIENT`），只有最大化／还原返回 `HTMAXBUTTON` 以显示贴靠布局，与普通窗口一致；为最大化另加的悬停计时和 `WM_NCMOUSEHOVER` 拦截已删除。最大化后客户区本来就铺到屏幕边缘，边缘像素仍落在 Qt 按钮上，屏幕边缘和四角的点击测试改走 Qt 鼠标事件后通过。

**提示气泡（2026-10-20）**：

- 从一个控件快速移到另一个控件时，Qt 会复用正在显示的气泡，复用时丢掉窗口样式表里的内边距和边框，气泡变小（实测高度 30 → 20）。现在提示规则同时写进应用样式表中带标记的一段（宿主自己的应用样式不受影响，主题不变时不重设），复用后的气泡大小和样式与第一次相同。
- 长提示按形状换行：400 个逻辑像素以内保持一行；更长时选最少的行数，使每行不超过 400 像素，或气泡宽度不超过高度的 8 倍，所以文字越长气泡越宽，而不是固定宽度后越来越高。实测：约 1000 像素长的文字为 299×80，六倍长度为 721×128（最初按固定 400 像素换行时，很长的文字会变成又高又窄的竖条；Qt 自己在超出屏幕时换行则得到 476×192）。富文本和自带换行符的提示不改。规范 §4.5 原来写的 60 个汉字宽度同步更新。
- 最大化时三个窗口控制按钮曾是系统标题按钮命中，悬停时显示 Windows 默认的黑边黄底提示。先尝试拦下 `WM_NCMOUSEHOVER` 并另行显示 Qt 提示，结果两种提示同时出现，已改为下面“只显示一种提示”的做法。
- 测试：复用不变小、长提示换行（新建与复用两种）、最大化时显示主题提示并在相邻按钮间立即切换，撤掉对应修复时三项都失败。测试中关闭了系统的提示淡入动画（淡入窗口激活会在测试里提前关掉气泡）并先激活窗口（非活动窗口的气泡会立即关闭）。最大化提示测试在关闭按钮被其他程序的置顶窗口遮住时会明确报告遮挡。整组运行时，用户正在使用其他程序会触发 Windows 的前台锁，测试窗口提不到最上层（`raise()` 也无效），这一项会报告被当时排在上面的程序遮挡；单独运行稳定通过。

**滚轮不再激活数字框（2026-10-20）**：数字框、下拉框等控件的焦点策略默认是 `WheelFocus`，Qt 在交给任何事件过滤器之前就把焦点给了滚轮下面的控件，所以页面虽然照常滚动，数字框仍会被激活并显示文字光标。现在这些值控件在第一次显示前改为 `StrongFocus`：点击和 Tab 键照常聚焦，滚轮不再聚焦。用真实鼠标在设置页“悬停时间”数字框上滚一格核对过：修复前焦点落到该数字框、出现文字光标；修复后页面滚动，焦点留在原处。自动测试检查各值控件的焦点策略不再是 `WheelFocus`（撤掉修复时失败）。在测试进程里模拟的滚轮事件无法复现“滚轮给焦点”这一步，因此“滚动后焦点不变”的断言撤掉修复时同样通过，真正的核对靠上面的真实鼠标检查。

**贴靠弹窗实测（2026-10-20）**：用户报告悬停最大化按钮只出现“最大化”提示、没有贴靠布局。在本机用真实鼠标悬停（computer use）检查当时部署的版本，以下四种情况都正常弹出系统贴靠布局：普通窗口、最大化后悬停“还原”、窗口未激活、运行中新建的第二个完整窗口。用户看到的情况尚未复现，触发条件待确认。

本轮修改部署后，又用布局副本（仍带旧的 138／349 宽度）以真实鼠标复测：菜单“文件”距窗口左边缘只有 1 像素边框；“保存”按钮到“最小化”之间只剩 4 个逻辑像素的工具条间距（此前是 16）；关闭按钮右边缘紧贴边框。普通窗口悬停最大化按钮、最大化后悬停“还原”按钮，都弹出系统贴靠布局；最大化时屏幕右上角最外侧像素落在关闭按钮上。

测试中发现：Claude 桌面窗口带“始终置顶”样式，正好盖住 Muxora 右上角。光标实际落在 Claude 窗口上，Muxora 收不到悬停，按钮既不高亮也不弹出贴靠布局；`native-frame` 测试中那 20 项“测试点下是 Claude 窗口”的失败也是同一原因。最小化 Claude 窗口后结果正常。

`window-system.lua` 的 `panelPoliciesCanBeConfiguredWithoutNestedExecution` 偶发失败（点击外部即关闭的窗口选择器在检查前已关闭）。撤下本轮改动后，在已提交的代码上同样失败（4 次中 1 次），不是本轮引入的，原因待查。

此前最大化时只有右上角能用鼠标顶到屏幕边缘直接点中关闭按钮；放到左上角时，工具条左侧还留着 2 像素空白，按钮又在条内靠右，最左上角那一像素点不到按钮。现在窗口控制工具条在所在行的最前或最后时，最大化和全屏下都不留这段空白。新增测试检查四个角在“完整窗口／轻量窗口 × 最大化／全屏”下，屏幕角上那一个物理像素都落在关闭按钮上，并能点击生效：最大化走 Windows 原生命中路径（`WM_NCHITTEST` 返回 `HTCLOSE`），全屏走 Qt 自己的命中。底部两个角要求全局状态栏隐藏，否则状态栏在按钮与屏幕边缘之间。本机任务栏在底部，没有修改系统任务栏设置：底部两个角用全屏覆盖整个屏幕来检查；最大化时底边就是任务栏上沿（工作区边缘），检查方式相同。

验证：Release 全量 60 个套件中 59 个通过，2215 行通过、20 行失败，失败全部在 `native-frame`，检查点上的窗口是 Claude 桌面应用（`claude` 进程），测试窗口被遮挡，与之前几次相同。`caption-strip`（含新增 18 行）连续两次 65 行全部通过。没有用真实鼠标在屏幕角上手动点击，也没有在任务栏位于顶部或侧边的系统上试用。

### 布局变化只重建变化的部分（2026-10-19）

阶段 1.4–1.6：关闭、移动标签、拆分窗格等布局变化不再重建全部标签视图。

- 拖动分隔条（`layout.setRatio`）直接找到对应的分割器，不再在所有标签视图中查找。`LayoutModel` 新增公开查询 `ownerOfNode()`，返回分割节点所在的布局树。
- 窗格树、内容和窗格栏都没变的标签保留原来的分割器和窗格框，内容控件不再改 parent。
- 标签留在同一窗口时，其视图直接在组之间移动，不再经过隐藏的存储控件。
- 标签列表、标题、颜色、图标、外观都没变的组保留原来的标签条。分割结构（中央和固定侧的分割节点与组）不变时，根、分割器和未变化的组原地保留，只替换变化的组。新建或删除组、固定或取消固定时仍整体重建。
- 宿主在内容的 resize 回调里修改布局时，正在布局的分割器不会被改动其子控件列表；现有用例曾在这里崩溃，已修复并加了回归用例。
- `setTheme()` 后的下一次刷新会按新主题重建标签条（原来所有刷新都重建，所以没有这个问题）。

基准（offscreen，本机，1000 个标签，p50／p95）：关闭一个标签 3.88／4.01 s → 55／65 ms，移动 3.91／4.00 s → 80／103 ms，拆分 3.90／4.02 s → 67／89 ms；创建到 1000 个标签 1303 s → 92 s；一次“添加 + 关闭”约 8 s → 97／126 ms。阶段 0 记录的“循环 1000 次后私有提交增加 37 MiB”核对为分配器保留，不是泄漏，改动后循环 1000 次只增加 0.1 MiB。各步数字和测法见 [阶段 1 状态](../../roadmap/implementation/phase-1-layout-performance.md#14-分隔条到控件的映射)。

现有用例修订：`pinned-ui` 中一行原来断言“相邻新建组时，被缩放窗格的框会被替换”，这依赖旧的全量重建，与本阶段目标冲突。修订后保留了原有的延迟删除覆盖（改由拆分该窗格本身触发），提交 `fdd6d9c`，需要评审。

验证：Release 全量 60 个套件中 59 个通过，2195 行通过、20 行失败。失败全部在 `native-frame`：检查点上的窗口是 Claude 桌面应用（`claude` 进程），测试窗口被遮住，不是代码缺陷；同一轮改动在遮挡消失时单独运行全部 55 个窗口模块套件均通过。本工作区的固定 Release 已覆盖 `out/package/muxora-preview/`，`application-exit-test.ps1` 通过；独立模块安装后外部宿主夹具通过。没有执行 Debug 矩阵、DPI、7-Zip 打包或真实桌面试用；结构变化（新建或删除组）在大量标签下的耗时没有单独测量。

### 布局模型索引、快速路径与重入检查（2026-10-19）

阶段 1.1：`LayoutModel` 为“标签所在组”“窗格所在标签”“分割节点所在树”建立反向索引，`groupForTab()`、`tabForPane()` 从遍历全部记录改为查表。每次提交事务和读入快照后重建索引，`validate()` 会核对索引与记录一致。

阶段 1.2：点击标签、焦点变化（`activateTab`、`activatePane`）和调整分隔条比例（`setSplitRatio`）不再复制整个模型并全量校验，只改相关记录；比例只路径复制所在的那一棵树。1000 个标签时模型内单次操作从约 0.65 ms 降到 0.1 µs；原来每次焦点变化要做两次完整事务。

阶段 1.3：在相邻位置新建标签组（`addTabToNewGroup`）和关闭全部窗口时，原来为检测回调中的重入修改要序列化整个模型。现在先比较模型标识：`LayoutModel` 新增公开的 `stateId()`，副本共享、每次成功修改或读入快照都换新值，回调没有提交修改时不再序列化模型。只比 revision 不够：回调中恢复布局会得到 revision 相同、内容不同的新模型，现有用例覆盖了这种情况。关闭全部窗口时，窗口位置、选项、工具条这些窗口状态仍参与比较，回调改了它们照旧取消关闭；回调里激活已经活动的标签仍可照常关闭。

1.1 和 1.2 的 `toJson()` 输出与 revision 经新旧代码对比逐字节相同。默认 Release 编译选项不变；新增的公开 API 只有 `stateId()`，模块说明和外部宿主夹具已同步。

5. 增加标签和窗格移到相邻组、已有窗口及窗格前后标签的命令，以及当前标签内的方向交换。空间导航包括中央组与固定组，按实际位置和同一行列优先选择；前后和方向操作在各自范围内循环。移动保留内容、Pane ID 和附加栏，最小化目标窗口会恢复显示。
6. 拖到标签条时，同一个浮窗临时收起全局标题和窗口按钮，保留标签与真实内容；拖到四边收纳条时采用对应方向的紧凑标签与面板。目标条带让出插入空位并绘制标签色块，模型不增加占位标签。收纳条提供有界滚动，靠两端停留 200 毫秒后自动滚动，随后每 35 毫秒更新落点；离开或结束拖动恢复常规呈现，取消时恢复原布局。

本轮补充了以下行为：

1. 标签离条拆出时尽量保持原条带的滚动位置。拖到两端自动滚动后，即使移开且没有投放，滚动位置也保留；拖动中可用滚轮滚动鼠标下的标签条或四边收纳条。
2. 每个收纳标签独立记住临时展开大小。拖动面板靠内容区一侧的细边可调整宽度或高度；右键或命令面板提供“设置临时展开大小…”和重置入口。窗口较小时只约束实际显示，不改写保存的请求值。固定后的分区尺寸与此独立。
3. 完整窗口和浮窗分别保存工具条布局，窗口升降级也保留各自缓存。当前窗口保持自己的排列；新窗口采用本类型最近完成的工具条编辑。旧窗口的保存、缩放和退出不会覆盖较新的默认配置；在旧窗口完成新编辑时，只合并这次改变的属性或排列。
4. 中央组之间及固定侧栏分区与中央区域之间使用 2 个逻辑像素的分隔，内部窗格使用 1 像素；边界仍可用鼠标及键盘调整。
5. 非最大化时，最大化按钮的实际可见区域优先于顶部缩放边缘命中。浮窗反复进入标签预览再离开时保留同一个原生窗口，恢复窗口样式和完整轮廓，避免系统主题绘制的 Basic 三控件叠到自绘工具条上。Windows 11 的系统 Snap 弹窗已在本机实际悬停验证；低性能设备逐帧效果仍待试用。

主菜单采用“文件、视图、布局、窗口、工具、帮助”。文件菜单包含新建、保存工作区布局、关闭标签、关闭窗口与退出；工具菜单只保留统一设置和键盘快捷方式入口。标签组、窗格、移动、导航和窗口形态按操作对象分成二级菜单，工具条大小与定制保留在相应右键／选项菜单，不把每个设置项重复列进主菜单。命令面板与可绑定快捷键的命令仍完整保留。

“文件 → 退出”默认使用 `Ctrl+Q`，保存整个工作区后统一申请关闭许可，覆盖全部完整窗口族及轻量窗口。保存失败时保留窗口并提示；许可拒绝或回调改变布局时不部分关闭。关闭单个窗口仍通过“文件 → 关闭窗口”及原生窗口按钮完成。

边缘投放指示保持在本侧边缘；标签条横跨中部时，指示只沿边避让，不横推到内容中央。目标窗口移动、调整大小、最大化／恢复以及 DPI 通知会使指示失效并合并刷新，即使鼠标静止、悬停唤起关闭也能更新。四边收纳条仅在实际溢出时显示细滚动条，刚好放下、删掉多余标签或取消插入空位后重新隐藏。

菜单“视图 → 显示 → 显示标签栏”或 `Ctrl+Alt+T` 可切换当前窗口中央标签组的标签栏，其他窗口不受影响。侧边收纳条、固定面板标签栏和临时展开标题继续显示。隐藏的中央栏不保留占位；内容与键盘导航继续可用。新建中央组继承本窗口的显示状态，重启后恢复。

菜单“视图 → 显示 → 显示侧边栏”、命令面板或 `Ctrl+Alt+B` 单独切换本窗口四边收纳条。隐藏时收起当前临时面板，固定分区继续显示；明确通过命令激活收纳标签仍可临时展开。中央标签栏显隐与此独立，两个状态分别保存。没有固定历史的收纳标签首次固定时位于该侧最靠外的分区，与直接固定投放一致；已有历史的标签仍恢复原位置。

工具栏与全局状态栏也有独立开关。工具栏开关同时控制顶部和底部工具区；全屏不改变这些开关。三种全屏范围均铺满当前显示器，分别呈现整个工作区、当前标签组或当前窗格，内容 ID 和控件保持。退出后恢复正常矩形、最大化状态及原分割尺寸；范围内目标消失时退出全屏，选择范围外内容时切换为窗口全屏。

普通窗口启动禅模式时，自动进入设置指定的窗口、标签组或窗格全屏；已有全屏保留当前范围。禅模式临时隐藏全部栏，包括固定组标题和内容上下附加栏。菜单及设置的四项有效开关均显示关闭，原偏好继续保存。显示任一栏会退出禅模式，恢复其他偏好并应用这次显示操作；关闭禅模式保留全屏，退出全屏则同时退出禅模式并恢复原偏好。

顶部和底部工具区支持多行，底部在下侧收纳条之下、全局状态栏之上，行从状态栏一侧向上排列。解锁后可跨区拖动；到达末行时，在靠工作区的一侧出现一行临时空白投放区。移走一行最后的工具条后该行立即收起。普通行基准高 28 个逻辑像素，随字体和内容最小高度扩展；窗口控制保留 32 像素高度。保存的空逻辑行不创建隐藏控件。

“视图 → 工具条 → 移动工具条…”及命令面板提供键盘选择工具条、顶部／底部及目标行的路径。宿主可调用 `moveToolbar(window, stripId, ToolbarArea, row, index)`；移动保留工具条内容、按钮选择和尺寸策略。

窗格上下附加栏分别支持共享和逐窗格显示，默认为共享。宿主通过 `TabOptions.topBarSharing` / `bottomBarSharing` 或 setter 设置；模式切换保持原栏、内容和焦点，提取窗格时策略随描述保留。显式 Tab 栏仍只在整个标签外围显示一次。标签图标采用紧凑排布；溢出悬停时，标签底边的四像素细滚动条可拖动，没有前后按钮，滚轮不切换标签。

窗口移动、缩放和最大化状态变化合并通知保存；最小化保留正常几何。恢复使用所有屏幕的逻辑可用区域，越界或原屏幕消失时调整，保留仍有效的负坐标和跨屏位置。关闭最后一个窗口前同步保存当前快照，避免立即退出错过延迟保存。

此前已实现逐标签固定／取消固定、原分区与尺寸恢复、四边收纳／固定双目标、紧凑窗格及随焦点切换的共用上下栏。标签条提供细滚动条、滚轮滚动、拖拽边缘自动滚动和完整列表；右键可关闭该组左侧、右侧、其他或全部标签。

工具条及拖动预览显式使用当前主题背景，系统深色调色板不再从截图透明区域透出。拖动前、首次浮动显示及后续鼠标移动采用同一颜色。

临时侧栏关闭按钮关闭实际标签，宿主拒绝关闭时保留面板和内容。收纳标签右键使用现有标签菜单，菜单 Esc 只关闭菜单；标签完整列表悬停使用主题选择背景和文字颜色，运行中切换主题也更新。

工具条可显隐、拖动、压缩、显示溢出和增删按钮；每行只保留一个弹性条带，吸收余量并将右侧条带推到右边。标题必须保持弹性，移入标题行的弹性条自动改为普通条；该行其他条带不能设置弹性。没有标题或其他强制弹性条的行仍允许切换弹性归属。拖走后一条时，前条按新邻居恢复自然宽度或接收腾出的空间；弹性右侧的普通条带可改变左边界，后方条带或窗口边界保持不动。窗口转换保留两种形态各自的条带布局及按钮选择。轻量窗口最后一个标签拖出后，Esc 也会恢复当前及另一种形态缓存的工具条配置和内容实例。完整交互规则见 [修订设计](../../design/window-interaction-design.md)。

旧布局即使把标题保存成普通宽度，也会按宿主约束恢复为弹性；加载过程不直接改写用户文件，后续正常保存使用修正后的状态。菜单条重置能回收标题空间，保持右侧条带位置。命令面板“切换工具条弹性空间…”列出可编辑条带，标题行和窗口控制不进入候选。

普通工具条选项增加“重置尺寸”，恢复自然宽度；弹性左侧保持头部位置，右侧保持尾部位置，先调整弹性空间，再按最小宽度让邻条腾出空间。其他条带的请求宽度和顺序保持不变。命令面板中的“重置工具条大小…”提供键盘选择列表，标题和窗口控制条也可从这里重置。窗口缩放时，弹性右侧的条带相对右边缘定位，最后一条与边框的距离保持不变；放大后恢复请求宽度。

完整和轻量窗口的标题均在自己的条带内居中，过长时显示省略号，可访问名称保留完整文字，悬停不显示提示气泡。标题内容区至少 96 个逻辑像素，解锁把手的宽度另计。

三个窗口按钮组成独立的窗口控制工具条，可移动和拉伸，不能压缩到按钮自然宽度以下，不允许弹性且没有选项按钮。按钮靠顶部排列，最大化／还原同步更新图标与提示。轻量窗口在标题同行左侧增加局部菜单，使用本浮窗的标签与窗格上下文，不提供退出程序、布局重置等全局入口；不另建工作区工具条或全局状态栏。独立菜单条带保留完整窗口的菜单位置与定制，升降级和拖拽取消均恢复原缓存。

Windows 完整和轻量窗口在首次显示前准备原生帧，保留原生窗口样式并允许 DWM 过渡。拖出的窗口先放到鼠标位置再显示，移除原有透明度淡入；最大化可见边框与完整内容区对齐工作区。正常矩形由模块单独记录，避免 Qt 用最大化边框扣减正常尺寸；最小化、保存恢复和拖拽取消使用同一矩形。原生调用和状态测试已通过，创建／关闭等动画的实际运动效果仍需桌面试用确认。

临时展开显示真实标签内容与可用附加栏；全部固定按钮移到侧栏标签末尾，并以内部透明的叠层图标区分单个操作。侧栏标签可拖动调整顺序，按四边条带的横／纵位置插入，支持跨窗口和整窗载荷；排序命令可使用 `Ctrl+Shift+PgUp` / `Ctrl+Shift+PgDown`。边栏相邻角由底栏优先占底角、左右栏优先占顶角；仅一条邻边显示时由它占角。设置页以类别标题排列全部设置，分类树支持折叠、点击定位和随滚动同步，当前位置为粗体及独立竖线，箭头悬停只变深色且与竖线留有间距。箭头、数字按钮和勾选框统一采用主题绘制；下拉菜单重复点击关闭。

标题条取消了选项按钮及其宽度占位，普通工具条继续支持定制。菜单每次事件保持禁止回放，避免关闭后遗留左键状态或下一次关闭时重新打开。选项按钮区分鼠标与键盘产生的焦点提示；鼠标打开菜单不留下焦点外框，关闭后清除遗留悬停，不需要额外点击或移动。真实进入和离开继续更新悬停，键盘导航仍显示焦点。

窗口设置与快捷键编辑分别可从菜单或命令面板打开。快捷键修改立即生效，并独立保存到用户快捷键文件；下次启动恢复。

上一阶段条内预览的销毁回调回归发现重复删除：宿主关闭源标签时，清理流程再次删除正在销毁的预览。现先清空观察成员再删除对象，并保留关闭源标签、拆出通知销毁宿主及目标菜单中关闭／销毁的四行回归；修复后通过。调用栈为 `out/diagnostics/strip-lifecycle-crash.log`，修复记录为 `out/test-results/strip-lifecycle-fixed.txt`。

上一阶段的独立 Win32 夹具证明：带完整原生标题样式的窗口设置 region 后，即使策略写入成功，也会关闭 DWM 非客户区绘制。本轮发现正常窗口恢复时，系统主题还可能重新设置 region 并画出 Basic 三控件。现在紧凑预览移除原生标题样式，保留缩放与系统控制能力；正常窗口恢复完整样式并清除 native region。独立夹具保留原来的限制检查，另验证从正常样式切换到无标题样式的两种调用顺序：精确 region 在显示、重算和消息处理后保持，实际 DWM 状态为启用。

实际 Qt 窗口回归检查精确原生轮廓及缺口命中，三控件位于中间、第二行或底部时各覆盖投放与取消。正常恢复后的九处屏幕像素须精确等于 Qt 客户区参考，普通内容另须等于指定 RGB；捕获、句柄、内容实例、最大化和恢复几何断言均保留，没有增加色差容差。低性能设备逐帧视觉仍待试用。

临时面板尺寸回归还发现，宿主在内容 resize 回调中销毁管理器会打断 Qt 正在进行的布局。此时窗口和内容延期释放，让当前布局调用结束；回归检查延期删除前的排队输入安全停止，并确认窗口与内容随后释放。普通销毁路径继续立即释放。失败调用栈保留在 `out/diagnostics/current-peek-crash.log`。

本轮旧夹具的修订经过独立审阅：窗格分隔从 4 改为需求明确的 1 像素，同时增加真实外层间隔和拖动尺寸检查；三条形态切换用例改为严格检查两份独立配置及原内容身份；最大化命中在排队布局完成后再采样原生坐标，保留精确命中与像素断言。滚动条键盘方向由独立 Qt 滚动条核验，再同步派发按键并检查计时器运行前后的精确位置，避免键盘模拟延迟提前消耗待恢复状态。临时分区尺寸夹具通过取消固定再固定使内部模型尺寸应用到控件；原尺寸、滚动和身份断言未放宽。

补充 200% 原生检查发现两项旧夹具错误：本机叠加系统缩放后 DPR 为 4，逻辑工作区高 516；像素夹具从 y=140 放置高 520 的窗口，底部采样已经越出屏幕。经独立审阅，只调整夹具位置和大小，并增加完整可见前置断言，所有顶部／底部采样及精确像素检查保留。另一项最大化尺寸原预期为 680×4=2720，超过工作区实际高 2064；现在由独立 `GetMonitorInfoW` 取工作区与公开最大尺寸的较小值，并新增 `ptMaxSize` 精确比较，原四项拖动限制和正常几何恢复断言全部保留。[最大化与拖动尺寸定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-minmaxinfo)、[显示器工作区定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfo)。失败证据保留在 `out/diagnostics/scale-2-native-before-fixture-fix.txt`。

逐点诊断还显示，DWM 创建过渡会短暂混合前后画面，像素条件并非单调；Qt 的 `QTRY` 多次立即读取同一条件，可能在首次匹配后再次读到过渡帧，产生误导性的超时提示。经独立审阅，改为每 50 毫秒采样原位置，连续三次全部精确匹配才判定稳定，任一点失败就清零。预期只生成一次，原 5 秒超时不变，原生消息后的即时像素、轮廓、捕获和身份断言全部保留。诊断记录为 `out/diagnostics/scale-2-top-pixel-misses.txt`，比原先一次匹配要求更严格。
