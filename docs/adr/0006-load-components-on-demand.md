# 0006 可选组件按需加载，用完销毁

**状态**：采用

## 背景

Muxora 的目标是同时打开成百上千个会话，内存是实现约束（[工程设计 §3](../development/engineering-design.md#3-内存节约是实现约束)）。很多用户永远不会用到 Lua 脚本、内置编辑器、X11 或语言服务，但如果这些组件在启动时就创建，所有用户都要为它们付出内存和启动时间。

## 决定

按 [工程设计 §3.4](../development/engineering-design.md#34-不用的组件不加载)：

- **默认按需**：Lua 运行时（没有脚本时不创建线程和解释器）、内置编辑器（Scintilla 编译为插件 DLL）、SFTP 辅助程序、X11 显示服务、语言服务进程、JSON Schema 等派生数据，都在第一次真正使用时创建。
- **常驻的例外**：使用非常频繁、加载代价会影响交互的部分：窗口系统本身、终端核心与渲染、命令注册表。
- **实现方式**：较大的可选组件编译为单独的 DLL，用 `QPluginLoader` 在首次使用时加载，应用只依赖很小的接口头文件；较小的组件延迟构造。
- **用完就销毁**：控件、对话框、编辑器、面板、缓存、线程、辅助进程在关闭或不再使用时销毁，不为“下次可能还用”而保留（有明确收益、并在预算内的缓存除外）。
- **插件 DLL 不卸载**：含有 Qt 类型或静态数据的 DLL 加载后不在运行期间卸载（卸载后被访问会崩溃），但它创建的对象照常销毁。

## 后果

- 每个按需组件都要有测试，确认普通启动和常用操作之后它没有被加载（进程模块列表、线程名或对象计数），首次加载耗时记在预览说明中。
- 第一次使用某个功能会有一次加载延迟，需要控制在不影响交互的范围内；超出时要考虑常驻或预热。
- 组件和应用之间只通过小接口通信，组件内部类型不进入应用的公开头文件。
- 用户可见的设计要接受“首次打开稍慢”；不能为了消除这一次延迟默认全部预加载。

## 替代方案

- **启动时全部加载**：实现最简单，但所有用户都要承担用不到的组件的内存和启动时间。
- **全部做成独立进程**：隔离更好，但进程间通信和每个进程的固定开销更大，只适合 SFTP 辅助程序、语言服务这类本来就独立的程序。
