# 0007 消息通知使用 Windows 系统通知，不做通知中心

**状态**：采用

## 背景

早期设计参考 VS Code，计划做程序内的通知中心和自绘弹出提示。VS Code 的通知中心是为编辑器和扩展生态服务的；同类终端软件（Windows Terminal、Xshell、Tabby 等）普遍没有这套机制。界面规范要求参考之前先确认 Muxora 是否真的需要该功能（[界面设计规范](../design/ui-design-system.md)）。

## 决定

按 [界面设计规范 §4.4](../design/ui-design-system.md#44-通知使用-windows-系统通知)：

- 不做通知中心，也不做程序内自绘的弹出提示。
- 需要“弹一条带文字的消息”时，使用 Windows 系统通知：屏幕右下角弹出，进入系统通知中心，遵守用户的勿扰设置。点击通知时激活 Muxora 并切到发出通知的窗口或会话标签。
- 其他消息按场景分流：
  - 长时间运行的命令完成、后台终端响铃：Muxora 不在前台时发系统通知并闪烁任务栏按钮，在前台时不发（与 Windows Terminal 一致），可以在设置中关闭；
  - 连接失败、进程退出：显示在该会话自己的标签里，不发通知；
  - 需要用户输入或确认：统一对话框；
  - 命令失败、“布局已保存”这类短消息：状态栏消息。
- Lua 的 `muxora.ui.notify` 改为系统通知；需要程序内弹窗时用 `ui.message`、`ui.confirm`、`ui.dialog`。

## 后果

- 不需要维护通知中心的界面、存储和历史，通知的去留由系统管理。
- 依赖 Windows 的通知能力：未打包的桌面程序需要设置应用标识（AppUserModelID）并在用户注册表下登记显示名；首选 WinRT 通知接口，MinGW 头文件不可用时走 COM 或其他后备方案（见 [实现计划 8.7](../roadmap/implementation/phase-8-ui-quality.md) 与 [0004](0004-windows-toolchain.md)）。
- 用户关闭了系统通知时消息会看不到，所以重要状态必须同时留在会话标签或状态栏里，不能只靠通知。

## 替代方案

- **程序内通知中心（VS Code 式）**：要维护一套界面和历史，而终端类软件的消息量不需要它。
- **程序内自绘弹出提示**：Muxora 不在前台时用户看不到，也不遵守系统的勿扰设置。
