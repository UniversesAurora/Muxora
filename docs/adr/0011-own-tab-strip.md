# 0011 标签栏自绘，拖动时内容用画面预览

**状态**：采用（实施见阶段 8.21、8.22）

## 背景

标签栏一开始继承 `QTabBar`，只用来做单行横向排列。之后陆续加了多行、滚轮展开、钉住标签的三种尺寸、钉住标签单独一行、插入空位和紧凑拖拽预览。`QTabBar` 只认识单行，这些功能只能在它旁边另算一份显示矩形（`displayedRects_`），再逐个改写绘制、点击、提示和拖放命中，让它们不要用 `QTabBar` 自己的 `tabRect()`。每加一种排列，`layoutTabs()` 里就多一组相互影响的分支（钉住阶段、钉住行高度、折叠行平移），已经出现过绘制和命中不一致、提示找错标签的问题。

用户 2026-10-25 要求重新设计标签栏：置顶段可以单独滚动、多行可以收起并提示被收起的标签、增加左右两侧的竖向标签栏，拖动改成 Chrome 那样标签跟着鼠标、其他标签滑动让位，并要求整体重新审视、统一实现。规则见 [标签栏设计](../design/tab-strip-design.md)。

## 决定

1. **自绘标签栏，不再继承 `QTabBar`。** 标签数据（ID、标题、图标、颜色、置顶）由 `GroupTabs` 直接持有；控件只负责绘制、输入和可访问性。
2. **布局是纯函数。** 新增不依赖控件的布局模块：输入标签的各部分宽度、置顶数量、排列方式（横向单行／多行、竖向）、可视尺寸、各段滚动位置、收起状态和拖动状态（被拖标签块的宽度、插入位置），输出每个标签、空位、尾部控件的矩形、行数、被收起的标签数和内容范围。插入位置的计算也在这里。绘制、点击、提示、拖放和可访问性都只读这一份结果。
3. **外观与逻辑分开。** 布局、尺寸表、绘制器和控件分成四层（[标签栏设计 §11](../design/tab-strip-design.md#11-外观与逻辑分开)）；标签内容固定为编号、图标、标题、操作位几个槽，窗格活动和行内重命名放进这些槽，不改布局。
4. **动画只在绘制层。** 动画器保存上一份和这一份布局，按时间插值绘制位置；命中和模型始终用最新的布局。
5. **拖到标签栏时，内容用画面预览。** 浮窗拖到标签栏上时，目标内容区显示被拖内容进入标签栏时截取的画面；真实内容留在浮窗里（浮窗只显示标签），放下后才移到目标组。
6. **可访问性自己提供。** 自绘控件实现 Qt 的可访问接口，以页签列表和页签的角色暴露标签。

## 后果

- 原来散在 `DragTabBar` 里的钉住阶段、折叠平移、提示和命中补丁一起删除；`tab_strip.cpp` 按布局、绘制与输入、`GroupTabs` 宿主拆开。
- 布局模块可以不建控件就测试：所有排列方式和边界情况用数据驱动和随机生成的组合检查不变量（不重叠、顺序不变、在范围内、命中与绘制一致），控件测试只需验证接线。
- `QTabBar` 原来白送的键盘导航和辅助技术支持要自己实现并测试，可访问性核查（8.14）把它列为检查项。
- 拖到标签栏时目标区显示的是静态画面，悬停期间被拖内容的新输出看不到；对几秒钟的悬停可以接受。截取不到画面的内容（另一个进程的原生窗口）没有预览。
- 收纳条（`EdgeStrip`）暂时保留自己的实现，只共用标签绘制、空位和动画；以后要统一时也接入同一个布局模块。

## 替代方案

- **继续在 `QTabBar` 上打补丁**：改动最小，但每种新排列都要再改写一遍绘制和命中，竖向栏还要绕开 `QTabBar` 的形状系统，问题只会更多。
- **每段用一个 `QTabBar`，外面套滚动区**：能复用一部分原生行为，但多行、收起、跨段拖动和统一动画仍要在外面协调，命中仍分散在多个控件里。
- **拖动时把真实内容移进目标组**：Chrome 就是这样做的，画面是活的。但终端内容移动会改尺寸（伪终端、SSH 都要通知远端重排），GPU 绘制的内容换顶层窗口时要重建画面；鼠标在几个标签栏之间来回时会反复发生。画面预览在放下前看起来一样，代价小得多。
