# 0012 用统一尺寸倍率实现即时界面缩放

**状态**：采用。

## 背景

用户要求分别设置界面字体、字号和缩放，并用命令调整后立即生效。只增大字体无法同时调整图标、间距和自绘控件；把整窗画面放大又会损失文字清晰度，并使原生内容和命中坐标难以保持一致。

## 决定

应用持有一个 `InterfaceAppearanceController`，窗口模块只处理运行时值，配置文件仍由宿主管理。Qt 公共字体接口负责字体链和字形匹配；原生控件通过同一个应用级 `QProxyStyle` 查询缩放后的尺寸，自绘布局和绘制使用相同的尺寸转换入口。基础主题与当前绘制主题分开，既有主题 getter 保留未缩放值。

尺寸保留未缩放来源，设置变更时重排。静态布局约束绑定到其拥有者，只在设置变化时更新；自绘标签使用已有的布局和测量缓存失效机制，不在动画帧中重新读配置、选择字体或遍历全体控件。窗口、内容实例、布局模型和输入焦点不因缩放被重建。

屏幕 DPI 保持 Qt 的自动处理；应用倍率不修改屏幕 DPR 或平台 DPI 状态。设置语义、数值和命令只维护在 [设置设计 §3.3](../design/settings-and-commands-design.md#33-界面字体与缩放)。

## 后果

- 同一控制器服务完整窗口和浮窗，新建窗口直接读取当前倍率，避免多窗口旧值互相覆盖。
- 宿主的自绘内容需要在通知后使用公开的尺寸转换入口或自身渲染缩放接口，不能依赖放大旧位图。
- 主题改变与缩放改变都须更新现存控件的绘制令牌及视图签名，不能在下次模型操作时意外重建旧视图。
- Qt、宿主字体和屏幕像素排列会影响字形观感，不能承诺与浏览器逐像素相同；系统抗锯齿设置保持不变。

## 替代方案

- **重启后设置 Qt 全局屏幕倍率**：无法满足用户要求的立即生效。
- **Qt 私有 DPI 接口**：不作为已发布公共接口保证，增加工具链升级成本。
- **整窗图像或代理控件缩放**：文字重采样、原生子窗口与坐标转换的代价过大。
- **仅改变字号**：无法同时缩放图标和控件，保留为独立的字号设置。
