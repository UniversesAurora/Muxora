# 0010 界面翻译使用英文源文本

**状态**：采用；迁移见 [8.12](../roadmap/implementation/phase-8-ui-quality.md#812-英文源文本与全量翻译核查)。

## 背景

界面使用 Qt 的文本翻译机制，中英文分别维护翻译目录。中文源键需要先迁移，再继续扩展界面文字。Muxora 是公开项目，窗口模块也供其他宿主使用；后续主题、设置和终端阶段会继续增加大量文字。继续使用中文源文本会增加不懂中文的贡献者理解、维护和翻译这些文字的成本。

Qt 的工具链默认使用英文源文本，也允许指定其他源语言。选择英文是本项目的维护决定，中文源文本同样受 Qt 支持。[Qt 本地化说明](https://doc.qt.io/qt-6/localization.html)

## 决定

界面翻译的源文本统一改为英文，简体中文由翻译目录提供，继续使用 Qt Linguist 和 `QTranslator`。完整的源文本、翻译覆盖及兼容要求只维护在 [设置与命令设计](../design/settings-and-commands-design.md#83-翻译源文本与覆盖)。

迁移排在当前推荐步骤的前面，先于后续新增界面文字的工作；执行顺序和迁移状态见 [实现计划](../roadmap/implementation/README.md#推荐执行顺序)。

## 后果

- 需要同时迁移源码查找键、翻译目录、构建中的源语言声明及依赖旧查找键的测试；不能只把英文译文复制回源码。
- 源码扫描必须覆盖现有翻译目录之外的用户可见文本，动态查询也要具备可提取的标记和覆盖检查。
- 用户选择的界面语言及跟随系统的行为保持原样；源文本语言不决定界面默认语言。
- 英文措辞调整仍可能改变文本查找键，需要同步更新目录；本次保留现有 Qt 翻译机制。

## 替代方案

- **继续使用中文源文本**：实现成本最低，但不能满足用户要求，也不能减少后续跨语言协作的成本。
- **改为按 ID 翻译**：Qt 同样支持，但需要另行迁移查找方式和 ID 管理，超出本次源语言调整的范围。
