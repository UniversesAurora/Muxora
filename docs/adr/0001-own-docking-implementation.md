# 0001 自研停靠与窗口实现，不引入 KDDockWidgets

**状态**：采用

## 背景

Muxora 需要一套窗口系统：中央标签组可以任意分割，四边有可以固定或自动隐藏的边栏，标签和整组可以拖进拖出，拖出的内容成为轻量浮窗，浮窗可以升级为完整窗口；多个窗口组成窗口族，一起关闭、一起恢复。窗口系统还要作为 `modules/window-system/` 独立复用，公开 API 不能依赖 SSH、终端等业务。

KDDockWidgets 已经提供分割、标签、自动隐藏和跨窗口停靠，能省掉大量常规交互工作。调查结论（见 [V0 总览](../design/v0-design.md) 和 [工作区设计](../design/workspace-design.md)）：

- 它不是因为缺少基本能力被排除的。
- 它的自动隐藏会恢复到原停靠位置，和本设计中独立固定的边缘区语义不同，需要额外适配。
- 它的普通浮窗不等于 Muxora 的完整工作区窗口（标题工具条、菜单、状态栏、窗口族）。
- 深度定制视图可能需要使用私有 API。
- 免费许可是 GPL 2／GPL 3；链接进主程序会改变 Muxora（MIT）的发行条件，单独目录、API 或 DLL 都不能消除这一点。

## 决定

V0 采用自有的布局模型、停靠和拖拽实现，复用 Qt 的分割、事件、菜单和绘制等基础能力，不引入 KDDockWidgets，也不同时维护多套停靠引擎。窗口系统自有代码采用 MIT 许可。

## 后果

- 两层布局、边缘固定、窗口族、整窗拖拽、跨屏和生命周期的状态机都由我们自己负责，必须由完整的自动化测试和真实桌面试用来验证；自研不是没有风险。
- 公开 API 可以完全按 Muxora 的需要设计，不暴露第三方类型。
- 原生窗口框架、DPI、命中测试等平台细节也要自己处理（例如 [0005](0005-caption-button-hit-testing.md)）。
- 发行许可保持简单：主程序不链接 GPL-only 库。

## 替代方案

- **KDDockWidgets（GPL）**：功能最接近，但许可不符合，且语义需要深度适配。以后若重新考虑，必须先取得用户对许可变化的明确同意，并单独评审。
- **KDDockWidgets 商业许可**：需要付费，且语义差异依旧。
- **Qt 自带的 `QDockWidget`**：只能停靠在 `QMainWindow` 四周，没有中央标签组的任意分割、跨窗口合并和窗口族。
