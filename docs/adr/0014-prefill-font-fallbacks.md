# 0014 Windows 上预先给 Qt 填界面字体的后备字体表

**状态**：采用。

## 背景

Muxora 启动到第一个窗口约 1.7 秒，其中约 0.9 秒花在 Qt 第一次排版界面文字时（[归因记录](../development/verification-log/2026-11.md#quick-启动和顶部远距切换的耗时归因2026-11-07)）。界面字体是多字体列表（“Segoe UI, Microsoft YaHei, sans-serif”，见 [设置设计 §3.3](../design/settings-and-commands-design.md#33-界面字体与缩放)）。Qt 6.12 遇到这种请求，或第一次遇到缺字时，会算一张后备字体表：先放几种它为 Windows 精选的字体，再把系统里每个字体族都加载一遍，挑出支持这种文字的。耗时与装的字体数量成正比，开发机 720 个字体族时约 0.9 秒。

VS Code 用的是同类字体列表，但浏览器内核遇到缺字时只问 Windows 的系统后备（`IDWriteFontFallback`）这一个字符该用哪个字体，没有这笔启动开销。用户 2026-11-07 要求：不改默认字体，用和 VS Code 一样的机制，尽量做到一样快。

## 决定

界面字体确定后（启动时、用户改字体时、字体库变化时），`prefillFontFallbacks`（`src/platform/windows/font_families.cpp`）先替 Qt 把后备字体表填进它的缓存，Qt 查表时直接命中，不再逐个加载字体族：

- 每种文字的表开头与 Qt 自己的完全相同（`QWindowsFontDatabaseBase` 的精选字体，同样的顺序），所以现在能找到字形的字符仍由原来的字体显示。
- 表的末尾不再是“所有支持这种文字的字体”，换成 Windows 系统后备为这种文字的样本字符选出的字体，也就是浏览器会选的字体。
- 系统一个字体也选不出的文字不填，遇到时仍由 Qt 自己完整查找。
- Qt 会以表里的字体为键再查一次表，所以表里出现的字体也各填一份。

这要用 Qt 的私有接口：`QFontDatabasePrivate` 的后备字体缓存和 `QWindowsFontDatabaseBase` 的精选列表（`Qt6::GuiPrivate`），只在这一个源文件里用。

## 后果

- 启动快约 0.8 秒（Release，三轮 1663–2026 毫秒降到 913–929 毫秒）；预填本身在新进程里约 150 毫秒，同一进程再次预填时系统映射走缓存。
- 中英文、常用符号和表情的显示字体不变。少见文字改由 Windows 标准字体显示，而不是碰巧装着的某个字体：抽查的 35 个字符里有 6 个变了，例如天城文由 Nirmala UI 显示，生僻汉字由 SimSun-ExtB 显示，原来落到位图字体 MS Sans Serif 的埃塞俄比亚文、切罗基文改由 Ebrima、Gadugi 显示。
- 升级 Qt 时，私有接口可能改变。缓存键或成员变了会编译失败；Qt 改了查表的时机或范围，`font-fallback` 套件会失败（它检查第一次排版后仍有字体族没有加载；Qt 自己查表时会加载全部字体族）。两种情况都要先读新版本源码再改，不能删掉这个检查。
- Qt 的字体库锁没有导出。预填只在 GUI 线程上、界面字体变化时进行，此时没有别的线程在加载字体。

## 替代方案

- **保持现状**：每次启动多约 0.9 秒，字体越多越慢。
- **改用单一默认字体（例如“微软雅黑 UI”）**：中英文都在一个字体里，不会触发查表，但英文字母的外观会变；用户要求不改默认字体。
- **自己编译打过补丁的 Qt**：可以让 Qt 直接按字符问系统后备，但要长期维护一份 Qt 分支和它的构建，代价远大于一个源文件。
- **在后台线程提前完成 Qt 自己的查表**：Qt 查表期间持有字体库锁，GUI 线程第一次排版就要等它，省不下时间。
