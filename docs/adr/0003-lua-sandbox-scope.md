# 0003 Lua 沙箱只开放纯计算库，能力经宿主接口提供

**状态**：采用

## 背景

用户脚本可能来自网上的配置片段。脚本不应该在用户不知情时读写任意文件、启动程序、加载原生代码，或者绕开运行时的指令、时间和内存预算。同时，脚本确实需要操作窗口、标签、命令，以后还要读写终端、访问会话和文件（见 [Lua 扩展 API 设计](../design/lua-extension-api-design.md)）。

## 决定

解释器只打开纯计算的标准库，其余能力一律通过宿主提供的 `muxora.*` 接口给出，由宿主检查参数、目标和权限。当前实现（`modules/lua-runtime/src/script_worker.cpp` 的 `initialize()`）：

| 项目 | 状态 |
| --- | --- |
| 基础库、`string`、`table`、`math`、`utf8` | 打开 |
| `io`、`os`、`debug`、`package`（因此没有 `require`）、`coroutine` | 不打开 |
| `load`、`loadfile`、`dofile`、`collectgarbage` | 从全局表中移除 |
| `string.dump` | 移除，不能导出字节码 |
| `pcall`、`xpcall` | 换成带预算检查的包装：被保护的调用返回后立即检查是否已超出预算或被取消，脚本不能用 `pcall` 吞掉停止 |
| `print` | 换成宿主实现，输出进入脚本日志 |
| 宿主接口 | 全局表 `muxora` 中的 `_host`、`_callback`、`_release`、`_compile` 由适配层封装成正式 API |

文件、网络、外部程序、终端读写等能力以后都按扩展 API 设计以宿主接口提供，例如外部程序按独立参数启动，不经过 shell 拼接命令。

## 后果

- 脚本默认无法触碰文件系统、进程和原生代码；危险能力集中在宿主接口里，可以统一做权限检查、确认和审计。
- 预算对脚本自身的保护调用同样有效。
- [Lua 脚本设计](../design/lua-scripting-design.md) 中描述的受限 `require`（只加载用户 Lua 目录中的文本模块，带路径边界、大小、UTF-8 和循环加载检查）尚未实现；实现时作为宿主提供的加载器加入，不打开 `package` 库。
- 协程没有直接开放；扩展 API 计划的多任务挂起（阶段 9.1）由运行时管理，不让脚本自由创建可能绕过预算的协程。
- 每开放一项新能力，都要在本表和扩展 API 设计中同步记录，并有测试确认它受预算和权限约束。

## 替代方案

- **打开完整标准库**：最省事，但 `io`、`os.execute`、`package.loadlib` 让脚本拥有与程序相同的权限，`debug` 能改掉预算钩子。
- **按函数逐个过滤 `io`／`os`**：容易遗漏，且仍然需要宿主那一层的确认与审计，不如统一走宿主接口。
- **独立进程运行脚本**：隔离最强，但每次调用窗口 API 都要跨进程，延迟和复杂度都更高；当前用线程加预算已能满足需求。
