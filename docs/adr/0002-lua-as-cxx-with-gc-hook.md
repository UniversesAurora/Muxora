# 0002 Lua 按 C++ 编译，`__gc` 期间保留指令钩子

**状态**：采用。2026-10-21 补注：[0008](0008-full-standard-library-for-local-scripts.md) 去掉了执行预算并开放 `debug` 库。下文的“预算”现在对应停止请求（重载、退出、`lua.stop`），“脚本拿不到 `debug` 库”不再成立；保留指令钩子的理由不变。

## 背景

Lua 是 Muxora 的用户编程接口。脚本在独立的工作线程中运行，每个任务有指令数、执行时间和内存预算，超出预算或被取消时必须能停下来，关闭解释器时也不能卡住（见 [Lua 脚本设计](../design/lua-scripting-design.md)）。

两个问题：

1. 官方 Lua 默认按 C 编译，出错时用 `longjmp` 跳出。绑定层是 C++ 代码，`longjmp` 会跳过 C++ 栈帧的析构函数，造成资源泄漏或状态损坏。
2. 上游在执行 `__gc` 终结函数时临时关闭调试钩子（`lgc.c` 中的 `L->allowhook = 0`）。预算检查靠指令钩子实现，一个意外写成死循环的终结函数会同时挡住任务取消和 `lua_close()`。回归用例 `cleanupCannotExecuteUnboundedFinalizers` 复现过这个问题。

## 决定

- 固定使用官方 Lua 5.5.1 源码包（`third_party/lua/CMakeLists.txt` 中 URL 与 SHA-256 一起固定），在构建目录中编译进程序；用户不需要安装 Lua，也没有 Lua DLL。
- 全部源码按 C++ 编译（`LANGUAGE CXX`），Lua 错误以 C++ 异常展开，绑定层的析构函数正常执行。这个目标不能和按 C 编译的 Lua DLL 混用。
- 只改一处：构建时生成 `lgc.c` 的副本，把关闭钩子的那一行替换掉，`__gc` 执行期间仍然保留指令钩子。上游压缩包本身不变。
- CMake 在配置时核对这一行是否存在；升级 Lua 后找不到时配置直接失败，要求人工复核。

## 后果

- 预算和取消对终结函数同样有效，关闭解释器有上限。
- 升级 Lua 版本时必须复核修改位置，并重跑指令预算、终结函数、内存不足和关闭相关的回归测试（见 [`third_party/lua/README.md`](../../third_party/lua/README.md)）；不能为了通过而放宽测试的预期或时间限制。
- 脚本拿不到 `debug` 库，钩子只供宿主使用（见 [0003](0003-lua-sandbox-scope.md)）。

## 替代方案

- **按 C 编译，在绑定层避免跨 C++ 栈帧报错**：每个绑定函数都要小心不在持有 C++ 对象时触发 Lua 错误，很难全面保证。
- **LuaJIT**：停留在 Lua 5.1 语义，预算钩子在 JIT 代码中不可靠。
- **不修改 `lgc.c`，靠别的手段中断终结函数**：上游关闭钩子期间宿主没有可靠的切入点，只能强杀线程，违反工程设计中“不强杀线程完成普通清理”的约束。
