# 路线

设计文档（[`../design/`](../design/)）描述最终行为；这里回答“接下来做什么、按什么顺序做”。已经做出的决定见 [ADR](../adr/README.md)，每一轮的实际结果见 [验证日志](../development/verification-log/2026-10.md)，助手轮流开发时的交接见 [交接记录](../development/handoff.md)。

| 文档 | 内容 | 维护方式 |
| --- | --- | --- |
| [实现计划](implementation/README.md) | 按阶段拆分的逐步实现说明：改哪些文件、怎么改、加什么测试、怎么验证、完成标准；执行先后见其中的 [推荐执行顺序](implementation/README.md#推荐执行顺序) 和“当前位置” | 每完成或暂停一个步骤就更新 |
| [业务功能对标](feature-parity-plan.md) | 终端、SSH 管理、SFTP、X11 的对标清单与接入顺序 | 接入对应业务时更新 |
| [未来规划](future-plans.md) | 以后要做、现在不设计实现的事项：Windows 7 Aero 风格外观、AI 接入，以及其他已推迟的事项 | 新增或开始设计时更新 |
| [2026-10 整体审查](review-2026-10/README.md) | 当时的代码审查、界面审查和各方面方案，已拆进实现计划 | 快照，不再更新 |

以后再做整体审查时，同样放进 `review-<年>-<月>/` 目录，可执行的部分拆进实现计划，审查目录本身作为快照保留。
