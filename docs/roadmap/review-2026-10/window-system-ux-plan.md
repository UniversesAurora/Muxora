# 窗口系统与交互改进

> 2026-10 整体审查的快照，不再更新；可执行步骤以 [实现计划](../implementation/README.md) 为准，说明见 [审查目录](README.md)。

本文列出窗口系统在交互和配置上的缺口与冲突，并给出实现方案。设计约束沿用 [设置与命令](../../design/settings-and-commands-design.md)、[工作区](../../design/workspace-design.md) 等设计文档；这里只写“当前差什么”和“怎么补”。

## 1. 主题：深色与黑色

> 2026-10-19 修订：主题部分已扩展为独立的 [主题系统设计](../../design/theme-system-design.md)，实现步骤见 [阶段 2](../implementation/phase-2-themes.md)。原来“在现有 `Theme` 结构上加几个字段、给两套颜色”的方案不再采用。

要点：

- 行为与 VS Code 一致：`workbench.colorTheme`、`window.autoDetectColorScheme`、`workbench.preferredLightColorTheme`／`workbench.preferredDarkColorTheme`、高对比自动切换、`workbench.colorCustomizations`；“首选项：颜色主题”列表移动即预览、`Esc` 恢复；跟随系统时从列表选择会写入当前深浅色对应的首选项。
- 结构与 VS Code 一致：颜色注册表中每个颜色 ID 必须有浅色、深色、深色高对比、浅色高对比四类默认值；主题文件只写差异，可继承。
- 深色主题单独设计：以中性灰阶表达层次，强调色只用于少量位置；状态栏、收纳条、活动标签、标签颜色、拖拽指示、选中、阴影在深色下各有专门做法（设计 §3.2），不沿用浅色主题的大面积紫色。
- 协调性由机制保证：注册完整性测试、对比度测试、状态完整性测试、组件画廊及三套截图评审。
- 界面主题与终端配色分开；终端配色以颜色 ID（`terminal.*`）进入同一套主题。

## 2. 菜单与命令结构

**现状**：主菜单为“文件、视图、布局、窗口、工具、帮助”。

**问题**：

- **没有“编辑”菜单**。接入终端后，复制、粘贴、全选、查找、清屏都需要固定位置，Xshell、Windows Terminal、VS Code 都有。
- **“布局”和“窗口”边界模糊**。“布局”里按标签组、标签、窗格分层，“窗口”管窗口形态和切换；用户找“把这个标签移到新窗口”时不容易判断该去哪个菜单。
- **会话相关入口没有位置**。连接、重连、复制会话、打开 SFTP、端口转发以后都需要一个顶层菜单。

**建议结构**（接入业务时一并调整，现有菜单测试同步修订）：

| 菜单 | 内容 |
| --- | --- |
| 文件 | 新建标签／会话、打开会话管理器、保存／载入工作区布局、关闭标签、关闭窗口、退出 |
| 编辑 | 复制、粘贴、全选、查找、清屏／清除回滚（终端接入后）、RMB 行为切换 |
| 视图 | 命令面板、外观（主题、字体缩放）、显示各栏、全屏与禅模式 |
| 会话 | 连接、重连、复制会话、断开、SFTP、端口转发、广播输入（业务阶段） |
| 窗口 | 现在“布局”和“窗口”菜单的内容合并：标签组、标签、窗格、窗口形态、窗口切换、命名布局 |
| 工具 | 设置、键盘快捷方式、Lua（编辑器、脚本管理、重载） |
| 帮助 | 快捷键参考、打开日志目录、打开用户数据目录、关于 |

**建议新增的窗口功能**（按价值排序）：

1. **布局撤销**：模型使用不可变树，保存最近 N 个快照的成本很低（未变化的子树共享）。提供“撤销布局变更”（例如 `Ctrl+Alt+Z`），只恢复布局，不恢复已关闭的内容。快照数量有上限。
2. **命名布局**：类似 Visual Studio 的“保存窗口布局”（`Ctrl+Alt+1..4` 应用）。只保存结构和内容描述，不复制内容。
3. **最近关闭的标签**：保存最近关闭标签的内容描述（类型、会话配置 ID、标题），`Ctrl+Shift+T` 重新打开；容量有上限。
4. **按使用顺序切换**：`Ctrl+Tab` 按最近使用切换标签，松开 `Ctrl` 确认，和 Visual Studio、VS Code 一致。模型已有 `visitedOrder`。
5. **命令面板前缀模式**：`>` 命令、`%` 打开的标签、`#` 会话、`@` 当前标签内的窗格；匹配时高亮命中的字符，最近使用的排在前面。
6. **竖排标签／会话树**：上百个会话时横向标签条放不下。提供可选的竖排标签列表（Edge、Visual Studio 都有），支持按主机、标签颜色、分组过滤。
7. **窗格放大**：在标签内临时放大一个窗格，其他窗格保留（对应 tmux zoom、Windows Terminal 的切换窗格缩放），和现有“窗格全屏”区分开：后者铺满整个显示器。
8. **延迟恢复**：启动恢复上百个标签时，先只建标签条数据，内容在首次激活时创建；会话类内容在激活时才连接。这一条同时是内存要求，见 [性能 §2](performance-plan.md#2-非活动标签的视图按需创建)。

## 3. 快捷键：对标 VS Code

**现状**：支持 2–4 段序列、多绑定、逐绑定参数、`runCommands`、`User/keybindings.json`（严格 JSON）、按键查询。缺 `when` 条件、JSONC、文件监听、来源区分。

### 3.1 与终端按键的冲突（需要优先处理）

当前默认键位与终端控制字符或 shell 常用键直接冲突：

| 默认绑定 | 命令 | 终端中的常见含义 |
| --- | --- | --- |
| `Ctrl+W` | 关闭标签 | bash/zsh 删除前一个单词 |
| `Ctrl+S` | 保存布局 | XOFF（暂停输出）、Emacs 保存、bash 向前搜索历史 |
| `Ctrl+Q` | 退出 | XON |
| `Ctrl+K …` | 续键前缀 | readline 删除到行尾、nano 剪切 |
| `Ctrl+T` | 新建标签 | bash 交换字符 |
| `Alt+方向键` | 窗格导航 | 很多 shell 和编辑器按词移动 |

现在只有占位编辑器，所以问题还没暴露；终端一接入就会出现。参照 Windows Terminal 和 VS Code 的做法：

- 有了 `when` 之后，这些绑定加上 `!terminalFocus`，终端获得焦点时改用 `Ctrl+Shift+W/T/…`。
- 增加 `terminal.commandsToSkipShell` 一类设置：列出即使终端获得焦点也由应用处理的命令，其余按键都送给远端。
- 续键前缀 `Ctrl+K` 在终端焦点下默认不启用，或者改用 `Ctrl+Shift+K`。

### 3.2 `when` 条件与上下文键

按 [设置与命令 §8](../../design/settings-and-commands-design.md) 中已定的语法实现：

1. **上下文键服务**（放在窗口模块）：分层取值，顺序为全局 → 窗口 → 组 → 标签 → 窗格 → 内容。模块自动提供 `windowKind`、`groupLocation`、`contentType`、`paneCount`、`textInputFocus`、`viewMode`、`zenMode`、`sideBarsVisible`、`keybindingSequencePending` 等键；宿主可以给窗格或内容设置自定义键，例如 `terminalFocus`、`terminalMode`、`connectionState`。
2. **表达式**：手写小型解析器，支持 `!`、`&&`、`||`、括号、`==`、`!=`、`=~`（正则）、`in`、数值比较。解析结果缓存到绑定上，分发时只做求值。解析错误在快捷键界面和文件诊断中指出位置。
3. **分发**：本轮的“首键候选索引”可以直接扩展：先按首键取候选，再按 `when` 过滤；同一序列有多条规则时，后定义的用户规则优先，与 VS Code 一致。
4. **菜单**：菜单项和右键贡献使用同一套 `when` 决定是否显示。

### 3.3 快捷键编辑界面

参照 VS Code 的键盘快捷方式编辑器：

- 表格列：命令、按键、`when`、来源（默认、用户、Lua、扩展）。
- 搜索支持 `@source:user`、`@command:<id>`、按键录入搜索（已有“按键查询”，可以并入搜索框）。
- 行内操作：修改按键、修改 `when`、删除、重置为默认、复制命令 ID、“显示相同按键”（列出冲突）。
- 顶部按钮：打开 `keybindings.json`、打开默认绑定（只读 JSON）。
- **键位预设**：提供 VS Code、Visual Studio、Windows Terminal、Xshell 风格的导入预设，本质是生成一份用户规则。

### 3.4 文件格式

`keybindings.json` 改为 JSONC：允许注释和尾逗号。图形界面修改时只改动对应条目，保留用户的注释和格式（参照 VS Code `jsonc-parser` 的局部编辑方式，自己实现一个小的 JSONC 读写器）。外部修改通过 `QFileSystemWatcher` 加去抖动重新加载；文件损坏时保留上一次有效绑定并报告位置。

## 4. 设置界面与存储

**现状**：设置页每一项都手写控件；窗口行为设置随布局文件保存，界面语言在 `User/settings.json`（见审查 R10）。

**方案**：

1. **设置 schema 注册表**：每项声明 `id`、类型、默认值、枚举及显示名、范围、说明、作用域（应用、窗口、内容类型）、标签。模块和宿主各自注册，Lua 扩展也可以注册。
2. **界面从 schema 生成**：按类型生成开关、下拉框、数字框、颜色、文本、列表编辑器。保留现有的分类树、搜索和随滚动定位。
3. **对齐 VS Code 的细节**：
   - 修改过的项在行首显示竖条，齿轮菜单提供“重置”“复制设置 ID”“复制为 JSON”；
   - 搜索支持 `@modified`、`@id:`、`@tag:`；
   - 顶部“打开 settings.json”按钮；
   - 需要重启才生效的项显示提示。
4. **存储分层**：默认 < 用户（`User/settings.json`）< 配置文件／工作区 < 会话。窗口行为设置迁到用户设置；布局文件只存结构。迁移规则：用户设置里没有某项、而旧布局里有时，读取一次并写入用户设置。
5. **JSONC 与监听**：同 §3.4。
6. **配置文件（Profile）**：参照 VS Code 的 Profiles，一组设置、快捷键、Lua 和布局可以整体切换，例如“运维”和“开发”两套。放在 P2。

**验证**：schema 生成的每类控件有模型测试；修改、重置、外部编辑、损坏文件、迁移各有回归用例；界面测试只覆盖生成器和少量代表性设置项，避免每个设置都写一遍界面测试。

## 5. 其他交互问题

- **标签过多时的标签条**：已有细滚动条和完整列表。增加“标签搜索”（输入即过滤）和固定标签（钉住后靠左、只显示图标），与浏览器一致。
- **广播输入**：Xshell 的“发送到所有会话”、iTerm2 的广播输入、MobaXterm 的 MultiExec。窗口模块提供“窗格选择集”（多选窗格并显示标记），内容层负责实际发送。
- **通知**：不做通知中心（2026-10-20 用户决定，同类终端软件没有这个需求）。需要弹出文字消息时（Lua `ui.notify`、长任务完成等）一律使用 Windows 系统通知，不做程序内提示。
- **可访问性**：自绘控件已有可访问名称；还需要检查高对比主题和屏幕阅读器下的标签条、边栏。

## 6. 界面质量与面板调整

> 2026-10-19 新增。

- **整体标准**：所有界面以 Visual Studio、VS Code 为参照，遵守 [界面设计规范](../../design/ui-design-system.md)。现有界面与规范的差距见 [界面审查](ui-audit.md)：命令面板、窗口选择是带表头和按钮的居中对话框；标签组目标选择是三层嵌套菜单；重命名、Lua 运行、临时展开大小用系统默认输入框或 `exec()` 对话框；设置页和快捷键页信息过密、层次弱。处理方式是统一组件（快速输入、浮层、对话框、通知），见 [阶段 8](../implementation/phase-8-ui-quality.md)。
- **临时面板八向调整**：侧栏临时展开面板的四条边、四个角都可以拖动调整大小，位置仍按现有对齐规则，拖动只改变宽高（[窗口交互设计](../../design/window-interaction-design.md)，实现 8.2）。
- **贴窗口边缘时的冲突**：隐藏侧边栏后，左右面板一直延伸到窗口边缘；非最大化时窗口在客户区内侧约 8 像素的缩放命中区挡住了面板外侧边。解决方法是把窗口的左、右、下缩放区移到可见边框之外的不可见系统边框（与普通 Windows 窗口一致），可见外观和内容贴边都不变，不需要留白（[窗口交互设计“窗口缩放边框”](../../design/window-interaction-design.md#窗口缩放边框)，实现 8.1）。
